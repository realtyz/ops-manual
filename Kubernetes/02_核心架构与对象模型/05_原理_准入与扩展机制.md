# 准入与扩展机制

## 1. 问题背景：内置对象不够用时只剩"改核心"一条路

假设需要让这套系统认识一种新的对象，例如网关路由、快照或者训练队列。如果唯一的办法是往核心代码里加入新的类型与逻辑，那么会同时出现三类问题：

| 问题 | 具体表现 |
| --- | --- |
| 每新增一种对象都必须跟随上游的节奏 | 版本升级变成"把自身的补丁重放一遍" |
| 生态被核心的发版节奏阻塞 | 一个功能必须等待上游流程走完才能使用 |
| 核心会越来越重 | 存储、权限、校验与控制器逻辑全部堆积在同一个仓库中 |

解决的办法是**在链路上留出扩展点**，使外部既能声明新对象，也能为新对象编写逻辑，还能在对象落库前后介入处理。扩展点一共分为三类，它们位于链路的**不同位置**，所解决的问题也不相同：

| 扩展点 | 位于何处 | 能做什么 | 不能做什么 |
| --- | --- | --- | --- |
| 自定义资源 | 类型注册这一层 | 让 API 认识一个新的类型，并直接复用存储、权限、准入与事件等全部既有能力 | 它不会自动产生任何行为，只是能够被存储下来 |
| 聚合 API | 请求转发这一层 | 把某一组 API 请求转发给一个独立的服务处理，该服务可以使用自己的存储 | 它不参与其它对象的处理，其可用性由那个服务自行负责 |
| 准入钩子 | 写路径的中间 | 在对象落库之前改写它或者拒绝它 | 它不改变运行中对象的状态，也不能替代控制器 |

**"让对象产生行为"并不是扩展点的职责，而是控制器的职责**：声明了新类型之后，必须有控制器去观察它并采取行动。把自定义资源与控制器结合起来，就是通常所说的"Operator"模式。

## 2. 三类扩展点的边界

### 自定义资源

注册一个新的类型之后，它就获得了与内置对象同等的待遇：它能被授权系统管理，能被准入策略管理，能被选择器选中，也能出现在事件之中。然而，它不会自动具备行为，也不会自动拥有"状态"。按照约定，它同样使用期望态与观测态这两个字段区，但这一约定需要由编写它的人来遵守。

三条现场口径：

- **版本演进是自定义资源自身必须解决的问题**：同一个类型可以同时提供多个版本，其中一个被指定为存储版本，而不同版本之间需要进行转换。提交时写入哪一个版本，决定使用哪一套约定进行校验。
- **子资源可以单独开放**：声明"状态"子资源之后，写期望态与写观测态被拆分为两个请求，因此可以分别授权。这正是"调用方不该修改状态"这一原则的落地手段。
- **删除清理是它自身的责任**：当需要清理外部资源时，必须依靠 finalizer 与控制器相互配合。

### 聚合 API

当需要**自己的 API 语义或独立存储**时，可以把一组请求转发给独立服务。它与自定义资源之间的差别在于"由谁的代码来回答这个请求"：

| 维度 | 自定义资源 | 聚合 API |
| --- | --- | --- |
| 由谁处理请求 | 由入口组件自己处理 | 由一个独立服务处理 |
| 存储 | 与其它对象共用同一份存储 | 可以使用自己的存储 |
| 能力上限 | 受入口组件所支持的对象语义限制 | 可以实现完全不同的语义 |
| 代价 | 低；随集群一起升级 | 高；需要自行保证可用性、权限与升级兼容性 |

### 准入钩子

准入钩子在写路径中介入，并且分为两个阶段：第一阶段提供改写的机会，包括补充缺省值、注入内容与规范化；第二阶段提供拒绝的机会，用于合规判定。它们的作用范围与限制如下：

| 维度 | 事实 |
| --- | --- |
| 它只能看到本次被提交的对象 | 它不知道集群中最终会是什么样，因此跨对象的一致性判断很不牢靠 |
| 它只作用于写请求 | 已经存在的对象不会因为策略上线而被重新检查，除非该对象被再次写入 |
| 它是写路径上的强依赖 | 钩子不可用时，系统按失败策略可能拒绝相关写入；这属于可用性设计问题 |
| 它的超时时间很短 | 钩子适合完成快速判定，不适合调用响应缓慢的外部系统 |
| 它可以按条件裁剪触发范围 | 只对满足条件的请求触发，以避免给全部写入操作带来额外压力 |

## 3. 扩展的代价

扩展能力并不是没有代价的，其代价可以分为四类：

| 代价 | 表现 | 现场判据 |
| --- | --- | --- |
| 升级负担 | 自定义资源的版本、转换与存储版本必须跟随集群一起演进；聚合服务需要自行保证兼容性 | 升级之前检查弃用项与转换链 |
| 控制面负重 | 新类型的对象、事件与监听都与内置对象共享入口组件的资源 | 把对象数量与监听数量纳入容量考量 |
| 可用性风险 | 准入钩子与聚合服务都位于关键路径上 | 它们的副本数、超时设置、失败策略与降级预案 |
| 权限风险 | 能够注册新类型、能够修改策略配置，这本身就是一种高权限 | 这类权限应当按管理员级别对待，而不看它叫什么名字 |

## 4. 内置对象的版本演进也走同一套逻辑

理解了扩展机制之后，内置对象的版本演进就变得容易理解：一个新特性先以某个版本出现，经验证之后转正，旧的版本随后被弃用，并最终被移除。这条线索有固定的表述方式，**必须写成阶段式的过程，而不能只写终点**：

| 阶段 | 含义 | 现场含义 |
| --- | --- | --- |
| 引入 | 该版本可以使用，但不保证兼容 | 只有在明确接受风险的情况下才使用 |
| 转正（稳定） | 该版本被承诺保持兼容 | 可以放心依赖 |
| 弃用 | 仍然可以使用，但已经宣布将来会移除，使用时系统会给出提示 | 现在就应该安排迁移 |
| 默认关闭 / 锁定 | 该行为被改为默认不启用或者不可再启用 | 迁移窗口开始收窄 |
| 移除 | 该版本不再被接受 | 尚未迁移的对象与工具会直接失败 |

如果只写"将在某个版本中移除"，就会使人误判执行处置动作的时机；真正的判据是**当前处于哪一个阶段**，以及"默认关闭"发生在什么时候。这也是升级之前必须先检查一遍弃用项的原因。

## 5. 抽象模型的适用边界

1. **注册并不等于具备行为。** 自定义资源只是一份能够被存储下来的对象；如果没有控制器，它将始终停留在刚提交时的状态。
2. **版本兼容是扩展自身必须承担的责任。** 自定义资源的转换链与聚合服务的 API 语义，都必须由提供方保证；集群只提供机制。
3. **准入钩子的判断是"局部"的。** 它只能看到当前提交的对象，因此跨对象的全局一致性判断不能依靠它。
4. **策略上线不会回查存量对象。** 策略只作用于之后的写入，存量对象需要另行处理。
5. **钩子会带来可用性风险。** 当集群之外的组件挂在写路径上时，它的可用性也就成为集群的可用性。
6. **注册类型的权限等同于管理员权限。** 能够定义新类型、能够修改策略配置的人，也就能够间接影响整个集群的校验行为。

## 常见误解

| 常见说法 | 事实 |
| --- | --- |
| 「装了 CRD 就等于装好了功能」 | 还需要控制器；若没有控制器，它就只是一份能够被存取的对象定义 |
| 「准入钩子能看到整个集群的情况」 | 它只能看到这一次提交的对象；跨对象判断必须依靠控制器 |
| 「策略配好之后存量对象会被自动修正」 | 策略只作用于之后的写入；存量对象需要单独处理 |
| 「聚合 API 更灵活，所以更好」 | 它把可用性、权限与升级兼容的责任都交给了提供方；因此只在需要独立语义或独立存储时才使用 |
| 「扩展点不影响集群稳定性」 | 新类型、新监听与策略钩子都占用入口组件的资源，并且位于关键路径上 |
| 「旧 API 版本反正还能用，不急」 | 弃用是分阶段的，默认关闭与锁定之间可能只隔一个版本；等到升级时才处理就已经晚了 |

## 要点自测

**问：三类扩展点分别位于链路的什么位置，各自解决什么问题？**

答：自定义资源位于"类型"这一层，它让 API 认识新的对象并复用全部既有能力；聚合 API 位于"请求"这一层，它把一组请求交给独立服务处理，适合需要自己的语义或者独立存储的场景；准入钩子位于"写路径"这一层，它能够在对象落库之前改写或者拒绝该对象。这三者都不能让新对象自行产生行为，那必须依靠控制器。

**问：为什么"装了自定义资源"不等于"功能可用"？**

答：注册只是让对象能够被存储与校验。若要让对象产生实际效果，就必须有控制器去观察它并采取行动；此外，它所需要的清理动作也要依靠 finalizer 与控制器配合完成。缺少控制器时，对象将一直停留在提交时的状态。

**问：准入钩子为什么做不了"跨对象的全局一致性判断"？**

答：它的输入只是这一次提交的对象，既看不到集群中其它对象的最终状态，也看不到后续将会发生什么。要完成这类判断，必须使用控制器，让它在稳态上进行检查并加以纠正。

**问：为什么版本演进必须写成阶段式？**

答：因为"引入 → 转正 → 弃用 → 默认关闭/锁定 → 移除"之中的每一段，其现场动作并不相同。如果只写"某个版本会被移除"，就会让人以为还有很长时间；而实际上"默认关闭"可能更早发生，到那时尚未迁移的对象与工具就会开始失败。

**问：扩展机制带来的四类代价是什么？**

答：升级负担，即提供方需要自行维护兼容与转换；控制面负重，即对象与监听会占用入口组件的资源；可用性风险，即钩子与聚合服务位于关键路径上；权限风险，即注册类型与修改策略等同于高权限。

**第一反应不要做什么**：不要把"注册了新类型"当成功能已经完成；不要用准入钩子去做需要查看全局的判断；不要以为策略上线会修正存量对象；不要在写路径上挂载一个没有降级预案的外部服务；也不要把旧的 API 版本当成可以无限期保留的东西。
