
**本文件是本目录内容写作与结构的唯一依据。** `Linux/写作规约.md` 的写法可以借鉴，但不作为本目录的规则——两个领域的知识对象不同（见第二节），规则必须各自成文。

本目录的写作规则、12 章结构、判断性版本表与同步清单收在本文件；仓库总览见根 `README.md`。

## 一、定位与读者

- 定位：面向运维 / SRE 的生产判断力——把"生产现场真正会被追问的点"和"现场真正会遇到的故障"对齐。验收标准是**能不能在事故现场用出来**，不是能不能复述概念。
- 读者：会基本 Shell 与 `kubectl`，用过 `systemctl`、`top`、`docker`，但没有系统学过分布式控制面；容器与编排的机制由本目录负责补。
- 各章各篇都不写"这一章写给谁""需要什么基础""读完能回答什么"，也不出现应试口径（"脱稿讲 3~5 分钟""错题本""正确率""面试加分"）。需要限定推演时写"限时推演"，需要说追问时写"值班口径"。

## 二、知识体系怎么组织

### 主线：收敛链

Linux 的知识对象是**一台机器上的一个机制**（内核怎么处理它），证据在 `/proc`、`sysctl`、man。Kubernetes 的知识对象是**一条声明在分布式系统里怎么被收敛成事实**，证据在 API 契约、`status` 与 `conditions`、事件、控制器日志、节点侧工具。

因此每章内部统一跟**一条收敛链**走：

> 声明（API 契约：字段与准入把它变成什么）→ 谁在 watch 它 → 收敛动作（控制器 / 调度器 / kubelet 各做什么）→ 可观测事实（`status` / `conditions` / 事件）→ 代价与失败形态

每个领域都有自己的"一条声明"：工作负载是 Pod 声明，网络是 Service / EndpointSlice 声明，存储是 PVC 声明，安全是 Subject 与 Rule 声明。

**由这条主线派生的三条硬规定**：

1. **每条收敛链在"体系"层至多一篇，且必须是这条链的完整展开**；压缩成多篇短篇会让链条断裂。一章里存在多条链时（例如网络既有 Service 链也有入口链），每条链各有一篇体系篇；本章以哪条链为主，写在结构表的"主链"一列里。
2. **运维章的主链不是声明链**：可观测性与生产运维的知识对象是"一次告警到复盘"的时间线，按"看清 → 判定 → 改变 → 回退"展开，但不得因此省掉代价与失败形态。
3. **一个动作牵动几处，就要在几处分别给判据**：改一次 `requests` 会同时牵动调度、QoS 档位、驱逐顺序、配额、HPA/VPA，分布在不同的章就各写各的，不能只在一处写。

### 已裁定的分工

跨章主题的分工只写已经裁定过的部分，其余写作时按当章需要自行把握。通用规则一条：**主归属章写机制与判据，其余章只写自己那一段，同一机制不重讲第二遍。**

- 准入的关卡顺序与失败语义在第 02 章；扩展点类型、准入策略机制与 API 版本治理在第 03 章；策略内容与租户边界在第 09 章。
- 清单交付（模板化、服务端应用与漂移）在第 04 章；交付工具自身的实现不入库。
- 自动伸缩的机制与判据在第 06 章；容量规划与扩容流程在第 10 章；成本与装箱在第 06 章。
- etcd 的一致性与多数派原理在第 02 章；快照、恢复、成员变更与容量在第 10 章。
- 集群生命周期、控制面运维、节点池与节点基线、分层演练在第 10 章；多集群只保留纳管与批量升级窗口。
- 发布方式的机制（两组副本怎么并存、按什么判据确认可用、回退能恢复什么）在第 04 章；流量方向、入口规则与按比例分配在第 07 章。
- 存储声明的回收策略（集合删除与缩容时保留还是删除、缩容后还剩什么）在第 04 章；卷的供给、扩容、快照与数据一致性在第 08 章。

### 层的判定

沿收敛链依次问下面几句，问到哪句就落在哪层：

| 问句 | 落层 |
| --- | --- |
| 这句话在讲**声明本身**（字段契约、准入把它变成什么、API 语义），或**为什么必须这么设计** | 原理 |
| 在讲**谁 watch 它、按什么顺序收敛、`status` 怎么从一件事变成另一件事** | 体系 |
| 在讲**用哪把工具看哪个字段、怎么读、先看什么** | 实操 |
| 在讲**看起来是这个原因、其实是那个原因** | 判例 |
| 在讲**上限配在哪一层、交什么产物、和别的领域怎么接** | 治理 |

每层的**排除项**（越界即拆篇）：原理不写处置动作与现场案例；体系不写制度设计与参数怎么配；实操不写机制推演与制度设计；判例不写完整流程；治理不写机制原理。

原理篇与体系篇不写动手章节、不放脚本、不报告个人实测值。**需要读者自己验证的地方，在正文里可以少量命令演示，或者用一句话给思路。** 这两条都要按下面的限度执行：

- 正文里的命令是**判据的兑现方式**，不是工具清单。判据仍只写一次：已在读法表里写过的判据，命令侧只写清它取的是哪个字段、对照哪一条判据，不把判据重述一遍。
- **少量**按篇计：一篇之内点到为止，只在读者读到这里会产生"我凭什么信"或"我怎么确认"的地方给；凡不是判据兑现点的命令，一律挪到实操篇。
- 命令演示只给一行到两行，注释写 `# 验证：…`，只在可丢的实验集群执行的要当段标明并在同处给回滚步骤；贴输出要声明"数值仅示意"，并说明结果与集群形态、版本、发行版强相关。
- 只给思路的那一种是完整写法，不是省略写法：写清用哪个工具、读哪个字段、对照哪条判据即可，不承诺读者会看到什么数值。
- 原理篇的排除项仍然有效：**处置动作与现场案例不写进原理篇**。命令演示只服务于"确认机制确实这样工作"，不是为了指导现场动手。

### 章内构成与导航

- 篇目顺序固定：`原理 → 体系 → 实操 → 判例 → 治理`，篇名形如 `NN_层_关键词.md`；层名只有这五个、顺序不得变，**不规定每层或每章的篇数**。某层确实没有有出处的素材就整层不写，并在该章导读的篇目索引里留一行说明。
- 每章 `00_导读与知识地图.md` 写四块：知识地图（本章主链与横向关系）、术语速查（只收本章新引入的词）、关键字段的读法、篇目索引；**故障现场定位表放在本章实操篇**。导读不写参考文档，参考文档放各篇末尾。**第 01 章的导读作为遗留例外仍带一份参考文档**，由该章重写时按本节规则处理，其余各章不再出现例外。
- 第 12 章不套分层（对象是读者脑中的模型），篇名用 `NN_收口_关键词.md`，内部结构按收口需要自定。
- 每篇具体的节与顺序不在这里规定，写作时按已成章的写法自行把握；每篇结尾必备一句 `**第一反应不要做什么**：…`。

## 三、写作形态

- **行文用学术报告语体**：写完整句，主语与谓语齐全，句间用"因此 / 由于 / 若 / 反之 / 同时"这类显式逻辑连接；不把结论压缩成电报式的名词短语堆叠。
- **不用比喻与黑话代替机制本名**：把机制、占用与关系按本名写出来；任何结论都要落回字段名、单位、数值或错误文本。自检口径：把任意一句单独摘出来，读者不需要再问"这是什么意思"。
- **不使用跨章引用**：正文与导航篇都不写"见第 N 章""第 N 章"这类指路，也不写跨章的篇名。只允许**排除式划界**：用一句"这不是本篇负责的内容"划清范围，**不给方向**。正文同样不写"前面几节""上一节""后面会讲""下一节的前提"这类承接式指路：要承接上文就把结论重述一遍，要划界就用排除式表述。篇内的锚点式编号（`2.3`、`第 6 步`）不受此限，但不得指向本篇之外的篇。
- **黑话只在机制本名同句出现时可保留**：`水位`（文件系统已用容量）、`白障`（whiteout）这类社区用词，在**机制本名已在同一句内出现**时允许保留；只写黑话、不写本名的，不算通过。这类词若收进术语速查，首次出现处必须同时给出英文原词。
- **不使用 wikilink**（`[[...]]`），本章导读的篇目索引除外。引用块只用于呈现逐层演进中被剖析的回答。
- **不讨论文档自身结构**：不写"这篇讲什么""必须先读什么""本文将分三部分""30 秒速览""怎么用这篇笔记"，也不出现 `L1/L2`、`M1–M8` 这类等级与技能编号。
- **开篇形态不固定**：同一章同一层的多篇不得使用同一个开头标签（例如整章都以"问题背景："起笔），也不得逐篇套用同一种句式。开篇仍要先交代"这件事解决了什么问题、代价落在哪里"，再进入机制展开；可用结论前置、机制命名、边界设问或反事实设问，但同一章内要换着用。
- **给出数值就要给出读法**：凡让读者看某个字段，必须同时写清五件事——是什么、单位、判据、与谁同看、看到它转向哪一步。贴命令输出必须声明"数值仅示意、不代表你的环境"。
- 术语首次出现给中文解释 + 英文原词，缩写展开；**"首次"以章为界**，本章导读的术语速查负责本章新引入的词，前面章已展开过的词在本章不再重复解释。
- 破坏性操作标"只在可丢的实验集群"；只读观测标"生产集群上也可以做"。

## 四、事实纪律

**版本口径**

- **全库对照当前稳定版 1.37 与同主版本的官方文档与上游源码**；默认值、字段口径、版本门都以它们为准。本口径写在这里一次，各章正文不重复声明版本基线。与目标集群同一主版本取文档：老版本文档里的默认值已经变过，`latest` 描述的是尚未进入发行版的东西。
- **版本号只出现在判断点上**。判断点指三种情形：某个特性门控的默认值决定这个特性能不能用；某个默认值决定你怎么读现场（例如"没配"与"配了默认值"必须分开）；某次升级会改变行为或让旧写法失效。**不改变判断的演进史一律不写**，需要时以名带过（"门控默认关闭，在 kubelet / 调度器 / API 服务器的启动参数里查"），不追引入版本、不铺阶段对比。
- **版本门只在该门控决定判断时才写，写了就要是阶段式并给出处**：写成"弃用并告警 → 引入门控 → 默认关闭 → 锁定为不可再启用 → 删除门控"这样的阶段序列，每一段的版本号与 KEP 编号从下面的判断性版本表取值。只写"某个版本移除"会让人误判动手时机；不构成判断点的门控只写当前默认值与现场取值方式（见上一条）。
- **默认值要写清它是不是默认值、作用在什么范围**，且**不凭记忆写**：策略校验的字段与加固建议的字段常常不是一伙的（`readOnlyRootFilesystem` 是加固建议，不是 Pod Security Standards `restricted` 档的判定项），写混就是事实错误。取不到就写"未确认"，并说明还缺什么才能确认。
- **复核触发**：每当有新的次版本进入稳定发布，在下一个小版本发布之前完成两件事——核对下表的判断性版本行，以及核对各章默认值的现场取值方式。附录的长尾条目**不逐次复核**：读者需要时按表内来源自行核对。先改本文件的表，再改正文；两处不一致时以本表为准。

**实验环境与实测纪律**

- **能查文档就不实测；实测必须标环境与版本。** 实测分两档：**单机与 kind 档（默认）**用 Docker + containerd 与 kind 多节点集群跑 1.37，网络与 CSI 插件按需；**引导集群档**用 3 节点 `kubeadm` 加独立 etcd 或云上三台主机，控制面高可用、证书轮换与到期、etcd 快照与恢复、逐版本升级、驱逐与 `drain` 的长期行为必须在这一档做。
- **不允许用 kind 档的读数支撑**：etcd 恢复的 RTO 与 RPO、升级路径与版本偏斜、控制面容量与 etcd 性能、驱逐与回收的阈值行为。
- **上机结果不等于普遍结论**：命令输出与集群版本、发行版、CNI/CSI、节点规格强相关。没出现预想结果优先怀疑环境不匹配，而不是先改结论；实机结果写进正文必须写清环境，并说明可能只在该环境成立。字段名、路径、命令输出格式、版本门控这类客观事实可以也应当上机核对。
- 集群形态、插件与版本随篇注明；临时脚本、原始输出、草稿报告**不入库**，正文不引用它们。

## 五、高发错误清单

本节是第二至第四节规则的反例索引；规则修订时同步核对本节。以下错误类型按机制、版本、数值、口径四类合并，重写时逐条对照：

1. **机制讲偏**：把观察值安到错误的开关上；把加固建议与策略档位的判定项混为一谈（`readOnlyRootFilesystem` 不是 Pod Security Standards `restricted` 档的判定项）；术语类别混淆（准入控制器与准入插件、命令与内核接口文件、CRD 与内置对象、扩展资源与原生资源）；用比喻或黑话代替机制本名，让读者先解码措辞才能理解结论。
2. **版本号越界**：在不改变判断的地方给版本号（演进史、阶段对比、支持窗口外的引入版本，或只写"某个版本移除"）；引用无锚点（只写"官方文档""对应的 KEP"）；用了 `latest`、`main` 这类会漂移的形态；拿发行版文档或社区整理稿证默认值与字段语义。
3. **给出数值不给读法**：只写"看某个字段"，没写是什么、单位、判据、与谁同看、转向哪一步；输出样例未声明仅示意，或把自己的实测值当通用结论；破坏性操作缺边界（没有实验集群限制、没有回滚步骤、没有上限控制）。
4. **口径与形态**：同一件事两处写且数值或字段名不一致（含表格与正文两套口径、计数与自述不符）；归属错位的低配重复（把更深的专业篇章的内容在本章重讲一遍且讲得更浅）；文档自身结构声明（目标、关联复习、30 秒速览、怎么用这篇笔记、回到路线图）与应试口径；跨章 wikilink 与篇末缺边界句；同一章同一层同构开头，使各篇的问题意识被句式掩盖。

## 六、定稿自检

每篇写完立即逐条走：

1. 只有一个一级标题；除本章导读外没有 wikilink；引用块只出现在逐层演进处；
2. 篇末有「第一反应不要做什么」；
3. 正文无章号、无跨章指路、无"这篇讲什么"式声明、无应试口径；
4. 术语首次出现有中文解释 + 英文原词，缩写已展开；
5. 每个被引用的字段都给了"是什么 / 单位 / 判据 / 与谁同看 / 转向哪一步"；输出样例声明了仅示意或写明了环境；
6. 每个版本号都落在判断点上（它改变了哪个动作），且与判断性版本表一致；默认值带版本与现场取值方式，不把演进史写进正文；
7. 每层的内容没有越界；破坏性操作有边界与回滚；同一结论在本章没有两份写法，且与本章导读的篇目索引一致。
8. 正文里的命令都真的产生文中所说的输出；演示类命令是少量的、只出现在判据兑现点上，且没有把读法表里的判据重述一遍；只给思路的地方写清了工具、字段与对照的判据。
9. 同一章同一层的多篇没有使用同一个开篇标签，也没有逐篇套用同一种句式；开篇先交代问题或代价，再进入机制。
