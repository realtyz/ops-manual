# 运维 / SRE 岗位手册

> 一份面向 **运维 / SRE 岗位**的学习知识库，覆盖从单机 Linux 到容器编排、再到 GPU/RDMA 基础设施的完整链路。
>
> **定位**：不是把命令再过一遍，而是把「生产中真正会遇到的问题」和「现场真正会被追问的点」对齐——每个主题都按 **概念 → 生产实践 → 要点自测** 三层推进，验收标准从「能讲清」提升到「能交出东西」（一份基线卡、一份带回滚的变更记录、一段 Runbook）。
>
> **读者定位**：会基本 Shell、用过 `top`/`systemctl`/`kubectl`，但缺乏「从现象到根因」系统方法论、需要一套可复现、可交叉引用的复习地图的运维 / SRE 新人。

## 快速开始

1. **在 GitHub 上直接读**：所有目录与入口链接都是标准 Markdown 相对链接，点开即可浏览。
2. **在 Obsidian 中读（推荐）**：用 Obsidian 把本目录作为库打开，可获得篇内 wikilink、Mermaid、callout 的完整渲染与跳转（各篇笔记使用这些语法，GitHub 页面上不会渲染）。
3. 新人或按模块复习：从 [Linux 引言](Linux/00_引言.md) 进入，按「学习路径总览」逐阶段推进，每章入口是 `NN_主题/00_导读与知识地图.md`。
4. 容器与编排方向：从 `Kubernetes/01_容器技术/` 起，按章节目录顺序往下读（本库不设全局入口，也没有学习路线大纲）；GPU/RDMA 数据面方向：[AI-Infra 学习大纲](AI-Infra/00_简介.md)。
5. 跨主题复习：三份大纲各有一张「边界表」（见下），先厘清某个知识点属于哪份大纲，再回对应篇目深挖。

## 三大主题域的边界

同一个知识点只在一份大纲里展开，其余只引用不重复：

| 内容 | 归属 | 说明 |
| --- | --- | --- |
| 通用主机能力：systemd、内存/OOM、文件系统、TCP 排障、权限安全、日志监控、性能方法论 | [Linux 引言](Linux/00_引言.md) | 基础层，其余两份大纲的前置 |
| 通用主机侧调优：IRQ 亲和、软中断、MTU、网卡环形缓冲 | Linux 大纲 阶段 6 / 10 | 不放进 AI-Infra |
| 容器技术：镜像构建与层切分、镜像与内容寻址、分发与供应链、联合挂载与快照器、OCI 运行时与 CRI、节点侧的容器与镜像账目 | `Kubernetes/01_容器技术/` | 建立在 Linux 的 namespace / cgroup / 联合挂载之上，是编排层的前置；**Pod 层面的形态（沙箱、共享项、重启粒度）不属这一章**，归编排层 |
| 容器侧数据面：节点上的虚拟网卡与桥接、端口映射、绑定挂载的传播方式 | Kubernetes 大纲 第 07、08 章 | 第 01 章只保留「容器这一侧有几本账」与权限侧的挂载标志；数据面的落地归编排层的数据面两章 |
| 容器编排：对象与控制器、扩展机制与 API 治理、调度与容量、CNI/CSI、安全与多租户、GPU 编排与 gang 调度 | `Kubernetes/`（第 02 章起） | 编排与控制面 |
| GPU/RDMA 数据面：驱动与内核模块、PCIe/NUMA、RoCE/IB 无损网络、perftest、XID 硬件故障 | [AI-Infra 大纲](AI-Infra/00_简介.md) | 主机与网络数据面；K8s 侧只保留 Device Plugin / DRA 这类编排机制 |
| 训练 I/O 数据面：checkpoint、数据加载、共享文件系统、GPUDirect Storage | AI-Infra 大纲 阶段 7 | 通用文件系统知识仍见 Linux 大纲 |

**衔接关系**：Linux 是 Kubernetes 的地基——`namespace` / `cgroup` / 联合挂载这三个宿主侧机制是 `Kubernetes/01_容器技术/` 讲述的对象，Linux 侧只保留「站在宿主机上看容器」的入口。容器技术又是整个编排层的前置：一份制品怎么变成节点上的一组进程，决定了后面每一章讲对象与控制器时的现场口径。AI-Infra 依赖 Linux 主机能力，并与 Kubernetes 的 GPU / AI 编排章以「主机数据面 vs 编排控制面」为界；主机侧排障动作在三套体系下完全通用。
