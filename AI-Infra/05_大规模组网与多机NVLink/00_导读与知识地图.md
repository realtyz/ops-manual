# 大规模组网与多机 NVLink

## 知识地图

### 一次跨机集合通信在 fabric 上经过哪些跳：六段

本章的主链是**一次跨机通信**。它从通信库选定本机用哪块网卡、哪条轨道开始，经过交换机的叶层与脊层、子网管理器维护的转发表，最后到达对端；与单机内的 PCIe 路径不同，这条链路上有一半的判断对象不在本机上。

| 段 | 这一段在做什么 | 到这里要能说清 |
| --- | --- | --- |
| 1 选定本机出口 | 通信库按可用设备、轨道与平面选定用哪一块网卡 | 选路的判据是什么，以及选错时的现象 |
| 2 按轨道对齐 | 每台机器的第 n 块网卡接在第 n 条轨道上，同轨道的通信只走一跳 | 轨道对齐与「所有网卡接同一台交换机」在拥塞与等价多路径上的差别 |
| 3 在 fabric 内转发 | 交换机按子网管理器下发的转发表转发，或按以太网的等价多路径散列 | IB 与 RoCE 在这一段的运维差异是什么 |
| 4 分区与隔离 | 按分区键或虚拟局域网限定哪些端口可以互相通信 | 成员关系不对时的现象是什么 |
| 5 跨域扩展 | 同一个 NVLink 域内跨节点时，通信不走 RDMA 而走多机 NVLink | 什么条件下跨机不走 RDMA，以及它的诊断入口是哪一个服务 |
| 6 到达与确认 | 对端收下数据并回送确认，集合通信在软件栈上完成一次归约 | 归约是否被卸载到交换机（SHARP），以及开了之后数字该怎么变 |

**贯穿本章的三问**：这次失败是**本机侧**还是 **fabric 侧**；我手上的证据能不能证明是哪一条轨道、哪一个端口；这个问题该由主机侧还是网络侧先回答。

### 两个跨阶段的核对对象

| 核对对象 | 它贯穿哪几段 | 每一处读什么字段 |
| --- | --- | --- |
| 轨道与平面的编号 | 它贯穿段 1、段 2 与段 6，因为「第几块网卡走第几条轨道」这个对应关系同时由硬件接线、通信库选路与交换机端口三者确定 | 在段 1 读通信库日志里选定的设备与平面；在段 2 读网卡的 `:<port>:<rail>:<plane>` 一类字段与接线记录；在段 6 读故障时是哪几个 rank 掉队，再用拓扑发现工具把 rank 映射回交换机端口 |
| fabric 的身份与成员关系 | 它贯穿段 3 到段 6，因为转发表、分区键与 NVLink 域的标识分属三个不同的管理层 | 在段 3 读子网管理器的状态与转发表版本；在段 4 读端口的成员关系；在段 5 读 NVLink 域的标识在整个域内是否一致，以及交换服务的域状态与各节点的就绪状态 |

## 术语速查

| 名词 | 一句话解释 | 在哪一篇展开 |
| --- | --- | --- |
| 子网管理器（SM） | InfiniBand fabric 上负责发现拓扑、计算并下发转发表的集中组件 | 原理：IB 与 RoCE 在运维面上的差异 |
| UFM | 面向 InfiniBand fabric 的监控与管理平台，负责拓扑可视、告警与性能数据 | 原理：IB 与 RoCE 在运维面上的差异 |
| rail-optimized | 按轨道对齐的组网：每台机器的第 n 块网卡接到第 n 条轨道，每条轨道各有一组叶交换机 | 原理：rail-optimized 与多平面的取舍 |
| 轨道（rail）与平面（plane） | 轨道是「同一位置的那块网卡与它所属的交换机」，平面是同一轨道内互相独立的第二张并行网络 | 原理：rail-optimized 与多平面的取舍 |
| 超订比 | 下行带宽与上行带宽之比，决定多打一时会不会在脊层排队 | 原理：rail-optimized 与多平面的取舍 |
| ECMP | 等价多路径，以太网按散列在多条等价路径上分流；散列不均会让某条链路先拥塞 | 原理：rail-optimized 与多平面的取舍 |
| PKey | InfiniBand 的分区键，用来限定哪些端口可以互相通信，作用类似以太网的虚拟局域网 | 原理：IB 与 RoCE 在运维面上的差异 |
| SHARP | 把集合通信的归约动作卸载到交换机的机制 | 原理：IB 与 RoCE 在运维面上的差异 |
| MNNVL（多机 NVLink） | 把 NVLink 域扩展到多台机器，使跨节点通信不必经过 RDMA | 原理：多机 NVLink 与 IMEX 域 |
| IMEX（Internode Memory Exchange） | 管理多机 NVLink 域内跨节点内存交换的服务，也是这个域的诊断入口 | 原理：多机 NVLink 与 IMEX 域 |
| clique | 多机 NVLink 域里的一个连通分组标识，域内必须一致 | 原理：多机 NVLink 与 IMEX 域 |

## 关键字段的读法

| 字段 | 是什么与单位 | 判据 | 与谁同看 | 转向哪一步 |
| --- | --- | --- | --- | --- |
| 通信库日志里选定的网络设备 | 本次通信实际使用的网卡与端口 | 它应与该 rank 所在的轨道一致；若所有 rank 都选了同一块网卡，则轨道没排上 | 与该 rank 的节点名、以及主机侧网卡的 NUMA 归属同看 | 若选路与接线记录不一致，先查选路变量再看硬件接线 |
| 选路相关变量中与轨道有关的三项 | 分别是是否跨网卡取用、可用网卡清单及其轨道与平面字段、轨道与平面的分配策略 | 三项要与 fabric 的实际形态一致：轨道对齐的 fabric 与单一平面 fabric 需要不同的取值 | 与交换机侧的接线记录同看 | 取值与 fabric 形态不符时，先确认 fabric 到底是哪一种，再改取值 |
| 拓扑发现与诊断工具的输出 | 一张 fabric 的链路健康、错误扫描与资产清单 | 它回答的是「整张网」的问题；单机命令回答不了跨交换机的链路劣化 | 与主机侧的端口计数器同看 | 若某条轨道反复出问题，转入该轨道对应交换机端口的检查 |
| 交换服务报告的域状态 | 多机 NVLink 域的连通域是否处于工作状态、各节点是否就绪、连通矩阵是否成立 | 域状态应为工作态、各节点应为就绪态、矩阵对角线外应表示已连通 | 与 `nvidia-smi -q` 的 Fabric 段以及整个域内一致的 clique 标识同看 | 出现节点不可用或标识不一致时，先修域再加入训练任务 |
