## 知识地图

### 一次跨机集合通信在 fabric 上经过哪些跳：六段

本章的主链是**一次跨机集合通信**。它从通信库选定本机用哪块网卡、哪条轨道开始，经过交换机的叶层与脊层、子网管理器维护的转发表、分区或虚拟局域网的成员关系，最后到达对端并完成一次集合通信。与单机内的 PCIe / NVLink 路径不同，这条链路上有一半的判断对象不在本机上。

| 段 | 这一段在做什么 | 到这里要能说清 |
| --- | --- | --- |
| 1 选定本机出口 | 通信库按可见设备、轨道与平面选定用哪一块网卡 | 选路的判据是什么；显式变量、拓扑文件与实际接线三者不一致时现象分别是什么 |
| 2 按轨道对齐 | 每台机器的第 n 块网卡接在第 n 条轨道上，使同轨流量尽量留在本轨叶层 | rail-optimized 解决什么；它与「所有网卡接同一台交换机」在拥塞与等价多路径上的差别 |
| 3 在 fabric 内转发 | IB 交换机按子网管理器下发的转发表转发；RoCE 通常依赖以太网等价多路径散列 | IB 与 RoCE 在控制面、成员关系、遥测与故障收敛上的运维差异 |
| 4 分区与隔离 | 按 PKey 或 VLAN / VRF 限定哪些端口可以互相通信 | 成员关系不对时的现象；为什么它常表现为部分 rank 失败而不是整网不通 |
| 5 选择跨机域路径 | 通信库按拓扑探测结果选择 RDMA / IB / RoCE，或多机 NVLink 域内的路径 | MNNVL 硬件存在不等于路径被使用；域状态、clique 与通信库结论要同看 |
| 6 到达与确认 | 对端收下数据并回送传输层确认，集合通信在软件栈上完成归约或分发 | 传输完成与集合通信完成不是同一个口径；SHARP / NVLS 改变的是数据量与参与节点，不是「必然更快」 |

**贯穿本章的三问**：这次失败是**本机侧**还是 **fabric 侧**；手上的证据能不能证明是哪一条轨道、哪一个端口、哪一个域；这个问题该由主机侧、网络侧还是域管理服务先回答。

### 规模带来的四类变化

大规模 fabric 不是双机链路的简单放大。至少有四类变化会让同一个故障在现场表现出不同形态：

| 变化 | 它改变什么 | 排障时要补的证据 |
| --- | --- | --- |
| 故障影响面 | 一条 rail、一台叶交换机或一次 SM 切换可能影响一批节点与作业，而不是一个连接 | rank → node → NIC → rail → switch port 的映射，以及受影响作业清单 |
| 控制面收敛 | SM 重算、转发表更新、链路状态变化与 ECMP 重分布都有窗口期 | fabric 事件时间线与主机侧计数器差分必须按同一时间窗对齐 |
| 集合通信拥塞 | AllReduce / AllGather / ReduceScatter 的多打一与跨轨流量让超订比和散列不均在压力下暴露 | 交换机侧队列、丢包、拥塞标记与主机侧重传统计同看 |
| 证据聚合 | 单机命令无法回答「哪条 rail 反复劣化」这类整网问题 | 拓扑基线、fabric 体检结果、主机侧计数器与训练日志要能按 rail / port / time 聚合 |

### 三个跨阶段的核对对象

| 核对对象 | 它贯穿哪几段 | 每一处读什么字段 |
| --- | --- | --- |
| 轨道与平面编号 | 它贯穿段 1、段 2 与段 6：第几块网卡走第几条轨道，同时由硬件接线、通信库选路与交换机端口三者确定 | 段 1 读通信库日志里选定的设备、rail 与 plane；段 2 读网卡端口与接线记录；段 6 把掉队 rank 映射回交换机端口 |
| fabric 身份与成员关系 | 它贯穿段 3 到段 6：转发表、PKey / VLAN 与 NVLink 域标识分属不同管理层 | 段 3 读 SM 状态与路由信息；段 4 读端口成员关系；段 5 读 NVLink 域状态、clique 与各节点就绪状态 |
| 拓扑基线与变更记录 | 它贯穿交付、巡检、故障与回归：没有基线就无法判断「当前拓扑」是不是偏离了预期 | 交付时读 golden topology；巡检时读拓扑差异；故障时读事件与变更窗口；回归时读新旧拓扑、配置版本与计数器差分 |

## 术语速查

| 名词 | 一句话解释 | 在哪一篇展开 |
| --- | --- | --- |
| 子网管理器（Subnet Manager，SM） | InfiniBand fabric 上负责发现拓扑、计算并下发转发表的集中组件 | 原理：IB 与 RoCE 在运维面上的差异 |
| UFM | 面向 InfiniBand fabric 的监控与管理平台，负责拓扑可视、告警与性能数据 | 原理：IB 与 RoCE 在运维面上的差异 |
| 叶交换机（leaf）与脊交换机（spine） | 叶层直接连接主机网卡，脊层在叶之间转发跨轨或跨 Pod 流量 | 原理：rail-optimized 与多平面的取舍 |
| rail-optimized | 按轨道对齐的组网：每台机器的第 n 块网卡接到第 n 条轨道，每条轨道各有一组叶交换机 | 原理：rail-optimized 与多平面的取舍 |
| 轨道（rail）与平面（plane） | rail 是同一位置的网卡与其对应交换机组形成的并行通路；plane 是互相独立、可整体隔离的第二层并行网络 | 原理：rail-optimized 与多平面的取舍 |
| 超订比 | 下行带宽与上行带宽之比，用来描述多打一时上游需要排队的程度 | 原理：rail-optimized 与多平面的取舍 |
| ECMP | 等价多路径（Equal-Cost Multi-Path），以太网按散列把流量分到多条等价路径上 | 原理：rail-optimized 与多平面的取舍 |
| LID 与 GUID | IB 网络里端口在本子网内的地址标识，与全局唯一标识共同参与拓扑发现与转发 | 原理：IB 与 RoCE 在运维面上的差异 |
| 自适应路由 | 交换机按链路状态或拥塞情况在等价路径间调整转发路径的机制 | 原理：IB 与 RoCE 在运维面上的差异 |
| PKey | InfiniBand 的分区键（Partition Key），用来限定哪些端口可以互相通信 | 原理：IB 与 RoCE 在运维面上的差异 |
| SHARP | 把集合通信的归约动作卸载到 IB 交换机上的机制 | 原理：IB 与 RoCE 在运维面上的差异 |
| MNNVL（多机 NVLink） | 把 NVLink 域扩展到多台机器，使跨节点通信可以不经过 RDMA | 原理：多机 NVLink 与 IMEX 域 |
| IMEX（Internode Memory Exchange） | 管理多机 NVLink 域内跨节点内存交换的服务，也是这个域的诊断入口 | 原理：多机 NVLink 与 IMEX 域 |
| clique | 多机 NVLink 域里的一个连通分组标识，域内必须一致 | 原理：多机 NVLink 与 IMEX 域 |
| NVLS | NVLink SHARP，在 NVSwitch 域内提供归约与多播能力，与 IB SHARP 不是同一个机制 | 原理：多机 NVLink 与 IMEX 域 |
| 拓扑基线 | 交付时保存的预期拓扑、接线映射、成员关系与配置版本 | 治理：拓扑基线与变更治理 |
| golden topology | 拓扑基线中的标准拓扑图，用来和当前发现结果做差异比较 | 治理：拓扑基线与变更治理 |
| SM failover | 主 SM 不可用时备用 SM 接管并重算 fabric 的过程 | 原理：规模如何改变故障与证据 |
| 拓扑感知放置 | 按节点、网卡、GPU 与轨道的物理关系放置作业，属于编排层；本章只读它的数据面前提 | 原理：规模如何改变故障与证据 |

## 关键字段的读法

| 字段 | 是什么与单位 | 判据 | 与谁同看 | 转向哪一步 |
| --- | --- | --- | --- | --- |
| 通信库日志里选定的网络设备 | 本次通信实际使用的网卡、端口、rail 与 plane | 每个 rank 选择的设备应与它的节点位置和轨道一致；所有 rank 选同一块网卡时，先区分显式变量、拓扑文件与接线错误 | 与 rank 所在节点、网卡 NUMA 归属、接线记录同看 | 不一致时先核对生效变量与拓扑文件，再核对物理接线 |
| 选路相关变量 | 是否跨网卡取用、可用网卡清单及 rail / plane 字段、轨道与平面分配策略 | 三类取值要与 fabric 实际形态一致；rail-optimized 与单一平面 fabric 需要不同策略 | 与通信库日志开头打印的生效值、系统级配置文件同看 | 取值与 fabric 形态不符时，先确认 fabric 形态，再改取值 |
| 拓扑发现与诊断工具输出 | fabric 的链路健康、错误扫描、拓扑差异与资产清单 | 它回答整网问题；单机命令不能证明跨交换机链路劣化 | 与主机侧端口计数器、golden topology 同看 | 某条 rail 反复出问题时，转入该 rail 对应交换机端口与链路检查 |
| SM 状态与路由信息 | SM 是否运行、主备角色、拓扑发现与转发表状态 | SM 应处于稳定状态；重算、切换或拓扑差异期间不宜把瞬时计数当作稳态结论 | 与 fabric 事件时间线、作业异常时间窗同看 | 事件时间重叠时先按 SM / 路由收敛窗口分析 |
| PKey / VLAN 成员关系 | 端口属于哪个分区或虚拟网络 | 发端与收端必须在同一成员关系内；不对齐时常见部分 rank 建链失败 | 与 SM / 交换机配置、通信库报错文本同看 | 成员不一致时先修成员关系，再做性能测试 |
| 多机 NVLink 域状态 | 域是否工作、各节点是否就绪、连通矩阵是否成立 | 域应为工作态；节点应为就绪态；矩阵对角线外应表示连通 | 与 `nvidia-smi` 的 fabric / NVLink 状态、clique 标识、通信库拓扑探测结论同看 | 节点不可用或 clique 不一致时，先修域再加入训练 |
| 拓扑基线差异 | 当前发现结果与 golden topology 的差异清单 | 交付后差异应为空或对应已批准变更 | 与变更工单、SM 事件、作业异常时间同看 | 有未批准差异时先恢复拓扑或更新基线，再解释性能问题 |
| 交换机侧端口计数器 | 链路错误、队列、丢包、拥塞标记与流量速率，通常是累计值 | 取同一时间窗差分；必须与主机侧同链路计数器对齐 | 与该端口对应的 rail、节点与 rank 分布同看 | 差异集中在一条 rail 或端口时，把该 rail 从作业中隔离并继续定位 |
