# 第 06 章 从普通网络通信走向 RDMA｜内容大纲

## 读者起点与学习目标

读者具备 Linux 进程、内存和网络接口基础。第 05 章说明了多机作业的参与者为何交换数据，本章取其中一条跨机边，解释数据如何从一个参与者的缓冲区到达另一个。用到显存、CUDA Stream 和 PCIe 拓扑时，就地回顾第 02、04 章所需的概念。

1. 画出常规 TCP Socket、主机内存 RDMA 和两端显存直达的载荷路径，指出每段由谁搬运，解释卸载和减少拷贝的条件。
2. 从一次可靠连接上的工作请求推导两端要准备的队列、缓冲区和权限，按操作判断完成记录出现在哪里、缓冲区何时能复用、何时能交给接收应用或 GPU。
3. 将运行中的驱动和设备对回具体 GPU 与网卡，区分物理可达、内存可注册和传输成功的证据。能用主机内存与显存两轮测试定位缺口，并复算单向有效载荷带宽。

## 主例与推进顺序

两台裸机 Linux 服务器记为 A 和 B。各用一个 ConnectX 端口和一张 NVIDIA GPU。主路径为 A 写 B，先用主机内存走通一次可靠连接，再将两端缓冲区换成设备显存。第 02 篇用 1024 B 观察权限与边界，第 05 篇用 8 MiB 核算实际经过的路径，第 07 篇改为重复发送 64 KiB 的独立吞吐算例。设备标识和方向贯穿本章，例中数值、设备输出和故障记录均为教学设定。

第 07 章展开 InfiniBand、RoCE 与交换网络条件。第 08 章把双端点传输放回 NCCL 的多 Rank 通信。第 13 章讨论进程进入 Pod 后如何取得设备和网络。生产部署和长期基线留给相应章节。
