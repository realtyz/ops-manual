# 第 06 章 从普通网络通信走向 RDMA｜内容大纲

## 一、本章定位与前置知识

[第 05 章](../05_为什么一个作业需要多张GPU/00_内容大纲.md)解释了多机训练的梯度/激活同步与 PD 分离推理的跨节点 KV Cache 迁移为什么必须走出单机。本章聚焦跨机通信里最核心的一条点对点链路，从零讲透数据如何摆脱传统 TCP 协议栈的 CPU 拷贝泥潭，走向硬件 RDMA，最终经由 **GPUDirect RDMA** 实现两台服务器 GPU 显存之间的直接互访。

阅读本章默认读者已具备 Linux 进程、内存、Socket 网络基础，并了解前四章建立的 DMA、PCIe 拓扑、NUMA、BDF、HBM 与 CUDA Stream/Event 概念。网络底层封装与拥塞控制将交由 [第 07 章](../07_InfiniBand、RoCE与集群网络拓扑/00_内容大纲.md) 展开，多 Rank 集合通信编排归属 [第 08 章](../08_NCCL如何组织GPU间的通信/00_内容大纲.md)，Kubernetes Pod 接入高速网卡则延续至 [第 13 章](../13_Multus与RDMA_把高速网络交给Pod/00_内容大纲.md)。

## 二、核心学习目标

1. **看穿数据路径差异**：清晰对比传统 TCP Socket、主机内存 RDMA 与两端显存直达（GPUDirect RDMA）的数据路径，能独立核算每段载荷的搬运主体与主机内存中转拷贝量。
2. **掌握 Verbs 对象与操作语义**：建立 RNIC、保护域（PD）、内存区域（MR）、队列对（QP）、完成队列（CQ）与门铃机制的心智模型，准确区分双边 Send/Receive 与单边 RDMA Read/Write 的授权条件、完成记录落点与缓冲区复用时机。
3. **打通驱管栈与显存直达前提**：能把 Linux RDMA 驱动栈与 `lspci`、`rdma link`、`ibv_devinfo`、`devlink` 证据对回同一物理网卡，判读 GPU 与网卡之间的 PCIe 拓扑（`PIX`/`PHB`）、ACS 与 IOMMU 条件，厘清 DMA-BUF 与 `nvidia-peermem` 的分工。
4. **贯通训推场景与基准验证**：理解 GPUDirect RDMA 如何同时服务于分布式训练梯度交换与 PD 分离推理的 KV Cache 高速迁移（压低首字延迟 TTFT），并会用 `perftest`（`ib_write_bw`）做主机内存与显存对照测试、复算单向有效载荷带宽与定位故障断点。

## 四、本章贯穿场景说明

本章沿用 [全书基线与术语速查](../00_全书基线与术语速查.md) 的**双机互联最小集群**（`node-1` 作为发起端，`node-2` 作为远端；文内三张既有手绘插画将这两台节点对应标为 `节点 A` 与 `节点 B`）。

每台裸机配备一块挂载于同一 PCIe Switch 下的 NVIDIA GPU 与 ConnectX 高速网卡（`mlx5_0/1`），软件栈统一对齐 **Ubuntu 24.04 LTS（Linux 6.8+）**、**CUDA 13.2.1**、**rdma-core v57.0**、**perftest 26.07.8** 与 **NCCL 2.27.3**。
