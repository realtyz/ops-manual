
以下都是纸面材料。复用本章 A → B 的方向、两端 `mlx5_0/1` 和 GPU 0。A 与 B 各自的 GPU、网卡接到同一 PCIe Switch。先按题中给定的条件推导，再与参考推理核对。

## 材料一：只让 A 的网卡直接读取显存

一次分布式计算让 A 的 GPU 产生 `8 MiB`，B 的 GPU 消费这段数据。A 的显存可注册给本机网卡。B 暂时只把页锁定主机缓冲区注册给本机网卡。两端 RC QP 已就绪，B 发布目标 MR 的 RDMA 基址和 `rkey`，QP 与 MR 都允许远程写。A 用一条非 inline 普通 Write，从 B 目标 MR 的 `2 MiB` 偏移开始写入，A 要求成功完成通知。B 发布的 MR 长度是 `10 MiB`。

1. 从 A 的生产数据画到 B 的 GPU，标出两个网卡访问的本机缓冲区。指出只让 A 直达时的跨网载荷和中转拷贝量。若另用常规 TCP 搬运同样的 `8 MiB` 主机内存缓冲区，两端合计有多少用户与内核之间的 CPU 复制载荷？
2. 当前 Write 的目标范围有效吗？若只把长度加 `1 B`，且 A 的源 MR 足够大，会在哪端遇到什么条件？若地址范围保持原样，B 撤销旧 MR 并重新注册，A 继续使用已失效的 `rkey`，还会成功吗？
3. A 日志只有 `ibv_post_send() = 0` 时，它能否让 GPU 覆盖源缓冲区？A 随后取到 `IBV_WC_SUCCESS`，B 的接收 CQ 没有记录。补出 A 侧的生产依赖以及 B 的 GPU 可以读取结果前的其余步骤。若将普通 Write 换成 Write with Immediate，B 要增加什么操作，哪一步 GPU 依赖仍须建立？

### 参考推理

1. 载荷依次经过 A 显存、A 网卡、网络、B 网卡、B 已注册主机缓冲区，最后由 CUDA 复制进 B 显存。网卡在 A 发起本机 DMA 读，在 B 发起本机 DMA 写。跨网载荷 `8 MiB`，主机与显存之间还需在 B 复制 `8 MiB`，比两端主机内存中转少 A 的 `8 MiB`。这里的 GPU 拷贝与普通 Socket 的用户／内核复制属于不同的计数。常规 TCP 搬运同样大小的主机缓冲区时，两端各一次 `8 MiB` 的 CPU 复制，合计 `16 MiB`。
2. B 的合法区间为 `[0, 10 MiB)`，当前是 `[2 MiB, 2 MiB + 8 MiB)`，最后一个字节仍在 MR 内。再加 `1 B` 会触及 B 的偏移 `10 MiB`，超出远程目标。旧 `rkey` 已失效时，即使地址区间正确，远程授权也无法成立。必须按当前 MR 重新交付有效地址和密钥。
3. A 先等待生产 Stream 中代表数据就绪的 Event。提交成功只说明 WR 入队，A 的 GPU 要等这一条 Write 的成功 WC 且没有其他在途引用，再覆写源。普通 Write 不消耗 B 的接收项，B 的进程应先收到双方约定的通知，再从已写完的主机缓冲区发起 CUDA 复制，让消费 Kernel 在复制完成之后执行。例如将复制与消费排进同一 Stream，或用 Event 接起两条 Stream。若用 Write with Immediate，B 要预先投递 Receive，接收 WC 的立即数可用来找到目标槽位。该通知仍要接上主机到显存的复制与消费顺序。若后来 B 也改为显存直达，则以通知为起点，按所用 CUDA 映射和设备要求建立网卡写入对 GPU 的可见性。

## 材料二：两轮检验的证据断在何处

这是独立的 `ib_write_bw` 对照。保持 A 为客户端、B 为服务端，单 QP、单向 RC Write，每条请求 `65536 B`，共 `4096` 次。两端 `ibv_devinfo` 能打开所选设备，IB 端口均为 `ACTIVE`。B 的 GPU 与网卡在 `topo -m` 中为 `PIX`。主机内存轮成功，题设的计时区间为 `25 ms`。显存轮两端选定 GPU 0，B 取得 CUDA 导出的 DMA-BUF 文件描述符，随后打印 `Calling ibv_reg_dmabuf_mr(...)` 和 MR 分配失败。没有显存轮带宽结果。B 的网卡侧下游桥 `ACSCtl` 为 `SrcValid+ ReqRedir+ CmpltRedir-`。

4. 复算第一轮单向有效载荷和平均速率。两端端口状态、第一轮成功和第二轮的两条日志各自支持什么判断？
5. 如何用只读证据缩小 B 端的失败范围？对第二轮，哪几项证据齐备后才能判断 A 的 GPU 数据已经直达 B 的显存？如果两轮都成功，这些数据能否给出反向性能或集合通信吞吐？

### 参考推理

4. 总载荷 `65536 × 4096 = 268435456 B = 256 MiB`，按 `268435456 × 8 ÷ 0.025 ÷ 10^9` 得 `85.90 Gbit/s`。端口状态是本机就绪证据。第一轮进一步验证 A 写 B 的主机内存路径。第二轮的调用信息加失败记录说明 B 到达 DMA-BUF 导入并在 MR 注册处失败，因此现有材料还没有显存轮的传输结果。
5. 先对回 B 的实际 GPU、网卡 BDF 及进程加载的 provider，保存导出参数、注册调用、访问标志和错误码。再核对所用 GPU 分配、NIC 驱动与固件、上游桥和 IOMMU 的有效条件。`PIX` 描述连接级数，`ReqRedir+` 提示 B 网卡发起的对等请求可能被送往上游。是否经过上游、能否转回及是否导致此次注册失败，还须结合全路径、平台支持和错误信息判断。要支持第二轮的显存直达结论，应确认两端实际用了指定 GPU 的设备显存、相应 DMA-BUF MR 注册成功、A 对这些 MR 的 Write 成功完成。反向的网卡读写角色不同，需要反向测试。集合通信还需实际的 Rank、路径、算法和并发证据。

## 从设备、请求到可消费的数据

两端网卡和传输网络提供跨机路径，PCIe 与驱动映射决定每张网卡能直接访问哪些本机内存。QP 提供传输上下文，MR 限定设备可访问的地址与权限，WR 把操作和缓冲区交给设备，WC 报告执行结果。应用再用通知和同步把结果交给下一段工作。沿这几层看，同一份数据为什么需要中转、停在资源准备还是传输阶段、哪一方还在等待，都能用具体证据解释。

第 07 章将这对网卡放回 InfiniBand 和 RoCE 网络，解释地址、链路和拥塞如何影响跨机路径。第 08 章再把一条双端点传输放回多 Rank 通信，考察通信库如何组合多条路径。
