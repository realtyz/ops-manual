# 内容大纲

第 19 章 **节点交付、版本变更与集群持续运行** 训练读者评审一份生产交付与变更方案。从新节点应具备的能力出发，推导如何逐层验证、能承载几组作业、一次可退出多少节点，以及故障和变更之后凭什么重新开放容量。第 20 章将把这些决策放回作业的完整生命周期。

## 前置知识与本章深化

读者具备 Linux 与 Kubernetes 基础。本章沿用已完成章节的关键机制，在证据出现处回顾所需定义和约束。

| 已完成章节提供的前置 | 本章要深化的问题 |
| --- | --- |
| 第 01、03、04、12 章的 BMC 与机架条件、驱动和 CUDA 依赖、PCIe/NVLink、Operator 与节点验收 | 将组件版本扩展为可重建的目标基线与有效状态证据，明确节点镜像、Operator 和网络各自的管理方及版本耦合。将单卡探针扩展为可对照的跨节点验收。 |
| 第 06—09、13、15、16 章的 RDMA 与集合通信、割面、存储窗口、VF、成组放置和重试 | 把独立系统的约束换算成机架和整组的可承载容量，推导单路失效与滚动维护造成的缺口。 |
| 第 10、11、13、14 章的容器设备访问、资源上报、双网络、整卡与共享隔离 | 从交付路径识别能改变宿主状态的主体，区分权限入口、GPU 请求、物理设备隔离和网络执行点。 |
| 第 17、18 章的分层基线、时间窗、故障隔离、作业恢复与节点复归 | 将局部处置扩展到变更批次、性能门槛、回滚边界、资源撤回和恢复演练。 |

## 学习目标

1. 从硬件到工作负载写出一份可核对的基线，判断分层验收的证据覆盖了什么，以及节点何时可开放给生产调度。
2. 用供电、散热、网络割面、存储窗口和成组放置条件复算有效容量及维护余量，解释改变其中一项时的结果。
3. 根据版本耦合、作业状态和实测口径评审试点、排空、扩批与回滚。区分节点隔离、具体设备撤回、作业恢复和维修复归的完成条件。
4. 找到 GPU 管理权限和两张 Pod 网络的执行边界，设计最小的允许与拒绝验证。
5. 按依赖顺序组织配置、制品、检查点、外部服务与恢复证据，复算恢复预算并识别缺项。

## 贯穿场景与教学材料

- 将第 17—18 章的三节点十二卡作业规格扩展到双机架，保持每节点 200 Gb/s RoCEv2 与独立存储网。主例采用四卡 HGX H100 的直连 NVLink，八卡 HGX H100 的 NVSwitch 作为验收条件的变体。机架 A 为 `h1–h4`，机架 B 为 `h5–h8`，网络域在本例分别与两台 leaf 的接入范围重合。第 02 篇将 `h8` 从验收区放入 B。同步训练固定三 worker、每 worker 四 Rank，每个 Pod 需 4 GPU、16 CPU、96 GiB 内存和一个 SR-IOV VF，每节点至多放一个，同域为硬约束。后续发生的升级与故障是新的时间窗。
- 采用 Kubernetes v1.36 的 Device Plugin 和排空语义。主线取主机镜像维护内核与 GPU/NIC 驱动、GPU Operator 管理其余组件、Device Plugin 整卡发布与 CDI 注入。对照 v26.7.2 的 GPU Operator 机制和 NVIDIA CUDA 13.2 GA 工具资料。实际安装组合、驱动与固件支持、加载状态、应用镜像和运行时有效配置均需落到目标平台核对。
- 功率和冷却预算源于人为给定的整机输入及持续工况，网络算可用单向线路上界，存储用带读写混合比例的载荷速率。记录均为教学构造。集合对照保留三节点十二 Rank、64 MiB/Rank、FP32 求和、独立缓冲区和热身计时等固定条件。
- 验收、变更、恢复依赖用 Mermaid，容量、身份与观测值用正文表格。每图有图号、图注和紧邻的文字等价说明。检查图的对象、方向、状态、分支以及适用条件。当前编排以依赖、时序和账本为主。

## 写作与验收记录

| 易出现的推理缺口 | 写作与核验动作 |
| --- | --- |
| 把安装成功、组件就绪、设备上报和业务可用视为同一状态 | 用同一节点身份和一次容器启动对齐验收记录，第 08 篇要求指出缺少的下一层证据。核对各环节版本条件。 |
| 将空闲卡数直接作容量，或把端口标称相加当作实测 | 按工况分别计算节点、完整作业、方向性割面和存储峰值，再代入维护批量和失效条件。 |
| 在第一台新版本启动后立即扩批，或只保存 chart 版本作为回滚依据 | 对照混版本性能、已提交检查点和单域落点，分别验证试点功能、停批、原制品可取和回滚后复测。 |
| 把设备撤回、退出旧 Pod、维修结束或租户隔离混成同一个开关 | 使用状态表和策略执行点，检查旧分配、新库存、实际访问、默认网与附加网各自的证据。 |
| 只留 Kubernetes 配置，遗漏镜像、信任、外部数据和恢复顺序 | 演练资料查找、制品访问、节点和数据恢复、作业进度。用关键路径与已提交状态检查恢复目标。 |
