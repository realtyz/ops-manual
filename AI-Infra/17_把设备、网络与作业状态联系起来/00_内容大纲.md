# 第 17 章 把设备、网络与作业状态联系起来｜内容大纲

## 一、本章定位与前置知识

本章位于第四阶段“理解集群运维的完整过程”的开端。前 16 章已经打通单机硬件与 NVML（[第 01–04 章](../01_从一台GPU服务器认识基础设施/00_内容大纲.md)）、多机 RDMA/NCCL（[第 05–09 章](../05_为什么一个作业需要多张GPU/00_内容大纲.md)）及容器与多卡调度（[第 10–16 章](../10_GPU如何进入容器/00_内容大纲.md)）。

本章是 **DCGM / DCGM Exporter** 与 **Gauge / Counter** 的主定义章，不再重复展开上述基础机制。

本章聚焦把 GPU、网卡、交换机、存储和调度器的局部信号，组织成**带时间戳、带实体身份、带可比条件**的观测与基线体系，并补强**在线推理可观测性与性能基线**。这些记录将直接支撑 [第 18 章](../18_从故障现象追到具体层次/00_内容大纲.md) 故障定位与 [第 19 章](../19_节点交付、版本变更与集群持续运行/00_内容大纲.md) 交付验收。

## 二、核心学习目标

1. **掌握遥测采集链路与时序语义**：理解 `nvidia-smi`、DCGM、DCGM Exporter 与 Prometheus 的分层职责，区分 Gauge 与 Counter 两类时间序列及三个采样时钟，并能读懂 `/metrics` 暴露格式与缺测判读。
2. **闭合跨层身份关联**：结合主机设备清单、kubelet PodResources、Kubernetes 对象与容器进程探针，将物理 GPU 或 MIG 实例指标准确归属到当时的 Pod、作业尝试、训练 Rank 或推理副本，并用 PromQL 关联工作负载。
3. **拆解 GPU 硬件指标与推理因果映射**：辨析 GPU-Util、SM Active、Tensor Active、DRAM Active 与显存占用的分母差异；**打通在线推理业务指标（TTFT、TPOT/ITL、吞吐、排队、KV Cache 利用率、抢占率）与底层硬件指标的因果映射**，一眼识破显存与算力监控假象。
4. **对齐网络、交换机与存储时间窗**：沿 Pod 附加网卡追到 VF、PF、物理网口与交换机端口，复算端口发送速率，联动解读 ECN/PFC/CRC 与存储客户端/服务端队列，把握时钟同步误差边界。
5. **建立训推分层性能基线与有效进展账本**：逐层建立物理链路、单机卡间、跨机 RDMA、集合通信与**在线推理 / PD 分离 KV 迁移**基线；用统一分母核算排队、失败率与有效进展，并在双窗口对照中锁定训练与推理的主导瓶颈。

## 四、本章贯穿场景说明

本章围绕一套 **8 卡 HGX H100（80 GB）** 三节点训推共存集群展开。

软件基准统一为 `Linux 6.8–6.18`、`CUDA 13.2.1`、`PyTorch 2.9`、`NCCL 2.27.3`、`Cumulus Linux 5.11`、`Kubernetes v1.36`、`GPU Operator v26.7.2`、`DCGM 4.6.1`、`DCGM Exporter 4.8.4` 与 `Volcano v1.16.0`：

- **训练主线（`ai-demo/train-12`）**：三台节点（`node-1`、`node-2`、`node-3`）共 24 卡可分配，每台配备 NVSwitch 机内互联与独立 `200 Gb/s` RoCEv2 高速网口；训练作业在每节点运行 1 个 worker Pod，各占 4 张 H100 整卡与 1 个 SR-IOV VF。
- **推理主线（`ai-demo/infer-svc-1`）**：同集群推理池部署的大模型在线服务（单副本 4 卡 TP 或 MIG/Time-Slicing 共享实例），用于演示推理业务 SLO 指标与底层 GPU 指标的联动诊断及 PD 分离 KV 迁移基线对照。
