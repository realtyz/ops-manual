# 第 14 章配图说明

## fig-14-01-01 一张 GPU 的访问与显存容量

- **插入位置**　《一张 GPU 怎样给多个任务用》的 16 GiB 教学算例之后。
- **图注**　两侧各画同一张假想 GPU 的一种使用情形。左边只有任务 A 获得访问权，占用 12 GiB。右边两个任务均可访问 GPU，但 A 保留的 12 GiB 和 B 请求的 8 GiB 合计 20 GiB，超过这张卡的 16 GiB。数字为教学假设。
- **替代文本**　同一张 16 GiB GPU 的左右对照。独占时只有 A 可以访问，显存还有 4 GiB。共享访问时 B 也可以提交请求，但在 A 保留 12 GiB 的同时，B 的 8 GiB 请求无法放入剩余的 4 GiB。
- **验收重点**　两侧 GPU 与 16 GiB 显存槽的长度相同。右侧的 8 GiB 表示一次申请，画在显存槽外并标明容量不足。箭头表示设备访问权限，显存容量以槽内色块表示。
- **候选文件名**　`fig-14-01-01-gpu-access-and-memory-v01.png`

```text
为已有 Linux 基础的中文读者绘制 AI 基础设施教材手绘插画。图要回答两个任务都能访问同一张 GPU 时，为什么一个任务的显存申请仍可能失败。采用教学假设，一张 GPU 有 16 GiB 可用显存，任务 A 已占 12 GiB，任务 B 请求 8 GiB，其他开销忽略。

采用左右并排、同尺度的正视示意图。左侧标题是“整卡独占”，右侧标题是“共享访问”。每侧上方从左到右各放一张软件任务卡片，分别为任务 A 和任务 B。下方各放一张标为 GPU 0 的物理 GPU 模组，大小、位置与形状保持一致。每个模组上有小的 SM 运算单元区和长条形显存槽。在两侧各自的 GPU 边界内画出一根等长的显存槽，容量都为 16 GiB。显存槽左侧四分之三以浅琥珀色标出 A 的 12 GiB，右侧四分之一留空，标出剩余 4 GiB。两边显存槽的占用相同。

左侧任务 A 画一条灰色实线箭头连接到 GPU 0 边框，任务 B 的灰色短线在到达 GPU 前停止，在停止处画柔红色叉，标“未分配”。右侧两个任务各画一条灰色实线箭头到同一个 GPU 0 边框。靠近右侧模组的显存槽外部，画一个长约为整个显存槽一半的琥珀色虚线申请块，标“B 申请 8 GiB”。从申请块画琥珀色虚线箭头指向剩余的 4 GiB，箭头停在槽外并用柔红色小提示标“容量不足”。灰色实线箭头的图例是“可访问设备”，琥珀色虚线箭头的图例是“显存申请”。B 的申请块在显存槽之外，两个画区各自只画一个物理模组和一份显存。插图表达访问与容量，用同样的 SM 形状，省略执行时序。

逐字文字仅包含“整卡独占”“共享访问”“任务 A”“任务 B”“GPU 0”“SM”“显存 16 GiB”“A 占用 12 GiB”“剩余 4 GiB”“未分配”“B 申请 8 GiB”“容量不足”“可访问设备”“显存申请”。左右重复对象在各自画区各标一次，保留 GiB 大小写与数字。没有任务卡片占据 GPU 内部的物理空间，也没有在右侧凭空新增一段显存。

横向 16:9，按 1920×1080 构图，不透明暖白底 #FFFCF7，可有极淡纸纹。采用深灰 #1F2937 的细记号笔勾线，低饱和彩铅或淡马克笔。中文为端正手写印刷体，英文与技术标识为等宽手写印刷体，主标签约 44 px，次标签至少 36 px，水平排布。GPU、SM 与显存槽用绿 #2E8B70 和浅底 #E6F4EE，软件卡片和结构用灰 #64748B 和 #F1F5F9，显存占用和申请用琥珀 #D99A2B，阻断提示用柔红 #C65B5B。关键边界、线条端点和数量清晰，图例留白，不遮挡 GPU 和任务卡片。
```

## fig-14-03-01 跨 GI 与同 GI 的边界

- **插入位置**　《MIG 怎样切出硬件实例》「GI 定资源边界，CI 定计算范围」的两种布局对照表之后。
- **图注**　A100 40GB 的示意布局。左图的 A、B 使用不同 GI。右图的 A、B 在同一 GI 内各用一个 CI，计算边界分开，父 GI 的显存和相关路径由两者共同使用。图中的块大小不表示硬件数量。
- **替代文本**　两幅图各有一张物理 GPU 和两个 GI。左图每个任务连到一个不同 GI 内的 CI，各 CI 使用所在 GI 的显存。右图两个任务连到同一 GI 内的不同 CI，两个 CI 连到同一 GI 中唯一的显存块，另一个 GI 空闲。
- **验收重点**　右图的两个 CI 同属 GI 0，连接的显存块数量为一。GI 1 有独立的显存块，右图没有任务连入其中。左右各一张物理 GPU，GI 嵌套在 GPU 内，CI 嵌套在所属 GI 内。
- **候选文件名**　`fig-14-03-01-mig-gi-and-ci-v01.png`

```text
为已有 Linux 和 Kubernetes 基础的读者绘制中文 AI 基础设施教材插画。回答两个任务各拿到一个 CI 时，在哪种布局下它们共享同一份显存。平台为 NVIDIA A100-SXM4-40GB，画同一张物理 GPU 的两种示意状态。每个状态均设有两个 GPU Instance（GI），同一个 GI 内的计算可以划给一个或多个 Compute Instance（CI）。图表达资源归属，省略 Profile 数字、引擎数量和硬件比例。

采用同尺度的左右并排正视剖面。左右各只有一个标为 GPU 0 的物理边界。左侧题为“不同 GI”，右侧题为“同一 GI”。两画区中的 GPU 0 边框宽高相同。边框内左右各有一个较粗绿色圆角边界，左边标 GI 0，右边标 GI 1。每个 GI 的下部都画一个单独的绿色显存块，并在块内标“GI 显存”。每个 GI 的上部为计算区，计算区中的更小绿色卡片是 CI。两个 GI 的边界分明。每侧 GPU 上方有任务 A、任务 B 两张软件卡片。

左侧图中，GI 0 和 GI 1 各画一个标为 CI 0 的计算卡片。任务 A 的灰色实线箭头指向 GI 0 内的 CI 0，任务 B 的灰色实线箭头指向 GI 1 内的 CI 0。各 CI 向下用一条琥珀色虚线箭头连接所在 GI 自己的显存块。两条虚线都保持在各自 GI 边界内。

右侧图中，GI 0 上部并排画 CI 0 和 CI 1，各自有清晰轮廓。任务 A 的灰色实线箭头指向 GI 0 中的 CI 0，任务 B 的灰色实线箭头指向 GI 0 中的 CI 1。两个 CI 分别用琥珀色虚线箭头指向 GI 0 内同一个显存块，箭头端点并排落在该显存块的上沿。GI 1 的 CI 0 与显存保持和左图相同的位置，加小字“空闲”，没有任务箭头指向 GI 1。CI 的编号只在各自的 GI 内使用。两侧显存块都只属于各自的 GI，任何虚线都不得跨过 GI 边界。所有箭头都是逻辑关系，省略物理线路与实际比例。

逐字文字仅包含“不同 GI”“同一 GI”“任务 A”“任务 B”“GPU 0”“GI 0”“GI 1”“CI 0”“CI 1”“GI 显存”“空闲”“任务使用 CI”“访问 GI 显存”“示意布局”。“任务使用 CI”用于灰色实线箭头图例，“访问 GI 显存”用于琥珀色虚线箭头图例。相同对象仅在所属画区与边界内标注，数字零写成 0，CI 用大写字母。

横向 16:9，按 1920×1080 构图，不透明暖白底 #FFFCF7，可有极淡纸纹。深灰 #1F2937 细记号笔勾线，低饱和彩铅或淡马克笔。中文端正手写印刷体，英文和技术标识为等宽手写印刷体。主标签约 44 px，次标签至少 36 px，全部水平排布。GPU、GI、CI 与显存用绿 #2E8B70 / 浅底 #E6F4EE，通过轮廓粗细区分层级，软件任务卡片用灰 #64748B / #F1F5F9，访问显存高亮用琥珀 #D99A2B。采用克制的教材手绘风，留空放置图例和标签，保持隶属关系、对象计数和连线端点清晰。
```
