# 第 14 章 GPU 共享、切分与隔离｜内容大纲

## 读者起点与学习目标

第 02 章建立 GPU 执行、显存和利用率的关系，第 03 章建立 CUDA 与驱动的分工。第 10—12 章把设备从宿主机交到容器，区分资源上报、调度、设备分配和注入。第 13 章应用同样的分析方法，比较共享 HCA 和独占 VF。本章回到 GPU，解释分配单位改变后，任务实际上共享哪些资源、各自能得到什么。

读者有 Linux 和 Kubernetes 基础。本章在使用处回顾 Kernel、CUDA 上下文、UUID 与扩展资源，首次讲解共享机制及其硬件和软件边界。学完后应能完成四项任务。

1. 给定两个任务的驻留需求和执行时序，推导整卡独占、Time-Slicing、MPS 与 HAMi-core 分别改变哪些访问、容量和计算条件，指出如何验证干扰。
2. 从 GI、CI、Profile 和合法位置推导 MIG 设备的资源边界和可创建布局，解释同卡故障与实例隔离的关系。
3. 由节点配置和请求计算 Kubernetes 同名资源余量，区分调度、分配、注入和应用执行。对 HAMi 进一步推导逐卡预算及预留如何落实为设备。
4. 从负载需求选择候选池，跟踪一次 MIG 变更后的实例、库存及监控关系，并为性能和隔离要求提出可核对的证据。

## 案例、资料与适用范围

- 开篇沿用 16 GiB 教学设备。第 02 篇以后涉及具体型号时改用两卡节点 `gpu-mixed` 的独立教学快照，两张 A100-SXM4-40GB 分别记为 `GPU-A`、`GPU-B`。HAMi 使用同型独立池。配置间仅在明确的变更案例中有先后关系。Profile 保留厂商命名，应用和账本按 GiB、MiB 判读。
- NVIDIA 交付主例沿用第 12 章的 Kubernetes v1.36 和 GPU Operator v26.7.2，插件与 GFD 对照 v0.20.1，MIG Manager 对照 v0.15.1。MIG 与 MPS 分别依据指南 620 和 R595，HAMi 对照 v2.11.0 的发行资料和 chart。计算、配置摘录及对象快照属于教学材料。 [GPU Operator v26.7 组件矩阵](https://docs.nvidia.com/datacenter/cloud-native/gpu-operator/26.7/platform-support.html#gpu-operator-component-matrix) · [HAMi v2.11.0](https://github.com/Project-HAMi/HAMi/releases/tag/v2.11.0)
- 配图沿用第 01、03 篇各一幅手绘边界图并复核图注、替代文本与路径。时序、库存和放置算例以表格表达，变更流程使用 Mermaid。
