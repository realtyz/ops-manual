# GPU 集群与 AI 基础设施学习大纲

## 文档定位

本体系面向已经具备 **Linux 与 Kubernetes 基础**、希望系统掌握 **NVIDIA GPU 集群与 Kubernetes AI 基础设施**的工程师与读者。内容从单台服务器硬件与 CUDA 软件栈出发，逐步扩展到多机高速互联、数据与缓存供给、容器化设备与网络交付、资源共享与调度，最终落到观测、排障、变更交付与全流程串联。

**训练与推理双主线并重**：全书不局限于单一的同步训练场景，而是将**分布式训练**（大吞吐、长驻显存、同步集合通信、Checkpoint、Gang 成组调度）与**在线大模型推理**（Prefill/Decode 异构瓶颈、KV Cache 动态显存与多级卸载、量化、PD 分离、低尾延迟通信、模型冷启动加载、TTFT/TPOT SLO、细粒度共享隔离与弹性扩缩容）作为并列核心需求贯穿全书。上层范围止于 AI 基础设施层，模型算法训练技巧与完整业务 MLOps 平台不进入主线。

> [!info] 阅读前约定
> 无需 GPU 实机实验环境，全书统一采用推演、拓扑对照、带注释的命令/配置片段与章末实战检验建立工程直觉。全书统一的参考软件版本栈、示例口径、参考集群拓扑及核心术语索引见 [00_全书基线与术语速查.md](00_全书基线与术语速查.md)。

## 学习顺序

主线是：**一台 GPU 服务器如何工作 → 多台服务器如何协同与供给数据 → Kubernetes 如何交付与调度训推资源 → 如何观测、排障并持续运维整个集群。**

| 阶段 | 章节 | 学习结束后应能说明的事情 |
| --- | --- | --- |
| 一、理解一台 GPU 服务器 | 01—04 | GPU 如何执行训练与推理计算，软件如何驱动硬件，数据在 CPU、内存、GPU 与外设之间如何移动 |
| 二、理解多机协同与数据供给 | 05—09 | 训练与推理为何需要多卡多机，RDMA、网络与 NCCL 如何配合，存储与缓存如何决定吞吐与延迟 |
| 三、将 GPU 集群能力接入 Kubernetes | 10—16 | GPU 与高速网卡如何进入容器，如何被发现、切分共享与隔离，以及批处理训练与在线推理如何调度混部 |
| 四、理解集群运维的完整过程 | 17—20 | 如何建立训推观测与性能基线，逐层定位软硬件故障，完成节点交付与安全变更，并串联集群全生命周期 |

## 第一阶段：理解一台 GPU 服务器

### 01 从一台 GPU 服务器认识整套基础设施
- 沿输入到显存的数据路径理解 CPU、主机内存、GPU、网卡、NVMe 与 PCIe Switch 的职责分工，掌握逐卡显存核算。
- 从 PCIe 根端口、CPU Socket、NUMA 亲和与缓冲区落点推导本地及跨 Socket 路径，按链路方向核算并发带宽约束。
- 区分 PCIe 插卡、SXM 模组、HGX GPU 底板与整机规格，明确选型与上架需要核对的关键参数。
- 理解带内管理、BMC 带外管理，以及供电冗余、散热和机架条件对高密 GPU 节点的物理约束。
- 从单机延伸到集群网络平面：区分管理流量、协调控制流量、GPU 高速通信流量与存储流量的职责与故障域。

### 02 GPU 如何计算，显存为什么重要
- 理解 SM、CUDA Core、Tensor Core、Grid/Block/Warp 的并行粒度与 SIMT 执行模型，掌握寄存器/共享内存对驻留率的影响。
- 理解 HBM、片上缓存、主机内存的存储层次，区分显存容量与显存带宽分别卡住哪类工作。
- 掌握 FP32/BF16/FP16/FP8/INT8 等运算精度、算术强度与 Roofline 性能上界，区分纸面峰值与实际吞吐。
- **深入对比训练与推理两类核心计算特征**：
  - 训练的大批量矩阵乘（计算受限）与显存静态/激活构成；
  - **LLM 推理的 Prefill（计算受限）vs Decode（HBM 带宽受限）**双阶段本质；
  - **KV Cache 显存动态增长核算**、**FP8/INT8/FP4 量化**对容量与带宽的双重收益，以及 **Continuous Batching** 如何拉高 Decode 算术强度。
- 理解 Kernel、CUDA Stream 异步提交、事件同步与拷贝/计算重叠，厘清 GPU 利用率、计算效率与真实作业瓶颈的区别。

### 03 从驱动到 CUDA 应用的软件依赖
- 厘清 GPU 固件（含 GSP）、内核驱动模块、用户态驱动库（`libcuda`）、CUDA Runtime（`libcudart`）与 Toolkit（`nvcc`）的职责边界。
- 跟踪一个 CUDA 进程启动时的动态库装载、设备枚举、上下文建立与首次 Kernel 执行。
- 区分 `nvidia-smi`/NVML 管理支路与 CUDA 计算支路，理解为什么“能查卡不等于能算”。
- 掌握驱动版本、Toolkit 版本、设备架构（`sm_xx` / PTX JIT）与向后/次版本兼容性的判读方法。
- 理解 Linux 内核升级、模块构建/签名与动态链接库解析冲突如何导致 GPU 失效，能够按报错分层定位。

### 04 单机多卡与 GPU 数据路径
- 跟踪 CPU↔GPU 与 GPU↔GPU 数据搬运经过的物理组件与内存缓冲。
- 从 PCIe 代际、位宽、交换层级和共享上行带宽核算传输速率，理解分块流水与串行中转的耗时差异。
- 理解 CUDA P2P 访问条件、ACS/PCIe 路由与主机内存中转的切换条件。
- 理解 NVLink、NVSwitch 与多卡互联底板的优势，以及 Fabric Manager 等管理组件在互联就绪中的职责。
- 会读 `nvidia-smi topo -m`、PCIe 拓扑树与设备标识（UUID/BDF），将进程序号映射回物理卡与 NUMA 亲和布局。

## 第二阶段：理解多机协同与数据供给

### 05 为什么一个作业需要多张 GPU（训练与推理并行架构）
- 从显存墙、算力墙与延迟墙出发，分别说明**大规模训练**与**大模型在线推理**突破单卡边界的驱动力。
- 掌握分布式基本对象：进程、Worker、Rank、Local Rank、World Size、Rendezvous 会合与设备映射。
- 理解核心集合通信原语（AllReduce、AllGather、ReduceScatter、Broadcast、All-to-All）的数据输入输出语义。
- 系统梳理**训练并行形态**（DP、FSDP/ZeRO、TP、PP、EP）的数据归属、显存收益与通信模式。
- **系统梳理推理多卡架构与并行形态**：
  - 推理侧 **TP（追求极致低延迟、每层强依赖高带宽低延迟 AllReduce）**、**MoE 推理的 EP（All-to-All 负载均衡与延迟敏感）** 与 **多副本 DP 水平扩容**；
  - **Prefill / Decode 分离（PD Disaggregation）架构**：为何要将 Prefill 与 Decode 拆池部署，以及由此产生的**跨实例 KV Cache 点对点高速迁移**需求。
- 理解同步训练中的慢成员与重试放大效应，以及推理侧单副本异常或通信抖动对尾延迟（P99）的冲击。

### 06 从普通网络通信走向 RDMA
- 对比传统 TCP Socket 与硬件 RDMA 的数据路径，理解 CPU 拷贝、内核协议栈开销与硬件卸载的本质差别。
- 掌握 RDMA 核心对象（RNIC、Verbs、QP、CQ、MR、PD）与内存注册、门铃通知及访问授权机制。
- 区分 Send/Receive 与单边 RDMA Read/Write 的控制流差异，理解 RC 建连与完成通知过程。
- 理解 Linux RDMA 驱动栈与厂商软件栈的关系，学会解读常见设备状态与 `perftest` 基准。
- 深入理解 **GPUDirect RDMA** 如何让网卡直达 GPU 显存，以及 PCIe 拓扑、IOMMU、ACS、DMA-BUF 等核心前提。
- **结合训推场景**：除了训练梯度传输，解释 **PD 分离推理架构下利用 RDMA / GPUDirect RDMA 跨节点直接传输 KV Cache** 的数据路径与同步要点。

### 07 InfiniBand、RoCE 与集群网络拓扑
- 比较 InfiniBand 与 RoCEv2 的协议封装、寻址方式（LID/GID/IP）与路由特点，理解原生 RDMA 与 IPoIB 的分工。
- 理解 Spine-Leaf / Clos 拓扑、收敛比、ECMP 哈希冲突与多 Rail（按 GPU 隔离平面）设计如何影响多机通信。
- 掌握 RoCEv2 无损/有损拥塞控制机制：队列积压、DSCP/PCP 映射、ECN/CNP 端到端降速与 PFC 逐跳暂停及背压扩散风险。
- 理解 **Scale-up（机柜级 NVLink 域，如 GB200 NVL72）与 Scale-out（IB/RoCE 计算网）** 的架构分工，剖析超大 NVLink 域对大 MoE 推理低延迟与大 EP 通信的变革意义。
- 对比训练大流（带宽敏感、ECMP 哈希碰撞）与推理小消息/KV 突发流（尾延迟敏感、微突发排队）对集群网络的差异化要求，学会区分有效吞吐、拥塞与物理链路错误。

### 08 NCCL 如何组织 GPU 间的通信
- 厘清启动器、训练/推理框架、NCCL、CUDA 与底层互联/网络之间的职责边界。
- 理解通信组（Communicator）建立、集合操作提交到 CUDA Stream 与设备真正完成之间的异步关系。
- 剖析 Ring 与 Tree 等核心集合算法在不同节点规模和消息大小下的权衡，理解**训练大梯度（吞吐优先，偏向 Ring/多通道）**与**推理 TP 小消息（微秒级延迟优先，偏向 Tree/NVLink 直连/LL 协议）**的路径与算法选择差异。
- 理解 NCCL 如何自动发现拓扑并映射到 NVLink、PCIe P2P、SHM、RDMA/Socket 传输层，以及推理 KV Cache 传输中点对点通信（P2P/专用传输库）与集合通信的职责分工。
- 会读 `NCCL_DEBUG` 日志、识别选路与卡顿阶段，并正确解读与复算 `nccl-tests`（`algbw` / `busbw`）与 `perftest` 结果。

### 09 GPU 的数据从哪里来：存储与 I/O
- 沿“存储介质 → 主机页缓存 → CPU 预处理 → 锁页缓冲 → H2D → 显存”跟踪训练数据供给链路，理解 DataLoader 并发、预取与 H2D 流水线。
- 对比本地 NVMe、共享文件系统、并行文件系统与对象存储的访问特点，区分元数据小文件瓶颈与顺序大吞吐瓶颈。
- 掌握训练 **Checkpoint 写入与恢复读取**的一致性、突发带宽冲击与异步落盘思路。
- 理解 **GPUDirect Storage（GDS）** 的直达路径、前置条件与适用边界。
- **深入强化推理侧存储与多级缓存路径**：
  - **百 GB 级模型权重冷启动加载**：从对象存储/共享存储/本地 NVMe/主机内存预热到显存的耗时拆解，如何成为推理弹性扩容（Scale-out）的速度瓶颈；
  - **KV Cache 多级卸载与 Prefix Caching**：热数据留 HBM、温数据卸载至主机内存、冷前缀下沉到本地 NVMe 或分布式缓存池的数据路径与带宽权衡。

## 第三阶段：将 GPU 集群能力接入 Kubernetes

### 10 GPU 如何进入容器
- 理解容器共享宿主机内核而隔离文件系统/设备视图的本质，厘清镜像内 CUDA Runtime 与宿主机驱动库的边界。
- 掌握 OCI 配置中的设备节点（`linux.devices`）、cgroup 访问权限规则与只读库挂载。
- 深入理解 **CDI（Container Device Interface）** 如何用标准设备描述文件实现 containerd 原生注入，明确“设备注入”与“资源分配”的分工。
- 对比原生 CDI 与 NVIDIA Container Toolkit 包装层（JIT CDI / Legacy Hook）的运行时路径差异。
- 掌握宿主机物理卡、UUID、BDF、设备节点与容器内 CUDA 进程序号的映射，以及“宿主机可见、容器不可用”的分层排障思路。

### 11 Kubernetes 如何发现与分配 GPU
- 跟踪 Device Plugin 的注册、设备列表上报、健康状态更新与 `Allocate` 交接全流程。
- 厘清扩展资源（`nvidia.com/gpu`）、Node `Capacity`/`Allocatable`、调度器请求账本与 kubelet 本地选卡的职责分离。
- 理解 NFD 与 GFD 如何通过节点标签表达卡型、显存、互联能力，区分“节点标签筛选”与“设备资源计数”。
- 掌握 **DRA（Dynamic Resource Allocation）** 的核心对象（`DeviceClass`、`ResourceSlice`、`ResourceClaim`），理解它为何能突破传统整数扩展资源的表达瓶颈。
- 梳理 Device Plugin、DRA 与 CDI 三者在发现、分配与注入链路中的协作关系。

### 12 GPU Operator 如何管理节点软件
- 将驱动、Container Toolkit、Device Plugin、GFD、DCGM Exporter 等零散组件收束到同一张节点依赖图。
- 理解 GPU Operator 通过 Helm、`ClusterPolicy` 与 DaemonSet 协调节点组件的工作机制。
- 厘清宿主机预装驱动与 Operator 托管驱动的维护责任边界，以及离线环境、异构节点池的部署策略。
- 跟踪新节点入池状态流转，学会用 Validator、组件日志与节点状态定位部署异常，了解托管 DRA 的演进路径。

### 13 Multus 与 RDMA：把高速网络交给 Pod
- 理解 Pod 默认网络（协调控制与服务流量）与附加高速网络（RDMA/RoCE 数据流量）的分工与路由机制。
- 掌握 Multus 委派机制、`NetworkAttachmentDefinition`（NAD）及附加网络 IPAM、路由与 MTU 配置。
- 对比 **SR-IOV 独占 VF** 与 **共享 HCA / RDMA 命名空间**两类高速网络接入方案的隔离性、资源形态与选型取舍。
- 理解 GPU 与 VF 的节点内 NUMA/PCIe 对齐，以及 Network Operator 与 GPU Operator 协作实现 Pod 内 GPUDirect RDMA 的条件。
- 明确默认网与附加网在安全策略覆盖（NetworkPolicy vs MultiNetworkPolicy）与故障定位上的边界。

### 14 GPU 共享、切分与隔离（以在线推理为主战场）
- 从整卡独占的利用率浪费与显存驻留约束出发，剖析为什么在线推理服务是 GPU 共享与切分的核心诉求场景。
- 建立在线推理的核心隔离评判标尺：**TTFT（首字延迟）、TPOT/ITL（单 token 生成延迟）、P99 尾延迟抖动与邻居干扰**。
- 深入对比四类共享切分机制的底层原理、显存与算力隔离强度及故障传播域：
  - **Time-Slicing（时分轮转）**；
  - **CUDA MPS（多进程并发与算力/显存上限）**；
  - **MIG（硬件级 GI/CI 物理隔离、Profile 与卡内碎片）**；
  - **HAMi（逐卡调度、软件层显存/算力硬限额与按需 MIG）**。
- 跟踪 Kubernetes 中整卡、共享名额、预建 MIG 与按需切分的资源库存、重配置生命周期与监控归因，学会按推理/开发/训练负载特征选定资源池策略。

### 15 从单个 Pod 放置到多卡作业调度（训练与推理双轨调度）
- 从分布式训练的成员会合依赖出发，解释为什么普通逐个 Pod 调度会导致部分占卡死锁，引出 **Gang 成组调度**与弹性作业。
- 梳理“作业准入 → Pod 跨节点/网络域放置 → 节点内 Topology Manager / CPU Manager 的 NUMA 对齐”三层调度职责。
- 剖析 GPU 碎片、装箱（Binpack）、队列公平、优先级与抢占对集群利用率和大作业排队时长的影响。
- **建立在线推理服务调度与训推混部视角**：
  - 推理调度为何不需要 Gang，而聚焦**高可用反亲和、快速冷启动、亲和权重缓存节点、以及感知 KV Cache 压力与队列深度的请求级智能路由/弹性扩缩容（HPA/自定义指标）**；
  - 训推混部集群中，如何在白昼推理高峰期通过高优先级抢占与灵活资源池切分保护推理 SLO，并在夜间把空闲算力平滑释放给离线训练。

### 16 Volcano 的作业调度与队列管理
- 掌握 Volcano 的 Scheduler、Controller、Admission 组件，以及 `VolcanoJob`、`PodGroup`、`Queue` 的状态流转。
- 跟踪作业入队、成组放置、Queue 份额分配、装箱排序、同队列抢占与跨队列回收的完整决策逻辑。
- 厘清调度器与训练框架在成员失败重试、Checkpoint 恢复和资源归账之间的责任边界。
- 对照 **Kueue** 的准入控制模式与 Volcano 的调度分工，说明组合架构下的控制权边界，以及如何用 Queue 配额与优先级体系隔离在线推理池与离线训练池。

## 第四阶段：理解集群运维的完整过程

### 17 把设备、网络与作业状态联系起来
- 掌握 NVML、`nvidia-smi`、DCGM、DCGM Exporter 与 Prometheus 的遥测采集链路，区分 Gauge 与 Counter 及多级采样时钟。
- 建立跨层身份关联：将物理 GPU UUID、MIG 实例、节点、Pod、训练 Rank 或推理副本串联到同一时间窗。
- 学会联动解读 GPU（SM 活动、Tensor Core、显存、HBM 带宽、温度功耗、ECC、NVLink）、网卡/交换机（ECN/PFC/CRC/吞吐）与存储指标。
- 建立分层性能基线：物理链路 → 单机多卡 → 跨机 RDMA → 集合通信。
- **建立在线推理可观测性与性能基线**：打通业务侧指标（**TTFT、TPOT/ITL、吞吐 tokens/s、请求排队时长、KV Cache 利用率、请求抢占/换出次数**）与底层 GPU 算力/HBM 带宽利用率的因果映射。

### 18 从故障现象追到具体层次
- 建立分层排查思路：从现象出发，按硬件枚举 → 驱动与容器注入 → CUDA 执行 → 多机网络与集合通信逐层缩小范围。
- 掌握单机故障定位：“GPU 不可见”与“GPU 可见但初始化/显存/计算失败”的关键证据区分。
- 掌握运行期硬故障分析：将 Xid 错误码、ECC 不可纠正错误、PCIe AER、NVLink 异常与交换机 CRC 对齐到同一时间线，区分根因与下游超时症状。
- 掌握多机启动异常与训练步退化分析：定位会合失败、RDMA 注册失败、慢 Rank、网络拥塞、数据等待与硬件降频。
- **掌握在线推理典型故障定位**：排查 TTFT/TPOT 尾延迟飙升、KV Cache 耗尽导致大量请求抢占重算（吞吐雪崩）、同卡共享邻居干扰、以及 PD 分离下 KV Cache 传输超时。
- 闭合处置流程：故障隔离、区分作业恢复验收与故障节点维修复归验收。

### 19 节点交付、版本变更与集群持续运行
- 建立新节点从硬件上架到进入生产池的生命周期管理与统一配置基线，防范配置漂移。
- 明确 GPU 节点管理权限、设备访问控制与多租户附加网络隔离边界。
- 制定**分层交付验收体系**，并区分**训练资源池**（全互联 NVLink/RoCE 集合基线、存储吞吐）与**推理资源池**（MIG 切分验收、本地盘权重预热、单卡/多卡延迟 SLO 基线）的准入标准。
- 结合机架供电、散热、网络域容量与维护余量规划集群，建立检查点与配置恢复预算。
- 掌握驱动、内核、镜像与 Operator 升级的排空（训练等检查点 / 推理无损摘流）、小批试点、回滚策略与故障设备撤回复归闭环。

### 20 用完整场景串联整套知识
以一个**训推共存的多机 GPU 集群**为统一实战背景，完整串联前 19 章知识：
- **一次多节点作业的完整生命周期**：提交 → 排队准入 → 成组放置 → GPU/VF 交付 → 容器启动 → 会合与通信 → 运行与资源回收。
- **一次容量与调度冲突分析**：集群看似“还有空闲 GPU”，却叠加了在线推理高峰占位、型号/网络域隔离、VF 配额、队列上限与 GPU 碎片等多重约束。
- **一次跨层性能退化定位**：对照正常基线，在训练步退化与推理尾延迟飙升场景中横跨存储/KV 缓存、CPU、网络队列与 GPU 硬件锁定真凶。
- **一次硬件故障与恢复闭环**：将 PCIe/GPU 硬故障、训练整组重试、推理副本无损漂移、节点隔离与维修复归连成一条时间线。
- **一次集群版本变更评审**：审查节点镜像/内核升级的兼容性影响，评估试点回归证据，执行安全回滚并验证业务恢复。
