# 第 09 章 GPU 的数据从哪里来：存储与 I/O｜内容大纲

## 一、本章定位与前置知识

前八章已经打通了 GPU 计算、单机总线、RDMA 与集合通信。本章补上第二阶段的最后一块核心拼图——**存储、数据供给与多级缓存**，全面覆盖训练与推理两条截然不同的 I/O 主线：

- **分布式训练主线**：源源不断地把磁盘或远端存储里的训练样本送进显存（避免 GPU 算力空等），并在周期性保存与故障重启时稳住百 GB 级 **Checkpoint** 的突发读写。
- **在线推理主线**：在流量脉冲触发弹性扩容时，把百 GB 级只读模型权重以最短冷启动时间（RTO）装进显存；并在长上下文高并发下，借助 **Prefix Caching** 与 **KV Cache 多级卸载**避免反复重算 Prefill。

阅读本章默认读者已掌握[第 01 章](../01_从一台GPU服务器认识基础设施/00_内容大纲.md)至[第 04 章](../04_单机多卡与GPU数据路径/00_内容大纲.md)的主机内存、PCIe/NUMA 与 CUDA Stream，[第 02 章](../02_GPU如何计算与显存/00_内容大纲.md)的 Prefill/Decode 与 KV Cache 显存账本，以及[第 05 章](../05_为什么一个作业需要多张GPU/00_内容大纲.md)至[第 08 章](../08_NCCL如何组织GPU间的通信/00_内容大纲.md)的多 Rank 同步与 GPUDirect RDMA 概念。

学完本章后，[第 10 章](../10_GPU如何进入容器/00_内容大纲.md)至[第 13 章](../13_Multus与RDMA_把高速网络交给Pod/00_内容大纲.md)将把这些设备与存储挂载引入容器与 Kubernetes 边界，[第 15 章](../15_从单个Pod放置到多卡作业调度/00_内容大纲.md)与[第 17 章](../17_把设备、网络与作业状态联系起来/00_内容大纲.md)至[第 19 章](../19_节点交付、版本变更与集群持续运行/00_内容大纲.md)则会把本地权重预热、数据等待指标与存储验收融入调度和运维体系。

## 二、核心学习目标

读完本章后，你应当具备以下可检验的工程推演能力：

1. **走通训练供给与字节核算**：能够沿页缓存、应用解码、锁页缓冲与 H2D 跟踪一批训练样本的形态变化，按目标步时分别反推存储有效载荷与设备输入吞吐，明确页缓存命中究竟省掉了哪一段工作。
2. **拆解文件布局与多类存储瓶颈**：能够区分元数据操作率与数据吞吐量，定量对比小文件与分片布局的访问账本，辨识本地 NVMe、NFS、Lustre 与对象存储的共享瓶颈与关键观测口径。
3. **量化加载流水线与 Checkpoint 压力**：能够推导串行、单 worker 与多 worker 的稳态出批间隔，估算 DataLoader 预取内存预算与设备拷贝重叠条件；能区分 Checkpoint 四类完成时点，核算突发写窗口、保留容量与恢复下界。
4. **判断 GPUDirect Storage 适用边界**：能够对比普通缓冲读、GDS 直达与兼容路径的硬件和软件条件，通过配置与统计证据核实请求实走路径，并从关键路径视角评估端到端收益。
5. **掌握推理权重冷启动与 KV 多级缓存权衡**：能够拆解 70B/405B 模型权重跨存储层次的冷启动耗时账本与加速方案；能够追踪热门前缀在 HBM、主机内存与本地 NVMe/共享缓存之间的换入换出，并定量计算“读缓存”与“重算 Prefill”的盈亏平衡带宽。
6. **在多 Rank 时间线中隔离数据等待**：能够对齐多 Rank 训练步、集合通信与存储/CPU 指标，识别单成员晚到导致的虚假通信拉长，并设计由外到内的三轮对照实验锁定真实瓶颈。

## 四、本章贯穿场景说明

本章软件栈统一对齐[全书基线与术语速查](../00_全书基线与术语速查.md)中的 `Ubuntu 24.04 LTS`（Linux 6.8+）、`NVIDIA OpenRM R595`、`CUDA 13.2.1`（内置 `cuFile / GDS 1.17.0.44`）与 `PyTorch 2.9`，并围绕两套清晰场景展开推演：

- **训练供给与持久化场景（第 01–04、06、99 篇）**：两台服务器 `gpu-a` 与 `gpu-b` 跑 4 进程（每 Rank 独享 1 卡），每 Rank 每步 32 个图像样本（编码均值 `256 KiB`、解码张量 `1 MiB`），目标步时 `125 ms`。
  - 每份训练 Checkpoint 有效载荷为 `64 GiB`（4 个 Rank 各分片 `16 GiB`）；第 05 篇则以单机本地 NVMe 定长张量记录隔离验证 GDS 搬运收益。
- **在线推理冷启动与多级缓存场景（第 07、99 篇）**：沿用[第 02 章](../02_GPU如何计算与显存/00_内容大纲.md)的 **Llama 3 70B（BF16 权重 `140 GB ≈ 130.4 GiB`，GQA 8 头，单 token KV `320 KiB`）**在 4× H100 SXM（TP=4）上的部署基线，并与 **405B** 超大模型对照，拆解弹性扩容冷启动耗时与三级 KV 缓存换入换出权衡。
