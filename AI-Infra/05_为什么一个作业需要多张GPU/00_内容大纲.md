# 第 05 章 为什么一个作业需要多张 GPU｜内容大纲

## 一、本章定位与前置知识

[第 02 章](../02_GPU如何计算与显存/00_内容大纲.md) 剖析了单卡内部的计算、显存带宽以及推理 Prefill/Decode 的本质差异，[第 04 章](../04_单机多卡与GPU数据路径/00_内容大纲.md) 打通了单机多卡的 PCIe、P2P 与 NVLink 数据路径。本章正式迈入第二阶段“多机协同与数据供给”，从**分布式训练**与**大模型在线推理**两条主线回答同一个根本问题：**作业为何必须冲破单卡边界，不同并行切分与分离架构究竟把什么样的通信压力抛给了底层集群？**

阅读本章只需具备 Linux 进程、环境变量与网络地址基础，无需预先掌握分布式框架源码。学完本章后，[第 06 章](../06_从普通网络通信走向RDMA/00_内容大纲.md) 会追踪跨机梯度与 KV Cache 如何经 RDMA 直达显存，[第 07 章](../07_InfiniBand、RoCE与集群网络拓扑/00_内容大纲.md) 与 [第 08 章](../08_NCCL如何组织GPU间的通信/00_内容大纲.md) 展开集群网络拓扑与 NCCL 选路算法，[第 09 章](../09_GPU的数据从哪里来_存储与IO/00_内容大纲.md) 覆盖数据供给与检查点存储，[第 15 章](../15_从单个Pod放置到多卡作业调度/00_内容大纲.md) 与 [第 16 章](../16_Volcano的作业调度与队列管理/00_内容大纲.md) 则将这些多卡需求映射为 Kubernetes 调度策略。

## 二、核心学习目标

读完本章后，你应当能够：

1. **核算训推双主线的多卡驱动力**：分别拆解训练的峰值显存预算与固定工作量步时，以及在线推理的权重+KV Cache 显存墙与 TTFT/TPOT 延迟墙，判断扩卡何时真正有效。
2. **打通进程身份、会合与物理设备映射**：区分 Worker、Agent、Rank、Local Rank、World Size 与组内 Rank，跟踪 `torchrun` 会合、Store、进程组与 NCCL Communicator 的完整启动链条。
3. **推导五大集合原语与训练并行通信**：准确推演 AllReduce、ReduceScatter、AllGather、Broadcast 与 All-to-All 的输入输出语义，由 DP/FSDP、TP、PP、EP 的数据归属推出通信频率与跨机放卡权衡。
4. **掌握推理多卡并行与 PD 分离架构**：说清推理 TP、MoE EP、多副本 DP 的通信特征与放置约束，剖析 Prefill/Decode 混部干扰的根因，并核算 PD 分离对跨实例 KV Cache 高速网络传输的硬指标。
5. **用同轮证据定位慢成员与恢复成本**：对齐多 Rank 故障事件区分晚到、调用不匹配、进程退出与 GPU 卡死，核算同步训练的步时放大与检查点回滚成本，并对比在线推理的故障传播与尾延迟冲击。

## 四、本章贯穿场景与版本口径

本章软件行为对齐 [全书基线与术语速查](../00_全书基线与术语速查.md) 的 **PyTorch 2.9**（启动与进程组源码参考 `v2.9.1`）、**CUDA 13.2.1**、**NCCL 2.27.3**，MoE 路由分发参考 **Megatron Core 0.15.0**，推理 PD 分离配置示例参考 **vLLM**。

除局部原理演示使用两成员子组外，全章贯穿一套最小多机拓扑：**两台裸机服务器 `node-1` 与 `node-2`（配图中简记为节点 A 与节点 B），每台配置 4 张整卡、运行 1 个 `torchrun` Agent 与 4 个独占 GPU 的 Worker，合计 8 卡**。先看单卡与单机四卡，再跨入双机八卡，直观暴露机内高速互联与跨机网络的分水岭。
