# 第 05 章 为什么一个作业需要多张 GPU｜写作大纲

## 读者起点与学习目标

本章接续第 02 章的显存和 CUDA Stream、第 04 章的设备标识和机内数据路径。读者需具备 Linux 进程、环境变量和网络地址的基础。训练步、梯度、数据布局和集合通信从本章开始建立。以同步训练为例，深度以能推导基础设施需求为准。

1. 分别核算每卡峰值显存和固定工作量下的完成时间，说明增加 GPU 在什么条件下才有效。
2. 把本轮 Worker 的全局、本地、组内编号映射到设备，跟踪从 Agent 会合到首次 GPU 通信完成的条件。
3. 推导五种集合操作的输出。从四种并行策略的数据归属推到通信内容、频率、依赖与参与者，并判断改变 DP × TP 放置后哪些交换跨节点。
4. 根据同一轮、同一组的事件区分晚到、调用不匹配、成员退出和完成证据不足，估算关键路径延迟与保存点回滚。

贯穿案例先看节点 A 的单卡、四卡，再到 A、B 各四张整卡。八卡示例中每节点一个 Agent、四个 Worker，每 Worker 独占一张可见 GPU，固定规模。首次通信走八人默认组；集合语义和部分切分从中取两成员作局部示范；组合并行复用原设备表，对比两种独立布置。显存、性能和事件数据均为教学设定，各变体明示假设。
