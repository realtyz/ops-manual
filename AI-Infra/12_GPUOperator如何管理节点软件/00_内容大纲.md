# 第 12 章 GPU Operator 如何管理节点软件｜内容大纲

## 本章定位与前置知识

阅读本章需要具备 Kubernetes 基础（Node、Pod、DaemonSet、kubelet 与容器运行时），并默认已掌握前文三块拼图：[第 03 章](../03_从驱动到CUDA应用的软件依赖/00_内容大纲.md)区分的宿主机内核驱动与容器内 CUDA 用户态、[第 10 章](../10_GPU如何进入容器/00_内容大纲.md)建立的 NVIDIA Container Toolkit 与 CDI 注入路径，以及[第 11 章](../11_Kubernetes如何发现与分配GPU/00_内容大纲.md)梳理的 NFD、GFD、Device Plugin 与 DRA 设备供给模型。

本章不再重复上述基础定义，而是解决集群规模化运维的核心难题：**如何把驱动、运行时配置、设备插件、标签发现与遥测采集收束为一套可声明、可自愈、可分层取证的节点软件生命周期体系**。学完本章后，[第 13 章](../13_Multus与RDMA_把高速网络交给Pod/00_内容大纲.md)将把同一套自动化管理思路延伸到高速网卡与 RDMA 网络，[第 14 章](../14_GPU共享、切分与隔离/00_内容大纲.md)展开推理主导的共享与切分策略，[第 17—19 章](../17_把设备、网络与作业状态联系起来/00_内容大纲.md)则继续深化监控、故障排查与生产变更交付。

## 核心学习目标

1. **理清控制环路与组件依赖**：能从 Helm 配置、线上 `ClusterPolicy` 追到节点部署标签、DaemonSet 模板与组件 Pod，解释新 GPU 节点如何自动完成软件就绪与资源上报。
2. **具备分层排障与取证能力**：能联合解读 `ClusterPolicy` 状态、DaemonSet 覆盖计数、Validator 四项校验、Node 资源计数与单卡 CUDA 测试结果，准确指出链路上最早缺失证据的一环。
3. **划分混合与离线集群的维护边界**：能在预装驱动/Toolkit、多版本驱动池、异构 OS 与隔离网络条件下，确定维护责任方、驱动根目录、镜像与内核包源依赖，并权衡传统编译驱动与预编译驱动。
4. **掌握托管 DRA 的部署与验收**：能区分 `GPUCluster` 与 `ClusterPolicy` 的管控边界及互斥前提，并沿 `ResourceSlice`、`DeviceClass`、`ResourceClaim` 到容器 CDI 注入走通托管 DRA 验收路径。

## 本章贯穿场景

全章围绕一个最小化的多节点集群展开：集群已有普通 CPU 节点 `cpu-0` 与已就绪的双卡节点 `gpu-h0`，现在接入新上架的双卡节点 `gpu-h1`。两台 GPU 节点均配备两张 H100 PCIe（整卡独占、无 NVSwitch），运行 x86_64 Ubuntu 24.04 LTS。

默认主线采用 **Kubernetes `v1.36`**、**GPU Operator `v26.7.2`** 与 **containerd `2.3.0`**，启用内置 NFD 与原生 CDI，关闭 NRI 插件。

`v26.7.2` 默认搭载开源内核驱动 `595.91.07`、NVIDIA Container Toolkit `1.20.1`、Device Plugin 与 GFD `0.20.1` 以及 DCGM Exporter `4.8.4`；第 07 篇托管 DRA 对照环境使用 NVIDIA DRA Driver `v0.5.1`。
