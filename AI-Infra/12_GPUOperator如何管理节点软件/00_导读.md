# GPU Operator 如何管理节点软件

一台节点已经加入集群，`Ready=True`，却没有 GPU 资源。另一台有 GPU 数量，监控组件却一直重启。把这些现象都叫作“Operator 没装好”，很难找到下一步。本章把前两章分别解释的组件放回同一套维护过程，沿着配置、节点变化与证据逐步判断。

读完应能**画出驱动、Toolkit、设备插件、发现与监控的依赖；为每项组件指定管理者；解释 Helm、ClusterPolicy、控制器和节点工作负载的分工；推导新节点到资源可用的变化；用 Validator、日志、DaemonSet 与 Node 材料定位阻塞；评审离线供给与异构节点池的配置边界。**

## 前置与章节边界

已有基础包括 Linux 内核模块、动态库、设备文件，以及 Kubernetes 的 Node、Pod、DaemonSet、调度、事件与镜像拉取。[第 03 章](../03_从驱动到CUDA应用的软件依赖/00_导读.md)提供驱动依赖，[第 10 章](../10_GPU如何进入容器/00_导读.md)提供 Toolkit、运行时与设备注入，[第 11 章](../11_Kubernetes如何发现与分配GPU/00_导读.md)提供 Device Plugin、资源记账和 NFD/GFD。这里会建立 Operator 的调谐、ClusterPolicy、节点侧安装与分层验证概念。

第 11 章解释设备怎样被分配，本章解释承担这些工作的软件怎样得到维护。第 13 章负责 Multus、RDMA/NIC 和 Network Operator 的接入，第 14 章负责 MIG、MPS 与共享策略，第 17 章负责指标解释，第 19 章负责排空、升级、回滚与交付全流程。本章讲清这些机制所需的组件边界，不展开网络配置、共享策略或生产升级手册。DRA 不进入本章传统 Device Plugin 主线。

## 独立教学模型与版本基线

本章重新建立两台 Linux x86_64 裸机：`op-a`、`op-b` 各有两张 NVIDIA L4，整卡独占，没有 MIG、Time-Slicing、MPS、NVSwitch、RDMA 或 GDS。卡仅用节点内代号 A0/A1、B0/B1 表示；没有跨章 UUID 映射。本章不需要推断 PCIe 拓扑或显存容量。

| 项目 | 本章固定条件 |
| --- | --- |
| 节点系统 | Ubuntu 22.04，内核 `5.15.0-134-generic`，Kubernetes `1.32.3`，containerd `1.7.27` |
| Operator / Validator | GPU Operator Helm 发布版 `v25.3.0`，命名空间 `gpu-operator`，策略名 `cluster-policy` |
| 驱动 | `570.124.06`，显式选 `kernelModuleType: open`；普通驱动容器路径，不使用预编译驱动或 NVIDIADriver CR |
| Toolkit | `v1.17.5-ubuntu20.04` 镜像标签；目标节点仍是 Ubuntu 22.04 |
| 设备插件 / GFD | `v0.17.1`；Device Plugin 使用 `envvar` 与 UUID 设备 ID |
| NFD | `v0.17.2`，本章由同一 Helm release 的依赖 chart 部署 |
| 监控 | DCGM Exporter `4.1.1-4.0.4-ubuntu22.04`，使用内嵌 hostengine；`dcgm.enabled=false` |
| 容器交付 | `cdi.enabled=false`；最终运行时配置明确为 legacy，提供 `nvidia` handler；教学探针显式使用 `runtimeClassName: nvidia` |

组件标签与开关依据 [v25.3.0 values.yaml](https://github.com/NVIDIA/gpu-operator/blob/v25.3.0/deployments/gpu-operator/values.yaml)，NFD 依赖依据 [同 tag Chart.yaml](https://github.com/NVIDIA/gpu-operator/blob/v25.3.0/deployments/gpu-operator/Chart.yaml)。镜像标签中的发行版后缀描述容器用户态构建，并不改写宿主机 OS；是否可用仍要核对整套支持条件。平台参考 [25.3.0 Platform Support](https://docs.nvidia.com/datacenter/cloud-native/gpu-operator/25.3.0/platform-support.html)。

这是用于固定机制的历史阅读基线，与第 11 章的 Kubernetes 1.34 / Toolkit 1.18 场景独立。它未经端到端实测，也不表示当前推荐部署组合。版本化文档仍可能增补组件推荐值：本章原始配置值以固定 tag 为准，不将页面后来更新的“默认驱动”倒写成该 tag 的原值。资料核对日期：**2026-11-08**。

主线先假设 `op-a` 已可用，`op-b` 新加入；两者的驱动、Toolkit、插件、GFD、Exporter 由 Operator 体系维护。节点系统、内核、containerd 服务本体、网络和硬件由节点平台团队维护。预装、离线和异构案例会就近声明改变的条件。所有配置片段、时间线、日志、命令输出、探针和数值均为**自拟教学材料**，使用处分别注明；无需实际运行命令或准备 GPU。
