# AI-Infra 教材编写与重写执行规范（AGENT 指令）

本文件适用于操作 `AI-Infra/` 目录下任何章节的 AI Agent。执行任何新写或重写任务时，**以“读者能建立清晰直觉、顺畅读懂并迁移应用”为最高目标**，严禁产出法条式、审计报告式的僵硬文本。

---

## 一、开始任务前必读

1. 阅读 [00_学习大纲.md](00_学习大纲.md)（了解全书 20 章定位及训练+推理双主线）。
2. 阅读 [00_全书基线与术语速查.md](00_全书基线与术语速查.md)（获取统一的参考版本栈、标准拓扑命名及术语唯一主定义章，避免重复定义或版本漂移）。
3. 阅读 [写作方法论.md](写作方法论.md)（严格执行 v2.0 风格原则、八条禁令与格式标准）。
4. 阅读目标章的 `00_内容大纲.md`、本章所有正文文件，以及 `images/` 下已有的图片清单；如涉及配图调整，另读 [配图规范.md](配图规范.md)。

## 二、写作与重写核心约束

### 1. 保内核、换外壳
- **必须保留**：原稿中经过核实的技术事实、核心因果推导、有效数值算例（如显存预算、带宽/Roofline 推导、队列积压、Ring 分块、MIG 放置、队列装箱等）、官方参考链接，以及 `images/` 下已有的高质量手绘插画。
- **必须重写外壳**：把压缩在长段里的内容重构为“痛点/直觉 → 主线流程与图示 → 带注释的命令/配置/日志/独立公式块 → 边界与易错 Callout”。
- **必须按总纲增强推理负载**：在涉及计算/显存、并行形态、通信、存储、共享隔离、调度与运维的章节，按 `00_学习大纲.md` 要求扎实展开**推理负载**（Prefill/Decode、KV Cache、量化、PD 分离、权重冷启动、TTFT/TPOT SLO、训推混部等），不可将其弱化为一句带过。

### 2. 必须遵守的硬格式
- **正文一级标题（H1）**：每篇正文第 1 行**必须保留 `# 标题`**，并与 `00_内容大纲.md` 篇名、文件名主体保持一致。章末综合检验统一使用 `99_` 前缀命名。
- **参考文献归位**：严禁在正文段落结尾堆叠外部 URL。每篇正文末尾统一使用一个默认折叠的 Obsidian Callout 收纳参考来源：
  ```markdown
  > [!info]- 参考资料
  > - **主题说明**：[文档标题](https://...)
  ```
- **视觉层次**：普通正文段控制在 **80–150 字**（硬上限 200 字）；使用 Obsidian Callout（`> [!summary]` / `> [!tip]` / `> [!warning]` / `> [!note]`）突出核心结论、工程直觉和误区；重要定量计算使用独立 `$$...$$` 公式块或分步对齐格式。
- **图注与替代文本**：图片与 Mermaid 图下方图注统一格式为 `*图 XX-YY-ZZ：说明*`。替代文本仅写入 `![替代文本](...)` 或 Mermaid `accDescr:`，**严禁在正文另起段落输出 `**替代文本**`**。
- **大纲读写分离**：`00_内容大纲.md` 仅保留面向读者的定位、前置、学习目标、可点击的篇目导航表与场景概览。严禁在其中保留或新增“本轮修订记录”“P0/P1/P2 审计表”“待核实清单”等作者后台信息（如需留档，写入 `_维护记录/`）。

### 3. 严格禁止的八类反模式（Anti-Patterns）
- 严禁在正文段尾挂载外部 URL 列表。
- 严禁在正文出现“教学构造”“教学记录”“教学节录”“教学快照”“教学设定”“未在实机验证”等打破沉浸感的元话语（全书口径已在 `00_全书基线与术语速查.md` 一次性说明）。
- 严禁频繁使用“不能单独证明……”“不代表……”“取决于实际环境，需另行核实”等防御性车轱辘话冲淡正文主干。
- 严禁在讲解一般原理的段落中把句子绑死在 `GPU 0`、`h1/h2`、`P21`、`J17/R1`、`B0`、`GPU-H2-A` 等具体虚拟代号上——**原理段用语义角色，具体标识仅下沉到映射表、命令/日志片段、已有插画对照与章末检验题**。
- 严禁单段超过 200 字且不做结构拆分。
- 严禁对非本章主讲的基础术语（如 RDMA、BDF、NCCL、NVML、CDI、MIG、Rank、AllReduce 等）再次从零展开英文全称与基础定义。
- 严禁丢弃或无故破坏本章已有的 `images/*.png` 链接与图号对应关系。
- 严禁虚构不存在的命令参数、指标字段或官方文档结论；遇到版本相关行为，核对官方资料后以 `00_全书基线与术语速查.md` 的版本栈为基准说明，不臆造结论。

## 三、交付前自动化与人工自检

每完成一章重写后，交付前必须逐项验证以下清单：

1. **可读性体检**：
   - 全章纯正文平均段长 ≤ 140 字，无 >220 字文字墙；
   - 全章正文中 `教学构造|教学记录|教学节录|教学快照|教学假设|未在.*实测` 出现次数为 `0`；
   - 全章正文中泄露的 `替代文本` 出现次数为 `0`；
   - 全章正文段尾裸 URL 为 `0`，且每篇末尾均有 `> [!info]- 参考资料` 折叠块。
2. **结构与链接体检**：
   - 所有正文文件第 1 行均有 `# 一级标题`，与文件名及 `00_内容大纲.md` 链接一致；
   - `00_内容大纲.md` 无内部审计/修订表，全部本地链接与图片相对路径存在且有效；
   - 所有图号 `图 XX-YY-ZZ` 与当前章号、篇号一致，`images/` 目录下无孤立未引用图片。
3. **读者视角通读**：
   - 隐藏大纲直接通读本章，检查开头是否有清晰问题钩子、原理段是否摆脱代号轰炸、命令/日志/公式是否直观易懂、训练与推理视角是否按总纲到位、篇间过渡是否顺畅。
4. **交付汇报**：
   - 简要说明修改文件清单、核心教学/可读性改进、推理内容增强点（如适用）、自检结果及保留的已有插画核对情况。
