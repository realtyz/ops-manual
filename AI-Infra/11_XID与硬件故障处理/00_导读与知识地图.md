# XID 与硬件故障处理

## 知识地图

### 一次故障从现象到「重跑还是换卡」：五段

本章的主链是**一次硬件故障的处置**。它从业务侧报障或监控告警开始，经过取证、按错误码分类、隔离、执行恢复，最后落到复测与台账；这条链路上最贵的错误是分类错误——把应用越界当成硬件故障会换掉一张好卡，把显存不可纠正错误当成应用问题会让作业反复崩。

| 段 | 这一段在做什么 | 到这里要能说清 |
| --- | --- | --- |
| 1 现象与取证 | 先把现场固定下来：内核日志、设备状态、取证脚本、当时运行的作业 | 取证的顺序是什么，以及哪一步做了就再也回不去 |
| 2 按码分类 | 把上报的错误码对照官方码表逐码判读，读出它的恢复动作分类 | 每个码的适用范围与恢复动作，以及为什么不能凭印象判断 |
| 3 判定影响面 | 区分这次错误只影响一个应用、影响多个应用，还是需要整机重启 | 判定影响面的依据是哪几个码的组合 |
| 4 隔离与恢复 | 先隔离节点再执行恢复动作，恢复动作的强度按分类来定 | 三个恢复档位各自的适用条件与代价 |
| 5 复测与台账 | 复跑基线与冒烟项，把这一码的记录写进台账 | 复测的判据是什么，以及台账要累计出什么结论 |

**贯穿本章的三问**：这个码的恢复动作分类是哪一档；这次故障是**偶发**还是**劣化趋势**；判定依据是官方码表里的哪一列。

### 三个跨阶段的核对对象

| 核对对象 | 它贯穿哪几段 | 每一处读什么字段 |
| --- | --- | --- |
| 错误码与恢复动作 | 它贯穿段 2 到段 5，因为同一个现象可以由不同码引起，而不同码的动作强度不同 | 在段 2 读官方码表里该码的触发条件、适用范围与恢复动作；在段 3 读与它同时出现的其它码；在段 4 按分类执行对应强度的动作；在段 5 记录实际执行的动作与结果 |
| 计数与生命周期 | 它贯穿段 1、段 3 与段 5，因为可纠正错误的两组计数生命周期不同，只有一组能反映板卡劣化 | 在段 1 同时读两组可纠正错误计数与是否启用持久化；在段 3 读不可纠正错误的计数与行重映射状态；在段 5 用同一口径复读并比较增长 |
| 现场材料 | 它贯穿段 1、段 4 与段 5，因为重启会清掉内核日志的一部分与全部运行态信息 | 在段 1 确认取证脚本已落盘、内核日志已留存；在段 4 之前记录涉及的应用与容器；在段 5 用这些材料判断是偶发还是劣化 |

## 术语速查

| 名词 | 一句话解释 | 在哪一篇展开 |
| --- | --- | --- |
| XID | NVIDIA 驱动上报的错误码，是硬件与驱动故障的第一现场 | 原理：错误码是怎么被上报的 |
| Xid Catalog | 官方维护的错误码表，每个码给出触发条件、适用范围与恢复动作 | 原理：错误码是怎么被上报的 |
| Resolution Bucket | 官方码表里给出的恢复动作分类，是「重跑还是换卡」的第一判据 | 原理：恢复动作的语义与判据 |
| 恢复动作汇总码 | 一个直接给出恢复动作强度的错误码，看到它先读它再读它指向的那个码 | 原理：恢复动作的语义与判据 |
| 错误容纳（error containment） | 有硬件与驱动支持时把故障限制在单个应用范围的能力，与之相对的是影响多个应用 | 原理：恢复动作的语义与判据 |
| 掉卡（fallen off the bus） | GPU 从 PCIe 总线上消失，表现为设备列举不到、驱动失联 | 原理：掉卡与显存错误的机制 |
| PCIe AER | PCIe 的高级错误报告机制，掉卡的现场常常伴随它的记录 | 原理：掉卡与显存错误的机制 |
| 行重映射 | 把有问题的显存行重映射到备用行的机制，它的事件与失败各有一个码 | 原理：掉卡与显存错误的机制 |
| volatile 与 aggregate 计数 | 可纠正错误的两组计数，前者随设备反初始化清零，后者接近板卡终身累计 | 原理：掉卡与显存错误的机制 |
| 降频与功耗墙 | 温度或功耗越过限制后设备主动降低频率的状态 | 原理：温度与功耗的降频路径 |
| 故障台账 | 记录错误码、动作与复测结果的累积记录，用来判断某一批卡或某个机型的故障率 | 治理：故障台账与硬件劣化趋势 |

## 关键字段的读法

| 字段 | 是什么与单位 | 判据 | 与谁同看 | 转向哪一步 |
| --- | --- | --- | --- | --- |
| 内核日志里的错误码行 | 驱动上报的错误码及其上下文 | 每一个码都要回官方码表核对适用范围与恢复动作；同一现象可能由不同码引起 | 与设备状态和取证脚本同看 | 按码表给出的恢复动作分类决定动作强度 |
| 官方码表里的恢复动作列 | 该码对应的动作分类，例如重跑作业、重置单卡、重启整机、忽略或联系支持 | 它是动作的第一判据，先读它再看码的含义 | 与该码的适用范围列同看 | 按分类执行对应强度的动作，不越级也不降级 |
| 恢复动作汇总码 | 一个把恢复动作直接写出来的码 | 出现它时先读它给出的动作，再回查它指向的那个码 | 与同时出现的其它码同看 | 按它给出的动作执行，并把两个码一起记入台账 |
| 可纠正错误的 aggregate 计数 | 板卡终身范围内的可纠正错误累计数 | 判据是增长率；只在手动清除时归零 | 与 volatile 计数、以及是否启用持久化同看 | 增长明显时登记该卡，排入维护窗口 |
| 不可纠正错误的计数与行重映射状态 | 不可纠正错误的累计数，以及重映射事件与失败的状态 | 出现不可纠正错误后，能否继续使用取决于它是否被容纳以及是否伴随其它码 | 与掉卡相关记录、以及同一批次其它卡的表现同看 | 按分类执行重置或换卡，并在复测后决定是否回池 |

## 篇目

| # | 篇目 | 一句话 |
| --- | --- | --- |
| 01 | 原理_错误码是怎么被上报的 | 它讲驱动与固件各自在什么路径上产生这些码，以及为什么必须按官方码表逐码判读 |
| 02 | 原理_恢复动作的语义与判据 | 它讲各档恢复动作分别意味着什么影响面，以及容纳能力如何把故障限定在单个应用 |
| 03 | 原理_掉卡与显存错误的机制 | 它讲设备从总线上消失的判定依据、可纠正与不可纠正错误的分界，以及行重映射在做什么 |
| 04 | 原理_温度与功耗的降频路径 | 它讲温度与功耗越过限制之后设备会做什么，以及为什么它表现为性能问题而不是报错 |
| 05 | 体系_一次故障处置的完整旅程 | 它把「取证 → 分类 → 判定影响面 → 隔离与恢复 → 复测与台账」一次走完，并给出每段的失败落点 |
| 06 | 实操_健康检查与故障取证 | 它讲一张卡一次全量检查读哪些字段、取证顺序是什么，以及切分能力的检查项 |
| 07 | 判例_高频误判 | 它按场景、误判、判据与出处给出本章的高频误判 |
| 08 | 治理_故障台账与硬件劣化趋势 | 它讲台账要累计出什么、换卡的流程与验收，以及故障率怎么按批次与机型统计 |
