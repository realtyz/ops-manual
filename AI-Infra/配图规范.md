# AI-Infra 配图规范

## 选图

每篇优先考虑一张核心总结图，放在主要解释之后或篇末。流程、时序和依赖用 Mermaid，精确数值和曲线用表格或程序绘图。空间位置、设备边界、资源分布和局部结构会影响理解时，采用手绘插画。需要解释独立难点时补图，已有表达足够清楚时直接沿用。

## 提示词

正文的机制和适用条件确定后，为每幅生成图写一份完整提示词，集中放在本章 `_配图/配图说明.md`。每幅图用一个代码块写齐画面要求和公共风格。填完所有占位符，删掉不适用的字段，使提示词脱离正文也能直接复制使用。

把约束写到具体对象。例如要避免把两块独立显存画成共享池，就指定 GPU 0 和 GPU 1 的显存分别画在各自设备的边界内。

### 可复制模板

```text
任务与结论
为已有 Linux/Kubernetes 基础的读者绘制中文 AI 基础设施手绘插画。
回答［读者看图前最容易混淆的一个问题］。
让读者通过［画面中能看到的空间、数量或边界差异］理解［一句明确结论］。
采用［与正文一致的场景、平台或版本、初始状态］。

构图与阅读顺序
使用［整体场景／整体加局部放大／同尺度并排对照］，采用［俯视／正视／剖面］。
按［从左到右／从整体到局部］阅读，依次绘制［各画区的位置、主体、范围和视觉焦点］。
对照图中，两侧保持［共同对象、位置、比例和颜色］一致，仅改变［条件］，突出［可见差异］。
放大图中，在总图圈出［具体位置］，引线连接［局部窗位置］，两处标为［同一对象编号］。
让关键边界和差异占据主要空间。给标签和图例留白，避免遮挡对象或连线端点。

对象、边界与关系
可见对象［名称｜数量及编号｜所属范围｜画面位置｜需要看清的形态，逐项填写］。
边界［范围框名称｜框内对象｜框外对象，逐项填写］。相同对象跨画区保持编号一致。
连线［起点对象或端口 → 终点对象或端口｜物理连接、数据流、控制或标注｜单向、双向或无向｜线型，逐条填写］。
图例［本图各类线条、箭头和状态符号的含义］。
数量关系［容量、单位、比例、共享条件］。简化画法［合并或省略了什么，在图上如何标注］。

逐字标签
逐字文字［所属对象或画区｜位置｜逐字文本，依次填写标题、短标签、数值和图例］。
逐字保留大小写、标点、版本和单位，区分 0/O 与 1/l。引号仅用于标记文本范围。
画面文字以标签清单为准。用对象的形态、占位和位置表达其余信息，把前提和推导留给图注。

技术约束
关键检查点［必须准确出现的数量、端点、方向、边界和关键状态］。
误画约束［容易画错的关系 → 正确画法，逐条填写］。
以本提示词的对象、连线和标签清单为准。省略、聚合和示意比例按本图约定执行。

公共风格
横向 16:9，按 1920×1080 构图。不透明暖白底 #FFFCF7，可有极淡纸纹。
用深灰 #1F2937 的细记号笔勾线，配低饱和彩铅或淡马克笔填色。边界、线条端点和可数对象保持清楚。
中文用端正手写印刷体，英文和技术标识用等宽手写印刷体。主标签约 44 px，次标签至少 36 px，水平排布。
CPU 与主机内存用蓝 #3B6EA8 / 浅底 #E8F0FA，GPU 与显存用绿 #2E8B70 / #E6F4EE，
NIC 与网络用青 #278A9B / #E7F5F7，BMC 与带外管理用紫 #8061A8 / #F0EBF7，
软件、存储、PCIe Switch 和普通结构用灰 #64748B / #F1F5F9。
观察重点用琥珀 #D99A2B，缺失或阻断用柔红 #C65B5B。状态辅以轮廓、空位、斜线或短词。
采用克制的教材插画风格，用空间、对象形态和局部细节解释机制。

参考图（有参考图时填写）
仅参考所附图片的笔触、字体、填色与排版。对象、数量、关系和标签以本提示词为准。
```

### 填写示例：NUMA 与设备路径

以下示例取自第 01 章的双路服务器教学场景，用一组同尺度对照图解释 GPU 读取本地与远端主机内存时的路径。对象形态、连线方向、文字和公共风格都写进同一个代码块，可以单独复制。

```text
为已有 Linux 和 Kubernetes 基础的读者绘制中文 AI 基础设施教材插画。问题是 GPU 接口位置固定时，主机缓冲区的不同 NUMA 落点如何改变读取路径。采用教学假设：双 Socket，每个 Socket 一个 NUMA 节点，GPU DMA 直接读取页锁定主机缓冲区。图只表达路径，不表示真实性能。
横向 16:9，左右两画区严格同尺度、同对象、同连线。每个画区都有 Socket 0 和 Socket 1、各自连接的主机内存节点 0 和主机内存节点 1、两个 Socket 之间的互联。Socket 0 连接一个 PCIe Root Port，再连一个 PCIe Switch；Switch 两条独立下行分别连接 GPU 0 和 NIC。右侧 Socket 1 没有直接连接 GPU 或 NIC。
两画区使用相同的俯视硬件图标。每个 Socket 画成带边框和金属顶盖的方形 CPU 封装，旁边各画一组细长的 DIMM 内存条，内存条上有小存储芯片与金手指。GPU 0 画成带中央芯片和旁侧 HBM 堆叠的独立模组，NIC 画成带金属挡板、网络端口和金手指的扩展卡。PCIe Switch 是板上的芯片封装，Root Port 以 Socket 0 边缘的连接端点表示。各设备以符号化连线表达拓扑，CPU 间的互联和 PCIe 连线不画成机箱外的网络线。
左画区在内存节点 0 的 DIMM 组旁画一块琥珀色区域，标为缓冲区，并用短引线指向该组内存；右画区只将此区域移到内存节点 1 的 DIMM 组旁。琥珀区域代表该内存中的逻辑数据位置，画成标注层而非额外内存硬件。左侧按 GPU 0 → Switch → Root Port → Socket 0 → 内存节点 0 高亮 DMA 读取请求路径；右侧按 GPU 0 → Switch → Root Port → Socket 0 → Socket 1 → 内存节点 1 高亮。连接用灰色实线，DMA 读取请求用琥珀色虚线箭头；箭头指向被读取的内存，返回数据方向不单独画。图例清晰区分连接与请求方向。画面外加小字“教学拓扑”，省略其他设备。
逐字文字仅包含“本地缓冲区”“远端缓冲区”“Socket 0”“Socket 1”“内存节点 0”“内存节点 1”“处理器互联”“Root Port”“PCIe Switch”“GPU 0”“NIC”“缓冲区”“物理连接”“DMA 读取请求”“教学拓扑”。每侧标签重复一次，保持水平和可读。右图清晰标出跨 Socket 线段。无共享显存，无从 GPU 直接连内存的物理线。
不透明暖白底 #FFFCF7，可有极淡纸纹，按 1920×1080 构图。深灰 #1F2937 细记号笔勾线，低饱和彩铅或淡马克笔。中文端正手写印刷体，英文等宽手写印刷体，主标签约 44 px，次标签至少 36 px。CPU 和主机内存蓝 #3B6EA8 / #E8F0FA，GPU 绿 #2E8B70 / #E6F4EE，NIC 青 #278A9B / #E7F5F7，PCIe Switch 灰 #64748B / #F1F5F9，路径和缓冲区琥珀 #D99A2B。克制的手绘教材风，边界、连线端点与可数对象清晰。
```

示例图号为 `fig-01-02-01`，插在第 01 章第 02 篇比较本地与远端缓冲区之后。图注说明该双路系统每个 Socket 对应一个 NUMA 节点，GPU DMA 直接读取页锁定缓冲区。替代文本概括两幅图的设备连接、缓冲区位置和跨 Socket 路径。验收时核对两侧拓扑一致、缓冲区落点和箭头方向，以及 GPU 与 NIC 是否共用 Switch 上行。

### 图外说明

每幅图附上图号、正文中的插入位置、图注、替代文本和本图最容易画错的两三处。图注补足适用条件与结论，替代文本概括读者应看懂的关系。这些信息随方案交付，逐字标签清单决定哪些文字进入图片。

## 验收与入库

1. 助手提供提示词，用户生成图片并将候选放入本章 `_配图/待审/`。候选文件名用 `fig-NN-PP-II-topic-v01.png`，以版本号区分修改稿。
2. 打开实际图片，核对图文一致性、对象数量、边界、连线、标签和可读性。需修改时指出具体位置、应改成什么及应保留的内容。验收范围为图片本身及其与正文的一致性。
3. 将合格图片存为 `images/fig-NN-PP-II-topic.png` 并嵌入正文，附图注和替代文本。正文修改涉及图中事实时，复核受影响的图片。
