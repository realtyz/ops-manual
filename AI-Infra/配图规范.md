# AI-Infra 配图规范

本规范与[写作方法论](写作方法论.md)共同用于配图规划、提示词编写和图片验收。

**旧生成图片、旧配图方案与旧提示词全部作废**，包括已嵌入的正式图、待审候选和未生成的旧方案。后续从当前正文重新选题，不继承旧图数量、构图、插入计划或验收结论，也不只替换旧提示词的风格前缀。旧图片文件暂留作历史资料，处理对应章节时清理旧引用；已有 Mermaid、表格和代码块按教学用途判断。

## 选图与构图

**每篇正文优先规划一张核心总结图。** 先提炼全文最值得记住的一个主问题和一个核心结论，再选择少量支撑关系，用完整场景、整体加局部或并排对照组织画面，帮助读者整理认识和复习。多个概念共同解释同一结论，完整前提与推导留在图注和正文，不把全篇名词、配置单或目录搬进图片。

核心总结图默认放在正文主要解释之后或篇末。以一张为默认安排，按内容说明例外：流程类文章可由 Mermaid 承担总结；需要解释独立局部难点时可补图，缺少合适视觉内容时可不新增生成图片。导读保持简短，练习答案图放在参考分析之后。

| 需要表达的内容 | 优先方式 |
| --- | --- |
| 调用顺序、条件分支、时序、依赖、对象引用、调谐闭环 | Mermaid 或对照表 |
| 精确数值、比例、性能曲线、计算结果 | 表格、SVG 或程序绘图 |
| 形态差异、软件边界、缓冲区位置、共享层面、整体与局部 | 说明式插画、剖面、局部放大 |
| 资源占位、跨节点分布、容量边界、必要物料缺失 | 空间对照、装箱或缺件示意 |

每份生成图方案必须回答：**改成普通方框箭头图，会丢失什么关键教学信息？** 并指出由哪处位置、形态、边界、数量或局部细节承载。若几乎不丢失，就使用 Mermaid 或表格；给流程节点加图标不算增加视觉解释。

图中可以有箭头，但连接、数据搬运、调用、挂载对应和状态变化应分别定义。范围框表示包含或明确分组，虚线逐图说明含义。对照保持同样布局和尺度，只改变当前问题需要的条件；对象、格数与数字一致，聚合与省略须说明。不得虚构直连、合并独立容量，或暗示 CPU 核逐字节中转所有 DMA 数据。

总结图帮助读者回顾全文主线，正文内的 Mermaid、表格与补充局部图承担具体流程、精确数据或局部推导，避免重复。类比必须说明对应范围，不由类比推导真实物理关系。

## 统一手绘风格

采用暖白纸底、细记号笔轮廓、端正手写印刷体、低饱和彩铅或淡马克笔填色。统一笔触、字体、配色和标注习惯，构图随教学问题变化。

每幅完整提示词均须包含以下公共风格说明，不能只写“沿用统一风格”或要求用户自行拼接：

```text
生成一幅中文 AI 基础设施手绘教材插画，面向已有 Linux/Kubernetes 基础的读者。整体采用“细记号笔勾线 + 淡彩铅笔或浅马克笔填色”的课堂手绘笔记风格，横向 16:9，按 1920×1080 构图。背景为不透明暖白纸色 #FFFCF7，可有极淡细纸纹；纹理不能盖过文字或降低对比。留白充足，用器件示意、文件页、剖面、观察窗口或资源占位解释问题，不画成电脑 UI 卡片或矢量图标拼贴。
轮廓使用深灰 #1F2937 或蓝黑色细记号笔，笔画有自然、轻微的不规则和少量笔锋变化，边界与端点仍清楚；不画重影、断裂边界或含糊交叉。填色采用低饱和、可见轻微笔触的彩铅或浅马克笔平涂，色块控制在对象轮廓内。用于“已请求”等状态的斜线应与普通填色笔触明显区别。对照图中可数对象、格数、边界和相对尺度仍须准确。
中文标题和标签统一使用端正、清晰的手写印刷体，像认真书写的课堂板书；主标签约 44 像素，次标签至少 36 像素，水平排列，避免草书、连笔和夸张卡通字。英文缩写、库名、数字与版本号使用整洁的等宽手写印刷体，准确保留大小写、标点、斜杠、下划线和连字符，清楚区别 0/O、1/l；手绘风格不能改变技术标识或数字。
统一语义色作为彩铅/淡马克笔的主调参考：CPU/主机内存蓝 #3B6EA8、浅底 #E8F0FA；GPU/显存绿 #2E8B70、浅底 #E6F4EE；NIC/网络青 #278A9B、浅底 #E7F5F7；BMC/管理访问紫 #8061A8、浅底 #F0EBF7；软件文件、内核层、机箱及普通结构灰 #64748B、浅底 #F1F5F9。当前观察对象或约束用琥珀 #D99A2B 的手绘圈线、括线或浅色划线强调，缺失或不能满足的局部用柔红 #C65B5B。对象颜色保持类别语义，状态另用斜线、空位、轮廓和短词标注，不能单靠颜色表达。
这是一幅用空间与对象形态解释机制的手绘图。先让读者看清下文指定的对象分布、边界和局部细节，再用必要的少量手绘引线补充；不把组件调用链、步骤流程、依赖树或控制闭环换成手绘框箭头。图内只放下文指定的必要短标签与少量短解释，完整前提和结论由图外图注承担。整体清晰克制，不做写实产品渲染、3D 塑料质感、炫光或大段文字海报；教学示意不代表真实物理接线、实际软件界面或产品布局。
```

软件与存储、PCIe Switch、机箱等普通结构采用灰色；普通管理软件不因“管理”二字使用 BMC 紫色。颜色跨图保持类别语义，状态同时用斜线、空位、轮廓或文字表达。排不下时减少内容或拆图，不靠缩小文字硬塞。

若模型支持参考图，可随提示词提供，并注明：“仅参考手绘笔触、字体、填色和视觉组织，图中对象、数量、标签与技术关系以本提示词为准。”

## 提示词交付要求

规划整章时先通读当前导读、全部正文及必要前后篇，再逐篇记录“主问题—核心结论—总结图形式—与现有材料的分工”；不采用一张主总结图或需要补图时说明原因。重构单幅图时核对所属正文的上下文，明确它承担全文总结还是局部解释，重新论证教学问题与构图。

章节方案集中放在本章 `_配图/配图说明.md`。重写旧版方案时更新图单、提示词和进度，不将历史状态表当作新版记录。每幅图交付以下内容：

| 交付项 | 必填要求 |
| --- | --- |
| 图号与教学问题 | 稳定图号，注明核心总结图或补充局部图；主问题、核心结论，以及读者看完后能解释什么 |
| 视觉价值 | 普通流程图会丢失什么，由哪处画面承载 |
| 正文位置与分工 | 所属正文、小节及可唯一定位的原句；与已有 Mermaid、表格及其他新图的关系 |
| 构图与文字 | 主体、视角、边界、阅读顺序、对照与放大方式、留白；列出必要短标签与图例 |
| 技术约束 | 精确对象、数量、编号、容量、单位、关系、方向、条件、聚合及省略；事实取自当前正文，禁止模型自行补充 |
| 完整提示词 | 同一个代码块写全主问题与核心结论、公共风格、色值、本图构图、标签、技术约束及应避免的误画，可独立复制到其他模型 |
| 图注、文件与验收 | 图注说明前提和范围，替代文本概括含义；给出候选/正式文件名，以及易错数量、边界、拼写和视觉解释检查点 |

技术标识须准确保留大小写、数字与标点，区分 0/O、1/l。示意不冒充真实产品照片、实测截图或精确接线图。只有重新选题时需要相同知识点，才重新设计该问题的图，不因旧图存在就安排重绘。

## 生成、验收与入库

1. **助手设计，用户生成。** 助手按任务范围提供方案与完整提示词；用户在其他模型生成，将原始候选放入本章 `_配图/待审/`。记录实际模型、可得版本及提示词改动，不代填未知信息。
2. **逐张检查实际图片。** 先核对总结图是否呈现全文主问题与核心结论、局部图是否补充了不同理解，再检查约定的视觉解释、技术关系、对象数量、范围边界、文字拼写、数值单位、线型箭头、正文一致性，以及手绘风格、配色、布局和图片自身的可读性。文件存在、文字正确或外观好看均不足以单独判定合格。
3. **针对问题修改。** 指出具体对象、线或文字的问题，提供该图的修改提示词，保留正确内容。多次仍不能保证技术关系、数值或几何时，改用可编辑图形，不降低验收要求。
4. **验收通过后入库。** 将定稿放入本章 `images/`，以相对路径嵌入正文，维护图注与替代文本；按新方案清理旧图引用和失效占位说明。未生成或未通过审查的图片不建立引用。
5. **记录并按需复核。** 新图记录“待生成、待审、需修改、已验收、已嵌入”，旧图与旧提示词记为“作废”。正文修改影响图中数量、关系、版本或条件时，只复核受影响图片。

图号采用 `fig-章号-篇号-序号`，不把旧图号重新绑定到另一个教学问题；新选题使用未占用图号。候选如 `_配图/待审/fig-NN-PP-II-topic-v01.png`，定稿如 `images/fig-NN-PP-II-topic.png`；候选用 v01、v02 区分，定稿保持稳定名称，与旧图留档区分。PNG 优先，验收期间保留原始候选。

**只验收图片本身及其与正文的一致性，无需打开 Obsidian 或其他阅读器检查显示效果。** 路径与图注仍需正确；阅读器主题、窗口宽度、缩放和实机验证均不属于图片验收。
