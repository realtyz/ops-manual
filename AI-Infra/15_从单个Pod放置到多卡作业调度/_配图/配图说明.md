# 第 15 章配图说明

## fig-15-02-01 网络域内能放下几个 worker

- **插入位置**　第二篇「给整组增加同域约束后再算一次」，对照表和关于 `h-a3` 的推导之后。
- **图注**　教学作业需要 3 个同域 worker，每台节点至多放 1 个。两个画面均用同一节点库存和标签，右画面仅让 `h-a3` 再释放两张 H100。A 域由两个合格落点变为三个，B 域仍只有一个。
- **替代文本**　左右画面各有 A、B 两个网络域。左图 A 域的 h-a1、h-a2 各可放一个 worker，h-a3 因只有两张可分配 GPU 而无法放置。右图 h-a3 的 GPU 余量达到四张，A 域可放满三个。B 域两个画面都只有 h-b1 可放一个。
- **验收要点**　两侧始终各有六台节点，两域的成员和节点顺序完全相同。只有 `h-a3` 的余量和可放状态改变，域合计由 `2 / 1` 变为 `3 / 1`。不要把两个域的名额相加来满足同域约束。

```text
为已有 Linux 和 Kubernetes 基础的读者绘制中文 AI 基础设施教材插画。回答为什么三个 worker 可以分到两个网络域，却要等一个域内出现三台合格节点才能同域放置。教学作业需要 3 个同域 worker，每个 worker 占一台不同节点，需要同一节点有 4 张可分配 H100，且 CPU、主机内存、RDMA VF 都要够。图只显示每台节点通过全部条件后的可放名额，只有一台节点显示改变的 GPU 余量。

横向 16:9，两组独立快照左右并排，严格同尺度。每组都有上下两个描边区域，上方 A 域，下方 B 域，各放三个相同大小的服务器图标，节点按从左到右读。A 域放 h-a1、h-a2、h-a3，B 域放 h-b1、h-b2、a-b3。每台服务器旁放一个代表 worker 名额的可数小方格。用带对勾的浅绿方格表示可放 1 个，用灰色斜线方格表示可放 0 个，图例写明含义。服务器形态可以简化成带前面板的机架式服务器，域框只表示调度用的网络域范围，省略交换机、网线和设备内部。

左画面为原余量。h-a1、h-a2、h-b1 的方格各为可放 1 个，另外三台为可放 0 个。h-a3 下方写“2 张 GPU 可分配”。A 域标题旁写“可放 2 个”，B 域标题旁写“可放 1 个”。左画面底部写“单域放不下 3 个”。

右画面与左画面一一对齐。只让 h-a3 的空闲 GPU 增加到 4 张，h-a3 下方写“4 张 GPU 可分配”，将此服务器的名额方格改为可放 1 个，并用琥珀色轮廓高亮它。A 域标题旁写“可放 3 个”，B 域仍写“可放 1 个”。右画面底部写“A 域可放下 3 个”。A、B 两域始终分框。没有把 worker 画成 GPU，没有跨框合并名额，也没有加入第七台服务器。

图中文字以如下清单为准。全图标题“3 个 worker 能同域放下吗”。左右画面标题“原余量”“h-a3 再释放两张卡”。两边分别使用“A 域”“B 域”“h-a1”“h-a2”“h-a3”“h-b1”“h-b2”“a-b3”，特别区分 a-b3 与 h-b3。按上述位置放“2 张 GPU 可分配”“4 张 GPU 可分配”“可放 1 个”“可放 2 个”“可放 3 个”“单域放不下 3 个”“A 域可放下 3 个”。底部只需一个图例，逐字写“可放 1 个 worker”“可放 0 个 worker”。保留大小写、空格与连字符，标签不压住方格和边界。

按 1920×1080 构图，不透明暖白底 #FFFCF7，可有极淡纸纹。用深灰 #1F2937 细记号笔勾线，配低饱和彩铅或淡马克笔填色。中文用端正手写印刷体，英文和设备标识用等宽手写印刷体。主标签约 44 px，次标签至少 36 px，水平排布。服务器用灰 #64748B 和浅灰 #F1F5F9，网络域用青 #278A9B 和浅青 #E7F5F7，可用名额用绿 #2E8B70 和浅绿 #E6F4EE，发生变化的 h-a3 用琥珀 #D99A2B 高亮。克制的教材插画风，依靠域框、数量和服务器位置传达结果。
```

## fig-15-03-01 GPU、独占 CPU 和 VF 能在同一侧可用吗

- **插入位置**　第三篇「kubelet 怎么得到对齐结果」，策略对照表之后。
- **图注**　两个教学快照采用相同的双 NUMA 节点 `h-a2`，GPU、独占 CPU 和两处 VF 的物理位置保持不变。只有一个 VF 可用。将可用的 VF 候选从 NUMA 0 换到 NUMA 1 后，4 张 GPU、16 个独占 CPU 和 1 个 VF 才有同一 NUMA 落点。图中结果适用于设备提示准确、其余准入条件满足的 `single-numa-node` 策略。
- **替代文本**　左右各是一台同样的双 NUMA 服务器，4 张可用 GPU 和 16 个可独占 CPU 都位于 NUMA 1。左侧只有 NUMA 0 的 VF 可用，严格策略拒绝。右侧只有 NUMA 1 的 VF 可用，三个请求可在 NUMA 1 对齐。
- **验收要点**　每个快照只有一台服务器、两个 NUMA 范围和两个固定位置的 VF。左右均仅有一个可用 VF。GPU 和 CPU 的可用数量严格相同，图中结论只对应这些资源的提示。

```text
为已有 Linux 和 Kubernetes 基础的读者绘制中文 AI 基础设施教材插画。回答为什么一台节点的 4 张 GPU、16 个可独占 CPU 和 1 个可用 VF 数量都够，kubelet 的 single-numa-node 策略仍可能拒绝。教学条件为双 NUMA 的 h-a2，准确上报 GPU 和 VF 拓扑，CPU Manager 采用 static 策略且可独占 CPU 可用，其他准入条件满足。机器上 NUMA 0 和 NUMA 1 各有一个同资源名的 VF。两个快照之间只交换哪个 VF 已占用，VF 本身仍位于原来的 NIC 上。

横向 16:9，左右两个等宽画区，各有一台同样的服务器，按从左到右阅读为跨 NUMA 候选与同 NUMA 候选。每台服务器剖面分两个同尺度的竖框，左框 NUMA 0，右框 NUMA 1。服务器内部连接采用简化标注，NUMA 框表示资源归属。图上省略主机内存及具体 PCIe 路径。两个快照中各对象的位置和物理数量保持一致。

两个画区中，NUMA 0 画灰蓝色的 CPU 封装，标“0 CPU 可独占”，它下方放一张 NIC，NIC 图标旁用一个小状态格标“VF 0”。NUMA 1 的同样位置画蓝色 CPU 封装，标“16 CPU 可独占”。其下放四个可数绿色 GPU 模组，每个用 GPU 芯片和旁侧显存简化表达，一并标“4 张 GPU 可分配”。NUMA 1 也画一张 NIC，旁边用同样的状态格标“VF 1”。两个状态格是所属 NIC 的逻辑 VF，使用短标注线指向 NIC，别把 VF 画成能在机箱中移动的实体卡。

左图中 VF 0 的状态为“可用”，高亮边框；VF 1 为“已占用”，用灰色斜线。左图底部写“无单 NUMA 候选”。不把跨 NUMA 资源画成可以合并到同一框。右图中 VF 0 为“已占用”，VF 1 为“可用”。只在右图用琥珀色内轮廓圈出 NUMA 1 内的 16 CPU、4 张 GPU、VF 1 三处资源，完整保留 NUMA 边界，底部写“NUMA 1 能满足”。两张图各自都只有一个 VF 处于“可用”，两次快照没有物理设备移动、增加或删除。

逐字文字仅使用标题“资源能放在同一 NUMA 节点吗”、两种状态的标题“跨 NUMA 候选”“同 NUMA 候选”、每边的“h-a2”“NUMA 0”“NUMA 1”“0 CPU 可独占”“16 CPU 可独占”“4 张 GPU 可分配”“VF 0”“VF 1”“可用”“已占用”，底部的“无单 NUMA 候选”“NUMA 1 能满足”，以及公共小标签“single-numa-node”。不加入自动推论文字。保留大小写、空格、数字及连字符。

按 1920×1080 构图，不透明暖白底 #FFFCF7，可有极淡纸纹。用深灰 #1F2937 细记号笔勾线，配低饱和彩铅或淡马克笔填色。中文用端正手写印刷体，英文和设备标识用等宽手写印刷体。主标签约 44 px，次标签至少 36 px，水平排布。CPU 用蓝 #3B6EA8 和浅蓝 #E8F0FA，GPU 用绿 #2E8B70 和浅绿 #E6F4EE，NIC 用青 #278A9B 和浅青 #E7F5F7，普通结构用灰 #64748B 和浅灰 #F1F5F9，候选范围用琥珀 #D99A2B。状态兼用斜线和文字。轴线、标注端点和边界清晰，采用克制的教材插画风格。
```
