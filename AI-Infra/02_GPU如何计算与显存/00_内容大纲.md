# 第 02 章 GPU 如何计算，显存为什么重要｜内容大纲

## 读者起点与学习目标

第 01 章已画出 CPU、主机内存、PCIe 和 GPU 的位置。本章跟着一次数据更新进入单张 NVIDIA GPU，解释 CUDA 如何组织设备上的工作、数据如何供给执行单元，以及怎样根据一份作业记录做判断。读者具备 Linux 和 Kubernetes 基础即可，数组、浮点格式与字节单位在正文使用处补充，无需编写 CUDA Kernel 或使用 GPU。

读完应能：

1. 给定元素数和启动形状，计算 Block、Warp 和有效线程数，并解释 SM 的分派、驻留限制和指令发射。
2. 画出主机缓冲区、HBM、L2 与 SM 内资源的关系，按分配的生命周期估算显存峰值，解释设备与框架统计的差异。
3. 选用匹配设备、精度和指令路径的峰值，以同一 Kernel 的运算量和 HBM 流量推导性能上界，写出判断所依赖的假设。
4. 在单批及双缓冲时间线上标出提交、执行和完成，按依赖判断能否重叠，再结合指标区分计算、内部访存和输入供给的证据。

## 从一批数组到一条作业时间线

| 篇次与正文标题 | 概念和案例如何推进 |
| --- | --- |
| 01 CUDA Kernel 的线程分组与 SM 执行 | 从主机通过 CUDA 复制两个数组、启动 Kernel 到 GPU 更新结果，先建立主机和设备分工。以 1,000 个元素推导 Grid、Block、Warp 与尾部掩码，再把已定义的 Warp 映射到 SM 调度器、CUDA Core 和 Tensor Core。用大 Grid 比较寄存器和共享内存对驻留率的约束，回看小 Grid 能覆盖多少 SM。 |
| 02 HBM、片上存储与显存容量预算 | 跟踪同一数组从主机 DRAM 到 HBM，再沿全局内存读走到 SM。解释缓存自动复用和 Block 显式复用。先按数组和槽位核算字节，再用独立模型案例解释权重、活跃状态和工作区的峰值。用 PyTorch 的释放前后记录解释活跃张量、分配器保留与设备用量。 |
| 03 运算精度、算术强度与 Roofline 性能上界 | 从每个元素需要多少字节和运算进入规格选择，先分清存储、乘法、累加和写回格式，再由计算/搬运时间下界推导 Roofline。把数组放大到 1 亿元素，与稠密矩阵乘法对照，通过增加矩阵的实际 HBM 流量观察分界如何跨越。 |
| 04 CUDA Stream 的执行顺序、事件与拷贝重叠 | 把 Kernel 放回作业时间线。单流示范数据从 H2D 经 Kernel 到可选 D2H 的完成条件，再用独立的三批教学时长和设备双缓冲推导依赖、复用和重叠。Event、默认流、页锁定及计时接口随相应问题引入。 |
| 05 GPU 利用率、Kernel 吞吐与作业瓶颈 | 先按批次完成依赖找耗时，再对照各指标分母。复用逐元素和稠密矩阵算例作诊断示范，另用预备输入的对照区分输入供给与 GPU 内部执行。说明系统级时间线和 Kernel profiler 各自能支持的判断。 |
| 99 综合检验与本章小结 | 在同一个三批数组作业中，检查线程映射、单槽与双槽预算、HBM 上界以及 H2D 与计算的重叠收益。给出完整参考推理和进一步取证点。章末将执行资源、数据位置、规格上界与完成条件接回单机主线。 |

核心部分讲到能推导数量和状态变化。CUDA API 作为观察与解释依赖的材料。统一内存的迁移、默认流变体、结构化稀疏和分配器细节放在各自主例之后。第 03 章沿首次 Kernel 继续解释依赖库和上下文，第 04 章展开 H2D 的物理路径和多卡互联。第 05、08、09 章分别将容量、同步和输入供给扩展到多卡作业、通信库和数据管线，第 17—18 章继续用指标与时间线做归因。

## 材料适用条件

案例以 Linux 上的一张未启用 MIG 切分的 H100 SXM 80 GB 或明确声明的独立教学预算为背景。CUDA 行为以 13.2.1 归档文档为准，PyTorch 对照采用 2.8 原生缓存分配器。保留三张原配图，Stream 的执行依赖用 Mermaid，精确数字用表。

所有时间、流量和作业记录均作为教学材料。真实设备的可用显存、默认流模式、拷贝与计算重叠、实际指令路径、持续峰值和计数器可用性仍需在目标环境核实。
