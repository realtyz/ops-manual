# 第 02 章 GPU 如何计算，显存为什么重要｜内容大纲

## 一、本章定位与前置知识

第 01 章在服务器整机视角下画清了 CPU、主机内存、PCIe 与 GPU 的位置关系。本章推开单张 GPU 的芯片大门，回答两个直接影响基础设施规划与调优的核心问题：**GPU 内部如何并行执行计算，以及显存容量与带宽为何成为大模型训练与推理的头号瓶颈**。

阅读本章只需具备 Linux 与 Kubernetes 基础，无需编写 CUDA 代码或拥有实机环境。第 03 章将沿首次 Kernel 启动继续深入驱动与 CUDA 软件栈，第 04 章将把这里的 H2D 搬运扩展到单机多卡 PCIe 与 NVLink 路径，第 05、08、09、17–18 章则会把单卡容量、吞吐与瓶颈定位方法延展至多机集群。

## 二、核心学习目标

读完本章后，你应当能够：

1. **掌握 GPU 并行执行模型**：给定任务规模与启动形状，计算 Grid、Block、Warp 与有效线程数，解释 SM 分派、SIMT 调度隐藏延迟以及寄存器/共享内存对驻留率（Occupancy）的制约。
2. **核算训练与推理两类显存预算**：理清 HBM、L2、L1/共享内存与寄存器的层次分工；按张量生命周期估算训练显存峰值，并能按层数、GQA 头数、上下文长度与并发数精确推导大模型推理的 **KV Cache** 显存占用，区分 PyTorch 活跃张量、分配器保留量与设备已用量。
3. **运用 Roofline 洞察训推瓶颈差异**：匹配设备精度规格（FP32/TF32/BF16/FP16/FP8/INT8）与 HBM 带宽，计算算术强度与性能上界；讲清为何训练与推理 **Prefill** 偏计算受限，而 **Decode** 沦为 HBM 带宽受限，并定量解释量化与 **Continuous Batching** 的提速逻辑。
4. **理清异步执行与重叠条件**：在单流与双缓冲时间线上标出提交、执行与完成时点，利用 CUDA Stream、Event 与页锁定内存判断拷贝和计算能否真正重叠。
5. **穿透监控指标定位真实瓶颈**：解释为何 `nvidia-smi` 显示 `GPU-Util 95%` 时算力利用率依然极低，结合 Nsight Systems、Nsight Compute 与对照实验，在输入供给、H2D 搬运、HBM 带宽与计算路径之间锁定关键路径。

## 四、本章贯穿场景与参考设备

本章统一以 Linux 主机上的一张 **NVIDIA H100 SXM 80 GB**（未启用 MIG 切分，HBM3 带宽 3.35 TB/s）为硬件锚点，软件口径遵循 [全书基线与术语速查](../00_全书基线与术语速查.md) 中的 **CUDA 13.2.1** 与 **PyTorch 2.9**。

全章算例按“由简入繁、训推并进”的方式展开：前半段用一个直观的数组更新算例把线程分组、存储层次与异步流水线立稳，中后段将其平滑拓展至稠密矩阵乘法（训练与 Prefill 的计算核心）以及 32B/70B 级大语言模型的 KV Cache 与 Decode 推理场景，帮助读者把底层硬件机制直接映射到真实 AI 负载上。
