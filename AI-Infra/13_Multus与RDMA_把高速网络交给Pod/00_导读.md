# Multus 与 RDMA：把高速网络交给 Pod

Pod 能解析域名、访问 Service，为什么 RDMA 程序仍找不到设备？Pod 已有 `net1`，为什么 NCCL 仍走 Socket？本章从这两个问题出发，把网络接入拆成网络选择、设备分配、接口配置、RDMA 可见性和应用使用，逐层建立证据。

读完应能**解释默认网络与附加网络的分工；关联 Pod、NAD、资源名、PCI 地址、netdev 和 RDMA 设备；为共享 HCA 与独占 VF 选择组件；推导地址、路由、MTU 和 NUMA 约束；说明两个 Operator 的责任交界；根据完整材料定位故障并确定测试覆盖范围。**

## 前置与边界

已有基础是 Linux 网络命名空间、接口、路由、内核模块、设备文件，以及 Kubernetes Pod、扩展资源、CNI 和 NetworkPolicy 的基本概念。[第 06 章](../06_从普通网络通信走向RDMA/00_导读.md)提供 Verbs、内存注册与 GPUDirect RDMA，[第 07 章](../07_InfiniBand_RoCE与集群网络拓扑/00_导读.md)提供 RoCE/IB 和物理网络，[第 08 章](../08_NCCL如何组织GPU间的通信/00_导读.md)提供通信库选路，[第 10—11 章](../11_Kubernetes如何发现与分配GPU/00_导读.md)提供容器交付和设备分配，[第 12 章](../12_GPUOperator如何管理节点软件/00_导读.md)提供 Operator 调谐。正文就近补入当前推导需要的最小解释，不要求回看其他主题目录。

本章新建 Multus/NAD、PF/VF、两类网络设备插件、RDMA 命名空间模式和附加网络证据的概念。主线采用 **Ethernet/RoCEv2、传统 Device Plugin、内核驱动 VF**；IB/IPoIB、整接口接入和 SF 用对照说明边界，不展开它们的全量安装步骤。不把 GPU DRA 的字段直接移植为网络 DRA 配置。GPU 共享在第 14 章展开，跨 Pod 的组调度与作业组织在第 15—16 章展开，持续观测与生产变更在第 17—19 章展开。

## 两个互斥的教学场景

`net-a`、`net-b` 是两台 Linux x86_64 裸机，每台有两张支持 GPUDirect RDMA 的 NVIDIA A100 PCIe GPU，以及一个用于 RoCE 的 ConnectX-6 Dx 端口。GPU 使用节点内代号 G0/G1：G0 在 NUMA 0，G1 在 NUMA 1；NIC 在 NUMA 0。每台机器的 PCI 地址可以相同，**设备身份必须带节点名**。

| 项目 | 固定条件 |
| --- | --- |
| 主机与运行平台 | Ubuntu 22.04，Linux 5.15，Kubernetes 1.32.3，containerd 1.7；GPU 容器访问已完成第 10—12 章对应的独立交付 |
| NIC 映射 | PF `0000:41:00.0`，宿主机 netdev `enp65s0f0`，PF RDMA 设备 `mlx5_0`，NUMA 0 |
| 默认网络 | 已由集群 CNI 实现；`worker-a` 的 `eth0=10.244.1.20/24`，`worker-b` 的 `eth0=10.244.2.20/24`；本轮 Pod IP 等于各自 eth0 地址 |
| 附加网络 | 两节点接在同一无标签 Ethernet 二层域，子网 `192.0.2.0/24`，`net1` 的本轮地址分别为 `.101`、`.102`；不配置附加默认路由 |
| 链路与预算 | 每节点一个 100 Gb/s 物理端口；需要计算时另给定单向有效载荷预算 10 GB/s（十进制），不是实测值 |
| 场景 S | 不创建 VF；RDMA subsystem 为 `shared`；`rdma.example.com/shared_hca=4`；macvlan 接口共享 PF |
| 场景 V | 独立重建节点池；每个 PF 已创建两个 VF：VF0=`0000:41:00.2`、VF1=`0000:41:00.3`，关联 RDMA 名分别为 `mlx5_2`、`mlx5_3`；subsystem 为 `exclusive`；`example.com/roce_vf=2` |

S 与 V 是**互斥快照**，不在同一节点上同时配置。RDMA subsystem 模式是节点级条件；不能给每个 NAD 随意选一个不同的模式。后文的故障案例和练习如改变条件，会明确重置。

## 版本、材料与配图状态

机制核对采用 Multus `v4.1.0`、RDMA Shared Device Plugin `v1.5.3`、SR-IOV Device Plugin `v3.9.0`、SR-IOV CNI `v2.8.1`、RDMA CNI `v1.3.0`；Operator 管理边界固定 Network Operator `v25.4.0` 和 GPU Operator `v25.3.0`。这些网络组件版本可追溯到 [25.4.0 文档变量](https://github.com/Mellanox/network-operator-docs/blob/v25.4.0/docs/common/vars.rst)。Network Operator 中的 Multus 版本不用其他章节或 `latest` 的值替换。

为直接展示跨节点 IPAM 的输入，本章 NAD 使用**独立管理的 Whereabouts v0.8.0**，并假设其二进制、Kubernetes 后端、认证、CRD 和权限已正确安装；它不是 25.4.0 的默认配套版本。25.4 已弃用 Whereabouts 集成，后续版本的变化在第 05 篇单独说明。以上是固定接口的历史教学基线，不宣称整套组合获得生产认证，也未经端到端实测。核对日期：**2026-11-08**。

所有 YAML/JSON、命令输出、日志、地址分配结果、测试摘要和性能数字均为**自拟教学材料**，使用处也标明性质。`registry.example.invalid` 是未制作、未发布的教学镜像占位；Pod 清单用于阅读，不能直接执行。无需 GPU/RDMA 环境即可完成全部练习。
