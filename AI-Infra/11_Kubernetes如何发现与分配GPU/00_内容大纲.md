# 第 11 章 Kubernetes 如何发现与分配 GPU｜内容大纲

## 读者起点与学习目标

读者能读 Pod、Node 和容器资源字段，知道 API Server、调度器、kubelet 和容器运行时的基本分工。第 03 章的驱动和第 10 章的容器访问是起点：主机已能枚举 GPU，运行时能按设备描述配置容器。本章从一个 Pod 请求一张卡开始，建立**主机发现、Pod 放置、具体设备分配、容器交付**四个连续问题。

读完应能完成四项任务：

1. 根据插件上报、Node 状态和已有请求，推导健康变化如何影响资源数，算出单个 Pod 的节点候选，并解释型号标签的保证范围。
2. 沿 Device Plugin 路径从节点绑定追踪到本地设备 ID、分配响应、容器创建请求与进程可见的 GPU，判断各阶段何时成功。
3. 根据 DRA 的设备库存、设备类、申请条件及已有分配推导可选设备，用 Claim 的分配与消费者记录追踪节点准备、交付和释放。
4. 在只有部分证据时辨认供给后端及最早失败的环节，给出下一项有区分力的检查，并用设备身份和最小 CUDA 计算验收交付。

## 贯穿案例与技术口径

- `gpu-h` 有两张同型 H100 SXM（A、B），`gpu-a` 有两张同型 A100（C、D）。Device Plugin 的健康主例中 A 已分给另一个 Pod，B 是健康、未分配的整卡。两节点和四卡与第 10 章示例是独立场景，仅复用 A、B 的示例 UUID 表记与 H100 探针思路。
- DRA 用同一组节点名和设备简称重建独立快照，由另一个 Claim 占用 A。切片报告的总显存按教学值设为 A/B `80Gi`、C/D `40Gi`，实际值读取驱动发布的设备条目。额外的混装节点 `gpu-mix` 使用 X、Y，表示型号筛选粒度的独立对照。
- 主例使用普通单容器 Pod、Linux、整卡、默认调度器，关闭 MIG 与共享。除另行指出的条件，CPU、主机内存、污点及其他约束满足。版本锚点为 Kubernetes v1.36 / v1.36.0、独立 NVIDIA Device Plugin 与 GFD v0.19.2、NVIDIA DRA Driver v0.5.1、containerd v2.3.0。Operator v26.7 的前置条件只用于说明其托管路径。
- 保留三张原图。容量图留在第 02 篇，混装图随内容移到第 05 篇并更新图号和路径，注入图留在第 06 篇。验收时对照图中的节点、卡号、状态、单位和目录，注明图中缩写所指的案例对象；时序另用 Mermaid 表达。
- YAML、状态、算例和故障记录是按接口构造的教学材料，标明省略项和占位。第 12 章接组件安装与维护，第 13 章应用于网络设备，第 14 章讨论资源单位怎样随共享和切分变化，第 15 章推进到多 Pod 和拓扑放置。

## 技术依据与待核实项

- 计数路线用 [Kubernetes v1.36 Device Plugins](https://v1-36.docs.kubernetes.io/docs/concepts/extend-kubernetes/compute-storage-net/device-plugins/) 与 [v1.36.0 Device Manager](https://github.com/kubernetes/kubernetes/blob/v1.36.0/pkg/kubelet/cm/devicemanager/manager.go) 核对注册、健康、选卡和回收；以 [NodeResourcesFit](https://github.com/kubernetes/kubernetes/blob/v1.36.0/pkg/scheduler/framework/plugins/noderesources/fit.go) 核对余量；用 [NVIDIA Device Plugin v0.19.2](https://github.com/NVIDIA/k8s-device-plugin/tree/v0.19.2) 核对设备 ID、交接策略和 GFD。区分插件本地库存、调度快照、Node 状态及实际利用率。
- DRA 用 [Kubernetes v1.36 DRA](https://v1-36.docs.kubernetes.io/docs/concepts/scheduling-eviction/dynamic-resource-allocation/) 和固定版本实现核对切片、Claim 绑定顺序、消费者及扩展资源映射；用 [NVIDIA v0.5.1 节点实现](https://github.com/kubernetes-sigs/dra-driver-nvidia-gpu/tree/v0.5.1/cmd/gpu-kubelet-plugin) 检查准备、CDI 名称和释放。按 [containerd v2.3.0 CRI 配置](https://github.com/containerd/containerd/blob/v2.3.0/docs/cri/config.md) 核对运行时扫描条件。托管组件前置条件见 [GPU Operator v26.7 DRA](https://docs.nvidia.com/datacenter/cloud-native/gpu-operator/26.7/dra-intro-install.html)。
- 实机组合、有效运行时配置、实际切片数值、Node 状态更新时序、准备调用与最小 CUDA 探针输出需在目标环境采集。本轮设计以离线推导、字段与实现核对为验收范围。
