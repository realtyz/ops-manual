# 第 11 章 Kubernetes 如何发现与分配 GPU｜内容大纲

## 一、本章定位与前置知识

第 03 章讲清了宿主机驱动与 NVML 如何枚举物理 GPU，第 10 章打通了容器通过 CDI 或运行时包装层使用 GPU 的路径。本章把视角抬升到集群层面，回答一个核心问题：**当一个训练或推理 Pod 申请 GPU 时，Kubernetes 如何发现节点上的卡、决定把它放到哪台机器、挑出具体哪张卡，并交接给容器运行时？**

全章围绕两条架构主线展开：
- **先立住传统整卡路径的两次决策边界**：调度器只看“数量账本与节点标签”选节点，节点上的 kubelet 与 Device Plugin 才负责“挑具体哪张物理卡”并交接给 CDI。
- **再顺滑过渡到下一代 DRA 方案**：当集群进入异构卡型混装或需要按显存、互联属性精细选卡时，整数扩展资源会撞上表达瓶颈，**DRA（Dynamic Resource Allocation，动态资源分配）** 把调度视野从“节点总卡数”下沉到“逐卡属性与容量”。

阅读本章前，默认你熟悉 Pod、Node、容器资源字段，以及 API Server、调度器、kubelet 与容器运行时的基本分工。本章结束后，第 12 章将接手这些组件的自动化安装与运维（GPU Operator），第 13 章扩展到高速网卡设备，第 14—15 章则把整卡粒度推进到共享切分与多 Pod 拓扑调度。

---

## 二、核心学习目标

1. **算清容量与调度账本**：能跟踪 Device Plugin 注册与健康更新如何改变 Node 的 `Capacity` / `Allocatable`，复算单节点 GPU 余量，并厘清节点标签与资源计数的边界。
2. **打通节点本地选卡与 CDI 交接**：能沿 kubelet 本地候选集合、`Allocate` 响应、CRI 请求与 containerd 规格解析追踪单卡交付，定位“绑定后接纳前故障”与交接失败。
3. **掌握 DRA 逐卡匹配与全生命周期**：能读懂 `ResourceSlice`、`DeviceClass`、`ResourceClaim` 与 CEL 筛选表达式，推演逐卡匹配、节点 `NodePrepareResources` 准备及双平面资源回收。
4. **辨认双后端并分层取证**：能在 `nvidia.com/gpu` 同语法背后区分 Device Plugin 与 DRA 扩展资源映射，在部分证据下锁定最早失败环节，并以 UUID 核对与最小 CUDA 计算完成验收。

## 四、本章贯穿场景说明

本章统一对齐全书参考版本栈：**Kubernetes v1.36**、**NVIDIA Device Plugin（含 GFD）v0.20.1**、**NVIDIA DRA Driver v0.5.1**、**containerd 2.3.0** 与原生 CDI，聚焦 Linux 单容器整卡场景（暂关闭 MIG 与共享，留待第 14 章展开）。

正文讲普遍机制时均采用语义角色；具体 YAML、命令输出与状态快照采用三台直观命名的参考节点：
- **`node-h100`**：配备 2 张同型 80 GiB H100 SXM（主例中第 1 张已分配给已有工作负载，第 2 张健康空闲）。
- **`node-a100`**：配备 2 张同型 40 GiB A100（均健康空闲）。
- **`node-mix`**：同时装有 1 张 80 GiB H100 与 1 张 40 GiB A100 的异构混装节点，用于对比节点标签筛选与 DRA 逐卡筛选的粒度差异。
