# Kubernetes 如何发现与分配 GPU

运行时已经能够把选定 GPU 交给容器，Kubernetes 仍需回答三个问题：哪台节点有多少可调度资源，这个 Pod 应放在哪里，到达节点后究竟使用哪张卡。本章把资源账本、设备身份和运行环境接起来。

读完应能**追踪 Device Plugin 注册、上报、健康更新与 Allocate；从 Node 和 Pod 材料推导数量是否满足；区分调度器选节点与 kubelet 选设备；说明 NFD/GFD 标签如何参与筛选；读懂 DRA 的设备清单、需求、分配与准备；根据状态判断当前停在哪一步。**

## 前置与边界

Linux 进程、设备文件、Unix socket、容器及 Kubernetes 的 Node、Pod、调度与 DaemonSet 是已有基础。[第 03 章](../03_从驱动到CUDA应用的软件依赖/00_导读.md)的 NVML 与驱动、[第 04 章](../04_单机多卡与GPU数据路径/00_导读.md)的设备身份、[第 10 章](../10_GPU如何进入容器/00_导读.md)的 CRI/CDI 是直接前置。本章会解释新出现的资源字段与设备接口，不要求读者预先认识 Device Plugin 或 DRA。

第 10 章从“设备已选定”讲到容器可计算；本章把起点前移到设备发现，并在交付处接回它。第 12 章负责 GPU Operator 对组件的部署与维护，第 13 章负责 RDMA/NIC 接入，第 14 章负责共享与 MIG，第 15—16 章负责多 Pod 作业、队列和拓扑策略。本章提供这些主题需要的资源管理接口，不展开安装手册、共享策略或组调度算法。

## 两个互斥场景与固定基线

本章使用独立教学模型，不继承第 10 章的 ct-a 卡号。两台 Linux x86_64 节点中，`gpu-a` 有四张 A100-SXM4-40GB，`gpu-b` 有两张 NVIDIA L4；均关闭 MIG，使用整卡独占模型，没有 Time-Slicing 或 MPS。设备代号如下：

| 节点 | 代号 | 本轮主机 index / minor | 完整 UUID |
| --- | --- | --- | --- |
| gpu-a | U0 | 0 | `GPU-11111111-1111-4111-8111-111111111111` |
| gpu-a | U1 | 1 | `GPU-22222222-2222-4222-8222-222222222222` |
| gpu-a | U2 | 2 | `GPU-33333333-3333-4333-8333-333333333333` |
| gpu-a | U3 | 3 | `GPU-44444444-4444-4444-8444-444444444444` |
| gpu-b | V0 | 0 | `GPU-55555555-5555-4555-8555-555555555555` |
| gpu-b | V1 | 1 | `GPU-66666666-6666-4666-8666-666666666666` |

短代号用于叙述和插图；API 记录中的设备 ID 使用完整 UUID。index、minor 和 DRA 设备名的对应仅在本章当前枚举条件下成立，不能当成永久资产身份。显存教学读数设为 A100 每卡 **40536 MiB**、L4 每卡 **23034 MiB**，用于容量筛选，不能当成全部同型号设备的实测规格。

- **场景 P：Device Plugin。** Kubernetes **1.34.0**，NVIDIA Device Plugin / GFD **0.17.1**，NFD **0.17.4**。每节点只有一个分配者上报 `nvidia.com/gpu`；主线采用插件 `cdi-cri` 策略，经原生 CDI 运行时交付。envvar/legacy 作为独立对照。
- **场景 D：DRA。** 独立重置的同名节点，只由 NVIDIA DRA Driver **v25.8.0** 的 GPU 路径管理这些卡，不同时由传统插件发布它们。API 使用 Kubernetes **`resource.k8s.io/v1`**，只讲核心整卡分配；不启用优先候选、分区设备、设备污点、管理访问或 DRA 扩展资源桥接等可选能力。

Kubernetes DRA 核心在 1.34 进入 GA；这不等于每个厂商驱动的所有功能都已获支持。所选 NVIDIA tag 的 README 明确说 GPU 分配部分尚未正式支持，而 ComputeDomain 是另一条资源路径。因此场景 D 用来解释已核对的对象与实现，**不作为受支持的生产安装方案**。依据见 [Kubernetes 1.34 DRA 发布说明](https://kubernetes.io/blog/2025/09/01/kubernetes-v1-34-dra-updates/)与 [NVIDIA v25.8.0 README 的 GPUs 小节](https://github.com/NVIDIA/k8s-dra-driver/blob/v25.8.0/README.md)。

两场景的容器交付条件固定为驱动 **570.124.06**、Container Toolkit **1.18.0**、containerd **1.7.27**，CRI 原生 CDI 已启用，有效描述与实际主机文件一致。镜像提供 CUDA **12.8.1** Runtime，探针含 A100/L4 所需设备代码；镜像名 `lesson/gpu-probe:cuda12.8.1` 是虚构交付物。工作负载为普通非 privileged 容器，无额外宿主设备挂载，不覆盖插件的设备选择，也不设置 `CUDA_VISIBLE_DEVICES` 等附加过滤。具体库兼容与计算探针读法见第 10 章。这里的组件组合未经端到端实测，也不代表当前推荐版本。资料核对日期：**2026-11-08**。

所有 YAML、命令配套输出、RPC 摘要、时间线、日志与探针结果均为**自拟教学材料**，使用处标明；删节处保留推导所需信息。无需执行命令或拥有 GPU。每个故障/练习若改变基线，独立声明条件。
