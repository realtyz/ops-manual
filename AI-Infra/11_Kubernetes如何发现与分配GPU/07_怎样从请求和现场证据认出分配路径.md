# 怎样从请求和现场证据认出分配路径

同一个 `Pending` 状态可能出现在 Pod 还没选到节点时，也可能出现在已选节点、容器尚未启动时。从 `spec.nodeName`、`PodScheduled` 条件和最近的事件找第一处分界，再根据资源如何供给选择要查的字段。以下对照使用 Kubernetes v1.36、完整 GPU 和支持原生 CDI 的 containerd。 [Kubernetes v1.36 Pod phase 与条件](https://v1-36.docs.kubernetes.io/docs/concepts/workloads/pods/pod-lifecycle/)

| 要确认的环节 | Device Plugin 提供的扩展资源 | 显式 Claim 的 DRA |
| --- | --- | --- |
| Pod 请求 | 容器 `resources.limits["nvidia.com/gpu"]` 等字段表达数量。 | Pod `spec.resourceClaims` 指向 Claim 或模板，容器通过 `resources.claims` 引用。 |
| 调度器读取的设备信息 | Node `status.allocatable` 和已计入的请求给出资源余量。按型号放置时还检查节点标签。 | `ResourceSlice` 提供逐设备信息。调度器结合 `DeviceClass`、Claim 条件、已有分配和可达节点作选择。 |
| 何时确定设备 | 节点绑定后，kubelet 的 Device Manager 选择本地设备 ID，交给插件 `Allocate`。 | 调度器在绑定 Pod 前把具体设备写到 Claim，kubelet 让 DRA 节点插件按结果准备。 |
| 怎样进入容器 | `cdi-cri` 时，插件在分配响应里传 CDI 全名，kubelet 转交 CRI。其他策略可用环境变量、挂载或注解。 | NVIDIA DRA 节点插件在 `NodePrepareResources` 的结果里传 CDI 全名，kubelet 转交 CRI。 |
| 怎样验证 | 已运行 Pod 的 PodResources `List` 可查看分配 ID。再以容器枚举的 GPU UUID 核对实际注入。 | 用 Claim 结果的 `driver/pool/device` 关联切片 UUID，与容器枚举的 GPU UUID 核对。 |

两条路径都可由 containerd 消费 CDI。CDI 负责把已指定设备所需的节点、挂载等写入容器配置，看到 CDI 名只说明交接使用了这个接口。判断选卡发生在哪一层，要追该名称来自 `Allocate` 还是 `NodePrepareResources`。 [Kubernetes Device Plugin 与 PodResources](https://v1-36.docs.kubernetes.io/docs/concepts/extend-kubernetes/compute-storage-net/device-plugins/) · [NVIDIA DRA 的分配和注入](https://dra-driver-nvidia-gpu.sigs.k8s.io/docs/concepts/gpu-allocation/#how-scheduling-works) · [CDI 规范](https://github.com/cncf-tags/container-device-interface/blob/v1.1.0/SPEC.md)

## 扩展资源名也可以映射到 DRA

`DRAExtendedResource` 在 Kubernetes v1.34 引入时是默认关闭的 alpha 功能，v1.36 转为默认启用的 beta。启用后，可以通过 `DeviceClass.spec.extendedResourceName` 将扩展资源名映射到设备类。调度器选择 DRA 供给时，会创建 `ResourceClaim` 来表达请求的设备数量。GPU Operator v26.7 托管的默认 `gpu.nvidia.com` 类可用 `deviceclass.resource.kubernetes.io/gpu.nvidia.com` 申请，沿用 `nvidia.com/gpu` 则需要另一个设置了该 `extendedResourceName` 的类。读到 `nvidia.com/gpu` 时，要从目标节点的资源供给和对应的 Claim 判断实际后端。Kubernetes 允许同名资源在不同节点由不同后端提供。GPU Operator v26.7 自身的托管工作流要求在集群中选择 `GPUCluster` 或 `ClusterPolicy`。 [Kubernetes v1.34 扩展资源映射](https://v1-34.docs.kubernetes.io/docs/concepts/scheduling-eviction/dynamic-resource-allocation/#extended-resource-allocation-by-dra) · [Kubernetes v1.36 扩展资源映射](https://v1-36.docs.kubernetes.io/docs/concepts/scheduling-eviction/dynamic-resource-allocation/#extended-resource-allocation-by-dra) · [GPU Operator v26.7 的资源名与托管条件](https://docs.nvidia.com/datacenter/cloud-native/gpu-operator/26.7/dra-intro-install.html)

## 用五份记录定位最早失败的环节

以下均为独立的教学快照。先记录 Pod 的命名空间、名称、UID、`spec.nodeName`，以及 `status.conditions[]` 中与调度有关的类型、状态、原因和消息。对照事件的原因和消息，用节点、Pod UID、容器名和时间连接到 kubelet 与运行时。DRA 另记录 Claim 的命名空间、名称和 UID。名称可以被复用，UID 用来区分是不是同一次请求。 [Kubernetes Pod 条件](https://v1-36.docs.kubernetes.io/docs/concepts/workloads/pods/pod-lifecycle/#pod-conditions) · [Kubernetes 对象名称和 UID](https://kubernetes.io/docs/concepts/overview/working-with-objects/names/)

| 记录 | 已有证据 | 判断与下一项检查 |
| --- | --- | --- |
| 有 GPU 标签，Node 资源键缺失 | `gpu-h` 上能枚举 A、B，Node 有 PCI 和 GFD 标签，`status.allocatable` 缺少 `nvidia.com/gpu`。 | 已看到发现路径的结果。先取插件注册记录。若注册成功，再用 kubelet 所见的设备总数和健康数区分列表未到与 Node 尚未更新。 |
| Device Plugin 路径未调度 | Pod 要 H100 和两张 GPU。`PodScheduled=False`，事件包含 `Insufficient nvidia.com/gpu` 和节点选择器相关原因。`gpu-h` 有一张占用，`gpu-a` 两张 A100 均空闲。 | `gpu-h` 余量为 `2 − 1 = 1`，卡数不足。`gpu-a` 余量为 2，型号不符。下一次查看是否有符合型号的节点释放了资源或加入集群。 |
| Device Plugin 路径绑定后失败 | 请求一张卡，Pod 已绑定 `gpu-h`。A 已分配，B 在绑定后、节点内分配前变为不健康。kubelet 报本地可用设备不足。 | 失败发生在节点内选卡，健康未分配设备已从 B 一张降为零张。按时间对齐 `ListAndWatch` 更新与本地已有分配。若 kubelet 已向插件发出 `Allocate`，则继续读 RPC 的结果。 |
| DRA Claim 尚未分配 | Claim 已生成，`status.allocation` 为空。它要求总显存大于 `40Gi`。`gpu-h` 发布两张 `80Gi`，`gpu-a` 发布两张恰为 `40Gi` 的卡。 | 切片只证明 A、B 符合容量条件。查询其他 Claim 的分配。若 A、B 均已分配，缺可分配的合格卡。若 B 未分配，则再看 DeviceClass 其余条件、节点约束和调度事件。 |
| DRA Claim 已分配，容器未创建 | Claim 已选 B，且当前 Pod 的 UID 已在 `reservedFor`。记录一是 kubelet 报准备失败。记录二是准备成功，随后 CRI 报无法解析返回的 CDI 名。 | 记录一查目标节点的 DRA 插件和准备错误。记录二查 CRI 请求里的全名、节点规格及运行时的有效扫描目录。 |

如果容器已启动，先查分配的设备标识能否与容器枚举的 UUID 对上。UUID 对得上但 CUDA 探针失败时，保留探针的失败 API 与返回值，继续核对设备权限、实际加载的驱动库和应用对设备的筛选。 [NVIDIA SMI 设备标识](https://docs.nvidia.com/deploy/nvidia-smi/index.html) · [CUDA 设备 API](https://docs.nvidia.com/cuda/archive/13.2.1/cuda-runtime-api/group__CUDART__DEVICE.html)
