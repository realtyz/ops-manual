# 第 03 章 从驱动到 CUDA 应用的软件依赖｜内容大纲

## 读者起点与学习目标

第 01 章已经用 PCIe 设备地址和驱动绑定识别一张卡。第 02 章已经建立主机提交 Kernel、GPU 异步执行、结果写回显存的模型。本章补上两者之间的软件路径。读者从 Linux 进程、动态库和内核模块的基础出发，按给定材料推导，无需 CUDA 编程经验或 GPU 实验环境。

读完能完成四件事。

1. 从构建、CUDA 计算和 NVML 管理三个入口画出依赖，说明驱动、Runtime、Toolkit、固件各由谁提供及在哪里工作。
2. 根据一次探针的记录，判断库装载、进程内枚举、上下文、Kernel 提交与结果完成各通过了哪一步，并把逻辑设备号对齐到物理卡。
3. 给定实际加载的库、驱动、GPU 和产物中的设备代码，分别推导主机接口、驱动兼容路径和目标代码是否满足运行条件。
4. 从启动或软件更新后的材料找出最早有证据支持的失败点，再选一项能区分剩余原因的检查和一个下游复核动作。

## 阅读顺序与案例

主例为 Ubuntu 24.04 LTS、x86_64 Linux 裸机、单张未切分的 NVIDIA H100，教学 BDF 为 `0000:65:00.0`。构建侧用 Toolkit 13.2 GA 交付 `probe-sm90`，运行侧用 `595.45.04` 和交付所需的共享 Runtime。探针启动一个线程向显存写入整数 7，主机等待并拷回。API 语义以 CUDA 13.2.1 归档为参考。API 参考版本与构建版本分别登记。

| 篇次 | 正文标题 | 在已有认识上增加什么 |
| --- | --- | --- |
| 01 | CUDA 软件栈中的驱动、Runtime 与 Toolkit | 从“要让 GPU 把 7 写入显存”引出 CUDA 软件栈。先讲 Toolkit 怎样提供构建材料、产物为何同时需要主机代码和设备代码，再沿 Runtime、Driver API、设备文件、内核模块到 GPU，并用 NVML 支路对照。依赖图标出构建交付、主机调用、GPU 固件的边界。最后用 `lspci`、`nvidia-smi`、`nvcc` 识别观测层次。 |
| 02 | CUDA 进程的库装载、选卡与首次 Kernel 执行 | 用同一探针走完正常路径。先定义 ELF 共享库装载和进程内设备序号，再解释上下文为什么承载显存分配和工作队列。分别观察启动错误、同步和拷回值。只改变可见性做对照。保留可选源码与构建命令，Driver API 的显式入口和装载时机差异放在主例之后。 |
| 03 | CUDA 设备代码与驱动版本兼容性 | 固定驱动和 H100，仅改变同一 Kernel 的构建目标，推导 cubin 装入和 PTX 即时编译的条件。随后固定产物，比较三种驱动基线，解释为什么次版本兼容的下限不能保证 PTX JIT。最后给出交付件需要记录的版本和检查范围。 |
| 04 | Linux NVIDIA 模块加载与进程库解析 | 先沿启动内核、磁盘模块、已加载模块与目标 BDF 判断设备是否受当前驱动管理。再用同一个探针推导 glibc 如何选中共享库。把两条线合到 NVML 失配案例，比较更新后旧模块仍在运行与进程选中旧库，并验证两种原因所需的证据。 |
| 05 | CUDA 交付基线与故障记录判读 | 把产物、一次系统启动和应用进程关联起来。以主例为基准，提供独立变体及一道兼容性迁移题，要求找出首个失败点、选取下一条证据并预测复核结果。参考推理覆盖四个学习目标，篇末把三条软件路径接回后续章节。 |

核心机制讲到能够预测改变一个条件的后果。第 03 篇用 `probe-sm90`、`probe-sm80`、`probe-ptx80` 三份独立产物检验同一设备上的代码匹配。第 04 篇采用假设带 `DT_RUNPATH` 的打包版本，显式记录这一打包条件，推导环境变量如何影响加载路径。Ubuntu 的 DKMS、预编译包与签名只讲到能读懂取证记录。R570 前向兼容与架构特化目标作为相关机制后的补充。

第 04 章接着解释这些计算和拷贝实际走过的硬件路径。第 10 章在宿主机与容器间重新划分设备文件、驱动库和应用依赖，第 11—12 章分别说明如何分配设备、如何部署和协调节点组件。GPU 固件刷写、CUDA 编程与调优、生产升级和回滚流程留给相应专题。

## 技术依据与材料口径

- 接口和构建以 [CUDA 13.2.1 编程指南](https://docs.nvidia.com/cuda/archive/13.2.1/cuda-programming-guide/index.html) 和 [Toolkit 13.2 GA Release Notes](https://docs.nvidia.com/cuda/archive/13.2.0/cuda-toolkit-release-notes/index.html#cuda-driver) 为基线。区分 CUDA 12.0 的 `cudaSetDevice` 语义变化、延迟加载的最低条件和默认启用版本。
- 用 [Hopper 设备代码兼容指南](https://docs.nvidia.com/cuda/archive/12.6.0/hopper-compatibility-guide/index.html)、[CUDA 次版本兼容说明](https://docs.nvidia.com/deploy/cuda-compatibility/latest/minor-version-compatibility.html) 和 [前向兼容矩阵](https://docs.nvidia.com/deploy/cuda-compatibility/latest/forward-compatibility.html#deployment-considerations-for-forward-compatibility) 核对设备代码、版本和功能条件。表中 R580 下限、`595.45.04` 对应驱动和 R570 兼容包条目各回答不同的问题。滚动兼容矩阵于 2026-11-15 核对。
- 用 [Ubuntu 驱动安装文档](https://ubuntu.com/server/docs/how-to/graphics/install-nvidia-drivers/)、[Linux 模块签名文档](https://docs.kernel.org/admin-guide/module-signing.html) 与 [glibc 动态链接器手册](https://man7.org/linux/man-pages/man8/ld-linux.8.html) 核对状态与取证口径。Canonical 的 NVML 失配示例独立注明来源；其余节点、产物和运行结果均为教学推演。
- 沿用两张插图。设备代码图核对三个产物、H100 9.0、阻断点和主机侧 JIT；NVML 图核对磁盘、运行中模块和实际加载的库，左列 B/A/B，右列 B/B/A。依赖与执行顺序继续用 Mermaid。
