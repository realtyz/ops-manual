# 第 03 章 从驱动到 CUDA 应用的软件依赖｜内容大纲

## 一、本章定位与前置知识

[第 01 章](../01_从一台GPU服务器认识基础设施/00_内容大纲.md) 用 PCIe 拓扑与 BDF 定位了服务器里的每一张 GPU，[第 02 章](../02_GPU如何计算与显存/00_内容大纲.md) 讲清了主机提交 Kernel 后 GPU 内部如何计算与访存。本章补上两者之间最容易踩坑的软件桥梁：**一个 Linux 进程究竟怎样穿过动态库、用户态驱动、设备节点和内核模块，最终把代码送到 GPU 上执行**。

阅读本章只需具备 Linux 进程、ELF 动态库与内核模块基础，无需 CUDA 编程经验或 GPU 实机环境。学完本章后，[第 04 章](../04_单机多卡与GPU数据路径/00_内容大纲.md) 会继续追踪多卡与主机之间的数据物理路径，[第 10 章](../10_GPU如何进入容器/00_内容大纲.md) 会在容器与宿主机之间重新切分这些驱动库和设备节点，[第 11 章](../11_Kubernetes如何发现与分配GPU/00_内容大纲.md) 与 [第 12 章](../12_GPUOperator如何管理节点软件/00_内容大纲.md) 则将整条依赖链自动化交付到 Kubernetes 节点。

## 二、核心学习目标

读完本章后，你应当能够：

1. **理清三条软件路径与职责边界**：分别画出构建侧、CUDA 计算支路与 NVML 管理支路的组件依赖，说清 CUDA Toolkit、Runtime、用户态驱动、Linux 内核模块与 GSP 固件各自的位置与分工。
2. **跟踪 CUDA 进程启动与执行全流程**：沿 ELF 共享库装载、进程内设备枚举与重排、Primary Context 建立、Kernel 延迟装载与异步同步逐步判读日志，并将逻辑设备号对齐到物理 GPU。
3. **运用兼容规则判断设备代码与驱动版本**：掌握计算能力、cubin 与 PTX JIT 的匹配机制，熟练区分驱动向后兼容、CUDA 次版本兼容与前向兼容包（`cuda-compat`）的适用条件与报错边界。
4. **分层定位内核模块与动态库故障**：结合 `uname -r`、`modinfo`、`lspci`、`readelf`、`LD_DEBUG` 与内核日志，准确区分模块缺失、签名拒绝、内核未重载与进程加载错库等根因。

## 四、本章贯穿场景与参考设备

本章统一以运行 **Ubuntu 24.04 LTS（x86_64）** 的裸机服务器及单张未切分的 **NVIDIA H100**（计算能力 9.0）为参考环境，软件口径对齐 [全书基线与术语速查](../00_全书基线与术语速查.md) 的 **R595（`595.91.07`）** 与 **CUDA 13.2.1**。

为了让你不被庞杂的框架代码淹没，全章以一个极简的预编译探针 `probe-sm90`（仅启动 1 个线程向显存写入整数 7 并拷回 CPU 校验）充当“手术刀”，逐层剖开软件依赖；同时在关键环节自然对照 PyTorch 训练与大模型推理引擎的真实部署行为，确保你学到的排障方法能直接迁移到生产集群。
