# 第 10 章 GPU 如何进入容器｜内容大纲

## 一、本章定位与前置知识

从本章开始进入第三阶段——**将 GPU 集群能力接入 Kubernetes**。在引入整套集群调度之前，我们先把镜头收束到单台 Linux 节点：当上层已经为训练或推理容器选定了一张 GPU，容器运行时究竟如何把这张卡和所需的驱动文件交给容器里的进程？

阅读本章需要具备基础的 Linux 文件权限、进程与容器知识，并默认读者已了解[第 03 章](../03_从驱动到CUDA应用的软件依赖/00_内容大纲.md)的驱动/Runtime 依赖关系，以及[第 04 章](../04_单机多卡与GPU数据路径/00_内容大纲.md)的 UUID、PCI BDF 与 CUDA 进程序号。学完本章后，[第 11 章](../11_Kubernetes如何发现与分配GPU/00_内容大纲.md)将向前接上 Kubernetes 的设备发现、配额账本与选卡逻辑，[第 12 章](../12_GPUOperator如何管理节点软件/00_内容大纲.md)至[第 14 章](../14_GPU共享、切分与隔离/00_内容大纲.md)则进一步展开节点软件自动化、高速网络注入与 GPU 切分共享。

## 二、核心学习目标

读完本章后，你应当具备以下可检验的工程推演能力：

1. **理清容器边界的软件分工**：能够从“挂载命名空间隔离”与“cgroup 设备拦截”出发，分别画出容器内 CUDA 计算与 `nvidia-smi` 查询的完整通路，明确镜像、启动注入与宿主机各自的职责。
2. **读懂 OCI 设备配置与内核四关**：能够对照 OCI `mounts`、`linux.devices` 与 `linux.resources.devices` 字段，区分设备节点存在、cgroup v2 设备规则、Unix 权限与 LSM 安全策略对 `openat` 的不同拦截表现。
3. **追踪 CDI 原生注入与四条运行时路径**：能够沿 CRI 请求与 CDI 规格推导 containerd `2.3.0` 原生注入的 OCI 修改与启停时序；能够依据 `RuntimeClass` handler、模式与输入，辨认原生 CDI、JIT CDI、包装层 `cdi` 与 legacy Hook 四条路径。
4. **实现跨层设备身份精准对齐**：能够以 UUID 为锚、以同节点 PCI BDF 佐证，把宿主机管理索引、设备节点、容器设备集合与多进程 `CUDA_VISIBLE_DEVICES` 序号准确对应起来。
5. **分层定位容器 GPU 交付故障**：能够在 `CreateContainer`、`StartContainer` 与容器应用执行三阶段中迅速收窄失败点，选出有区分力的排查命令，并按单变量复核直至完整计算通过。

## 四、本章贯穿场景说明

本章软件栈统一对齐[全书基线与术语速查](../00_全书基线与术语速查.md)：`Ubuntu 24.04 LTS`（x86_64，cgroup v2）、`NVIDIA OpenRM R595`（`595.91.07`）、`CUDA 13.2.1`。

运行时主线采用 `containerd 2.3.0`（原生 CRI CDI）、`CDI 1.1.0`、`OCI Runtime Spec 1.2.1`、`CRI v0.36.0` 与 `NVIDIA Container Toolkit 1.18.2`。

全章以一台双卡服务器 `node-10` 为统一舞台，配备两张未切分的 NVIDIA H100（分别记为 GPU A 与 GPU B），使用 rootful containerd 运行普通非特权容器。

容器内沿用[第 03 章](../03_从驱动到CUDA应用的软件依赖/00_内容大纲.md)的预编译探针 `probe-sm90`（自带匹配 CUDA Runtime），测试目标是在目标 GPU 上运行单线程写入整数 `7`、同步并拷回校验 `output=7`。
