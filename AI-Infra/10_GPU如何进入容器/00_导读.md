# GPU 如何进入容器

宿主机能运行 CUDA 程序，把同一个程序放进容器却找不到 GPU。镜像缺少 Runtime，运行时没有交付设备，还是程序选错了卡？本章沿着一次容器创建和一次应用启动，把这几个问题分开，再将证据接回同一条路径。

学习结束后，应能**画出容器内应用到宿主机驱动的调用关系；说明设备节点、驱动库和访问权限为什么缺一不可；追踪 containerd、NVIDIA Container Toolkit 与 OCI Runtime 的衔接；读懂 CDI 的设备名和注入描述；用 UUID 对应容器内外设备；根据创建记录、库装载和计算结果定位失败阶段。**

## 前置与章节边界

读者已有 Linux 的进程、动态链接、设备文件、namespace、cgroup，以及容器镜像和 Kubernetes 的基础。本章会补充 OCI 配置、设备访问规则和运行时 handler 在 GPU 场景中的含义。[第 03 章](../03_从驱动到CUDA应用的软件依赖/00_导读.md)的 Driver API、CUDA Runtime 和 NVML 是直接前置；[第 04 章](../04_单机多卡与GPU数据路径/00_导读.md)的设备身份与 PCIe 位置帮助完成映射。其余通信与存储章节提供负载背景，不是读完本章的额外门槛。

[第 09 章](../09_GPU的数据从哪里来_存储与IO/00_导读.md)解释数据如何到达显存；本章解释容器中的进程如何获得使用 GPU 的运行条件。本章从“设备已经选定”开始，完整讲运行环境的交付。[第 11 章](../11_Kubernetes如何发现与分配GPU/00_导读.md)再讲 Device Plugin、DRA、资源上报和分配；第 12 章讲 GPU Operator 如何维护节点组件；第 13 章讲 RDMA/NIC 进入 Pod；第 14 章讲共享、MIG 和隔离策略。这里介绍 RuntimeClass 只为读懂运行时入口，不提前展开 Pod 调度与设备分配。

## 教学基线与材料约定

节点 `ct-a` 是 Linux x86_64、rootful 容器环境，使用 cgroup v2 与 systemd cgroup 管理。以下是独立教学模型，不继承前章卡号或拓扑：

| 代号 | 宿主机查询 index | 完整 GPU UUID | PCI Bus ID | 字符设备 |
| --- | --- | --- | --- | --- |
| G0 / U0 | 0 | `GPU-11111111-1111-4111-8111-111111111111` | `00000000:31:00.0` | `/dev/nvidia0`，195:0 |
| G1 / U1 | 1 | `GPU-22222222-2222-4222-8222-222222222222` | `00000000:b1:00.0` | `/dev/nvidia1`，195:1 |

两张卡均设为 A100、无 MIG、无共享策略。U0、U1 是正文与插图中的短代号，传给命令时使用表中的完整 UUID。宿主机驱动内核模块与用户态组件均设为 **570.124.06**；镜像内应用按 **CUDA 12.8.1** 构建，包含 `sm_80` 设备代码、动态链接的 `libcudart.so.12`，不使用 forward compatibility 包。该驱动与 Toolkit 对应版本可查 [CUDA 12.8 Update 1 Release Notes，Table 3：CUDA Toolkit and Corresponding Driver Versions](https://docs.nvidia.com/cuda/archive/12.8.1/cuda-toolkit-release-notes/index.html)。

容器接入机制固定参考 **NVIDIA Container Toolkit 1.18.0、containerd 1.7.27 的 CRI 配置、OCI Runtime Specification 1.2.1**。legacy 示例均显式选定模式；第 03 篇另说明 1.18.0 的 `jit-cdi` 自动选择，避免把历史 Hook 架构当成该版本默认行为。CDI 字段依据 **CDI 0.8.0 规范**核对，正文的最小示例声明 `cdiVersion: 0.5.0`，仅使用这一版本已经具备的字段，不冒充 Toolkit 的完整生成文件。选用历史版本是为了固定解释条件；这些版本组成阅读基线，未作为部署组合实测，也不代表当前推荐版本。资料核对日期：**2026-11-08**。

所有命令配套输出、配置片段、日志和应用结果均为**自拟教学材料**，使用处分别标明。`lesson/gpu-probe:cuda12.8.1` 是本章虚构的已构建镜像名，不是可直接拉取的公开镜像；`gpu-probe` 是教学探针，其输出字段在正文定义。命令用于阅读推导，无需准备 GPU 或执行安装。两个不同注入方案采用独立容器，不能把一条路径的配置直接当作另一条路径的生效证据。
