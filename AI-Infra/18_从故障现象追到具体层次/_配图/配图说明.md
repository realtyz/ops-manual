# 配图说明

第 18 章的阅读难点在于从局部观测推回整条工作路径。读者容易把「查询到设备」「启动检查通过」「通信组已初始化」当成更下游的完成证据，也容易把出现在同一节点、同一时间窗的异常串成一条未经证实的因果链。下面五幅图分别补足这些判断所需的空间关系、对象边界和时间量级。

| 建议图 | 读者需要看清的区别 |
| --- | --- |
| GPU 管理查询与 CUDA 探针 | 同一张 GPU 可以被管理接口枚举，计算还需要提交、同步和结果回读。 |
| AER、Xid 与网卡的观察位置 | PCIe 分支、GPU 设备和网口是不同观察位置。报错的位置限定调查范围，部件责任需要更多证据。 |
| 主机缓冲区与显存缓冲区的 RDMA 对照 | 端口相同，换用显存会改变网卡访问缓冲区的前置条件。显存注册失败时，Write 还没提交。 |
| 晚到、完成尾部和 GPU 计算时间 | 步时变长时，先看增加的时间落在就绪前、成员到达跨度中，还是最晚成员就绪后。 |
| 训练恢复与故障节点复归 | 一组新 worker 可以在备用节点继续推进，原节点仍须用原路径和代表性负载验收。 |

下方五个代码块是完整的 AI 原生生图提示词，可逐个复制到生图工具，从空白画布生成。慢步图采用无刻度时序对照，精确时点见正文表格。后续修订的候选可放在本章 `_配图/待审/`，文件名使用完整图号并追加递增的版本号。
