# 第 18 章 从故障现象追到具体层次｜内容大纲

## 读者起点与学习目标

读者有 Linux 和 Kubernetes 基础。第 02—04 章建立了 Kernel、显存、异步执行与 GPU–NIC 拓扑；第 05、08 章建立了 Rank、会合与集合完成；第 06、07 章建立了 RDMA、RoCE 与缓冲区注册；第 10—13 章建立了 CDI 注入、设备库存与分配、Operator 组件和 Pod 双网络；第 15、16 章建立了成组放置、重试层级与检查点恢复；第 17 章把这些局部证据组织成带时间、带身份、带条件的观测体系与分层基线。本章把基线用于故障定位：先建立通用的证据规则与排查顺序，再沿设备交付、运行异常、跨节点启动、慢步时序和恢复验收逐层推进。第 19 章把复归证据扩展到节点交付、升级和回滚评审。

1. 在同一次尝试、同一设备和同一容器环境中，沿枚举、分配、注入、初始化、显存分配、执行与回读找出首个有证据的故障点，并设计一个只改变单一变量、能区分候选解释的对照。
2. 把 Xid、ECC、PCIe AER、NVLink 和网卡错误对回设备、端口方向及故障窗口，说明它们各自支持的影响范围、因果假设和仍然缺少的证据，区分最早事件、最早失败交接与下游症状。
3. 对单机正常而多机异常、运行中挂起或变慢的材料，定位到会合、引导、RDMA、显存路径、成员进度或关键路径；复算就绪跨度、完成余量、等待和完成区间，并提出对应的验证。
4. 从故障范围推导隔离和重试方式，确定可用检查点、重做量与有效进展，分别给出作业恢复与节点复归所需的功能、性能和稳定性证据。

## 案例与适用条件

- 主例沿用第 17 章 `ai-demo/train-12`，作业 UID 短写 `J17`，故障尝试 `R1`。三只 worker Pod 分驻 `h1/h2/h3`，分别承载 Rank 0–3、4–7、8–11，每只请求 4 张 H100 SXM 80 GB 整卡、16 CPU、96 GiB 主机内存和 1 个支持 RDMA 的 SR-IOV VF；每节点可供请求 8 GPU、32 CPU、192 GiB 内存和 2 VF。节点内经 NVSwitch 互通，每节点一条 200 Gb/s RoCEv2 物理口承载作业 RDMA，存储走独立网络。重点跟踪 `h2/P21/Rank 5/GPU-H2-A`，保留 GPU、VF 及交换机端口映射。替代节点 `h4` 到第 07 篇才引入。各篇独立故障变体均明确标记。
- 管理与分配以 Kubernetes v1.36、Volcano v1.16.0、NVIDIA Device Plugin v0.20.1 的 `cdi-cri` 策略与 containerd v2.1.5 原生 CDI 为阅读口径，DRA 仅提供分支定位。CUDA API 与异步语义采用 CUDA 13.2.1 文档。训练与通信采用 PyTorch 2.9、NCCL 2.27.3、perftest 26.07.8、nccl-tests v2.17.9 及第 17 章的基准口径。Linux AER 按 6.18 文档，Xid 依据 NVIDIA 当前 H100 目录，DCGM Exporter 4.8.4 用于字段口径。引用版本用于核对机制，不构成装机兼容组合；现场动作仍需 GPU 型号、驱动、固件与平台文档支持。
- 所有故障、耗时、计数、身份短写与恢复记录均为教学构造，未在 GPU 或 Kubernetes 集群实测。流程、时序与状态依赖用 Mermaid，精确数值用表格。五幅手绘插画均已验收并入库，随图附图注与替代文本：图 18-03-01 采用第三轮图稿，图 18-04-02、18-05-02、18-07-01 采用第二轮图稿，图 18-06-02 采用已验收的首轮图稿。图号随本轮篇序调整重排，提示词、图注与替代文本集中在 [配图说明](_配图/配图说明.md)。
