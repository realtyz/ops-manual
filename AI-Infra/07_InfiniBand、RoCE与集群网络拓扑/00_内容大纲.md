# 第 07 章 InfiniBand、RoCE 与集群网络拓扑｜内容大纲

## 一、本章定位与前置知识

前六章已经打通了“节点内 GPU 路径 → 并行切分需求 → 两端网卡 RDMA 传输”的完整主干：[第 04 章](../04_单机多卡与GPU数据路径/00_内容大纲.md)梳理了单机 PCIe 与 NVLink 路径，[第 05 章](../05_为什么一个作业需要多张GPU/00_内容大纲.md)拆解了训练与推理的多卡并行形态，[第 06 章](../06_从普通网络通信走向RDMA/00_内容大纲.md)追踪了两端网卡如何绕过 CPU 直接搬运显存。

本章把视线移到**两张网卡之间的交换网络**，回答三个集群级核心问题：报文在 InfiniBand 和 RoCEv2 网络里依靠什么寻址转发？多机架 Spine-Leaf 拓扑、多 Rail 布线与机柜级 NVLink 域如何决定容量与故障域？当训练大象流或推理微突发汇入同一出口时，拥塞反馈与物理链路错误又该如何凭证据拆开定位？

阅读本章默认读者熟悉 IP 路由、子网、下一跳和第 06 章建立的 RDMA 基础对象。集合通信库如何自动选路将在 [第 08 章](../08_NCCL如何组织GPU间的通信/00_内容大纲.md) 展开，Pod 如何接入高速网络将在 [第 13 章](../13_Multus与RDMA_把高速网络交给Pod/00_内容大纲.md) 深入。

## 二、核心学习目标

读完本章后，你应当具备以下可检验的工程推演能力：

1. **走通两套协议的封装与寻址**：能画出原生 InfiniBand 与 RoCEv2 的报文头部与跨机路径，依据 `ibstat`、P_Key 分区表、IP 路由与 GID 表判断连通性验证已确认到哪一层。
2. **量化拓扑容量与故障边界**：给定 Spine-Leaf 拓扑、双 Rail 布线与链路速率，能复算收敛比、单向割面上界、ECMP 哈希碰撞积压，并从 GPU 标识一路追查到物理线缆与交换机端口，厘清独立与共享故障域。
3. **建立 Scale-up 与 Scale-out 架构分工**：能解释超大规模训练与 MoE 推理为何需要突破单机 8 卡边界、走向机柜级 Scale-up NVLink 域（如 DGX GB200 NVL72），并准确核算同域与跨域的带宽口径。
4. **贯通拥塞反馈与训推差异化排障**：能定量估算出口排队与 PFC Headroom，追踪 ECN、CNP 与 PFC 的传递方向，区分训练大象流拥塞与推理微突发尾延迟抖动，并在同时间窗内把有效吞吐、队列拥塞与物理层误码拆开取证。

## 四、本章贯穿场景说明

本章沿两条清晰演进的参考拓扑展开，软件栈以 [00_全书基线与术语速查.md](../00_全书基线与术语速查.md) 中的 `Linux 6.8+`、`rdma-core v57.0`、`iproute2 v6.12.0` 与 `Cumulus Linux 5.11` 为锚点：

- **双机寻址场景（第 01–03 篇）**：两台标准 GPU 节点（命令行示例中记为 `node-1` 与 `node-2`），分别对比单子网原生 InfiniBand 与跨 IP 子网 RoCEv2 的报文封装和端口配置。
- **双机架双 Rail 集群（第 04–05、07–08、99 篇）**：两个机架各部署 4 台节点，每台节点配备两张独立的 `200 Gb/s` 全双工高速网卡，分别接入本机架的 Rail 0 与 Rail 1 接入交换机（Leaf），全部四台 Leaf 共同上联至两台共享脊交换机（Spine）。
- **机柜级 Scale-up 平台对照（第 06 篇）**：引入真实的 **DGX GB200 NVL72 SuperPOD** 参考架构（单机架 18 个计算托盘、72 张 B200 GPU 共处同一 NVLink 域，对外经 NDR InfiniBand 计算网互联），与双 Rail 以太网集群形成清晰的尺度对比。
