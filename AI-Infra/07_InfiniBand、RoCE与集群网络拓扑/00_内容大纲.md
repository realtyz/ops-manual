# 第 07 章 InfiniBand、RoCE 与集群网络拓扑｜内容大纲

## 从一次远端写入到整个计算网

读者具备 Linux 与 Kubernetes 基础，能识别 IP 地址、子网和下一跳。第 04 章建立了 PCIe、GPU 与网卡的节点内路径，第 05 章说明了多个进程为什么要交换数据，第 06 章跟踪了一次远程直接内存访问（RDMA）写入。本章接着问，两个网卡之间的交换网络如何把报文送到对端，多条通信共享网络时容量和等待从哪里来。队列对、GPU 与网卡亲和、全双工和交换队列在使用时就地解释。

读完应能完成以下任务。

1. 画出一条原生 InfiniBand 或 RoCEv2 的跨机路径，指出沿途采用的转发标识。根据端口状态、分区、路由和 GID 表判断配置与观测能确认到哪一层。
2. 给定 GPU、网卡、交换机和布线，找到同 leaf、跨 leaf 或跨 NVLink 域的候选路径。复算单向割面、故障后余量与按流散列后的单链路约束，并判断双 Rail 的共享故障点。
3. 从入流与出口速率推导队列形成，跟踪 ECN、CNP 和 PFC 的方向。将相同时间窗的载荷、路径、队列与物理错误证据结合起来，给出慢因判断和能区分候选原因的下一项观测。

## 案例、材料与范围

- 第 01—03 篇从 A0 向 B0 写主机内存。IB 与 RoCEv2 是两套备选网络快照。IB 在单子网内，RoCEv2 骨干用 IPv4 举例。第 04、05、07、08、99 篇沿用 RoCEv2 后者，扩为 A、B 各四个节点，各节点两个独立单端口网卡，分别接本机架两个 leaf。四个 leaf 都分别连接共享 spine S0、S1。各物理链路均为 200 Gb/s 全双工，容量默认取单向。每次改变并发、目的端或故障部位都在案例处重申。
- 第 06 篇是独立平台例，图中 A0、A1、B0 指计算托盘。该例的 NVLink 域、计算网端口数和速率采用 DGX GB200 NVL72 SuperPOD 参考配置。此处解决候选路径和统计边界。NCCL 如何实际选路、组织集合操作及读取基准由第 08 章展开，Pod 接入由第 13 章展开。
- 核对采用 IETF RFC 4392、RFC 3168、MLNX_OFED v24.10-0.7.0.0、Cumulus Linux 5.11、rdma-core v57.0、iproute2 v6.12.0、Linux v6.6/v6.12、OpenSM 配置说明及 NVIDIA 平台官方资料。IB 信用流控只解释与本章队列和计数相关的部分。RoCEv1、跨 IB 子网、IB 自适应路由和生产级阈值调优点到为止。
- 布线、计时、故障和计数记录为教学设定。交换机示例限定对应版本。实际软硬件组合、计数可用性、阈值、吞吐及回退行为需以目标环境复核。沿用双 Rail 和 NVLink 域两张插图，核对原图的标签、端点、图注和替代文本。报文流程用 Mermaid，速率与端口记录用表格。
