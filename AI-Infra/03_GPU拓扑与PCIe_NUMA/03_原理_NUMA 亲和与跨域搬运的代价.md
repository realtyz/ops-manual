# NUMA 亲和与跨域搬运的代价

距离不只在 PCIe 树上。一颗处理器连同它直接挂载的内存构成一个内存域（NUMA 节点），设备挂在哪个域上，决定了它的显存与主机内存之间那一段搬运落在哪条通路上。同一台机器上，两个进程做同样大小的主机内存拷贝，只因为内存落在不同的域，耗时可能差出近一倍——而功能一切正常，没有任何报错。这就是跨域搬运的代价：**它不报错，只是把本来走本地内存的流量改走了一条更窄、更远的通路**。

## 内存域与它的代价

在一台多处理器的机器上，每颗处理器访问内存的速度并不相同：访问自己直接挂载的那部分内存快，访问另一颗处理器挂载的内存要经过处理器之间的互连（UPI、Infinity Fabric 一类），多一段路径、带宽也更窄。内核把这种不对称暴露为节点距离矩阵，把物理位置暴露为一个节点号。

| 读法 | 单位 | 判据 | 与谁同看 |
| --- | --- | --- | --- |
| 节点距离矩阵 | 无量纲的相对值，本域通常为基准值 10 | 远端节点的值明显大于本域，说明跨域代价更大；差值越大代价越高 | 与设备各自挂在哪号节点同看 |
| 设备所属节点 | 节点号，无归属时为 -1 | 设备与该域的处理器、内存之间是本地关系；读到 -1 说明固件没有上报，不能就地配置成别的值 | 与节点距离矩阵、`nvidia-smi topo -m` 的 `NUMA Affinity` 列同看 |
| GPU 的亲和核 | CPU 编号列表 | 与设备所属节点一致的核才是本地核 | 与 `CPU Affinity` 列同看 |
| GPU 最近的内存域 | 节点号 | 显存对应的本地主机内存应落在这一号节点上 | 与 `NUMA Affinity` 列同看 |

`-1` 是一个需要单独解释的值：它表示固件没有为这件设备上报 NUMA 归属，常见于平台没有把设备到节点的映射暴露出来。它是**上层读数缺失**，不是一个可以就地改写的参数；此时 NUMA 相关的判断要转而依赖整机的节点清单与设备位置，而不能把 -1 当成「属于节点 -1」。

## 设备挂在哪个域：三处读数

判定一台机器上 GPU、网卡、本地盘各自挂在哪个域，用三处互相印证的读数。

```bash
# 验证：三处读数的取值入口（只读，生产节点上也可以做）
numactl --hardware; nvidia-smi topo -m; cat /sys/bus/pci/devices/<BDF>/numa_node
```

第一处是整机的节点清单与节点距离矩阵，它给出这台机器有几个内存域、各域有多少核与多少内存、以及域之间的距离；第二处是管理工具的拓扑矩阵，它按 GPU 逐行给出 `CPU Affinity` 与 `NUMA Affinity` 两列；第三处是 PCI 设备在 sysfs 里的节点归属，逐个设备给出它的节点号。三处的对象不同——第一处是内存域，第二处是 GPU 的亲和，第三处是任意一件 PCI 设备——因此要判断「某张网卡与某张 GPU 是不是同一域」，第三处与第一处对照才成立。

这里要留意一处口径差异：管理工具给出的 GPU 亲和是**建议绑定的核集合**，它可能与当前进程可见的核集合没有交集，此时那一列显示 `N/A`。`N/A` 是进程可见范围造成的，不是设备拓扑异常，读到时不要据此判断设备挂错。

## 跨域影响的是带宽，还是延迟

跨域主要吃**带宽**，同时抬高**延迟**。带宽这一头来自互连本身的容量：处理器之间的互连带宽通常低于单颗处理器到本地内存的带宽，因此单位时间能搬的数据更少。延迟这一头来自多出的那一段路径。两者的相对权重取决于这次搬运是「大块连续传输」还是「大量小随机访问」——前者更受带宽限制，后者更受延迟限制。

判断这次搬运是不是真的跨了域，最终要落到一次对照：让同一段代码分别在本域与跨域各跑一次，用同一口径比较结果。**没有对照就没有结论**，因为节点距离矩阵给的是相对值，量级必须由实测给出。

两个换算点与一个反推判据（数值仅示意，量级随机型与内存代际变化）：若本地内存带宽按 200 GB/s、经互连的跨域带宽按 100 GB/s 计，搬 1 GB 数据的理想时间从约 5 ms 变为约 10 ms，即翻倍；反推过来，如果一次主机内存中转的吞吐恰好落在本地的一半附近，就要优先怀疑这一趟跨了域，而不是怀疑内存故障。

## 绑核绑内存在哪一层生效

把任务钉在某颗处理器附近，有两类手段，作用层次不同。

- **进程与线程的核绑定**：把进程或线程限制在某一组核上执行，决定它的计算发生在哪颗处理器附近。它只约束执行位置，不决定内存落在哪个域。
- **内存分配域绑定**：让进程分配的内存落在指定的域上，决定它的数据放哪。对 GPU 而言这一点尤其关键：显存与主机内存之间的直接搬运（direct memory access，设备不经过处理器直接读写主机内存）要想代价最低，内存就应落在与设备同域的位置；数据落在远端域时这段搬运仍然成立，只是要先跨域再进出显存。

| 手段 | 作用对象 | 生效层次 | 判据 |
| --- | --- | --- | --- |
| 限制核集合 | 进程或线程 | 执行位置 | 进程是否只在指定核上运行 |
| 指定内存域 | 进程分配的内存 | 数据位置 | 分配到的内存节点是否与设备同域 |

两组约束要**成对使用**才会得到本地关系：只绑核不绑内存，计算在本地而数据可能在远端，多走一段；只绑内存不绑核，数据在本地而计算可能在远端，同样多走。容器与编排侧的核归集属于编排主题域，本篇只做这一处划界，主机侧的绑定手段与判据到这里为止。

## 什么时候不必动这一项

NUMA 不是每次都要调的对象。三种情形下它的影响会退到次要位置：搬运只在单张卡内部发生，不经过主机内存；卡间通信主要走 NVLink 而不是经主机内存中转；任务本身就是小数据或延迟不敏感。反过来，当主机内存吞吐成为瓶颈、且对照实验显示跨域时才值得在这一项上做动作。先判是不是瓶颈，再判是不是跨域，最后才谈绑定——顺序颠倒会把不是 NUMA 的问题也归到 NUMA 上。

**第一反应不要做什么**：不要把设备节点读到 -1 当成「属于节点 -1」；不要把亲和列的 `N/A` 当成设备挂错；不要只绑核不绑内存，或相反；不要在没做本域与跨域对照前就断言瓶颈在 NUMA；不要用节点距离矩阵的相对值直接当带宽结论。正确的顺序是先取节点清单与设备归属三处读数，再用同口径对照区分本域与跨域，最后才决定要不要绑定。
