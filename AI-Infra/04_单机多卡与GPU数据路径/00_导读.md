# 单机多卡与 GPU 数据路径

两张 GPU 都有空闲显存，复制却很慢；四张卡单独测试都正常，同时收数据时吞吐却下降。这些现象需要把复制请求放回服务器：数据从哪块内存出发，经过哪些设备和链路，哪些传输共享同一段资源。

本章的学习任务是：**画出主机与 GPU、GPU 与 GPU 的数据路径，计算共享链路的传输预算，将逻辑编号映射回设备位置，并用能力、状态与传输材料判断互联是否按预期工作。** 学完后应能解释为什么“设备可见”“支持 P2P”“互联已就绪”“作业传得快”需要不同证据。

## 必要前置与章节边界

读者已有 Linux 进程、虚拟内存和 Kubernetes 的基础。从[第 01 章](../01_从一台GPU服务器认识基础设施/00_导读.md)带来 Socket、NUMA、PCIe 层级、设备查询与身份映射；从[第 02 章](../02_GPU如何计算与显存/00_导读.md)带来显存独立容量、Kernel、Stream、异步完成与时间预算。

[第 03 章](../03_从驱动到CUDA应用的软件依赖/00_导读.md)负责驱动与 CUDA 软件依赖，本章承接其中的设备发现、上下文与 API 调用。本章所需的最小前置是：应用通过 CUDA API 提交工作，用户态库与内核驱动协作访问设备；查询成功只说明相应查询链路可用。设备发现、显存分配、复制和 Kernel 执行仍各有成功条件。本章不要求先安装 Toolkit 或编写 CUDA 程序，API 片段只用于读懂能力和权限的区别。

本章完整解释单机 PCIe、主机中转、GPU P2P、NVLink/NVSwitch、NUMA 亲和与互联就绪。第 05 章解释为什么多卡作业需要协作与通信；[第 06 章](../06_从普通网络通信走向RDMA/00_导读.md)展开 RDMA 和 GPU—NIC 直接访问的支持条件；第 07 章展开跨服务器与机架级互联；第 08 章解释 NCCL 的实际路径选择。本章只建立 NIC 的位置关系，不从“靠近 GPU”直接推断 GPUDirect RDMA 可用。容器编号、设备注入与 Kubernetes 放置策略分别留给第 10—15 章。

## 一套贯穿模型与一个平台对照

本章使用 Linux x86_64 裸机场景，沿用第 01 章的虚构节点 `gpu-node-a`：双 Socket、每 Socket 一个 NUMA Node、每 Node 256 GiB 主机内存；关闭 SMT，逻辑 CPU 0—31 属于 Node 0，32—63 属于 Node 1。四张未切分、独占的 PCIe GPU 各有 48 GiB 显存，无 NVLink；每组三个设备共用一个 PCIe Switch。它与第 02 章的单卡 GPU-T、第 03 章的 `cuda-node-a` 都无型号、编号或性能映射。

| 图内代号／本次主机 index | UUID 教学占位值 | PCI BDF | 局部性与分支 |
| --- | --- | --- | --- |
| GPU0 / 0 | GPU-11111111-1111-1111-1111-111111111111 | `0000:41:00.0` | Node 0 / Switch A |
| GPU1 / 1 | GPU-22222222-2222-2222-2222-222222222222 | `0000:42:00.0` | Node 0 / Switch A |
| GPU2 / 2 | GPU-33333333-3333-3333-3333-333333333333 | `0000:c1:00.0` | Node 1 / Switch B |
| GPU3 / 3 | GPU-44444444-4444-4444-4444-444444444444 | `0000:c2:00.0` | Node 1 / Switch B |
| NIC0、NIC1 | 不使用 GPU UUID | `0000:43:00.0`、`0000:c3:00.0` | 分别在 Switch A、B 下 |

本章新增条件：各 GPU 下行与两个 Switch 上行，健康负载状态均为 Gen4 x16；预算题给定每段单向有效预算 25 GB/s，其他条件就近给出。这替代第 01 章某道独立预算题的假设值，不是该虚构节点的测量结果。本次 CUDA 材料已通过 UUID 核对，应用 ordinal 0—3 与上述主机 index 恰好同序；第四篇再解释重排后的映射。P2P 能力在第三篇明确给定，不由连接图自动推出。

所有图、日志式材料、速率与时间都是**自拟教学示例**，使用处说明删节或人工整理方式；没有 GPU 实测。带宽使用十进制 `GB/s`，`1 GB = 10^9 B`；显存与主机内存容量使用二进制 `GiB`，`1 GiB = 2^30 B`。传输计时包含等待复制完成，不能以异步 API 返回时刻代替完成。

机制资料以 CUDA **12.8.1** 归档文档为基线；PCIe 预算仅覆盖 Gen3—Gen5。NVSwitch 管理对照采用 **HGX H100 八 GPU、第三代 NVSwitch、裸机运行**，不把该平台和四卡模型混用。另参考核对日的 Fabric Manager 与 `nvidia-smi` 官方文档，及 NCCL 2.31.2 归档中的 PCIe 支持性说明。资料核对日期：**2026-11-08**。
