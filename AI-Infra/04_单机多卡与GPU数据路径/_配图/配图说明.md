# 第 04 章配图说明

第 01 篇用同一拓扑的并排对照说明有效载荷是否经过主机 DRAM。第 04 篇用底板示意区分 PCIe 和 NVLink，正文另有 Mermaid 图说明就绪检查。第 02、03、05、06 篇用链路字段、方向表、拓扑矩阵和可复算的传输表呈现证据。

## fig-04-01-01-p2p-vs-host-staging

- **插入位置**　第 01 篇「源和目的都在显存时」，在以“后续章节再展开框架与通信库如何选路”结尾的段落之后、路径汇总表之前。
- **图注**　同一 PCIe 教学拓扑下，GPU 0 向 GPU 1 交付数据。左图的 P2P 在 Switch A 内转发。右图的琥珀色 ① D2H 先把数据送到 M0 中转缓冲区，紫色 ② H2D 再把数据从同一缓冲区送到 GPU 1。箭头表示有效载荷方向，点线标记 CPU 提交。
- **替代文本**　左图的数据从 GPU 0 经 Switch A 到 GPU 1，避开上行与主机内存。右图的琥珀箭头从 GPU 0 经上行指向 M0 缓冲区，紫色箭头从同一缓冲区经上行的反方向指向 GPU 1 显存。
- **验收重点**　两侧 PCIe 连接完全相同。左侧箭头避开上行。右侧 ① 琥珀色、② 紫色，两条箭头各自全程保持同色，编号和图例与箭头匹配，并在 M0 的同一缓冲区衔接。
- **首版验收**　`fig-01.png` 右图的 ② H2D 从根端口附近开始，缺少中转缓冲区到根端口的有效数据箭头。保留左图、右图的物理拓扑和两张卡各自的显存。右图应让 ① D2H 和 ② H2D 都连续经过根端口，① 止于 M0 缓冲区，② 从同一缓冲区起笔，最后指向 GPU 1 显存。
- **下一版候选文件名**　`fig-04-01-01-p2p-vs-host-staging-v02.png`

```text
任务与结论
为已有 Linux/Kubernetes 基础的读者绘制中文 AI 基础设施手绘插画。比较同一台 x86_64 Linux 裸机中 GPU 0 向 GPU 1 交付数据的两种方式。左侧已确认 PCIe P2P 在 Switch A 内转发，右侧先 D2H 再 H2D，采用整块主机中转。用箭头展示有效载荷是否进入主机内存。两侧均为教学拓扑，无 NVLink。

构图与阅读顺序
左右两区严格同尺度、同布局。每区左上是主机内存 M0，右上是 Socket 0 和其边缘的根端口，中间是 PCIe Switch A，下方并列 GPU 0 和 GPU 1。有效载荷路径是画面焦点。主机内存和上行旁留白，以容纳方向相反的两段标记。

对象、边界与关系
每区画一个蓝色 CPU 封装、蓝色 DIMM 条、灰色 PCIe Switch 芯片、两个绿色 GPU 设备框。每个 GPU 框内各有一块显存。仅在右图的 M0 内画一块浅灰色区域表示两段共用的中转缓冲区。两个画区都用细灰色无向实线连接 M0 与 Socket 0、根端口与 Switch A，以及 Switch A 到两张 GPU 的两条下行。CPU 提交用一条短深灰点线标注箭头指向 Socket 内部，只标发起方，不接入设备路径。
左图沿 GPU 0 显存 → Switch A → GPU 1 显存叠加粗琥珀色数据箭头。右图的两条箭头分别着色，从起点到终点保持同色。① D2H 全程用琥珀色 #D99A2B，从 GPU 0 显存经 Switch A、根端口和 Socket 0 到 M0，箭头尖指向中转缓冲区。② H2D 全程用紫色 #7851A9，从同一缓冲区的右边缘起笔，向右跨过 M0 到 Socket 0 的空隙，经根端口向下转弯，再经 Switch A 指向 GPU 1 显存。在 M0 和 Socket 0 之间让琥珀线与紫线一上一下，方向相反。在根端口与 Switch A 的共用上行旁，让两条线一左一右，方向相反。两条线留足间距，标签和边框不遮挡线段。图例在右图下方分别用琥珀箭头标记“① D2H”、紫色箭头标记“② H2D”，与右图内的步骤标签对应。另列细灰实线和深灰点线。省略另一 Socket 和其余设备。

逐字标签
左区标题“PCIe P2P”，右区标题“主机内存中转”。两区各有“Socket 0”“主机内存 M0”“根端口”“PCIe Switch A”“GPU 0”“GPU 1”，每卡内各有“显存”。右区另外写“中转缓冲区”“① D2H”“② H2D”。页脚写“物理连接”“CPU 提交”“教学拓扑”，右图图例重复“① D2H”“② H2D”。画面文字仅用这份清单。

技术约束
左图的琥珀数据箭头止于 GPU 1 显存，完全留在 Switch A 的两个下行之间。右图的①和②在同一 M0 缓冲区衔接，②在①完成后开始。验图时从 M0 缓冲区沿②逐段追到 GPU 1，必须能看到缓冲区到 Socket 0 根端口的独立紫线。①的琥珀线也要连续经过根端口再转向缓冲区。用编号和箭头方向辅助区分两段，使图在灰度下也能读懂。箭头表示有效数据，省略 DMA 读取请求。显存分别画在 GPU 0 与 GPU 1 内。两区均无连接两张 GPU 的额外线，也无跨 Socket 线。

公共风格
```

## fig-04-04-01-hgx-h100-pcie-and-nvlink

- **插入位置**　第 04 篇「把主机 PCIe 和卡间 NVLink 分开」，在以“主机到显存的复制应沿主机 PCIe 另算”结尾的段落之后。
- **图注**　HGX H100 八卡底板有八张 H100 SXM 与四个第三代 NVSwitch。图按逻辑关系展示主机 PCIe 和卡间 NVLink。仅展开一张 GPU 的四组 NVLink 连接，4 + 5 + 5 + 4 = 18。其余 PCIe 和 NVLink 布线从略，图中编号用于示意。
- **替代文本**　主机以 PCIe 接入底板。底板上有八张 GPU 和四个 NVSwitch，其中一张 GPU 的四束 NVLink 各接一个交换机，标有 4、5、5、4 条。两类连接使用不同线型。
- **验收重点**　八张 GPU、四个 NVSwitch。高亮 GPU 的四束连线各接到不同交换机，合计 18 条。主机 PCIe 的线不应延伸成 NVLink，单卡显存各自位于设备内。
- **验收结果**　`fig-02.png` 通过。图已按 `images/fig-04-04-01-hgx-h100-pcie-and-nvlink.png` 入库并嵌入第 04 篇。
