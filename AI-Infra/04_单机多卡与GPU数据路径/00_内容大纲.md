# 第 04 章 单机多卡与 GPU 数据路径｜内容大纲

## 一、本章定位与前置知识

[第 01 章](../01_从一台GPU服务器认识基础设施/00_内容大纲.md) 拆解了双路服务器中的 PCIe 根端口、交换机与 NUMA 拓扑，[第 02 章](../02_GPU如何计算与显存/00_内容大纲.md) 讲清了 GPU 内部计算、显存带宽瓶颈与 CUDA Stream 异步执行，[第 03 章](../03_从驱动到CUDA应用的软件依赖/00_内容大纲.md) 跑通了进程通过驱动选卡并提交任务的软件链条。

本章把这三条线索拧成一股：**从一份备好待传的数据出发，全程追踪它在主机内存、PCIe 交换机、处理器互联与 NVLink Fabric 上的物理走向，并据此核算单路带宽、并发排队与多卡放置收益**。

阅读本章只需具备 Linux 与 Kubernetes 基础，无需 CUDA 编程经验或 GPU 实机环境。学完本章后，[第 05 章](../05_为什么一个作业需要多张GPU/00_内容大纲.md) 会解释分布式训练与大模型推理为何需要跨卡交换数据，[第 06 章](../06_从普通网络通信走向RDMA/00_内容大纲.md) 会把 PCIe 路径进一步延伸到网卡直达显存（GPUDirect RDMA），[第 07 章](../07_InfiniBand、RoCE与集群网络拓扑/00_内容大纲.md) 与 [第 08 章](../08_NCCL如何组织GPU间的通信/00_内容大纲.md) 则把视野扩展到机柜级 NVLink 域与集群通信库选路。

## 二、核心学习目标

读完本章后，你应当能够：

1. **完整追踪单机数据路径**：画出本地与跨 NUMA 的主机到显存（H2D）路径，以及同卡槽直达（P2P）与主机内存中转路径，准确标出提交者、搬运者、有效载荷方向与数据落点。
2. **量化核算带宽与流水耗时**：根据 PCIe 协商速率与位宽推算编码后单向带宽上界，按链路方向叠加并发载荷计算完成时间下界，并推导串行整块中转与分块双槽流水的耗时差异。
3. **分层验证卡间互联与 Fabric 就绪**：掌握 CUDA P2P 访问权限、PCIe Switch 转发、ACS 重定向、裸机 IOMMU 约束，以及 HGX H100 上 NVLink、NVSwitch、ALI 与 Fabric Manager 的逐层就绪判据。
4. **对齐设备身份并权衡多卡放置**：将进程序号、`nvidia-smi topo -m`、PCIe 桥树、网卡 BDF 与缓冲区实际驻留页对齐到同一拓扑，结合输入量与交换量做出合理的训练与推理放卡决策。

## 四、本章贯穿场景与参考拓扑

本章以两套经典裸机拓扑贯穿全篇，软件栈统一对齐 [全书基线与术语速查](../00_全书基线与术语速查.md) 中的 **Ubuntu 24.04 LTS**、**CUDA 13.2.1**、**NCCL 2.27.3** 与 **`nvbandwidth v0.11.0`**：

- **主线拓扑（双路四卡 PCIe 服务器）**：双路 x86\_64 服务器，每个 CPU Socket 对应一个 NUMA 节点，本地主机内存分别记为 `M0` 与 `M1`。两条独立 PCIe Switch 分支各下挂两张 GPU 与一块高速网卡（无 NVLink），健康负载下各段均为 Gen4 x16，定量预算以每段每方向有效速率 `25 GB/s`、跨 Socket 远端 H2D `20 GB/s` 展开推演。
- **高阶互联对照（八卡 HGX H100 裸机）**：第 04 篇与第 99 篇独立引入标准八卡 HGX H100 底板，每张 H100 SXM 通过 18 条第四代 NVLink 连入四颗第三代 NVSwitch，用来对比 PCIe 拓扑与全互联 NVLink Fabric 在带宽量级和软件就绪流程上的本质差别。
