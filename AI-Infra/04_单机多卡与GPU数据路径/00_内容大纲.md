# 第 04 章 单机多卡与 GPU 数据路径｜内容大纲

## 读者起点与学习目标

第 01 章已经建立 PCIe 根端口、交换机和 NUMA 的连接关系，第 02 章从 Stream 看过一次拷贝何时完成，第 03 章解释了 CUDA 应用如何借助驱动选卡并提交任务。本章把三者接起来。从一份已经备好的数据开始，追踪它走过的内存和互联，并用这个过程解释单路带宽、并发等待和设备放置。必要背景在各篇使用处回顾，读者只需 Linux 与 Kubernetes 基础，无需 CUDA 编程或 GPU 实验环境。

1. 画出本地与跨 NUMA 的主机到显存路径，以及同一对 GPU 直达和经主机中转的路径。能标明提交者、搬运者、载荷方向与数据落点。
2. 从 PCIe 协商状态换算单向速率上界，按链路和方向计算并发时间下界。能解释串行中转与分块流水的耗时差异。
3. 根据物理连接、CUDA 有向访问能力、访问启用、Fabric 状态和完成校验，判断分别确认了哪一层。能提出验证实际传输路径所需的证据。
4. 将进程序号、GPU、网口、PCIe 分支和缓冲区驻留节点对齐，比较两种多卡放置的阶段耗时，并判断输入量或交换量变化后的取舍。

**共同场景**　双路 x86_64 Linux 裸机，每个 Socket 对应一个 NUMA 节点。Switch A 接 GPU 0、GPU 1 和 NIC 0，Switch B 接 GPU 2、GPU 3 和 NIC 1。两条独立上行，无 NVLink。M0、M1 分别是两侧主机内存。健康负载下 GPU 下行和 Switch 上行均设为 Gen4 x16，预算题另设每段每方向的有效预算为 25 GB/s。GPU 0/1 在题设条件下双向支持 P2P 且在 Switch A 内转发，GPU 0/2 的两方向均无所需能力。跨分支整块中转使用 M0，远端 H2D 整条路径的有效速率设为 20 GB/s。HGX H100 是独立平台案例，沿用底板图的编号。

## 技术依据与范围

CUDA 语义沿用第 03 章的 13.2.1 归档基线，工具例使用 NCCL 2.31.2 文档与 nvbandwidth v0.10.0 的 README 和实现。PCIe 本章计算覆盖 Gen3—Gen5。Fabric Manager 和 NVIDIA SMI 以本轮核对的在线官方资料为准，将平台、字段和版本限定在相关论断处。四卡拓扑、吞吐和故障材料均为教学设定。目标环境的 GPU 互通、计数器、驱动与 FM 软件包组合及性能待有可追溯的实机记录时验证。

第 05 章从两张卡怎样搬运数据转到作业为什么交换数据，第 06 章把 PCIe 路径延伸到网卡访问显存，第 07 章区分机架级 NVLink 域与集群网络，第 08 章讲通信库怎样把一次通信映射到实际传输。存储输入、容器设备与调度策略按第 09、10、13、15 章的范围展开。
