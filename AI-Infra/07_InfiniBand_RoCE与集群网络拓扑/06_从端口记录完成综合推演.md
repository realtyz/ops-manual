# 从端口记录完成综合推演

## 先区分速率、吞吐和物理质量

链路协商到 400 Gb/s，说明该时刻的链路工作速率。有效吞吐还受报文开销、端点注入、共享路径、暂停和丢包恢复影响。若应用在 10 秒内交付 `360,000,000,000 B` 不重复有效数据，则吞吐为 `36 GB/s = 288 Gb/s`，不能把接口上的 400 Gb/s 改写为“应用已获得 50 GB/s”。

**FEC（Forward Error Correction，前向纠错）**在物理编码层纠正一定范围的错误。已纠正错误增加，表示纠错正在工作，不等于这些数据已经丢失；应结合观察窗口、传输比特量和相同链路基线。纠正不了的错误、FCS/CRC 错误或链路反复重新训练，则是物理质量方面的证据。FCS 是帧校验字段，CRC 是所用的循环冗余校验方式。它们不同于交换机因无缓冲而丢包。

mlx5 的 `rx_corrected_bits_phy`、`rx_pcs_symbol_err_phy` 与 `rx_crc_errors_phy` 等字段定义可查 [Linux mlx5：Ethtool counters，Physical Port Counters](https://docs.kernel.org/networking/device_drivers/ethernet/mellanox/mlx5/counters.html#physical-port-counters)。其中 `rx_pcs_symbol_err_phy` 计入未被 FEC 纠正或未启用 FEC 时的相关符号错误。字段可用性与计量范围要按驱动、固件和硬件读取；不能把别的平台同名的“块”“位”“帧”当成同一单位。

以太网端口的观察入口可以是下面这些 Linux 只读命令。IB 对应读 `ibstat`、`ibv_devinfo`、适用的 Fabric 诊断与端口计数，不把以太网专用工具强套到所有 IB 设备上。

```bash
ethtool ens6f0np0
ethtool --show-fec ens6f0np0
ethtool -S ens6f0np0
ethtool -m ens6f0np0
```

最后一条在设备支持时读取模块 EEPROM/数字诊断，包括模块身份、温度和光功率等；有源光模块、DAC 铜缆等不保证提供相同字段。接收光功率应与该模块的规格、告警界限和链路预算比较，不能给所有模块套一个 dBm 门槛。用模块/线缆序列号、两端端口与布线表关联，才知道观察的是否同一条链路。EEPROM 查询接口见 [ethtool(8) 上游手册收录页：-m/--dump-module-eeprom](https://man7.org/linux/man-pages/man8/ethtool.8.html)，该页 COLOPHON 标明来源为 ethtool 项目。

## 一份可连续阅读的链路材料

下面是 `net-a/N0` 的**自拟、删节输出**。这些字段属于同一健康快照，不与后文独立故障快照叠加：

```text
[ethtool ens6f0np0]
Settings for ens6f0np0:
    Speed: 400000Mb/s
    Duplex: Full
    Link detected: yes

[ethtool --show-fec ens6f0np0，删节]
    Configured FEC encodings: RS
    Active FEC encoding: RS

[人工整理的身份与数据结果]
mlx5_0/1 ↔ ens6f0np0 ↔ 0000:43:00.0 ↔ C-a0 ↔ L0-R0/p1
接收端 net-c/N0，本次 QP 与内存访问均成功
应用 10 秒交付的不重复有效数据：360,000,000,000 B
窗口内 CRC/不可纠正错误增量：0
```

这份材料可以确定所查接口是 Rail 0 的 A 端口、当前 400 Gb/s 全双工，且本次负载传输完成，应用吞吐为 36 GB/s。它没有给出饱和负载、所有链路利用率和暂停记录，因此不能仅由 36 与 50 的差额归因于某个故障。`Configured` 是配置目标，`Active` 才是当前启用的 FEC 模式；此处两者都显示 RS，即 Reed–Solomon 类纠错编码。

以下两张表是**独立教学窗口**，已把计数器求成差值，未清零或回绕。交换机与拥塞计数字段是人工归一化名称，不能当成可原样执行的 CLI。

### 窗口 Q：数据过量注入，反馈也受阻

沿用 Rail 0：A→C、B→C，应用各自持续提出 30 GB/s 的交付需求；这是流量需求，实际发出速率仍受流控限制。C/N0 的可服务预算为 45 GB/s。已确认没有其他流量占用数据出口，物理错误增量为 0。

| 1 秒窗口内证据 | 观察值 |
| --- | --- |
| L1-R0 → C/N0 的出口 | 数据队列持续有积压，长期服务率达到 45 GB/s |
| 同出口带 CE 的数据包增量 | 6000 |
| C/N0 向 A/B 合计发出的 CNP | 400 |
| L1-R0 反向分类检查 | DSCP 48 被错误映射到 TC0；本应进入 TC6 |
| 同窗、按 CNP 单独识别的反向丢弃 | 400；这批 CNP 均在拥塞的 TC0 丢弃 |
| A/B 合计处理到的 CNP | 0 |
| A/N0 `rx_prio3_pause_duration` 增量 | 200000 μs |

需求 `60 > 45 GB/s` 已确定目的端口容量不足以持续接住注入。交换机标记与接收端发 CNP 的两个环节已经有正证据，但反向分类错误又使本窗口的反馈全部丢弃，所以发送端未获得这批降速通知。修复 CNP 分类解决反馈路径；仍需发送速率实际收敛到容量内，不能凭修改一条映射就宣称 60 GB/s 都可以交付。6000 个 CE 数据包对应 400 个 CNP，不构成数量矛盾。

### 窗口 P：物理质量问题落在另一条 Rail

本次读取 `net-c/N1`，即 `mlx5_1/1`、`ens7f0np0`、线缆 C-c1、L1-R1/p1，不是窗口 Q 的 C/N0。窗口为 10 秒：

```text
Speed = 400000Mb/s；Active FEC = RS；窗口内 Link 一直 Up
Δrx_bits_phy              = 4,000,000,000,000
Δrx_corrected_bits_phy    = 4,000,000
Δrx_pcs_symbol_err_phy    = 12
Δrx_crc_errors_phy        = 80
Δrx_prio3_pause_duration  = 0 μs
人工记录：接收模块光功率触发本模块厂商给出的低告警
```

已纠正比特比例按本例计数口径为 `4,000,000 / 4×10^12 = 10^-6`；还有未纠正符号和 CRC 错误增量，即使链路始终 Up，也不能称为“物理层完全正常”。应沿 C-c1 的模块、线缆与两端端口核对。低光告警增加了物理链路方向的证据，但尚不能唯一确定是某只模块损坏：光路、连接、远端发送及本端接收等仍需区分。暂停为 0 也不会消除这些错误。

## 十组练习

先独立写出条件、路径或计算，再阅读答案。各题修改的条件只在该题生效，未说明时采用本章主模型。带宽与数据量均为十进制；需要公平分担时会明确给出。

### 1. IB 地址与分区

在第一篇 IB 场景，A 的 LID=17、C 的 LID=33、SM LID=1，交换表不变。A 的 P_Key 表索引 2 为 `0x1234`，C 的索引 5 为 `0x9234`，其他访问条件满足。A 的目的 LID 和交换出口各是什么？分区是否允许双向通信？把 C 改为 `0x1234` 后呢？

### 2. GID、IP 与下一跳

用第二篇的 `net-a` GID 表和路由记录，选择 A→C 的源 GID 索引，写出第一跳的目的 MAC 与目的 IP。C 的本地 GID 索引必须也是 3 吗？

### 3. DSCP 与 ECN

目标为 DSCP 26、ECT(0)。应写入完整 IP 8 位字段的值是多少？被标记 CE 后是多少？若误把整个字段写成十进制 26，实际 DSCP 和 ECN 各是多少？另给分类规则“除 DSCP 26/48 外均映射为优先级 0”，此误写将进入哪个优先级？

### 4. MTU 的对象

普通 RDMA Write 第一包，采用第二篇相同的头部、无 VLAN、数据 4096 B。路径最小 IP MTU=4200 B，最小以太网最大帧长=4200 B，是否满足这包的长度条件？若其中一条 IP 链路变成 1500 B，而端点仍发相同包，结论怎样变化？

### 5. 队列增长与暂停余量

使用第三篇的 600 Gb/s 输入、400 Gb/s 服务率，队列从空开始，前 20 μs 没有反馈。随后 ECN 闭环再过 8 μs 才影响注入，期间速率不变，缓冲足够且没有丢弃或其他暂停，共积压多少字节？另有一条 400 Gb/s 入口，暂停生效及在途排空等效为 4 μs，其在途量是多少？为什么两题不能都用净增长率计算？

### 6. 收敛比、耗时与双向口径

Rail 0 上 A→C、B→D，各交付 4.5 GB，两流分到不同 Spine 分支，均以 45 GB/s 有效负载运行，同时启动且忽略启动开销。求正常完成时间与本 Leaf 收敛比。若仅 L0-R0/p50 失效，网络已收敛、健康传输已公平共享剩余上联，其他条件不变，再求耗时与收敛比。正常时再同时加入 C→A、D→B 两条 45 GB/s 反向流，单向总吞吐和双向聚合吞吐分别多少？

### 7. ECMP 碰撞与多 Rail

A→C、B→D 各希望发送 45 GB/s，均被稳定散列到 S0-R0，两流公平共享且无其他限制。可得总吞吐及每流吞吐多少？S1-R0 空闲是否可直接推断一个流可以再加 45 GB/s？此时 Rail 1 全部空闲，但应用只创建了 N0 上的 QP，能否把 Rail 1 容量加进当前结果？

### 8. 窗口 Q 的反馈链

根据上表，指出已被证实的容量约束、反馈失效位置和 A 端的暂停比例。如果修复 DSCP 48 的反向映射，能否保证持续交付 A/B 合计 60 GB/s？下一组有用的验证材料应包含什么？

### 9. 窗口 P 的归属与结论

写出该错误端口的主机、GPU—NIC 组合、Rail、线缆与交换端口。计算已纠正比特比例。Link Up 和暂停为 0 是否足以否定物理质量问题？现有材料是否足以指定要更换的唯一器件？

### 10. NVLink 与 IMEX

第五篇中 X0/X1 在同一受支持 NVLink 域及相容分区，Fabric、IMEX 服务均已就绪，但 U 在 x0/x1 只分别有 channel7/channel8 权限。此次跨 OS 内存共享是否满足授权条件？如果改为 X0 与另一域 Y0 通信，按图应走什么网络？把 x0/x1 都加入一个 IP 网段能否修复以上两个问题？

## 参考答案

**1.** 目的 LID=33，Switch 出 p2；SM 的 LID=1 不作为目的数据地址。`0x1234 & 0x7fff = 0x9234 & 0x7fff = 0x1234`，且 C 为 Full，所以允许双向通信，本地表索引 2/5 无需一致。C 改为 Limited 后两端均 Limited，不满足该分区成员规则。

**2.** 本次源索引为 3，值 `::ffff:c000:020b`、类型 v2、netdev 为 N0 的 `ens6f0np0`。第一跳目的 MAC=`02:00:00:00:10:01`，目的 IP=`198.51.100.11`。C 的索引是 C 的本地表位置，需要独立读取；不要求也是 3。

**3.** `26×4+2=106=0x6a`；CE 后 `26×4+3=107=0x6b`。误写 26=`0x1a` 时，高 6 位 `26>>2=6`、低 2 位 `26&3=2`，即 DSCP 6、ECT(0)，依题给规则进入优先级 0，未进入预期的优先级 3。

**4.** IP 数据报 4156 B，以太网帧 4174 B，均小于 4200 B，长度条件满足。1500 B 中间 IP 链路不能承载当前报文，端点自身大 MTU 不足以修复；需要调整路径或选择适用的较小 RDMA 数据粒度并重新核对。题目仅证明大小条件，不替代其余路径和访问条件。

**5.** 净增长率 `200 Gb/s÷8=25 GB/s`，总时间 28 μs，积压 `700,000 B`，其中等待闭环的额外 8 μs 增加 200,000 B。另一题是在计算停止前入口仍会到达的数据，使用 `400 Gb/s÷8×4 μs=200,000 B`，另加实际余量；它不是用输入减去输出的队列净增长模型。

**6.** 正常每流 `4.5/45=0.1 s`，同时启动时都在 0.1 s 完成，收敛比 `800:800=1:1`。失效后上联剩 45 GB/s，每流公平分得 22.5 GB/s，耗时 `4.5/22.5=0.2 s`，收敛比 `800:400=2:1`。题目已给故障后的网络与传输就绪条件，未断言失效当时可无缝恢复。正常两条正向流总计 90 GB/s，反向另有 90 GB/s，双向聚合 180 GB/s；这不改变单向上界。

**7.** L0→S0 的有效预算 45 GB/s，两流各 22.5 GB/s。空闲的 S1 不会改变题给稳定散列结果，单流也受自身 NIC 链路 45 GB/s 限制。Rail 1 没有承载当前 QP，不能计入；需要软件实际使用相应 NIC/路径，才讨论另一个 Rail 的独立流量容量。

**8.** 目的 C/N0 为 45 GB/s，而输入需求为 60 GB/s；反馈经过 CP 标记、C 端 NP 发 CNP，随后在 L1-R0 反向 TC0 丢弃，未到 A/B 的 RP。A 端暂停占比 `200000/1000000=20%`。修复映射后仍不能持续交付超过 C/N0 容量的数据。应核对修复后的实际分类、CNP 接收与处理、注入速率收敛、目的出口吞吐/队列、暂停及丢弃的同窗变化；不要求标记、CNP 数量逐包相等。

**9.** net-c 的 G1—N1，Rail 1，`mlx5_1/1`、`ens7f0np0`，C-c1 对 L1-R1/p1；不能归到窗口 Q 的 Rail 0。比例为 `10^-6`。未纠正符号与 CRC 增量构成物理错误证据，持续 Up、无暂停均不否定。低光告警支持继续检查该链路，但尚未区分线缆、连接、两端模块及端口，不能唯一指定器件。

**10.** 本次没有共同获准的 Channel，授权条件不满足；物理就绪和服务就绪不能替代它。按图 X0→Y0 经本地 NIC、跨域 IB/RoCE、对端 NIC。相同 IP 网段既不能授予 IMEX Channel 权限，也不能凭空增加跨域 NVLink 连接；IP 地址只参与相应控制或网络路径。
