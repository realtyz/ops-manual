# 第 01 章 从一台 GPU 服务器认识整套基础设施｜内容大纲

## 本章定位与前置知识

本章面向已经具备 **Linux 与 Kubernetes 基础**（熟悉进程、文件系统、块设备、网卡与路由）、但尚未系统接触 GPU 基础设施的读者。我们从“把 8 张显卡插进普通服务器为什么远远不够”出发，沿着一条真实的数据流，把一台 GPU 服务器内部的硬件分工、PCIe/NUMA 拓扑、安装形态、带外管理与供电散热，一路延伸到双节点集群的网络平面与故障域。

本章是全书 **PCIe（含 Root Port / Switch）、NUMA、DMA、BDF、SXM / HGX、BMC / Redfish** 六组基础概念的主定义章；全书统一的示例口径、版本栈与命名约定见 [00_全书基线与术语速查.md](../00_全书基线与术语速查.md)。

## 核心学习目标

1. **走通单机数据路径**：画出本地文件或远端输入到达目标 GPU 显存的完整路径，说明 CPU、主机内存、PCIe Switch、DMA、驱动与 GPU 各自做什么，并按目标卡独立核算显存余量。
2. **定位硬件拓扑与带宽瓶颈**：通过 PCIe 桥树、线程位置与缓冲区页驻留，判断数据走本地内存还是跨 Socket 远端路径，并按链路方向核算共享上行的并发带宽缺口。
3. **拆解硬件选型与机架约束**：分清 PCIe 插卡、SXM 模组、HGX 底板与整机四层边界；能从带内/BMC 带外双路径定位开机故障，并核算机架 A/B 路供电余量与散热前提。
4. **划分集群网络平面与故障域**：从通信双方、路由与 VLAN/端口映射还原管理、作业协调、高速计算和存储四条主通路，准确预测单点断线的影响范围并设计恢复验证。

## 本章贯穿场景与后续衔接

- **标准硬件背景**：全章以一台**双路 CPU GPU 服务器**为模型逐步加码——单机内包含两个 Socket（对应两个 NUMA 节点），PCIe Switch 下挂多张 GPU、以太网卡与 NVMe 盘，另一侧 Socket 独立挂载高速网卡。
  - 第 05 篇与第 99 篇将其复制为 `node-1` 与 `node-2` 组成最小双机集群，并以真实 **DGX H100/H200**、**Dell PowerEdge XE9680** 及 **DGX BasePOD** 规格作为生产对照。
- **后续章节衔接**：学完本章后，[第 02 章](../02_GPU如何计算与显存/00_内容大纲.md) 深入 GPU 内部计算与显存（涵盖训练与推理双负载），[第 03 章](../03_从驱动到CUDA应用的软件依赖/00_内容大纲.md) 拆解驱动到 CUDA 应用的软件栈，[第 04 章](../04_单机多卡与GPU数据路径/00_内容大纲.md) 展开单机多卡 P2P 与 NVLink/NVSwitch 实测；[第 05 章](../05_为什么一个作业需要多张GPU/00_内容大纲.md) 至 [第 09 章](../09_GPU的数据从哪里来_存储与IO/00_内容大纲.md) 则全面走向多机并行、RDMA、集群网络、NCCL 与存储供给。
