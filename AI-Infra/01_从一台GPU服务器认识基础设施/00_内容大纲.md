# 第 01 章 从一台 GPU 服务器认识整套基础设施｜内容大纲

读者已有 Linux 与 Kubernetes 基础，能辨认进程、块设备、网口和路由。本章从 CPU 上的应用处理一批输入开始，建立 GPU 加速节点的硬件与数据路径，再把节点放进机架和集群。案例与综合检验所需的设备树、地址、接线和状态记录都在章内给出。

## 学习目标

1. 画出本地文件或远端输入到达 GPU 的普通路径，说明驱动、CPU、设备搬运引擎各做什么，并按目标卡预算显存。
2. 从 PCIe 桥树、线程位置和缓冲区页驻留推导本地及跨 Socket 的路径，按同一链路方向核算并发载荷。
3. 区分 GPU 安装形态、HGX 底板、整机和机架各自的规格。给定管理接线与电源预算，判断主机状态能从哪里观察、失一路后能维持什么运行目标。
4. 从通信双方、路由、物理端口和交换机还原管理、会合、GPU 通信及存储路径，预测断点的影响并提出复核依据。

## 案例与后续章节

普通输入路径、双路桥树和双节点接线逐步增加条件。教学机的 GPU 0、GPU 1、NIC 0 与 NVMe 0 接在 Socket 0 的同一 Switch 下，只画当前推理所需的设备。高速网卡 `hca0` 接 Socket 1。A/B 在交付记录中对应 N21/N22。DGX H100/H200、XE9680 和 BasePOD 提供真实规格或部署对照，章末将 DGX H200 的规格和教学拓扑合用时单独标明。容量和速率题给定统计单位、方向、窗口和并发条件。

本章讲到能重建路径、推出资源约束和验证所需证据。第 02 章深入 GPU 执行与显存，第 03 章从枚举和驱动绑定走到应用完成，第 04 章展开链路协商、多卡直达和传输测量。第 05—09 章分别深化作业成员与集合操作、RDMA、集群网络、通信库和存储数据供给。
