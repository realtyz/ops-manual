# 用两机四卡材料完成综合推演

## 先把能比较的条件写在一起

本篇继续使用 `job-08` 身份与物理路径，所有材料均为**自拟教学摘要**。基线 M=256 MiB、float Sum AllReduce、四个 Rank；成员按时提交，校验启用且通过，运行完整结束。吞吐数值来自第五篇左侧结果；为了让路径计算有唯一答案，**本篇另给已由调用级证据确认：采用第二篇的单环，全部 M 交给这一条环，无网络归约卸载**。这项条件不能由连接表或 busbw 自行推出。

| 记录项 | 材料 |
| --- | --- |
| 组与设备 | r0/r1 在 A0/A1，r2/r3 在 B0/B1；每卡一进程 |
| 网络 | 每机一个 mlx5_0/1；Ethernet / RoCEv2；双端 GDRDMA |
| 逻辑顺序 | r0→r1→r2→r3→r0 |
| 有效预算 | 每台 NIC 每方向 20 GB/s，全双工；其余路径不限制本题 |
| AllReduce | out-of-place；time=25000 μs；algbw=10.74；busbw=16.11；#wrong=0 |
| 点对点补充 | 同机同端口主机内存 RDMA Write 单向稳定 20 GB/s；无并发背景 |

点对点补充只验证主机内存 Write。四卡的显存路径与校验由前面的 NCCL 记录及本篇题设另行成立；不要把两份证据的范围互相代替。

## 练习：先独立推导

### 1. 身份与职责

在 `nccl-b:5200 ... [0] ... rank 2 nranks 4 cudaDev 0 nvmlDev 0 busId 41000` 中，确定主机、进程、W Rank 和物理 GPU。若框架会合成功，却没有任一成员的 NCCL 初始化开始记录，先检查启动器/应用到通信器建立之间的什么信息？

### 2. 检查 Ring 的一块数据

使用第二篇初始数组，写出 c0 从 RS1 到 RS3 的位置、部分和及最终拥有者。若只把 r2 的 c0 从 100 改成 200，最终所有成员的输出是什么？其余块与顺序不变。

### 3. 流量、共享与单位

按本篇单环计算：每块大小、每 Rank 发送量、全组发送量、每机 NIC 的发送/接收量与网络字节预算下界。再将环顺序改为 r0→r2→r1→r3→r0，其他条件不变，重新计算 NIC 发送量与下界。

### 4. 时间和带宽

用原始 M、N 与 time 复算 algbw、busbw；解释为何 M 不能乘四。若 N 改为 8、消息和时间仍为原值，只问指标的公式结果，busbw 是多少？这个假设数值是否已经证明八卡拥有更高的实际 NIC 吞吐？

### 5. 比较两种算法模型

采用第二篇理想模型 N=4、α=5 μs、B=20 GB/s，M=1024 B。分别算 Ring 和未分片教学树的耗时。再给定实际日志仅列有 `Ring 00` 与 `Tree 0` 的拓扑资源，能否确定这一条 1024 B 调用选了哪一种？

### 6. API 返回与迟到

普通通信器的 AllReduce 成功返回后，r0 立即在另一 Stream 启动消费 Kernel，没有 Event 或等待；能否保证读取到归约结果？另有一份已对齐时间线：r0—r2 于 10 ms 进入，r3 于 14 ms 进入，所有结果在 16 ms 就绪；题设所有进入后的实际通信阶段固定为 2 ms。解释 r0 的 6 ms 中有哪些部分。

### 7. 两组启动参数

一个四进程测试使用 `-t 1 -g 1`，另一个四进程测试使用 `-t 2 -g 1`。分别有几个测试 Rank？本模型每机仅两张独占 GPU，如果两个进程都试图管理两卡，会破坏什么条件？

### 8. 读取路径证据

一次复现只有下面两行和端口 `Link Layer: Ethernet`，没有 Channel 行与校验结果：

```text
Bootstrap: Using eno1:192.0.2.11<0>
Using network IB
```

能否判定全部负载走 eno1、网络是物理 InfiniBand、双端显存直达、集合完成？对每个判断说明还需哪种材料，或给出已能成立的结论。

### 9. 两份独立故障记录

A：四个成员均初始化完成，r0—r2 的第 12 次调用是同参数 AllReduce，r3 第 12 次是 Broadcast，三人等待。

B：初始化阶段 r2 最先报 `ibv_reg_mr failed` 并返回系统错误；十秒后其他成员 timeout。没有 errno、缓冲类型或资源额度。

分别指出已确定的故障层次、应优先处理的对象与下一份证据。不能为 B 虚构唯一根因。

### 10. 从分层测试形成结论

已知主机内存 perftest 20 GB/s、两机各一卡 NCCL 校验通过、两机各两卡仅测 256 MiB 也通过。现在有人主张“所有 GPU 的 GPUDirect 都已验证，四卡小消息和八机性能都已达标”。这份结论哪些范围超出了材料？请给出至少三项用于扩大验证范围的测试或证据，并说明每项新增什么覆盖。

## 参考答案与推导

### 1. r2 是 B0，前缀 0 不改变成员编号

主机 nccl-b、PID 5200、W Rank 2、本地 CUDA ordinal 0、NVML index 0，对应 B0 / GPU-...b001 / `0000:41:00.0`。先核对应用是否实际走到创建通信器、Rank/规模是否传入、选卡是否完成、共同 Unique ID 是否分发；框架会合只证明其自身阶段，不替代这些动作。没有日志还应排除日志过滤或文件缺失。

### 2. c0 的改变只影响输出第一块

RS1 的 r1 得到 1+10=11；RS2 的 r2 得到 11+100=111；RS3 的 r3 得到 111+1000=1111。随后完整 c0 沿 r3→r0→r1→r2 传播。将 r2 的 c0 加 100 后，RS2 变为 211，RS3 变为 1211，最终每人得到 `[1211,2222,3333,4444]`。RS 阶段 c0 在 r3 是本例内部偏移，不是公开 ReduceScatter 的 Rank 对应语义。

### 3. 先数跨节点边，再除以单向预算

每块 64 MiB；每 Rank 发送 384 MiB，全组发送 `4×384=1536 MiB`。原环每机发送 384 MiB、接收 384 MiB，全双工并行，下界为 `384×2^20/(20×10^9)=20.1326592 ms`。不再额外把接收加一遍。

交错环每机有两条出边与两条入边，故每机发 768 MiB、收 768 MiB，下界 `40.2653184 ms`。这是忽略开销后的容量下界，实际耗时不能仅由这一个数定出。原环与交错环全组总发送量仍相同，变化的是其中跨 NIC 的比例。

### 4. busbw 是公式结果

`268435456/0.025/10^9=10.73741824 GB/s`；N=4 时乘 1.5 得 `16.10612736 GB/s`。M 已是每 Rank 完整输入，乘四将得到不同的聚合口径，与测试 algbw 定义不符。

N=8 的系数为 `2×7/8=1.75`，故 busbw=`18.79048192 GB/s`，约 18.79。题目只人为固定消息和时间、改变换算系数，没有给出八卡拓扑及端口负载，因此不构成实际 NIC 吞吐更高的证据。

### 5. 模型可算，实际调用另需关联

Ring 为 `6×5 μs+1.5×1024/(20×10^9) s=30.0768 μs`；教学树为 `4×5 μs+4×1024/(20×10^9) s=20.2048 μs`。给定模型中树更快。初始化资源同时列出 Ring 和 Tree，不能确定具体调用选择；需要将该消息调用与算法/协议选择记录关联，且真实 Tree 不等同于这里的未分片模型。

### 6. 结果可用需要依赖成立

另一 Stream 没有与通信完成建立依赖，不能保证消费正确；同一 Stream 顺序或明确的跨 Stream 同步可建立保证。伪代码的主机调用返回没有代替这一步。

时间线中 r0 先等最晚成员 4 ms，再经历固定通信 2 ms；将 6 ms 全部归到 NIC 搬运会误判。这里能分解，是因为题目给出了进入和通信条件；真实长 Kernel 仍需相应时间线。

### 7. 第二组有八个测试 Rank

第一组 `4×1×1=4`，第二组 `4×2×1=8`。每机两进程若各管理两卡，将重复使用本来只够两个独占成员的 GPU，破坏本章 W 中每张卡对应一个 Rank 的选卡条件；还改变并发和测试规模，结果不能与四卡基线直接比较。

### 8. 协调路径已知，其余逐层补证

可以确定 Bootstrap 报告采用 eno1，通信器报告选择名为 IB 的网络实现；这两行不能证明有效负载都走 eno1。结合 Ethernet 与本题 RoCEv2 条件，网络实现可以在 RoCE 上工作，不能称为已证明物理 InfiniBand。

要确定数据端口，补 NET 设备到 HCA/端口/接口的映射和相关边；要确定双端显存直达，补两端对应连接/注册及内存类型；要确定集合完成，补成员操作状态、Stream 完成、启用校验的结果和运行退出状态。连接准备与正确性是不同证据层次。

### 9. 优先追最早的具体问题

A 已有足够条件确定调用不匹配，应修正 r3 与其余成员的应用分支/次序，再验证所有人的第 12 次操作一致并可完成。改 Ring、加大 timeout 都不能修正这个语义问题。

B 已确定 r2 的 MR 注册失败发生在最前，其他超时是后续现象。先补 r2 完整返回信息、缓冲是主机还是 GPU、注册路径、errno、资源和版本条件，再区分额度不足、参数/范围、映射支持等假设。现有材料不足以认定“必然是 memlock”或“交换机丢包”。

### 10. 按端点、消息与规模扩大范围

现有主机内存测试只覆盖指定两端与参数；两机各一卡只覆盖选中的 GPU 对；四卡大消息通过不提供小消息时间曲线、其他 GPU—NIC 组合或八机拥塞状态。它们支持已测组的功能，不构成全域性能验收。

可新增：逐个目标 GPU—NIC 组合的 GPU 内存注册/传输及校验，补端点覆盖；四卡从小消息到大消息扫描并重复记录波动，补消息和延迟覆盖；八机目标布局的同条件集合测试与端口/链路计数，补规模、共享和跨机架路径覆盖；若关心并发，再给定背景负载重复对照。性能“达标”还需事先定义相同条件下的验收目标，不能由一个通过状态替代。

## 把通信完成接回作业

NCCL 可以正确完成既定通信，作业仍可能等待下一批数据，或者在计算中受显存和带宽约束。第 09 章转向数据读取、预处理与存储 I/O，继续解释 GPU 时间线里的等待来源；第 17—18 章再把这些层次与设备计数、系统基线和故障时间线串起来。
