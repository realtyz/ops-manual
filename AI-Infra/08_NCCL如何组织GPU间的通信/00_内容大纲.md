# 第 08 章 NCCL 如何组织 GPU 间的通信｜内容大纲

## 读者起点与学习目标

本章位于多机协同阶段。从两张 GPU 同步梯度的需求出发，解释 NVIDIA 集合通信库（NCCL）如何组织一次操作，再把操作接到实际的 GPU、主机缓冲和网络。读者具有 Linux 与 Kubernetes 基础，无需 CUDA 编程或 GPU 实验环境。第 05 章的组内 Rank 和集合语义在最小例子里回顾，第 02 章的 CUDA Stream 在讨论结果可用时回顾，第 04、06、07 章的设备互联、显存直达和计算网在画物理路径时引入。第 03 章的软件栈用于交代框架、库与驱动的分工。

1. 给定一次梯度同步，说明启动器、应用或框架、NCCL、CUDA 和互联的职责。能根据输入与结果布局选出操作，并区分组内 Rank 和设备编号。
2. 从四个进程的映射与调用记录还原组的建立、首轮提交及设备完成。能指出缺席、调用失配和传输故障分别需要什么证据。
3. 沿 Ring 和 Tree 跟踪数据块，按轮数与每方向字节量解释消息大小的影响。能把环上的逻辑边映射到同机与跨机路径，推导单端口上的负载变化。
4. 复算一次集合基准的 `algbw` 和 `busbw`，结合实际路径和端口增量判断双端点测试与整组测试各自覆盖的范围，并设计一次能区分慢因的对照。

## 贯穿案例与技术口径

- 教学主例是两台裸机 Linux 服务器 `gpu-a` 和 `gpu-b`。各有两张独立显存的 GPU、一个 `eno1` 引导接口和一个 200 Gb/s 全双工 RoCEv2 数据端口 `mlx5_0:1`，对应 `enp129s0f0`。每 GPU 一个进程，Rank 0/1 在 A，Rank 2/3 在 B。主例环顺序为 `0 → 1 → 2 → 3 → 0`。GPU 之间可走 PCIe P2P，跨机示意图假定对应收发端均选用 GPUDirect RDMA（GDR）。主机缓冲、选口、方向、通道顺序和规模的变体均在使用处注明。
- 两卡求和先建立概念。三 Rank 对照、四 Rank 的 4 MiB 分块、八 Rank 的延迟模型各自服务于不同推导。端口负载、基准计算和章末检验统一回到四 Rank 与每 Rank 64 MiB。
- NCCL 以 [2.27.3 归档文档](https://docs.nvidia.com/deeplearning/nccl/archives/nccl_2273/user-guide/docs/overview.html) 和 [v2.27.3-1 源码](https://github.com/NVIDIA/nccl/tree/v2.27.3-1) 为准，CUDA 示例使用发行说明列出的 12.9。并用 Open MPI 5.0.6、`nccl-tests v2.17.9` 和 perftest 26.07.8 的文档与固定源码核对命令、计时与字段。模型写明假设，日志和数值标为教学材料。
- 网络插件、多 Rail、跨节点 NVLink、NVLink SHARP 和 CollNet 只用于理解候选路径或算法为何变化。生产配置和调优留到后续章节。第 09 章从通信结果等待转入训练输入与存储 I/O 等待；第 17—19 章再将本章的局部证据纳入观测、故障定位与验收。
