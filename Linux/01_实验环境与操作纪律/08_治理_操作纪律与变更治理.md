# 操作纪律与变更治理

## 1. 没有制度的时候，会怎样

机制与判断可以被一个人掌握，但能不能被稳定地执行下去，取决于另一样东西：**制度。** 没有制度时，翻车方式是可以预测的四种：

- **只打快照而不留控制台访问能力，会让人进不去机器。** 快照给了"能回来"的错觉，而网络配置或挂载表被改坏之后，人进不去，因此判断不了要不要回滚、也验证不了回滚结果；
- **只把回滚方案留在脑子里，会在压力下记错。** 事故现场的压力会让人想错版本、记错路径、漏掉验收步骤；
- **回滚方案缺少触发条件，会让止损被推迟。** 由于没有"什么条件下必须回滚"，止损就会被一次次推迟，最后变成硬故障；
- **"顺手试一下"会绕开所有检查。** 在生产机上做一次未经评估、没有备份、没有记录的改动——它不属于任何风险级别，却制造了全部风险。

四种翻车方式的共同点是：**它们都不是技术能力问题，而是流程缺位问题。** 技术能力再强的人，在凌晨三点、在压力下、在被电话打断的情况下，也会漏掉步骤。因此制度的作用就是把"别漏"从个人品质变成结构约束。

## 2. 行业通行的做法

**变更管理把变更视为故障的主要来源，因此对它做分级、审批、窗口约定与事后复盘。** IT 服务管理实践（ITIL 一类的框架）与 SRE 实践都持这个判断。可操作化的最小集合是：变更分级（按影响面与可回滚性）、回滚预案随变更一起评审、低峰窗口、变更后观察期、以及"回滚也要复盘"。出处：ITIL 的变更使能实践、Google SRE 书中关于变更管理与"用工程手段降低变更风险"的章节。

**配置管理主张"能声明就不手工"。** 因此配置要写成代码、进版本管理、由工具（Ansible、Puppet、云初始化脚本等）施加。理由不是效率，而是**可复现与可审计**——手工改动没有历史、无法复算、无法批量验证。所以手工操作的位置应当被压缩到"应急"和"实验"两类场景。

**破坏性演练要求从真实故障假设出发，并控制爆炸半径。** 故障演练（Game Day）与混沌工程实践提供了这条纪律：实验可中止可回滚，影响面控制到最小。落地到单机就是那三件事——能快照、能进控制台、与生产隔离。出处：混沌工程原则（从稳态假设出发、控制爆炸半径、在生产中做小规模实验）与各厂商公开的演练方法论。

**环境隔离与防误操作要在视觉上做区分，让环境在提示符、配色与主机命名规范上可分辨。** 这条纪律的价值在于它作用于敲下回车之前的那一瞬间。

**备份与快照要当成两件事来管。** 3-2-1 原则（多份副本、多种介质、一份异地）描述的是备份，而快照不满足其中任何一条，因此制度上要把两者写成两件事、两套责任人、两套验证方式。

## 3. 可交付产物与字段

治理的产出是可检查的文件，而不是"大家都注意一点"。这套笔记涉及六种产物：

### 3.1 基线卡

它要记录的字段是：发行版、内核（含变体后缀）、内核启动参数、systemd 版本、cgroup 版本、资源（核数/内存/磁盘与 inode）、根文件系统类型与挂载选项、时间（时区与同步状态）、虚拟化类型与启动模式、工具箱版本。

它的用途是定义"正常"，因此回填时机是每次变更结束时——基线卡过期比没有更危险，因为它会给出错误的正常值。

### 3.2 变更记录

它要记录的六个要素是目标、范围、备份、回滚、验证与时间窗。另外两项必须显式写出来：**回滚的触发条件**（什么可观察的状态下必须回滚）与**实际结果**（成功、部分成功、已回滚，以及偏差原因）。

它的用途是让另一个人在不问你的情况下，能判断这次改动是否可回滚、是否已回滚。

### 3.3 同时刻取证包

它要记录的字段是一组在几分钟内取完的读数、一个统一的时间戳、一套文件命名（按顺序编号 + 内容名，例如 `00-id`、`01-load`、`02-memory`，便于事后按文件名回顾），以及"已复制出本机"这一状态。

它的纪律是**取完必须复制到机器之外**（工单、堡垒机、专门的采集目录），并且在排查结束前不清理。

### 3.4 演练记录

它要记录的字段是快照名与打快照的时间、破坏动作、现象证据、从弄坏到恢复的耗时、用了哪一个恢复点，以及"哪些环节没有按预期走"。

它的用途是把"我们以为能恢复"变成"上次实际用了多久恢复"。**耗时是这份记录的核心字段**，因为它决定了下一次故障能承诺多长的恢复时间。

### 3.5 Runbook 片段

它要记录的是一组对应关系：现象（怎么识别）、证据（先看什么）、动作（做什么，含具体命令的用途）、验收（怎么算好）、回滚（怎么退）。一段只覆盖一类现象，而且要写到能照着执行。

### 3.6 处置记录

它要按六段来写：现象与影响面（谁受影响、从几点开始、现在还在不在）、已取证据（取证包位置、关键读数、变更记录构成的时间线）、根因（一句话加支撑证据）、止损动作（做了什么、预期与实际）、回滚与验收（回滚命令、验收标准、观察了多久）、改进项（至少一条可落地，带责任人与期限）。

## 4. 几条接口字段的治理用法

**环境标识是一处防误操作的接口。** 主机命名规范与提示符差异不是审美问题，因为它决定"在敲下回车之前的那一瞬间"能不能被拦住。落地方式：命名里带环境与角色，登录时显示环境，危险环境用不同配色。

**风险分级要写在动作旁边。** 同一份文档里，只读动作标注"生产机上也可以做"，破坏性动作标注"只在能快照、能进控制台的实验机上做"。**标注的位置比标注的内容更重要**：它必须出现在读者动手的那一行，而不是文档开头。

**证据保留策略要写"排查期间不清理"。** 日志轮转、磁盘用量清理、临时文件回收都可能在你分析之前把证据删掉。因此制度上要给"故障相关的证据"一个例外状态，并说明谁可以解除它。

**机器身份要纳入上线检查项。** 克隆出来的机器要重置机器标识并检查主机密钥一类的身份文件；否则日志、授权与监控会把两台机器当成一台。这一项的价值在于它**只有在克隆时才出问题，而克隆时人通常在想别的事**。

**基线卡与采集配置要纳入巡检。** 巡检项应当包含"这台机器有没有基线卡、采集是否在开、保留期够不够"。它们的失效方式是静默的：没有基线卡不影响运行，直到需要判断"正常"的那一天。

## 5. 三个治理场景与产物

### 场景一：一次内核参数变更

你在一台生产 Web 服务器上要调整一个与连接行为相关的内核参数，用来缓解偶发的连接超时。现在是业务高峰期。

要交出的东西是：**实验机上的验证结果**（它要给出改前改后的对比与副作用观察）、**变更记录**（它要写明目标、范围、备份、回滚、验证、时间窗与触发条件）、**窗口与通知**（它要写明低峰期与通知了哪些相关方）、**改后验收**（它要记录参数当前值、业务侧探活、关键指标回到基线的情况与观察窗口）。其中"触发条件"要写成可观察的句子，例如"观察窗口内错误率超过变更前水平"，而不是"不行就改回去"。

### 场景二：一次凌晨故障的记录与复盘

凌晨两点服务异常，你取了证、止损、恢复。第二天要交的是事故记录。

要交出的东西是：**取证包**（它要处于已复制出机器的状态）、**处置记录六段**、**时间线**（它由取证包与变更记录拼成，要回答几点改了什么、几点开始异常、现场什么样）、**改进项**（它至少要有一条，并且带责任人与期限）。这份记录的价值在下一次：它让同类现象有了一条"先看什么"的路径。

### 场景三：巡检发现一批机器没有基线卡、采集也没开

一批服务器上线半年，没有基线卡，sysstat 装了但采集未启用，日志持久化也没开。

要交出的东西是：**批量采集计划**（它要先取基线，再逐步开启采集与持久化日志）、**保留期评估**（它要按磁盘容量与合规要求定保留天数）、**排期**（它要按业务重要性分批，避免一次性改动面过大）、**验收标准**（它要求每台机器都能回答"上一次启动发生了什么"与"昨天下午的负载曲线"）。这类工作的定位是**能力建设**，因此它的收益在故障发生的那一天才显现。

## 常见坑

| 常见做法或说法 | 后果或事实 |
| --- | --- |
| 只写"做了什么"，不写"怎么退" | 事故时无法决定止损路径，因为变更记录的核心字段是回滚与触发条件 |
| 变更记录写在脑子里或聊天记录里 | 没有可检索的历史，因此复盘时拼不出时间线 |
| 回滚没有触发条件 | 止损被无限推迟，最后变成硬故障 |
| 取证包只留在出事的机器上 | 机器起不来时等于没取 |
| 排查期间执行日志清理或轮转 | 证据被删，因此排查期间必须有例外状态 |
| 破坏性动作的边界写在文档开头 | 读者在动手时才需要它，因此标注必须贴着动作 |
| 巡检只看磁盘用量 | 没有基线卡、采集没有开启、日志没有持久化，这些都是静默失效，直到需要它们的那一天 |
| 演练记录只写"成功恢复" | 缺了耗时字段，因此无法据此承诺恢复时间 |
| 克隆机器不重置身份 | 日志、授权与监控把两台机器当成一台 |

## 要点自测

**问：为什么"回滚方案的触发条件"比"回滚命令"更容易被漏掉？**
答：因为命令是"技术动作"，写下来很自然；触发条件是"判断标准"，需要在动手之前就与业务方对齐可观察的指标。没有它，回滚会一直等到"确认真的不行了"才执行，而那时往往已经过了止损窗口。

**问：变更记录六要素之外，为什么还要写"实际结果"？**
答：六要素描述的是计划，实际结果描述的是事实。回滚过一次的变更同样需要记录：它证明了这条路径在当前环境下不可行，这个结论本身就是资产。没有这一项，下一个人会重复同一个尝试。

**问：演练记录里为什么"恢复耗时"是核心字段？**
答：因为它把"我们以为能恢复"变成"上次实际用了几分钟"。恢复时间是应急预案、SLA 承诺与演练排期的输入；只写"成功恢复"的记录无法支撑任何承诺。

**问：环境标识（提示符/配色/命名）为什么算治理产物而不是审美偏好？**
答：因为它作用在敲下回车之前的那一瞬间——此时人还没开始判断这是哪台机器，视觉信号已经先到了。它拦住的正是"顺手试一下"这类事故。

**问：一批机器"没有基线卡"为什么算治理问题，而不算技术问题？**
答：因为它不影响运行，只在需要判断"正常"的那一天暴露。这类静默失效只能靠巡检与制度覆盖，靠个人的谨慎是覆盖不到的。

**第一反应不要做什么**：不要在没有回滚路径与触发条件时开始变更；不要把证据留在出事的那台机器上；不要把"上次演练成功"当成"这次也能按时恢复"。
