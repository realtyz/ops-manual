## 0. 30 秒速览

> [!abstract] 这一篇只要记住四句话
> - **只读查询命令通常跨家族通用，写操作几乎都要换。**
>   证据：`ss`/`nstat`/`ip`/`df`/`vmstat` 两边一致；而「开端口、改 IP、装包、重启服务」的入口几乎都不一样。
> - **跨家族抄命令前，先 `command -v`。**
>   怎么验证：RHEL 上敲 `ufw`、Ubuntu 上敲 `firewall-cmd`，得到的都是「没这条命令」；命令不存在时不要怀疑权限。
> - **防火墙前端不同，底层是同一个 nftables。**
>   证据：`ufw` 与 `firewalld` 最终都落到 nftables（老系统上是 iptables），所以查实际规则要看 `nft list ruleset`。
> - **`command not found` 有三种原因：没装、PATH 里没有、家族不同。**
>   怎么验证：`command -v <cmd>` 与 `echo $PATH`；权限不足报的是 `Permission denied`，不是 `command not found`。

## 1. 四件事，四个家族

| 事情 | RHEL 系 | Debian / Ubuntu | SUSE | Alpine | 查本机现状 |
| --- | --- | --- | --- | --- | --- |
| 装/查/卸包 | `dnf install`、`dnf provides`、`dnf info` | `apt install`、`apt search`、`apt policy` | `zypper install`、`zypper search -f` | `apk add`、`apk info -L` | `command -v <cmd>` + `rpm -qf`/`dpkg -S` |
| 仓库配置 | `/etc/yum.repos.d/*.repo`；`dnf config-manager --add-repo` | `/etc/apt/sources.list`、`/etc/apt/sources.list.d/`；`add-apt-repository` | `/etc/zypp/repos.d/*.repo` | `/etc/apk/repositories` | `dnf repolist -v` / `apt policy` / `zypper lr -u` |
| 防火墙 | `firewalld`：`firewall-cmd --state`、`--add-port=80/tcp --permanent` | Ubuntu：`ufw status verbose`；Debian 最小安装默认无规则 | `firewalld`（`SuSEfirewall2` 已废弃） | 无前端，`nft list ruleset` | `firewall-cmd --state` / `ufw status` / `nft list ruleset` |
| 网络配置 | NetworkManager（`nmcli`/`nmtui`）；RHEL 9 起不再默认安装 `network-scripts` | Ubuntu Server：netplan（`/etc/netplan/*.yaml`，后端 systemd-networkd 或 NM）；Debian 传统 `/etc/network/interfaces` | `wicked` 或 NetworkManager | `/etc/network/interfaces`（BusyBox 风格） | `nmcli device status`、`networkctl status`、`cat /etc/netplan/*.yaml` |
| 强制访问控制 | SELinux：`getenforce`、`sestatus`、`ausearch -m AVC -ts recent`、`restorecon -Rv` | AppArmor：`aa-status`、`aa-enabled`、`journalctl -k \| grep -i apparmor` | AppArmor（默认启用） | 默认不启用 | `getenforce` / `aa-status` |
| cgroup 版本 | RHEL 8 默认 v1（可切 v2）、RHEL 9 默认 v2 | Ubuntu 22.04+ 默认 v2 | 以实测为准 | 以实测为准 | `stat -fc %T /sys/fs/cgroup` |

## 2. 四条纪律

1. **跨家族抄命令前，先 `command -v`。** 命令不存在时不要怀疑权限，先确认它在不在。
2. **只读查询命令通常可以跨家族复用，写操作几乎都要换。** `ss`/`nstat`/`ip`/`df`/`vmstat` 两边一致；「开端口、改 IP、装包、重启服务」的入口几乎都不一样。
3. **`nftables` 是底层，前端才是差异。** Ubuntu 的 `ufw` 与 RHEL 的 `firewalld` 最终都落到 nftables（老系统上是 iptables），所以「规则到底有没有生效」要看 `nft list ruleset`，而不是只看前端状态。
4. **文档要配套。** 查 Ubuntu 的行为看 Ubuntu Server Guide 与 man 页，查 RHEL 的看 RHEL 文档——同一个参数在两个家族里的默认值经常不同，混着看必然出错。

## 3. `command not found`：是没装、PATH，还是家族差异

> [!tip] 第一反应不要是「权限不够」
> `command not found` 与权限无关——权限不足会报 `Permission denied`。先分清三种情况。

按顺序排除：

1. **是不是没装**：`command -v <cmd>`；确认没装后用家族对应的包管理器装（`dnf`/`apt`/`zypper`/`apk`）。
2. **是不是 PATH 里没有**：管理命令常在 `/usr/sbin`、`/sbin`，非 root 用户默认不查这些目录——`echo $PATH`、`ls -l /usr/sbin/<cmd>` 确认，必要时用绝对路径或 `sudo`。
3. **是不是发行版差异**：`ifconfig`/`netstat`（net-tools，现代发行版默认不装）→ `ip`/`ss`；`service` → `systemctl`；`ufw` ↔ `firewall-cmd`。**这一类的正解是换命令，不是装老工具。**
4. **是不是同名不同包**：`python`/`python3`、`node`/`nodejs`、`perf` 与 `linux-tools-*`——先确认「这个命令属于哪个包」，再装。

```bash
command -v <cmd>; echo $PATH                 # 验证：命令是否存在、PATH 是否含 sbin
dpkg -S "$(command -v ss)"                   # 验证（Debian 系）：这个命令属于哪个包
rpm -qf "$(command -v ss)"                   # 验证（RHEL 系）：同上
dnf provides '*/iperf3'                      # 验证（RHEL 系）：哪个包提供这个文件（未安装时用这个）
apt-file search bin/iperf3                   # 验证（Debian 系，需先 apt install apt-file）
```

预期：`command -v` 有输出就说明命令存在且可执行；`echo $PATH` 里没有 `/usr/sbin` 时，用 `sudo` 或绝对路径即可验证第 2 种情况；`dpkg -S`/`rpm -qf` 会给出包名，据此就能判断「是不是同名不同包」。

## 4. 一次核对手册

接手一台陌生机器，需要判断「我能不能用习惯的那套命令」，按这个顺序走一遍，五分钟能得出清单：

```bash
cat /etc/os-release | head -3                # 验证：先确认家族（RHEL / Debian / SUSE / Alpine）
for c in dnf apt zypper apk firewall-cmd ufw nft nmcli netplan; do
    printf '%-12s %s\n' "$c" "$(command -v "$c" 2>/dev/null || echo MISSING)"
done                                          # 验证：四件套的入口在本机各是什么
getenforce 2>/dev/null || aa-status 2>/dev/null || echo "MAC 入口未找到"
                                              # 验证：强制访问控制是 SELinux 还是 AppArmor
stat -fc %T /sys/fs/cgroup                    # 验证：cgroup 版本
```

**验收标准**：能不看笔记说出「这台机器用哪套包管理、哪套防火墙、哪种 MAC、cgroup 是几版」；其中任何一项说不出，就先补子笔记 02 的基线。

## 常见坑

| 常见做法或说法 | 后果或事实 |
| --- | --- |
| 在 RHEL 上敲 `ufw` / 在 Ubuntu 上敲 `firewall-cmd` | 两边都只会报命令不存在；先 `command -v` 再动手 |
| 把 `command not found` 当成权限问题 | 权限不足报的是 `Permission denied`；缺少 `CAP_*` 或 euid 不匹配才是权限问题 |
| 装了 `net-tools` 就继续用 `ifconfig`/`netstat` | 现代发行版默认不装，且新命令 `ip`/`ss` 信息更全；正解是换命令 |
| 只看 `ufw status` 就断言「端口一定开着」 | 前端状态不等于实际规则；要看 `nft list ruleset`，还要确认服务真的在监听（`ss -lntp`） |
| 把 `setenforce 0` 当修复手段 | SELinux 报警说明策略拦了访问，关掉它等于关掉审计；应 `ausearch` 找被拦的上下文再处理 |
| 在两个家族之间混着看文档 | 默认值与参数名经常不同，混读会得出错误结论 |
| 用「发行版名字」代替实测 | 云厂商镜像与大版本都可能改默认栈，四件事一律 `command -v` + 实测确认 |

## 决策练习

> **场景**：一台 Ubuntu 服务器上，同事给了你一段「开放 8080 端口」的操作步骤，里面写的是 `firewall-cmd --permanent --add-port=8080/tcp`。你执行后报 `command not found`。
>
> A. 装 `firewalld`，让这条命令能跑起来。
> B. 先 `command -v firewall-cmd`；确认没有后，改用本机的 `ufw`（或 `nft`），并在最后用 `nft list ruleset` 与 `ss -lntp` 双重复核。
> C. 认为防火墙没装，直接跳过这一步。

**为什么选 B**：正解是「换成当前家族的入口」，并且用底层规则与实际监听两个证据来验收。命令不存在本身就是家族差异的信号。

**为什么 A 不对**：为了跑一段抄来的命令，把另一套防火墙前端装进系统，会和系统默认的 `ufw`/netfilter 管理方式冲突，也可能让原来的规则失效。

**为什么 C 不对**：跳过防火墙会让服务「本机通、外部不通」，故障只是被推迟到了联调时。Ubuntu 上要用 `ufw`（或直接用 `nft`）把规则放开。

## 要点自测

> [!question]- 为什么说「只读查询命令可以跨家族，写操作几乎都要换」？
> - `ss`/`nstat`/`ip`/`df`/`vmstat` 这些是内核接口的通用封装，各家族基本一致。
> - 写操作要经过「包管理 / 防火墙 / 网络配置 / 访问控制」四套前端，这四套的入口、配置文件、生效方式各家族都不同。
> - 所以拿到一条命令先分类：只读的就直接跑，写操作先 `command -v` 确认入口。
> - **第一反应不要是什么**：不要假设「Linux 都一样」——同一条命令换个家族可能根本不存在。

> [!question]- `command not found` 怎么分三种情况？
> - 没装：`command -v <cmd>` 无输出，且包管理里查不到；按家族装。
> - PATH 里没有：命令文件存在（`ls -l /usr/sbin/<cmd>`），但 `echo $PATH` 不含该目录；用绝对路径或 `sudo`。
> - 家族不同：本家族根本没这个入口（`ufw` 对 `firewall-cmd`）；换成当前家族的等价命令。
> - 还有一种要单独看：**同名不同包**（`python` 对 `python3`、`perf` 对 `linux-tools-*`）。
> - **第一反应不要是什么**：不要一上来就 `apt install` 或怀疑权限。

> [!question]- 防火墙前端不同，验收为什么要看 `nft list ruleset`？
> - `ufw` 与 `firewalld` 只是前端，最终都写进 netfilter 的表和链。
> - 前端显示「已激活」不等于规则真的落在正确的链上，也不等于端口真的有进程监听。
> - 所以验收要看两层：底层规则（`nft list ruleset`）与实际监听（`ss -lntp`），再加一次外部连通性测试。
> - **第一反应不要是什么**：不要只看前端状态就宣布问题解决。
