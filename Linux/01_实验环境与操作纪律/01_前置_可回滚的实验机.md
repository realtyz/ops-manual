## 0. 30 秒速览

> [!abstract] 这一篇只要记住四句话
> - **实验机的三要件是快照、控制台、隔离，不是「有 root」。**
>   证据：网络配置与 `/etc/fstab` 被写坏之后 SSH 已经进不去，此时 root 密码帮不上忙，只有控制台能救；演练打满磁盘时会波及同机业务，所以必须隔离。
> - **没有控制台，破坏性演练就不要做。**
>   怎么验证：动手前先用控制台（而不是 SSH）登录一次；登不进去就说明这条通道还没准备好。
> - **快照不是备份。**
>   证据：快照保护的是「这块磁盘在某个时刻的样子」，不保护误删的文件、不跨机器、不覆盖「忘了回滚又拿它做别的事」。
> - **本地虚拟化能覆盖全部演练，WSL2 和容器只能覆盖只读部分。**
>   证据：WSL2 共享微软定制内核、没有独立控制台，容器共享宿主内核——内核模块、SysRq、loop 挂载这三类实验在它们上面都做不了。

## 1. 为什么第一个产物是「一台敢弄坏的机器」

运维和开发最大的差别之一：**很多结论只有把系统弄坏一次才能真正记住**。磁盘写满之后 `df` 和 `du` 为什么对不上、`fstab` 写错之后系统停在哪、`kill -9 1` 为什么没用——这些都不是靠读文档能形成肌肉记忆的。

但「敢弄坏」不是「随便弄坏」。它有一个前提条件：**弄坏之后你能确定地救回来**。这个前提由三件事保证，缺任何一件，演练就会变成事故。

| 能力 | 为什么必须有 | 没有会怎样 |
| --- | --- | --- |
| **快照 / 快速重建** | 演练前打一份，弄坏了直接回滚 | 每次演练都要重装系统，最后你会放弃演练 |
| **控制台（带外 / VNC / 串口）** | 网络配置、`fstab`、`/etc/passwd` 写坏之后，SSH 已经进不去了 | 只能重装——「演练」变成「事故」 |
| **与生产隔离** | 演练会打满磁盘、触发 panic、伪造网络报文 | 影响真实业务；这是纪律问题，不是技术问题 |

> [!important] 一条经常被忽略的边界
> 三要件里最容易漏的是**控制台**。虚拟机上「我 SSH 能进」不等于「我有控制台」——很多云主机默认不开 VNC，很多虚拟机没配串口。**动手前用控制台登一次，比动手前打快照更重要。**

## 2. 四种常见环境的边界

选实验机时最容易想当然的地方，是「我以为它能做」。下表把四种常见做法按能力拆开：

| 方案 | 快照 | 独立控制台 | 改内核/模块、SysRq | loop 挂载、LVM | 能覆盖的演练 |
| --- | --- | --- | --- | --- | --- |
| 本地虚拟化（KVM/libvirt、VirtualBox、VMware、UTM） | 可用 | 可用 | 可用 | 可用 | **全部**，推荐 |
| 云主机（ECS/EC2 等） | 云盘快照 | 需**先确认**控制台/VNC 已开通 | 受虚拟化平台限制 | 可用 | 全部；注意安全组别把自己锁在外面 |
| WSL2 | 需手工导出/导入 tar | 不可用（只有终端窗口） | 不可用（内核由平台提供） | 多为受限 | 只覆盖基线、工具箱、库、命令差异 |
| 容器 | 靠镜像重建 | 不可用 | 不可用（共享宿主内核） | 不可用 | 只能练命令与配置语法 |

本目录的实测环境就是上表第三行的 WSL2。**它足够练版本基线、工具箱、动态库与全部只读命令，但覆盖不了子笔记 07 的破坏性演练**。这不是缺陷，是选型时要提前知道的边界——知道边界，才不会在演练当天才发现做不了。

```bash
ls /sys/firmware/efi                                  # 验证：UEFI（有输出）还是 legacy BIOS（无输出）
systemd-detect-virt                                   # 验证：当前是不是虚拟化环境，以及是哪一种
systemd-detect-virt -c                                # 验证：是否运行在容器里（输出 docker/lxc 等即为容器）
```

预期：本地虚拟化通常报 `kvm`/`vmware`/`oracle`；云主机会报对应平台名；容器与 WSL 会报 `docker`/`lxc`/`wsl`；裸机会报 `none`。把这三行输出记进基线卡，它决定了你能做哪些演练。

## 3. 三条快照纪律

1. **动手前打快照，并写下快照名与时间。** 回滚时不用猜哪一份是干净的；演练记录里也要写清「从哪个快照恢复」。
2. **快照不是备份。** 它保护的是磁盘，不覆盖误删、跨机器、跨时间的需求；重要数据要有独立备份。快照链越长，回滚越慢，也越容易选错。
3. **演练前用控制台登录一次。** 确认你能进去，比快照本身更重要。

## 4. 演练前的准备动作

下面这组动作不产生风险，但能把「演练变事故」的概率降一个数量级。**建议固化成一个 `lab-preflight` 脚本，每次动手前跑一遍。**

```bash
hostname; date; uptime                                # 验证：我在哪台机器、现在几点、负载如何
systemd-detect-virt; ls /sys/firmware/efi              # 验证：虚拟化类型与启动模式（决定哪些演练能做）
df -hT /; df -i /                                     # 验证：根分区容量与 inode 水位（演练前留足余量）
findmnt -o TARGET,SOURCE,FSTYPE,OPTIONS | head -10    # 验证：挂载关系（演练前先记录，回滚后拿来对照）
systemctl --failed                                    # 验证：演练前系统本身是干净的
```

**验收标准**：五条命令都有输出，`systemctl --failed` 为空，控制台能独立登录一次。三条都满足，才算「准备好」。

> [!warning] 破坏性操作的前提
> 子笔记 07 的所有演练都要求「可快照 + 有控制台 + 与生产隔离」。**只在可快照的实验机上做**，动手前先打快照，并确认你手边有控制台。

## 常见坑

| 常见做法或说法 | 后果或事实 |
| --- | --- |
| 在办公机或生产机上做演练 | 演练包含打满磁盘、改坏 `fstab`、触发 panic，只能在实验机做 |
| 只打快照、不留控制台 | 网络配置写错后 SSH 进不去，快照也救不了你——只能重装 |
| 把快照当备份 | 快照保护的是磁盘，不覆盖误删、跨机器、跨时间的需求 |
| 用云主机的「重启」代替控制台 | 系统进不了多用户时，重启只会让你更进不去；要的是 VNC/串口，不是重启 |
| 以为 WSL2 能练 SysRq、loop 挂载、内核模块 | WSL2 共享平台内核、无独立控制台，这三类都做不了 |
| 在容器里做「系统级」演练 | 容器共享宿主内核，改不了内核参数、看不到真实块设备 |
| 快照打完就忘了名字 | 回滚时面对一串时间戳无从下手；演练记录必须写清用了哪一份 |
| 回滚之后不校时 | 快照不保护时间，回滚后时间会跳回，日志时间线与证书校验都会乱 |

## 决策练习

> **场景**：你手头只有一台公司配的 WSL2 开发机和一台普通云主机（默认只开了 SSH，控制台未开通）。这周想练「写坏 `/etc/fstab` 之后从紧急模式恢复」。
>
> A. 直接在 WSL2 里改 `/etc/fstab`，反正它是共享内核，改坏了也不影响 Windows。
> B. 在云主机上开控制台、先打快照，再改 `/etc/fstab`，然后用控制台练习恢复。
> C. 在公司配的 WSL2 里用 Docker 起一个容器，在容器里改 `/etc/fstab`。

**为什么选 B**：`fstab` 写坏之后系统可能停在实际挂载之前，必须靠控制台进入 `emergency mode`——这正是这个实验要练的技能。B 同时满足快照、控制台、隔离三个条件，只是需要先做一步准备（开通控制台、打快照）。

**为什么 A 不对**：WSL2 没有独立控制台，`fstab` 写坏的后果是「发行版启动失败」，你在 Windows 侧只能靠 `wsl --shutdown` 或导出/导入镜像来救，练不到 `emergency.target` 那条真实路径。

**为什么 C 不对**：容器共享宿主内核，`/etc/fstab` 在容器里基本不参与启动挂载，改了既不触发紧急模式，也不是真实场景。

## 要点自测

> [!question]- 一台实验机的最低要求是什么？为什么不是「有 root」？
> - 三要件是**快照、控制台、隔离**：快照保证能回滚，控制台保证网络/挂载/认证写坏后还能进去，隔离保证演练不波及业务。
> - 「有 root」只解决权限问题：权限再高，SSH 进不去、磁盘被写满、系统停在紧急模式时，root 也帮不了你。
> - 三要件里最容易被忽略的是控制台——很多虚拟机与云主机默认不开 VNC/串口，动手前必须实测能登录。
> - **第一反应不要是什么**：不要因为「反正是虚拟机」就跳过控制台检查。

> [!question]- 快照和备份有什么区别？
> - 快照是**磁盘在某一时刻的样子**，回滚快、占用少，适合「演练前打一份」。
> - 备份是**独立副本**，覆盖误删、人为破坏、跨机器、长时间保留等场景，通常落在别的介质上。
> - 快照的三条局限：不保护时间与外部依赖状态、不跨机器、不替代数据备份。
> - **第一反应不要是什么**：不要把「我打了快照」当成「数据是安全的」。

> [!question]- 只有 WSL2 或容器时，这一章能练到哪一步？
> - **能练**：版本基线、工具箱体检、`man` 检索、动态链接库排障、`command not found` 排查、只读取证命令。
> - **不能练**：内核模块与 SysRq、loop 挂载与独立文件系统、`fstab` 与网络写坏后的紧急模式恢复（因为进不去控制台）。
> - 建议：用 WSL2 完成 T1，再用一台按量付费云主机补 T2、T3；**破坏性演练的机器要单独开、用完销毁**。
> - **第一反应不要是什么**：不要在唯一的开发机上一次做完所有破坏性演练。
