# 实验环境与操作纪律

## 知识地图

### 一次手工变更的旅程

时间主线跟着**一次手工变更**走：从接手一台机器、确认它现在是什么样，到改之前留下退路，到动手、复验、出事时留住现场，最后收口成记录并把认知回填到基线。

```mermaid
flowchart LR
  A["① 上机与基线<br/>这台机器是什么、退路在哪"] --> B["② 变更前<br/>备份 · 回滚 · 时间窗 · 预检"]
  B --> C["③ 执行<br/>一次只改一个变量"]
  C --> D["④ 立即复验<br/>语法自检 + 业务侧验收"]
  D --> E["⑤ 同时刻取证<br/>把现场留住"]
  E --> F["⑥ 收口与沉淀<br/>记录 · 回填基线"]
  F -.->|新的认知| A
```

| # | 站点 | 这一步在做什么 | 到这里要能说清 |
| --- | --- | --- | --- |
| 1 | 上机与基线 | 确认身份、版本、资源、时间与退路，取一份基线 | 这台机器是什么、它在哪、坏了有什么退路 |
| 2 | 变更前 | 备份、写下回滚命令与触发条件、约时间窗、只读预检 | 改哪个文件、怎么撤回、什么条件下撤回 |
| 3 | 执行 | 只改一个变量，改在持久生效的位置 | 改了什么、为什么现在改 |
| 4 | 立即复验 | 语法自检、服务与端口、业务侧探活与观察窗口 | 怎么知道改对了、观察多久 |
| 5 | 同时刻取证 | 现象出现时一次性取完各层证据并复制出机器 | 现场在哪、哪些证据重启就没 |
| 6 | 收口与沉淀 | 写记录、回填基线、把判断过程留成 Runbook | 下次遇到同类现象先看什么 |

### 三条横切线

| 横切线 | 贯穿内容 | 收口于 |
| --- | --- | --- |
| 发行版差异线 | 血统与派生 → 包管理与仓库 → 服务与网络配置 → 强制访问控制 → 默认值 | 「同一件事，这台机器上走哪个入口」 |
| 资料线 | 版本基线 → 默认值从哪查 → 字段口径核对 → 工具箱从哪装 → 依赖缺失怎么办 | 结论有出处，默认值现场取 |
| 风险分级线 | 只读 → 可回滚变更 → 破坏性演练 → 机器边界与防呆 | 「这个动作能不能在这台机器上做」 |

## 术语速查

| 名词 | 一句话解释 | 在哪一篇展开 |
| --- | --- | --- |
| 发行版 | 内核 + 用户态 + 包管理 + 一套默认选择的打包 | 原理：发行版的构成与差异来源 |
| 内核与用户态的分工 | 内核提供机制，发行版选择策略 | 原理：发行版的构成与差异来源 |
| 用户态 ABI | 库与程序之间的二进制接口约定，只增不减 | 原理：发行版的构成与差异来源 |
| backport | 把上游新版本的补丁回移到发行版自己的低版本内核分支 | 原理：发行版的构成与差异来源 |
| 发行版血统 | 派生关系决定补丁到达的延迟与文档的适用范围 | 原理：发行版的构成与差异来源 |
| 版本基线四项 | 发行版、内核、systemd、cgroup 版本，跨机器比较的最小集合 | 原理：发行版的构成与差异来源 |
| ELF | Linux 的可执行与可链接文件格式 | 原理：程序启动与依赖解析 |
| 动态链接器（`ld.so`） | 在程序 `main` 之前把依赖找齐并接好的那个程序 | 原理：程序启动与依赖解析 |
| SONAME | 库对外声明的名字，依赖记的是它而不是路径 | 原理：程序启动与依赖解析 |
| `DT_NEEDED` | ELF 里"我需要哪些库"的列表 | 原理：程序启动与依赖解析 |
| 搜索顺序 | 依赖查找的五级顺序：`RPATH` → 环境变量 → `RUNPATH` → 缓存 → 默认路径 | 原理：程序启动与依赖解析 |
| `ld.so.cache` | 由 `ldconfig` 扫描配置目录生成的库缓存 | 原理：程序启动与依赖解析 |
| 安全执行模式 | setuid 等特权程序的运行方式，会忽略部分环境变量 | 原理：程序启动与依赖解析 |
| `glibc-hwcaps` | 按硬件指令集分派更优库版本的搜索子目录机制 | 原理：程序启动与依赖解析 |
| 快照 | 虚拟化平台保存的某一时刻的机器状态（可含内存） | 原理：快照与状态一致性 |
| 崩溃一致性 | 只快照磁盘时得到的一致性等级，相当于断电 | 原理：快照与状态一致性 |
| 静默（quiesce） | 打快照时暂停写入并刷盘，把一致性等级抬高一级 | 原理：快照与状态一致性 |
| 机器身份（`machine-id`） | 安装时生成、此后不变的机器标识，克隆会连带复制 | 原理：快照与状态一致性 · 治理 |
| 证据易失性 | 证据的寿命由它存在哪一层介质决定 | 原理：观测的代价与证据的易失性 |
| 计数 / 采样 / 探针 | 观测的三档机制，代价与事件频率的关系完全不同 | 原理：观测的代价与证据的易失性 |
| 采集间隔与保留期 | 决定"历史数据能看到什么、能回溯多久"的两个量 | 实操：基线卡与观测工具箱 |
| 基线卡 | 一台机器"正常"的定义，变更收口时回填 | 实操：基线卡与观测工具箱 · 治理 |
| 取证包 | 几分钟内取完、带统一时间戳、已复制出机器的一组读数 | 实操：基线卡与观测工具箱 · 治理 |
| 变更记录六要素 | 目标、范围、备份、回滚、验证、时间窗 | 体系：一次手工变更的完整旅程 · 治理 |

## 故障现场定位表

排障的第一问不是"怎么修"，而是「**我现在在哪台机器上、这个现象属于哪一类、它的现场在哪一层**」。用这张表把现象定位到类别，再进对应篇目。

| 你看到的现象 | 属于哪一类 | 现场在哪 | 第一反应不要做 |
| --- | --- | --- | --- |
| 一条命令报 `command not found` | 入口不对，不是权限 | 本机的包管理家族、`command -v`、`PATH` | 不要加 `sudo` 反复重试 |
| 程序报 `error while loading shared libraries` | 依赖解析失败，程序一行没跑 | ELF 的 `NEEDED`、`ldconfig -p`、搜索路径配置 | 不要用 `LD_LIBRARY_PATH` 当修复 |
| 改了配置但没生效 | 生效层级与读取时机 | 文件位置与优先级、是否需要重新加载 | 不要反复改同一个值 |
| 写进 `sysctl.d` 的值没生效 | 目录优先级与字典序覆盖 | `/etc` 与 `/usr/lib` 下的同名文件、目录顺序 | 不要直接往运行时接口里写当持久方案 |
| SSH 不通，但控制台能进 | 网络、认证、服务、策略四层之一 | 地址与路由、22 端口监听、底层规则表 | 不要重装，也不要在没取证时重启 |
| 重启后停在紧急模式 | 启动期挂载失败 | 失败单元、内核启动日志、挂载表对照 | 不要在没确认控制台时反复重启 |
| 登录、`su`、`sudo` 都失败 | 账号库损坏或认证策略 | 账号解析结果、结构与格式自检 | 不要用普通编辑器继续改账号库 |
| 快照回滚后现象对不上 | 快照之外的状态 | 时间、外部依赖、机器身份、快照后数据 | 不要断定"回滚失败" |
| 装了采集工具却查不到历史 | 采集没开或已过保留期 | 采集计时器状态、数据目录、保留天数 | 不要现场补装后声称能回溯过去 |
| `journalctl -b -1` 报找不到启动偏移 | 日志没持久化或旧数据被清 | 启动列表、持久目录与存储配置 | 不要反复重试同一个偏移 |
| `systemctl --failed` 有内容 | 存在失败单元，未必是本次造成 | 单元名与失败时间 | 不要当成自己弄坏的 |
| 两台机器在监控里像同一台 | 身份重复 | `machine-id`、主机密钥 | 不要先把监控改成人工忽略 |

## 参考文档

- `man 5 os-release`、`man 1 uname`、`man 1 hostnamectl`、`man 1 systemd-detect-virt`、`man 5 machine-id`：机器身份与版本基线。
- `man 8 ld.so`、`man 8 ldconfig`、`man 5 ld.so.conf`、`man 1 ldd`、`man 1 readelf`、`man 2 execve`：程序启动与依赖解析。
- `man 5 sysctl.d`、`man 8 sysctl`、`man 5 systemd.unit`、`man 5 fstab`、`man 8 mount`、`man 1 findmnt`：配置的层级、覆盖与撤回。
- `man 1 journalctl`、`man 5 journald.conf`、`man 5 sysstat`、`man 1 sar`、`man 1 dmesg`、`man 2 ptrace`：现场与历史数据。
- `man 1 timedatectl`、`man 8 systemd-timesyncd`、`man 8 hwclock`：时钟与同步状态。
- 内核 6.x 文档 `Documentation/admin-guide/sysrq.rst`、`Documentation/admin-guide/kernel-parameters.rst`、`Documentation/process/stable-kernel-rules.rst`。内核文档一律按与目标机器同一主版本取（当前基线 6.x）——同一条路径在不同版本里可能同名而内容不同。
- 虚拟化平台的快照文档（快照类型、静默机制、Snapshot Limitations）、各发行版的发布说明与生命周期页、各家族的包管理与配置文档。
