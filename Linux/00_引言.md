# 引言

## 一、这套笔记在解决什么问题

你已经会敲命令，但现场的问题很少以命令的形式出现。用户说「服务连不上」，监控说「这台机器很慢」，交接班说「昨晚三点有一波报警」——这些都不是命令能直接回答的，它们要求你先把现象归到一个机制上，再决定看哪个字段、按什么顺序动。

因此这套笔记不按命令分类，而按**机制**组织：每一章讲一类对象的一生（一次启动、一个进程、一块内存、一条连接、一个 unit、一次变更），目标是让你在现象出现时知道自己在哪一层、下一句话该问什么。判断一篇写得好不好，看的是你读完能不能靠它做事，而不是看它覆盖了多少个选项。

读者的起点是：会基本的 Shell 操作，用过 `top`、`free`、`df`、`systemctl`，但没有系统学过操作系统原理。操作系统原理正是这套笔记负责补齐的部分——凡是需要先理解机制才能读懂的字段，笔记都会把机制讲在前面。

配套的另两份笔记覆盖其余两层：容器与编排层在 `Kubernetes/`，GPU 与高速网络的数据面在 `AI-Infra/`。同一个知识点只在一处展开，其余各处只引用不重复；遇到某道题时先确定它属于哪一层，再回对应笔记深挖，因此这套笔记里不会再出现容器运行时与编排对象的内容。引用它们时一律写成路径形式（例如 `[[AI-Infra/00_简介]]`），因为三套笔记里存在同名文件，只写文件名会被 Obsidian 解析到别的目录。

## 二、学习路径总览

| 阶段 | 主题 | 产出目标 |
| --- | --- | --- |
| 1 | 实验环境与操作纪律 | 有可快照的实验机，能交出基线卡、变更记录与演练记录 |
| 2 | 启动流程、内核与系统初始化 | 讲清从加电到登录的全链路，能救回一台起不来的机器 |
| 3 | 进程、信号与资源隔离 | 能定位进程卡死、杀不掉、进程数打满；讲清 namespace 与 cgroup |
| 4 | 内存管理与 OOM | 讲清地址空间、承诺额度与物理占用三类占用各是多少，能定性 OOM、配内存上限并复盘 |
| 5 | 存储、文件系统与 IO | 讲清 inode、挂载、LVM 与 RAID，处理磁盘满与 IO 瓶颈 |
| 6 | 网络协议栈与排障 ★ | 按六个阶段分层定位连接、丢包与吞吐问题，用 `ss` 与 `tcpdump` 取证 |
| 7 | 权限、账号与安全加固 | 按十个阶段定位权限拒绝与提权面，能按基线加固一台生产机并做应急取证 |
| 8 | systemd、服务与定时任务 | 能排查服务起不来，正确写 unit 与 timer |
| 9 | 日志、监控与可观测性 | 建立日志轮转与指标采集，让告警能落到具体动作 |
| 10 | 性能分析与故障排查 ★ | 用一套方法论把 CPU、内存、IO、网络问题定位到根因 |
| 11 | 生产运维、变更与高可用 | 独立完成一次带回滚的生产变更，交得出变更单、恢复记录与 Runbook |
| 12 | 复习与自测 | 交得出错题本、一页纸、限时推演记录与端到端演练记录 |

标 ★ 的阶段 6（网络）与阶段 10（性能排障）是运维现场区分度最高的两块：命令谁都会敲，能从现象推到根因的人不多，因此这两章值得优先打透。每章内部按「导读 → 原理 → 体系 → 实操 → 判例 → 治理」的顺序推进，不要跳着读：实操篇的字段读法依赖原理篇讲过的机制，判例篇的判据依赖体系篇串起来的主线。各章的篇目、术语速查、过关里程碑与故障现场定位表都在该章的 `00_导读与知识地图.md` 里，学到什么程度算过关以那里写的为准。

## 三、阅读与练习纪律

答任何一道运维题，都使用同一个骨架：现象与影响面 → 分层定位（先确定是哪一层）→ 用什么命令取证据 → 结论与根因 → 止损动作 → 长期改进。其中「先确定是哪一层」是这套笔记真正要练的部分：命令谁都会敲，能从现象推到根因的人不多。

与这个骨架配套的是一条必备句式：**先说出「第一反应不要做什么」，再动手**。面对一个现象，能主动讲出「不要随手 `kill -9`、不要在生产机上不限流抓包、不要用 `setenforce 0` 掩盖问题」，比多背十个命令更能体现经验，也更能避免把小故障处置成大故障。

另外三件容易走偏的事，值得在开始之前就避开：

- 把笔记当命令手册用：查到一个能用的选项就结束。可用的选项很多，能解释「为什么是这一条而不是另一条」才是这套笔记要练的部分。
- 只读不动手：基线卡、变更记录与演练记录都是产出物，只读不写就不会有。
- 一次改多个变量：改完不知道是哪一项起了作用，回滚时也说不清该退哪一步。

## 四、注意事项

### 实测环境与未实测部分

这套笔记里写下的机制、字段与判据来自内核与标准工具本身的语义，因此换一个发行版或换一个 6.x 内核版本大体仍然成立，真正随版本变化的是默认值与个别字段口径，遇到时现场取一次即可。文中给出的具体数字则只在采集它们的环境里严格成立：**Ubuntu 24.04.5 LTS，VMware 虚拟机，内核 `6.8.0-139-generic`，systemd 255，4 vCPU，`MemTotal` 7894 MiB**。

标注「未实测」的少数内容，原因是手头这台机器做不到，而不是结论存疑：需要控制台或快照的演练（写坏 `/etc/fstab`、根分区只读、内核 panic），需要第二台机器的动作（双机切换与脑裂、负载均衡摘流量、批量执行），以及需要真实硬件的观测（物理网卡多队列与 offload、PMU 计数器、GPU）。读到时按「待补做」对待；各章写了补齐方式。

### 写作与操作边界

- 单位统一用 MiB、GiB 与秒，容器相关的用量按 cgroup 的同一口径换算后再比较。
- 默认值、内核差异与发行版差异必须现场取，不凭记忆；`sysctl -n`、`tune2fs -l` 与启动日志是三个常用的取法。
- 破坏性操作只写在可快照的实验机上做，并且必须写出回滚路径与影响上限。只读观测在生产机上也可以做，这套笔记在相应位置标明了属于哪一类。
- 贴出来的命令输出只用来展示格式，其中的数值不代表你的机器。
- 新增篇目直接按 `写作规约.md` 第三节的骨架写，不再使用模板。
- 本笔记不使用等级与技能编号，也不给知识点编号打分；判断掌握程度看的是能不能交出第 12 章要求的那几件东西，而不是某个分数。

## 五、推荐资源

1. **`man` 页与发行版官方文档**（RHEL 文档、Ubuntu Server Guide、Debian Handbook）。讨论版本差异与默认值时以它们为准，本套笔记里凡涉及默认值的地方都按这一条取材。
2. **《Linux 性能优化实战》**（倪朋飞）。它的排障与性能分析部分最贴近运维现场，阶段 10 的处置顺序与它同源。
3. **《Systems Performance》**（Brendan Gregg）。它提供了 USE 方法与各资源章节的判据来源，FlameGraph 也出自同一个项目。
4. **Google SRE 手册（Site Reliability Engineering）与 SRE Workbook**。本套笔记在治理与排障部分反复引用其中的「Service Level Objectives」「Embracing Risk」「Monitoring Distributed Systems」「Effective Troubleshooting」「Managing Incidents」「Postmortem Culture」「Release Engineering」「Handling Overload」「Addressing Cascading Failures」等章节；它给的是判断口径，不提供具体命令。
5. **LWN.net 与 kernel.org 的 `Documentation/`**。它们是内核机制与新特性的第一出处，讨论某个行为为什么这样设计时以它们为准。
6. **《UNIX/Linux 系统管理手册》**（Nemeth 等）。它提供体系化的系统管理视角，适合在读完各章之后回头整理全局。
7. **各发行版的 release notes 与生命周期页**。它们是版本差异话题的依据，避免凭记忆答题。
8. **Prometheus、Alertmanager 与 OpenTelemetry 的官方文档**。设计指标与告警规则、规划链路追踪的采样时以它们为准。
9. **子系统专门文档**（`tc` 与 `netem`、`nft`、`systemd.*` 子手册页、kernel.org 的网络文档）。阶段 6 与阶段 10 用到它们的次数最多。
10. **演练环境**（本地 KVM 或虚拟机、按量云主机、Killercoda 场景）。破坏性实验只在实验机做，这些环境的作用是让第 11 章要求的恢复演练有地方可做。
