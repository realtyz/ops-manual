# 缺页与写时复制

## 1. 映射是"用到才建"的

`malloc`（C 库函数）与它底层的 `brk`/`mmap`（系统调用）成功时，内核做的是**记账**：把一段虚拟地址划到进程名下、写进映射表，并按超额分配策略记在承诺账本上。物理页**一个都没有分配**，页表里也没有对应的有效映射。

真正把承诺变成占用的，是第一次访问。硬件翻译地址时发现映射无效，触发**缺页异常（page fault）**，把控制权交给内核：

1. **判断这一页现在在哪里**——已经在内存里（匿名页首次写入、写时复制、文件页已在内核缓存），还是不在（文件页被回收过、匿名页被换出）；
2. **准备物理页**——取一块空闲页并填零，或复制一份共享页的内容，或从缓存/设备读入文件页；
3. **更新页表**——建立有效映射，此后访问走正常路径；
4. 若这次访问超出了进程的合法范围（真的越界），则投递 `SIGSEGV` 而不是修复。

这条机制决定了两个常被忽视的事实：**「申请成功」不是容量验收**；**内存不足可能在任意一次写入上爆发**，而不是在申请的那一刻。进程启动时申请成功、运行几小时后被杀，就是这条性质的表现。

## 2. 两类缺页，代价差一个量级

**minor fault（次要缺页）**：页已经在物理内存里，只是当前进程还没有建立映射。三种典型来源：

- **匿名页首次写入**：内核取一块空闲页（内容全零）分配给它；
- **写时复制**：页已存在，但要复制一份给写的那一方；
- **文件页已在内核缓存中**：只需把映射建起来，不需要访问设备。

**major fault（主要缺页）**：页不在内存里，必须从磁盘或 swap 读入，这一步要等 IO。代价强烈依赖存储介质——本地 NVMe、云盘、机械盘的差距可以达到两三个数量级。

**运维上的判据**：`minor` 高通常只是分配与映射行为活跃；**`major` 上升才是"工作集已经被挤出内存"的证据**（数据被迫从设备上取）。`/proc/vmstat` 的 `pgmajfault` 与 `/proc/<pid>/stat` 的 `maj_flt` 分别给出整机与单进程的计数；它们要配合内存压力指标一起看，因为一次冷启动或一次大范围扫描也会产生大量 major fault。

## 3. 零页：读一个从未写过的页几乎不占内存

如果进程读一个从未写过的匿名页，内核不会为它分配物理内存，而是把一块内容全零的共享页（**zero page**）映射进来。只有写入时才真正分配。

这条机制解释了三个现象：

- **缺页次数很多，但常驻集几乎不涨**——分配行为发生了，物理内存没有增加；
- **大量只读访问的进程常驻集很小**，尽管它的地址空间不小；
- **`min_flt` 与内存压力无关**：它数的是"建立映射"这件事，不是"占用内存"。

## 4. 缺页放大：一次缺页可以建立多个映射

文件页缺页时，内核通常会顺带把相邻页的映射一起建立（**缺页放大**，fault-around），预读也会把后续页提前读入缓存。结果是**文件映射的缺页次数往往远小于页数**。匿名页一般没有这个待遇，一页一次。

这条性质在核对证据时很有用：如果一段文件映射的 major fault 数明显小于它的页数，说明预读或放大在起作用；如果恰好等于页数，说明预读被关掉了（例如应用调用了 `madvise(MADV_RANDOM)`）。

## 5. 写时复制

`fork` 创建子进程时，内核**不复制内存内容**，只复制页表，并把父子双方对这些页的映射都标成只读。任何一方尝试写入，都会触发一次缺页，内核此时才复制那一页、改成可写，并把两边的映射分别指向各自的副本。这就是**写时复制（Copy-On-Write，COW）**。

由它推出四条实务结论：

- **`fork` 本身很快，内存也不会立刻翻倍。** 父子共享物理页，计量上表现为各自的均摊占用（`Pss`）只有原值的一半；
- **承诺账本会立刻增加。** `fork` 之后子进程的地址空间被记账，即使一个字节都还没写——所以"承诺"和"物理占用"在这里又一次分道扬镳；
- **真正的内存消耗发生在写入之后。** 备份、快照、`BGSAVE` 这类「`fork` + 大量写」的场景，真实内存需求由 **`fork` 之后写入多少**决定，而不是由"进程原本占多少"决定。写入还会同时吃掉 CPU（复制）与内存带宽；
- **父子双方的常驻集不能相加。** 共享页在两边各算一份，相加会大于物理占用。

COW 不只出现在 `fork`：`MAP_PRIVATE` 的文件映射在写入时也要复制私有副本；透明大页在把一组小页合并成大页（collapse）时同样涉及复制与迁移。

## 6. 缺页、换页与回收的关系

三件事容易混在一起：

- **缺页**是"建立映射"的动作，可能很便宜（minor）也可能要等 IO（major）；
- **换页（swap in/out）** 是回收与再次访问共同造成的：匿名页被换出后，再次访问就是一次 major fault，把页从 swap 读回来；
- **回收**是内核在空闲页低于水位时主动腾地方，被回收的页可能是直接丢弃（干净的文件页），也可能写入 swap（匿名页）。

所以「`si`/`so` 长期非 0」说明压力已经落到磁盘路径上，延迟必然抖动；而「major fault 上升」是同一件事在进程视角的体现。

## 常见误解

| 常见说法 | 事实 |
| --- | --- |
| 「`malloc` 成功就占用了内存」 | 成功只记账；物理页在第一次写入时才分配 |
| 「缺页是异常情况」 | 缺页是按需分配的常规路径，正常运行的进程持续产生 minor fault |
| 「缺页多说明内存紧张」 | minor 多为分配行为活跃；压力信号看 major fault 与内存压力指标 |
| 「读一个大数组会立刻占满内存」 | 读从未写过的匿名页映射零页，常驻集几乎不涨；写入才真正分配 |
| 「文件映射的缺页次数应等于页数」 | 有缺页放大与预读，通常远小于页数；恰好相等往往说明预读被关掉了 |
| 「`fork` 之后内存立刻翻倍」 | 物理页共享，但承诺账本立刻增加；写入之后物理占用才涨 |
| 「把父子的常驻集相加就是总占用」 | 共享页被重复计数，相加一定偏大；跨进程比较要用均摊或私有口径 |
| 「越界访问会导致缺页」 | 越界访问在合法映射之外的地址是 `SIGSEGV`，缺页只发生在合法但尚未建立映射的地址上 |

## 要点自测

**问：`malloc` 返回成功时，内核究竟做了什么？**
答：划出一段虚拟地址、写进映射表并按策略记账，**没有分配物理页**。物理页在第一次访问触发缺页时才给。

**问：minor fault 与 major fault 的分界与运维含义是什么？**
答：分界是"页是否已在物理内存里"。minor 只需建立映射（或复制），major 要等设备或 swap 的 IO。运维上 minor 高多为分配活跃，**major 上升才是工作集被挤出的证据**。

**问：为什么读一个从未写过的匿名页几乎不占内存？**
答：内核把内容全零的共享页（零页）映射进来；只有写入才分配真实物理页。因此"缺页次数"与"占用内存"是两件事。

**问：文件映射的缺页次数为什么常常小于页数？**
答：文件页缺页时有缺页放大与预读，一次缺页会顺带建立相邻页的映射。若次数恰好等于页数，往往说明预读被关掉了。

**问：`fork` 之后承诺账本与物理账本各发生了什么？**
答：承诺立刻增加（子进程地址空间被记账）；物理页共享、不翻倍，直到某一方真正写入才复制。

**第一反应不要做什么**：不要把"缺页多"当内存紧张；不要把 `fork` 成功当内存够用；不要用越界访问来解释缺页（越界是 `SIGSEGV`）。
