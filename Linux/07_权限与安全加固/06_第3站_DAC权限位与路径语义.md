## 0. 30 秒速览

> [!abstract] 这一篇只要记住五句话
> - **`r/w/x` 对文件和目录是两套语义**：文件看内容；目录的 `r` 是列出名字，`w` 是增删条目，`x` 是穿过。
> - **删文件看目录的 `w`，不看文件自己的 `w`**：只读文件也能被删，只要所在目录可写。
> - **路径解析需要每一级目录都有 `x`**：最后一级文件 mode 对，中间目录缺 `x`，仍然 `EACCES`。
> - **`umask` 有三个落点**：PAM 登录会话、systemd unit、进程自身；改错地方就不生效。
> - **`chmod -R 777` 不是授权，是扩大提权面**：先查 `namei`/`getfacl`，再用最小改动满足真实需求。

## 1. 文件与目录的 `rwx`

| 位 | 对文件 | 对目录 |
| --- | --- | --- |
| `r` | 读取内容 | 列出目录项名字 |
| `w` | 修改/截断内容 | 新建、删除、改名目录内的条目 |
| `x` | 作为程序执行 | 穿过目录，解析 `dir/file` 的路径 |

> [!important] 删一个只读文件需要什么？
> 需要**它所在目录的 `w` + `x`**，与文件自身的 `w` 无关。若目录带 sticky 位，还要满足「你是文件属主、目录属主或 root」。

## 2. 路径逐级 `x`：`namei -l`

```bash
namei -l /srv/app/config
                               # 验证：从 / 到目标文件逐级显示 mode、属主、属组
```

一个高频现场：服务日志显示 `Permission denied`，最后一级文件是 `644`，但中间某级目录是 `drwx------`，服务账号不在其属组，也没有其他用户 `x`。此时文件 mode 完全正常，问题在路径。

## 3. `umask` 的三个落点

新建文件基础权限是 `0666`，目录是 `0777`，再按位减掉 `umask`。

| `umask` | 文件 | 目录 | 用途 |
| --- | --- | --- | --- |
| `022` | `644` | `755` | 默认 |
| `027` | `640` | `750` | 同组可读，其他人不可 |
| `077` | `600` | `700` | 私钥、配置等私密对象 |

```bash
umask 022; : > f022; mkdir d022
umask 027; : > f027; mkdir d027
umask 077; : > f077; mkdir d077
stat -c "%a %n" f022 d022 f027 d027 f077 d077
                               # 验证：644/755、640/750、600/700
```

本机实测输出（`.labvm/evidence/07_dac_umask_real.out.txt`，以 `realtyz` 身份、2026-09-19 08:34 UTC 采集）：

```text
umask=022  file=644  dir=755  umask_now=0022
umask=027  file=640  dir=750  umask_now=0027
umask=077  file=600  dir=700  umask_now=0077
```

三个落点分别管三类进程：

- **登录会话**：PAM `pam_umask` 读 `/etc/login.defs`，登录 shell 启动脚本可覆盖。
- **systemd 服务**：unit `UMask=` 与 PID 1 的 `DefaultUMask`；`login.defs` 不影响已运行服务。
- **单个进程**：进程自己 `umask()`，或 `install -m`/`open(..., mode)` 显式指定。

## 4. 实验：目录 `r` 与 `x` 的差别

> [!example]- 实验：目录 400 与 100（本机已实测，2026-09-19 08:34 UTC）
> **怎么做**：**非 root 用户**（这里用 `realtyz`，uid=1000——root 会绕过 DAC 检查，测不出差别）在 `mktemp -d` 临时目录里建 `dr400`，放一个文件，分别 `chmod 400` 和 `chmod 100` 后测试 `ls`、`cat`、`cd`。
> **预期**：`400` 能 `ls`、不能 `cat`/`cd`；`100` 不能 `ls`，但知道文件名时能 `cat`/`cd`。
> **风险**：无；仅临时目录。
> **耗时**：约 5 分钟。
> **回滚**：退出并删除临时目录。

```bash
D=$(mktemp -d); mkdir "$D/dr400"; echo hi > "$D/dr400/secret"
chmod 400 "$D/dr400"
ls "$D/dr400"; cat "$D/dr400/secret"; cd "$D/dr400" 2>&1 || true
                               # 验证：能列出名字，但路径解析需要 x
chmod 100 "$D/dr400"
ls "$D/dr400" 2>&1 || true; cat "$D/dr400/secret"; cd "$D/dr400" && pwd
                               # 验证：不能列目录，但知道文件名可穿过
cd /; rm -rf "$D"
```

本机实测输出（`.labvm/evidence/07_dac_umask_real.out.txt`，以 `realtyz` 身份）：

```text
--- 目录 400（r--）---
ls 目录（列名字）: secret                                    rc=0
ls -l 目录（需 stat 每个条目）: ls: cannot access 'dr400/secret': Permission denied   rc=1
cat dr400/secret（路径解析需 x）: cat: dr400/secret: Permission denied                rc=1
cd dr400: cd: dr400: Permission denied                       rc=1
--- 目录 100（--x）---
ls 目录（列名字需 r）: ls: cannot open directory 'dr400': Permission denied           rc=2
cat dr400/secret（知道文件名可穿过）: hi                      rc=0
cd dr400: /tmp/07-dirperm-XXXX/dr400                         rc=0
--- 目录 000（---）---
cat dr400/secret: cat: dr400/secret: Permission denied       rc=1
```

顺带在同一轮里验证了「删文件看目录 `w`」这一条：目录可写时 `chmod 444` 的只读文件能被 `rm` 删掉；目录被 `chmod 555` 后 `rm dro/f` 报 `Permission denied`（`rc=1`）；`chmod 1777` 的 sticky 目录 `stat -c %a` 报 `1777`。

## 常见坑

| 常见做法或说法 | 后果或事实 |
| --- | --- |
| 用 `chmod -R 777` 解决 `EACCES` | 开放写和执行，把权限问题变成提权问题 |
| 只看最后一级文件 mode | 漏掉路径缺 `x` |
| 改 `login.defs` 期望 systemd 服务 umask 变化 | 服务用 unit `UMask=`，不是登录会话 |
| 以为只读文件删不掉 | 删除看目录 `w`，不看文件 `w` |
| 把目录 `x` 解释成「可执行」 | 目录的 `x` 是穿过/路径解析 |

## 决策练习

> [!question]- 场景：Web 服务以 `www-data` 运行，读 `/srv/app/config` 报 `EACCES`。文件 mode 是 `644`，你第一反应会怎么做？
> A. 把文件改成 777
> B. 先跑 `namei -l /srv/app/config` 和 `id www-data`，确认是路径缺 `x`、属主/属组不对，还是 ACL mask 削权，再最小改动
> C. 把服务改成 root 运行
>
> **答案：B。**
> A 给所有用户写权限，风险过大。
> C 提升整个进程身份，把局部问题变成全局提权。
> B 是正解：**先定位路径/主体/客体三层，再做最小授权。**

## 要点自测

> [!question]- 文件 755 与目录 755 分别意味着什么？
> - 文件 755：属主 rwx，同组与其他 rx。
> - 目录 755：属主 rwx，同组与其他 r-x，即可列可穿过但不可增删。
> - **第一反应不要是什么**：不要把目录的 `x` 理解成「执行目录」。

> [!question]- 删一个只读文件需要什么权限？
> - 所在目录的 `w` + `x`；文件自己的 `w` 无关。sticky 目录额外要求属主/目录属主/root。
> - **第一反应不要是什么**：不要以为只读文件删不掉。

> [!question]- `umask` 的三个落点分别是什么？
> - 登录会话（PAM/`login.defs`）、systemd 服务（unit `UMask=`）、进程自身（`umask()` 或显式 mode）。
> - **第一反应不要是什么**：不要在 `login.defs` 里改服务 umask。
