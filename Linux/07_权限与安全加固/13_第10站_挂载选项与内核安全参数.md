## 0. 30 秒速览

> [!abstract] 这一篇只要记住六句话
> - **`nosuid` 让该挂载点上的 SUID/SGID/file capabilities 失效**；`nodev` 禁止设备文件生效；`noexec` 禁止直接执行二进制。
> - **本机 `/tmp` 与 `/var/tmp` 根本不是一个独立挂载点**：`/tmp` 是根文件系统上的普通目录（mode `1777`），跟着 `/` 的 `rw,relatime`，**没有 `nosuid`/`nodev`/`noexec`**。只有 `/dev/shm` 是 tmpfs，带 `nosuid,nodev` 但不带 `noexec`。
> - **`noexec` 不防脚本和解释器**：本机实测在 `noexec` 的 tmpfs 上，直接执行二进制与脚本都被拒（`Permission denied`、`exit=1`），但 `bash /tmp/07-nosuid/x/s.sh` 与 `python3 /tmp/07-nosuid/x/a.py` **照常执行成功**（`exit=0`）。
> - **`fs.protected_*` 关掉普通用户对全局可写文件/管道的符号链接攻击**；本机 `fs.protected_regular=2`、`protected_fifos=1`、`protected_hardlinks=1`、`protected_symlinks=1`。
> - **安全参数常常牺牲可观测性**：本机 `kernel.dmesg_restrict=1` 让 `realtyz` 读 `dmesg` 直接 `Operation not permitted`，`kernel.perf_event_paranoid=4` 让非 root 的 `perf` 直接失败。
> - **sysctl 的值不都来自配置文件**：本机的 `perf_event_paranoid=4`、`dmesg_restrict=1` 在 `/etc/sysctl.d/` 和 `/usr/lib/sysctl.d/` 里**一份文件都找不到**，它们是发行版内核默认值。

## 1. 三个挂载选项

| 选项 | 防什么 | 典型对象 |
| --- | --- | --- |
| `nosuid` | 该挂载点上的 SUID/SGID 和 file capabilities 失效 | `/tmp`、`/var/tmp`、数据盘 |
| `nodev` | 设备文件不生效 | `/tmp`、用户可写挂载点 |
| `noexec` | 禁止直接执行该挂载点上的二进制 | 上传目录、备份盘 |

```bash
findmnt -no SOURCE,FSTYPE,OPTIONS /            # 验证：根文件系统的实际选项
findmnt -o TARGET,SOURCE,FSTYPE,OPTIONS        # 验证：全量挂载树与每个挂载点的选项
mountpoint -q /tmp && echo /tmp 是独立挂载 || echo /tmp 不是独立挂载
                                               # 验证：判断临时目录有没有自己的挂载选项
findmnt -T /dev/shm -o TARGET,SOURCE,FSTYPE,OPTIONS
                                               # 验证：按路径反查它属于哪个挂载点
```

本机实测（`text`）：

```text
TARGET                         SOURCE                            FSTYPE      OPTIONS
/                              /dev/mapper/ubuntu--vg-ubuntu--lv ext4        rw,relatime
├─/sys                         sysfs                             sysfs       rw,nosuid,nodev,noexec,relatime
│ ├─/sys/fs/cgroup             cgroup2                           cgroup2     rw,nosuid,nodev,noexec,relatime,nsdelegate,memory_recursiveprot
│ └─/sys/kernel/security       securityfs                        securityfs  rw,nosuid,nodev,noexec,relatime
├─/proc                        proc                              proc        rw,nosuid,nodev,noexec,relatime
├─/dev                         udev                              devtmpfs    rw,nosuid,relatime,size=3999920k,nr_inodes=999980,mode=755,inode64
│ ├─/dev/pts                   devpts                            devpts      rw,nosuid,noexec,relatime,gid=5,mode=620,ptmxmode=000
│ └─/dev/shm                   tmpfs                             tmpfs       rw,nosuid,nodev,inode64
├─/run                         tmpfs                             tmpfs       rw,nosuid,nodev,noexec,relatime,size=808352k,mode=755,inode64
└─/boot                        /dev/sda2                         ext4        rw,relatime
```

要点：

- **`/tmp` 和 `/var/tmp` 不在上面的挂载树里**——它们不是挂载点（`mountpoint -q /tmp` 返回非 0），而是根 ext4 上的普通目录。`stat -c %a` 显示 `1777`（sticky 位在），但**没有任何 `nosuid`/`nodev`/`noexec`**。`systemctl is-enabled tmp.mount` 返回 `not-found`，`is-active` 返回 `inactive`。
- `/dev/shm` 是 tmpfs，`rw,nosuid,nodev,inode64`：有 `nosuid`+`nodev`，**没有 `noexec`**。
- `/run` 三者齐全：`nosuid,nodev,noexec`。
- `/etc/fstab` 本机只有三行（`/`、`/boot`、`/swap.img`），**没有任何 `/tmp` 条目**。

```bash
grep -vE '^\s*#|^\s*$' /etc/fstab     # 验证：fstab 实际生效行，确认 /tmp 没有单独定义
```

`noexec` 的边界（本机实测，见第 4 节实验；挂载点是临时 tmpfs `/tmp/07-nosuid/x`，原始输出见 `.labvm/evidence/07_nosuid_noexec.out.txt` E 节）：

```bash
/tmp/07-nosuid/x/whoami            # 验证：直接执行二进制被拒（Permission denied，exit=1）
/tmp/07-nosuid/x/s.sh              # 验证：直接执行脚本同样被拒（Permission denied，exit=1）
bash /tmp/07-nosuid/x/s.sh         # 验证：经解释器执行脚本仍然成功（exit=0）
python3 /tmp/07-nosuid/x/a.py      # 验证：经解释器执行 python 仍然成功（exit=0）
```

## 2. 关键 sysctl

| 参数 | 本机实测值 | 加固方向 | 为什么 |
| --- | --- | --- | --- |
| `fs.protected_regular` | `2` | 建议 2 | 防止普通用户对全局可写普通文件的 O_CREAT 攻击 |
| `fs.protected_fifos` | `1` | 建议 2 | 防止普通用户打开全局可写 FIFO 造成提权；本机发行版给的是 `1` |
| `fs.protected_hardlinks` | `1` | 建议 1 | 限制硬链接攻击 |
| `fs.protected_symlinks` | `1` | 建议 1 | 限制符号链接攻击 |
| `kernel.yama.ptrace_scope` | `1` | 建议 1 | 限制普通用户 ptrace 其他进程 |
| `kernel.unprivileged_bpf_disabled` | `2` | 按需 1 | 禁止非特权 BPF；可能影响可观测工具 |
| `kernel.kptr_restrict` | `1` | 按需 1/2 | 隐藏内核指针，牺牲部分调试可观测性 |
| `kernel.dmesg_restrict` | `1` | 按需 1 | 禁止普通用户读 dmesg，减少信息泄露 |
| `kernel.perf_event_paranoid` | `4` | 按需提高 | 限制 perf 观测能力，权衡安全与排障 |
| `net.ipv4.ip_unprivileged_port_start` | `1024` | 保持 1024 | 不要为单服务改成 0 |
| `kernel.randomize_va_space` | `2` | 保持 2 | 完整 ASLR |
| `fs.suid_dumpable` | `2` | 按需 | SUID 进程 core dump 策略 |
| `net.ipv4.conf.all.rp_filter` | `2` | 按需 | 松散反向路径过滤 |

```bash
sysctl fs.protected_regular fs.protected_fifos fs.protected_hardlinks fs.protected_symlinks
sysctl kernel.yama.ptrace_scope kernel.unprivileged_bpf_disabled kernel.kptr_restrict kernel.dmesg_restrict kernel.perf_event_paranoid
sysctl net.ipv4.ip_unprivileged_port_start net.ipv4.conf.all.rp_filter
                               # 验证：当前内核安全参数；本机取值如上表
```

参数不是抽象开关，本机实测了它们的**可观测后果**：

```bash
runuser -u realtyz -- dmesg        # 验证：dmesg_restrict=1 时返回 read kernel buffer failed: Operation not permitted
runuser -u realtyz -- perf stat -e cycles true
                                   # 验证：perf_event_paranoid=4 时直接报 "Access to performance monitoring ... is limited"
head -3 /proc/kallsyms             # 验证：kptr_restrict=1 时普通用户看到地址被清零
```

实测输出：

```text
dmesg: read kernel buffer failed: Operation not permitted      (realtyz, exit=1)
Error: Access to performance monitoring and observability operations is limited.
perf_event_paranoid setting is 4:                              (realtyz, exit=255)
0000000000000000 A fixed_percpu_data                          (realtyz 看 /proc/kallsyms)
0000000000001000 A cpu_debug_store                            (root 看同一行，地址可见)
```

## 3. sysctl 的加载顺序

```text
/etc/sysctl.d/*.conf
/run/sysctl.d/*.conf
/usr/lib/sysctl.d/*.conf
```

规则是「**所有文件按文件名（字典序）排序，名字靠后的覆盖靠前的；同名文件则 `/etc` 覆盖 `/run`、`/usr/local/lib`、`/usr/lib`**」（`man 5 sysctl.d`）。注意 `/etc/sysctl.conf` 是通过 **`/etc/sysctl.d/99-sysctl.conf` 软链**参与合并的（本机实测该软链存在），名字排序很靠后，所以它常常能覆盖前面的 `.d` 文件——「最后应用」与「优先级最高」在这里是一致的。修改后用 `sysctl --system` 应用，或 `sysctl -w` 临时改。

```bash
sysctl --system                 # 验证：按目录顺序应用 sysctl
sysctl -w kernel.yama.ptrace_scope=1
                               # 验证：临时修改；持久化要写 /etc/sysctl.d/*.conf
```

> [!important] 值在文件里找不到，不代表配置错了
> 本机的 `kernel.perf_event_paranoid=4` 与 `kernel.dmesg_restrict=1` **在 `/etc/sysctl.d/` 和 `/usr/lib/sysctl.d/` 里没有任何一份文件设置**，它们来自发行版内核默认值。反过来，`kernel.kptr_restrict=1`、`kernel.yama.ptrace_scope=1`、`fs.protected_*` 都能在文件里找到出处。**排查参数来源要「查当前值 + 遍历文件 + 承认可能来自内核默认」三步走**，不要只看 `sysctl.conf`。

本机两份目录的实际内容——每个文件只列**有效行**（空行与注释已省略）：

- `/etc/sysctl.d/10-bufferbloat.conf`：`-net.core.default_qdisc = fq_codel`
- `/etc/sysctl.d/10-console-messages.conf`：`kernel.printk = 4 4 1 7`
- `/etc/sysctl.d/10-ipv6-privacy.conf`：`net.ipv6.conf.all.use_tempaddr = 2`、`net.ipv6.conf.default.use_tempaddr = 2`
- `/etc/sysctl.d/10-kernel-hardening.conf`：`kernel.kptr_restrict = 1`
- `/etc/sysctl.d/10-magic-sysrq.conf`：`kernel.sysrq = 176`
- `/etc/sysctl.d/10-map-count.conf`：`vm.max_map_count = 1048576`
- `/etc/sysctl.d/10-network-security.conf`：`net.ipv4.conf.default.rp_filter = 2`、`net.ipv4.conf.all.rp_filter = 2`
- `/etc/sysctl.d/10-ptrace.conf`：`kernel.yama.ptrace_scope = 1`
- `/etc/sysctl.d/10-zeropage.conf`：`vm.mmap_min_addr = 65536`
- `/etc/sysctl.d/99-sysctl.conf`：**是指向 `../sysctl.conf` 的软链接，本机无有效行**
- `/usr/lib/sysctl.d/10-apparmor.conf`：`kernel.apparmor_restrict_unprivileged_userns = 1`
- `/usr/lib/sysctl.d/50-pid-max.conf`：`kernel.pid_max = 4194304`
- `/usr/lib/sysctl.d/99-protect-links.conf`：`fs.protected_fifos = 1`、`fs.protected_hardlinks = 1`、`fs.protected_regular = 2`、`fs.protected_symlinks = 1`

注意 `10-bufferbloat.conf` 里那一行开头的 `-`：它表示「设置失败也继续」，不是注释。

> [!warning] 安全与可观测性要平衡
> `kptr_restrict=2`、`perf_event_paranoid=3` 能减少信息泄露，但会限制 perf、bcc、部分监控工具。本机 `perf_event_paranoid` 已经是 **4**，非 root 的 `perf` 直接报错退出（`exit=255`），root 不受影响。**生产基线要在「安全」和「出事能查」之间明确取舍，并把取舍写进变更记录。**

## 4. 实验

> [!example]- 实验 A：临时挂 `nosuid`/`noexec` 的 tmpfs，验证三个选项到底拦什么（本机已实测）
> **怎么做**：在 `/tmp/07-nosuid/` 下编译一个打印 `ruid/euid` 的 ELF 和一个申请 raw socket 的 ELF；先挂 `nosuid,nodev` 的 tmpfs，再挂 `noexec,nosuid,nodev` 的 tmpfs，分别以 `realtyz` 执行。
> **预期**：`nosuid` 下 SUID 二进制 `euid` 不变、file capabilities 失效；`noexec` 下直接执行被拒，但 `bash`/`python3` 仍能跑脚本。
> **风险**：低。只挂临时 tmpfs，必须在 `rm -rf` 前 `umount`。
> **耗时**：约 15 分钟。
> **回滚**：`umount /tmp/07-nosuid/m`、`umount /tmp/07-nosuid/x`，再 `rm -rf /tmp/07-nosuid`。
>
> ```bash
> mkdir -p /tmp/07-nosuid/m /tmp/07-nosuid/x && cd /tmp/07-nosuid
> cat > whoami.c <<'EOF'
> #include <stdio.h>
> #include <unistd.h>
> int main(void){ printf("ruid=%d euid=%d\n", getuid(), geteuid()); return 0; }
> EOF
> gcc -o whoami whoami.c
> chown root:root whoami && chmod 4755 whoami
> runuser -u realtyz -- /tmp/07-nosuid/whoami
> mount -t tmpfs -o nosuid,nodev tmpfs /tmp/07-nosuid/m
> cp whoami /tmp/07-nosuid/m/whoami && chown root:root /tmp/07-nosuid/m/whoami && chmod 4755 /tmp/07-nosuid/m/whoami
> runuser -u realtyz -- /tmp/07-nosuid/m/whoami
> umount /tmp/07-nosuid/m
> ```
>
> 实测输出：
>
> ```text
> ruid=1000 euid=0          （普通目录：SUID 生效）
> ruid=1000 euid=1000       （nosuid 挂载点：SUID 被忽略）
> ```
>
> file capabilities 同样被 `nosuid` 挡住：同一个带 `cap_net_raw=ep` 的二进制，放在普通目录里以 `realtyz` 运行输出 `raw ok`，放到 `nosuid` 挂载点上输出 `raw failed errno=1`。
>
> `noexec` 的边界（`noexec,nosuid,nodev` 的 tmpfs，`/tmp/07-nosuid/x`）：
>
> ```text
> runuser -u realtyz -- /tmp/07-nosuid/x/whoami   -> Permission denied（exit=1）
> runuser -u realtyz -- /tmp/07-nosuid/x/s.sh     -> Permission denied（exit=1）
> runuser -u realtyz -- bash /tmp/07-nosuid/x/s.sh -> script-ran-as-realtyz（exit=0）
> runuser -u realtyz -- python3 /tmp/07-nosuid/x/a.py -> python-ran（exit=0）
> ```
>
> **`noexec` 只拦「直接执行」，拦不住解释器**——这就是为什么上传目录除了 `noexec` 还要收紧属主和写权限。

> [!example]- 实验 B：在独立 netns 里改 net.* sysctl，宿主机不受影响（本机已实测）
> **怎么做**：`ip netns add` 建一个网络命名空间，在里面把 `net.ipv4.ip_unprivileged_port_start` 改成 0，对比宿主机的值，最后删掉命名空间。
> **预期**：命名空间内为 0，宿主机仍是 1024。
> **风险**：极低；`net.*` 在 netns 内改不影响全局。
> **耗时**：约 3 分钟。
> **回滚**：`ip netns del <name>`。
>
> ```bash
> ip netns add lab07ns
> ip netns exec lab07ns sysctl -w net.ipv4.ip_unprivileged_port_start=0
> ip netns exec lab07ns sysctl -n net.ipv4.ip_unprivileged_port_start
> sysctl -n net.ipv4.ip_unprivileged_port_start
> ip netns del lab07ns
> ```
>
> 实测输出：
>
> ```text
> net.ipv4.ip_unprivileged_port_start = 0        （netns 内）
> 1024                                           （宿主机，未被影响）
> ```
>
> 这是**并行做实验时最有用的一条纪律**：需要改 `net.*` 才能验证的东西，优先放进自己的 netns，不要去动宿主机。

## 常见坑

| 常见做法或说法 | 后果或事实 |
| --- | --- |
| 以为 `noexec` 防住脚本执行 | 解释器仍可执行脚本，只防直接执行二进制；本机实测 `bash`/`python3` 照跑 |
| 假设 `/tmp` 一定是带 `nosuid`/`nodev` 的 tmpfs | 本机 `/tmp` 根本不是独立挂载点，跟着 `/` 的 `rw,relatime`，三个选项一个都没有 |
| 只查 `mount \| grep /tmp` 就下结论 | 挂载树里没有 `/tmp` 不代表安全，要用 `mountpoint -q` 确认它是不是挂载点 |
| 把 `ip_unprivileged_port_start` 改成 0 | 任何用户都能绑低端口；要验证请在独立 netns 里做 |
| 临时 `sysctl -w` 就以为持久化 | 重启后失效，要写 `/etc/sysctl.d/` |
| 把安全参数一律拉到最严 | 可观测工具失效；本机 `perf_event_paranoid=4` 已让非 root `perf` 直接不可用 |
| 只看 `/etc/sysctl.conf` 就断言「这个参数没人设置」 | 本机 `perf_event_paranoid=4`、`dmesg_restrict=1` 确实不在任何 sysctl.d 文件里，是内核默认值 |
| 把 `10-bufferbloat.conf` 里行首的 `-` 当注释 | 那是「设置失败也继续」的前缀 |

## 决策练习

> [!question]- 场景：安全扫描要求所有数据盘都挂 `noexec`。你发现某个应用通过 `/data/tools` 运行二进制，业务会受影响。你怎么办？
> A. 直接挂 `noexec`，让业务故障再说
> B. 先盘点哪些路径确实需要执行，把「可写上传目录」与「只读工具目录」分开；前者 `noexec`，后者收紧属主和写权限，再做兼容性测试
> C. 忽略扫描，不加固
>
> **答案：B。**
> A 是只满足扫描、不负责业务。
> C 是放任风险。
> B 是正解：**挂载选项按「谁可写、是否需要执行」分层，不能一刀切。**

> [!question]- 场景：同事说「`/tmp` 已经有 sticky 位了，等于安全」。你在这台机器上会先跑哪条命令反驳或确认？
> A. `ls -ld /tmp`
> B. `mountpoint -q /tmp && findmnt -T /tmp -o TARGET,SOURCE,FSTYPE,OPTIONS || echo "/tmp 不是独立挂载点"`
> C. `chmod 1777 /tmp` 再确认一次
>
> **答案：B。**
> A 只看到 mode `1777`，看不出挂载选项——sticky 位和挂载选项是两件事。
> C 是对的操作但答非所问，而且它不会告诉你挂载选项。
> B 是正解：**先判断 `/tmp` 有没有自己的挂载选项，再谈它拦得住什么。**本机实测 `/tmp` 不是独立挂载点，因此它连 `nosuid` 都没有。

## 要点自测

> [!question]- `nosuid`/`nodev`/`noexec` 分别防什么？
> - `nosuid`：SUID/SGID/file capabilities 失效（本机实测 `euid` 不再变化、file caps 报 `errno=1`）；`nodev`：设备文件不生效；`noexec`：禁止直接执行二进制。
> - **第一反应不要是什么**：不要把 `noexec` 当成防住所有脚本执行，也不要假设 `/tmp` 一定挂了这些选项。

> [!question]- `fs.protected_*` 是防什么的？
> - 防普通用户对全局可写文件、FIFO、硬链接/符号链接的利用，属于内核级防护。本机值为 `protected_regular=2`、`protected_fifos=1`、`protected_hardlinks=1`、`protected_symlinks=1`。
> - **第一反应不要是什么**：不要以为文件权限正确就够了，内核还有这些保护。

> [!question]- 为什么安全 sysctl 不是越严越好？
> - `kptr_restrict`、`dmesg_restrict`、`perf_event_paranoid` 会降低可观测性，影响 perf/bcc/监控。本机实测非 root 读 `dmesg` 直接 `Operation not permitted`、跑 `perf` 直接退出。
> - 要按场景取舍并留档。
> - **第一反应不要是什么**：不要把所有安全参数设到最严而不验证排障工具。

> [!question]- 一个 sysctl 的当前值在任何配置文件里都找不到，可能是什么原因？
> - 它可能来自内核/发行版的编译默认值，本机 `kernel.perf_event_paranoid=4`、`kernel.dmesg_restrict=1` 就是这种情况。
> - 判断来源要「查当前值 → 遍历 `/etc/sysctl.d/` 与 `/usr/lib/sysctl.d/` → 承认可能来自内核默认」。
> - **第一反应不要是什么**：不要只 grep `/etc/sysctl.conf` 就断言「没人设置过」。
