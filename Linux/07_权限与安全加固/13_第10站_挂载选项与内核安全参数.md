## 0. 30 秒速览

> [!abstract] 这一篇只要记住五句话
> - **`nosuid` 让该挂载点上的 SUID/SGID/file capabilities 失效**；`nodev` 禁止设备文件生效；`noexec` 禁止直接执行二进制。
> - **`noexec` 不防脚本和解释器**：`bash /mnt/script.sh`、`python /mnt/app.py` 仍可执行。
> - **`/tmp`、`/var/tmp`、`/dev/shm` 常需要单独看挂载选项**，因为它们可被所有用户写。
> - **`fs.protected_*` 关掉普通用户对全局可写文件/管道的符号链接攻击**；`yama.ptrace_scope` 限制 ptrace。
> - **安全参数常常牺牲可观测性**：`kptr_restrict`/`dmesg_restrict`/`perf_event_paranoid` 要按场景取舍，不是越高越好。

## 1. 三个挂载选项

| 选项 | 防什么 | 典型对象 |
| --- | --- | --- |
| `nosuid` | 该挂载点上的 SUID/SGID 和 file capabilities 失效 | `/tmp`、`/var/tmp`、数据盘 |
| `nodev` | 设备文件不生效 | `/tmp`、用户可写挂载点 |
| `noexec` | 禁止直接执行该挂载点上的二进制 | 上传目录、备份盘 |

```bash
findmnt -o TARGET,SOURCE,FSTYPE,OPTIONS /tmp /var/tmp /dev/shm
                               # 验证：关键临时目录实际挂载选项
mount | grep -E '(/tmp|/var/tmp|/dev/shm)'
                               # 验证：内核当前生效的挂载选项
```

`noexec` 的边界：

```bash
/mnt/noexec/runme             # 直接执行会被拒
bash /mnt/noexec/runme.sh      # 解释器仍可执行脚本
python3 /mnt/noexec/app.py     # 解释器仍可执行脚本
```

## 2. 关键 sysctl

| 参数 | 加固方向 | 为什么 |
| --- | --- | --- |
| `fs.protected_regular` | 建议 2 | 防止普通用户对全局可写普通文件的 O_CREAT 攻击 |
| `fs.protected_fifos` | 建议 2 | 防止普通用户打开全局可写 FIFO 造成提权 |
| `fs.protected_hardlinks/symlinks` | 建议 1 | 限制硬链接/符号链接攻击 |
| `kernel.yama.ptrace_scope` | 建议 1 | 限制普通用户 ptrace 其他进程 |
| `kernel.unprivileged_bpf_disabled` | 按需 1 | 禁止非特权 BPF；可能影响可观测工具 |
| `kernel.kptr_restrict` | 按需 1/2 | 隐藏内核指针，牺牲部分调试可观测性 |
| `kernel.dmesg_restrict` | 按需 1 | 禁止普通用户读 dmesg，减少信息泄露 |
| `kernel.perf_event_paranoid` | 按需提高 | 限制 perf 观测能力，权衡安全与排障 |
| `net.ipv4.ip_unprivileged_port_start` | 保持 1024 | 不要为单服务改成 0 |

```bash
sysctl fs.protected_regular fs.protected_fifos kernel.yama.ptrace_scope
sysctl kernel.unprivileged_bpf_disabled kernel.kptr_restrict kernel.dmesg_restrict
sysctl net.ipv4.ip_unprivileged_port_start
                               # 验证：当前内核安全参数
```

## 3. sysctl 的加载顺序

```text
/etc/sysctl.d/*.conf
/run/sysctl.d/*.conf
/usr/lib/sysctl.d/*.conf
```

同名参数后者覆盖前者；`/etc/sysctl.d` 优先级最高。修改后用 `sysctl --system` 应用，或 `sysctl -w` 临时改。

```bash
sysctl --system                 # 验证：按目录顺序应用 sysctl
sysctl -w kernel.yama.ptrace_scope=1
                               # 验证：临时修改；持久化要写 /etc/sysctl.d/*.conf
```

> [!warning] 安全与可观测性要平衡
> `kptr_restrict=2`、`perf_event_paranoid=3` 能减少信息泄露，但会限制 perf、bcc、部分监控工具。**生产基线要在「安全」和「出事能查」之间明确取舍，并把取舍写进变更记录。**

## 常见坑

| 常见做法或说法 | 后果或事实 |
| --- | --- |
| 以为 `noexec` 防住脚本执行 | 解释器仍可执行脚本，只防直接执行二进制 |
| 给 `/tmp` 漏掉 `nosuid`/`nodev` | 留下临时目录提权面 |
| 把 `ip_unprivileged_port_start` 改成 0 | 任何用户都能绑低端口 |
| 临时 `sysctl -w` 就以为持久化 | 重启后失效，要写 `/etc/sysctl.d/` |
| 把安全参数一律拉到最严 | 可观测工具失效，出事后更难定位 |

## 决策练习

> [!question]- 场景：安全扫描要求所有数据盘都挂 `noexec`。你发现某个应用通过 `/data/tools` 运行二进制，业务会受影响。你怎么办？
> A. 直接挂 `noexec`，让业务故障再说
> B. 先盘点哪些路径确实需要执行，把「可写上传目录」与「只读工具目录」分开；前者 `noexec`，后者收紧属主和写权限，再做兼容性测试
> C. 忽略扫描，不加固
>
> **答案：B。**
> A 是只满足扫描、不负责业务。
> C 是放任风险。
> B 是正解：**挂载选项按「谁可写、是否需要执行」分层，不能一刀切。**

## 要点自测

> [!question]- `nosuid`/`nodev`/`noexec` 分别防什么？
> - `nosuid`：SUID/SGID/file capabilities 失效；`nodev`：设备文件不生效；`noexec`：禁止直接执行二进制。
> - **第一反应不要是什么**：不要把 `noexec` 当成防住所有脚本执行。

> [!question]- `fs.protected_*` 是防什么的？
> - 防普通用户对全局可写文件、FIFO、硬链接/符号链接的利用，属于内核级防护。
> - **第一反应不要是什么**：不要以为文件权限正确就够了，内核还有这些保护。

> [!question]- 为什么安全 sysctl 不是越严越好？
> - `kptr_restrict`、`dmesg_restrict`、`perf_event_paranoid` 会降低可观测性，影响 perf/bcc/监控。
> - 要按场景取舍并留档。
> - **第一反应不要是什么**：不要把所有安全参数设到最严而不验证排障工具。
