## 0. 30 秒速览

> [!abstract] 这一篇只要记住五句话
> - **ACL 是 mode 之外的精细授权**：`setfacl -m u:realtyz:rwx` 可以只给一个用户写权限，`ls -l` 只显示一个 `+`（实测：加之前 `realtyz` 和 `lab07u` 都读不了，加之后 `realtyz` 能写、`lab07u` 仍被拒）。
> - **`mask` 是所有 named 条目和 owning group 的有效权限上限**：本机把 `mask` 削成 `r` 后，`getfacl` 标出 `user:realtyz:rwx #effective:r--`，写操作立刻失败。
> - **`chmod` 会重算 ACL mask**：改完 ACL 又 `chmod` 后，务必用 `getfacl` 复查有效权限。
> - **默认 ACL 让目录成为模板**：`default:` 条目会被目录内新建对象继承，并按新建对象的权限收口（实测 `touch` 出的新文件 mask 落到 `rw-`）。
> - **`chattr +i` 连 root 也不能直接改，除非先去掉属性**：实测 `+i` 期间 root 的 `rm`/`mv`/`chmod`/追加全部 `Operation not permitted`；它会让 `logrotate` 轮转和包升级失败，不能批量加在 `/var/log` 和 `/etc` 上。

## 1. ACL：第四种授权

ACL 存在 inode 的扩展属性 `system.posix_acl_access` 里，操作入口是 `setfacl`/`getfacl`。

```bash
mkdir -p /tmp/07-acl && cd /tmp/07-acl
echo "line-one" > report.txt && chmod 640 report.txt && chown root:root report.txt
ls -l report.txt                       # 验证：基线 -rw-r-----，other 无权限
runuser -u realtyz -- cat report.txt   # 验证：非属主非属组被拒
setfacl -m u:realtyz:rwx report.txt
ls -l report.txt                       # 验证：结尾的 + 表示带 ACL；属组位显示的是 mask
getfacl report.txt                     # 验证：named user 与 mask
```

实测（本机用两个真实非 root 账号：`realtyz` uid=1000、临时账号 `lab07u` uid=1001）：

```text
-rw-r----- 1 root root 9 report.txt
user::rw-
group::r--
other::---
cat: /tmp/07-acl/report.txt: Permission denied      (realtyz, exit=1)
cat: /tmp/07-acl/report.txt: Permission denied      (lab07u, exit=1)

setfacl -m u:realtyz:rwx 之后：
-rw-rwx---+ 1 root root 9 report.txt
# file: report.txt
# owner: root
# group: root
user::rw-
user:realtyz:rwx
group::r--
mask::rwx
other::---
```

加完 ACL 后 `realtyz` 能追加（`rc=0`），`lab07u` 仍被拒（`exit=1`）。**这里能读出两个容易搞错的点**：`ls -l` 的属组三位显示的是 `mask`（`rwx`）而不是 `group::` 的 `r--`；`other::---` 保持不变，ACL 只对指定的 named 条目开口子。

## 2. `mask` 与 `#effective`

只要存在 named user/group 或 default 条目，内核就用 `mask` 限制 named 条目和 owning group 的有效权限。把 `mask` 削到只剩读，权限立刻被削掉：

```bash
setfacl -m m::r report.txt
getfacl report.txt                     # 验证：named 条目标 #effective:r--
runuser -u realtyz -- cat report.txt   # 验证：读仍可以
runuser -u realtyz -- bash -c 'echo x >> report.txt'
                                       # 验证：写被 mask 削掉，失败
```

实测：

```text
user::rw-
user:realtyz:rwx	#effective:r--
group::r--
mask::r--
other::---

-rw-r-----+ 1 root root 28 report.txt
realtyz 追加 -> exit=1
realtyz 读取 -> exit=0
```

注意 `ls -l` 随之变成 `-rw-r-----+`：**named 条目写着 `rwx`，但实际只有 `r--`**。把 mask 恢复成 `rwx`（`setfacl -m m::rwx report.txt`）后追加立刻恢复 `rc=0`。这就是「授权明明加了却不生效」最常见的成因。

> [!warning] `chmod` 会重算 mask
> `chmod g-w` 之类操作会改变 ACL mask，可能连带削掉 named 条目的有效权限。**改完 ACL 又改 `chmod` 后必须 `getfacl` 复查。**

## 3. 默认 ACL

目录设置 `default:` 条目后，新建子对象自动继承。

```bash
mkdir -p shared && chmod 770 shared
setfacl -m d:u:realtyz:rwx shared
getfacl shared                         # 验证：access 与 default 两组条目
touch shared/newfile && getfacl shared/newfile
                                       # 验证：新文件继承 default 条目
```

实测：

`getfacl shared` 的实测输出：

```text
user::rwx
group::rwx
other::---
default:user::rwx
default:user:realtyz:rwx
default:group::rwx
default:mask::rwx
default:other::---

```

`ls -l shared/newfile` 与 `getfacl shared/newfile`：

```text
-rw-rw----+ 1 root root 0 shared/newfile
user::rw-
user:realtyz:rwx	#effective:rw-
group::rwx	#effective:rw-
mask::rw-
other::---
```

**继承是「拷贝 default 条目、再按新建权限收口」**：`touch` 建的普通文件本身不带执行位，所以 mask 落到 `rw-`，named 条目的 `rwx` 被标成 `#effective:rw-`。

备份与复制时也要带上 ACL：

```bash
cp -a src dst                 # 验证：cp -a 保留 ACL 和常用属性
tar --acls --xattrs -cf archive.tar src
                               # 验证：tar 保留 ACL/xattr
rsync -A -X -a src/ dst/      # 验证：rsync 保留 ACL/xattr
```

## 4. `chattr`：不可变与只追加

| 属性 | 作用 | 典型风险 |
| --- | --- | --- |
| `+i` | 不可修改、删除、改名，连 root 也不能直接改 | `logrotate` 轮转失败、包升级失败 |
| `+a` | 只能追加，适合日志 | 需要提前设计轮转流程 |
| `+e` | ext4 的 extent 标志，正常值 | 不是异常，不要误判 |

```bash
cd /tmp/07-chattr && echo "important-data" > locked.txt
lsattr locked.txt               # 验证：起始只有 e（ext4 extent 标志）
chattr +i locked.txt            # 验证：root 可以设置
lsattr locked.txt               # 验证：多出 i
echo more >> locked.txt         # 验证：连 root 也被拒（Operation not permitted）
rm -f locked.txt                # 验证：删除同样被拒
chattr -i locked.txt            # 验证：必须先去掉属性
```

实测（全部以 root 执行）：

```text
--------------e------- locked.txt
chattr +i ok
----i---------e------- locked.txt
-rw-r--r-- 1 root root 15 locked.txt
echo more >> locked.txt   -> bash: locked.txt: Operation not permitted   (exit=1)
rm -f locked.txt          -> rm: cannot remove 'locked.txt': Operation not permitted  (exit=1)
mv locked.txt moved.txt   -> mv: cannot move ...: Operation not permitted（exit=1）
chmod 600 locked.txt      -> chmod: changing permissions ...: Operation not permitted（exit=1）
chattr -i ok
echo more >> locked.txt   -> 成功
```

`+a`（只可追加）的实测边界：

```text
-----a--------e------- app.txt
echo line2 >> app.txt   -> 成功
rm -f app.txt           -> Operation not permitted（exit=1）
: > app.txt             -> Operation not permitted（exit=1，不能截断）
```

目录加 `+i` 后，连在目录里创建文件都被拒（`touch dirtest/g` → `Operation not permitted`，exit=1）。

> [!important] `chattr +i` 不是「万能防篡改」
> 它防的是常规修改，但会让升级和轮转也改不了；而且真正拿 root 的攻击者同样可以 `chattr -i`。它的价值是**增加修改门槛和留下操作痕迹**，不能替代审计和完整性校验。

## 5. 扩展属性：`getfattr`/`setfattr`

ACL 和 `chattr` 属性都是扩展属性（xattr）的一种视图，想直接看原文用 `getfattr`/`setfattr`（`attr` 包）：

```bash
setfattr -n user.x -v y report.txt     # 验证：设一个自定义扩展属性
getfattr -d report.txt                 # 验证：列出全部扩展属性
getfattr -n user.x report.txt          # 验证：只取指定属性
```

实测：

`getfattr -d report.txt`：

```text
# file: report.txt
user.x="y"
```

file capability 在 xattr 层的原文（本机自建二进制 `setcap cap_net_raw+ep` 之后）：

`getfattr -d -m - rawtest`：

```text
# file: rawtest
security.capability=0sAQAAAgAgAAAAAAAAAAAAAAAAAAA=
```

> [!important] `ls -l` 的 `+` 只认 ACL
> 实测：一个只设了 `user.note=lab07`、没有 ACL 的文件，`ls -l` 显示的是普通的 `-rw-r--r--`，**没有 `+`**。所以 `+` 只能用来判断「有没有 ACL」，判断「有没有扩展属性」要用 `getfattr -d` 和 `lsattr`。

> [!example]- 实验：一次 ACL 授权的完整闭环（含 mask 削权、默认 ACL 继承、xattr 独立性；本机已实测）
> **怎么做**：在 `/tmp/07-acl/` 用 root 建 `report.txt`（`640 root:root`）→ 分别用 `realtyz`（uid=1000）与临时账号 `lab07u`（uid=1001）读，都该被拒 → `setfacl -m u:realtyz:rwx` 后再读 → `setfacl -m m::r` 把 mask 削到 `r`，观察 `getfacl` 里的 `#effective:r--` 与写失败 → 恢复 mask → 建目录设**默认 ACL**，看新建文件是否继承 → 用 `setfattr`/`getfattr` 验证「纯 xattr、无 ACL 的文件 `ls -l` 不显示 `+`」。
> **预期**：`setfacl` 后 `ls -l` 结尾出现 `+` 且属组位显示的是 **mask**；`mask::r--` 时 named user 的 `rwx` 被削到 `r--`（写失败、读成功）；默认 ACL 让新建文件自动带上 named user 条目；`user.note` 这类纯 xattr 不产生 `+`。
> **风险**：低。只在 `/tmp` 下自建目录与临时账号上操作；`chmod` 会重算 mask，改完必须 `getfacl` 复查。
> **耗时**：约 10 分钟。
> **回滚**：`userdel lab07u`、`rm -rf /tmp/07-acl`（本机实测清理后 `ls -d /tmp/07-*` 无匹配）。
>
> ```bash
> mkdir -p /tmp/07-acl && cd /tmp/07-acl
> useradd -m lab07u
> echo line-one > report.txt && chmod 640 report.txt && chown root:root report.txt
> runuser -u realtyz -- cat report.txt; runuser -u lab07u -- cat report.txt
> setfacl -m u:realtyz:rwx report.txt && getfacl report.txt
> setfacl -m m::r report.txt && getfacl report.txt
> runuser -u realtyz -- sh -c 'echo nope >> report.txt'   # 验证：mask 削权后写被拒
> setfacl -m m::rwx report.txt                             # 验证：恢复 mask
> mkdir shared && setfacl -d -m u:realtyz:rwx shared && touch shared/newfile && getfacl shared/newfile
> setfattr -n user.note -v lab07 xonly.txt && getfattr -d xonly.txt && ls -l xonly.txt
> cd /; userdel -r lab07u; rm -rf /tmp/07-acl
> ```
>
> 实测输出摘要（来源 `.labvm/evidence/07_acl.out.txt`，**2026-09-19 08:04 UTC 采集**；下面的片段**按步骤重排过**，不是一次连续运行的原始顺序）：
>
> ```text
> （基线 640 root:root）realtyz exit=1 / lab07u exit=1        → 两个非 root 都被拒
> （setfacl -m u:realtyz:rwx）-rw-rwx---+ 1 root root
> user::rw-  user:realtyz:rwx  group::r--  mask::rwx  other::---
> （setfacl -m m::r）user:realtyz:rwx	#effective:r--     mask::r--
> bash: line 1: /tmp/07-acl/report.txt: Permission denied     realtyz exit=1
> （默认 ACL 继承）shared/newfile 带 user:realtyz:rwx	#effective:rw-
> （纯 xattr）getfattr 显示 user.note="lab07"，而 ls -l 是 -rw-r--r--，无 +
> ```

## 常见坑

| 常见做法或说法 | 后果或事实 |
| --- | --- |
| 看到 `ls -l` 的 `+` 就当 ACL 已经读全 | 必须 `getfacl` 看 named 条目和 mask |
| 看到 `ls -l` 的属组位是 `rwx` 就以为组真的有写权限 | 有 ACL 时属组位显示的是 `mask`，不是 `group::` 的真实权限 |
| 改完 ACL 又 `chmod` 不复查 | mask 被重算，权限可能被悄悄削掉 |
| 只 `cp -r` 备份带 ACL 的文件 | ACL/xattr 丢失 |
| 给 `/var/log/*` 批量 `chattr +i` | logrotate 轮转失败，磁盘被日志写满 |
| 以为 `chattr +i` 后 root 也无法改，绝对安全 | root 可以先 `chattr -i`；它是门槛不是终点（不过 `+i` 生效期间**确实连 root 也被拒**，本机实测 `rm`/`mv`/`chmod`/追加全部 `Operation not permitted`） |
| 用 `ls -l` 的 `+` 判断有没有扩展属性 | `+` 只反映 ACL；纯 `user.*` xattr 的文件没有 `+`，要用 `getfattr -d` |

## 决策练习

> [!question]- 场景：你给用户 A 加了 ACL 读权限，测试时 A 仍读不到。`ls -l` 有 `+`，`getfacl` 显示 `user:a:r--  #effective:---`。同事说再重加一次 ACL。你怎么办？
> A. 再 `setfacl -m u:a:r` 一次
> B. 先看 mask 为什么是 0 或没有对应权限，用 `setfacl -m m::r` 恢复 mask，再复查 `#effective`
> C. 把文件 chmod 777
>
> **答案：B。**
> A 不会改变 mask，重加后仍可能 `#effective:---`。
> C 给所有人写和执行，风险过大。
> B 是正解：**ACL 不生效时先看 `mask`，不是重加授权。**

## 要点自测

> [!question]- `ls -l` 里的 `+` 是什么？为什么不能只看它？
> - `+` 表示 inode 带 ACL；要看 named user/group、mask、default 和 `#effective` 必须 `getfacl`。
> - **第一反应不要是什么**：不要看到 `+` 就以为授权一定有效。

> [!question]- ACL `mask` 的作用是什么？
> - 它是 named user/group 与 owning group 的有效权限上限；`#effective` 表示实际有效结果。
> - 本机实测：`setfacl -m m::r` 后 `getfacl` 显示 `user:realtyz:rwx #effective:r--`，`ls -l` 也从 `-rw-rwx---+` 变成 `-rw-r-----+`——**`ls -l` 的属组三位显示的就是 mask**。
> - **第一反应不要是什么**：不要把 `mask` 当成一个普通 group 的权限，也不要在授权不生效时反复重加 ACL（重加不改 mask）。

> [!question]- `chattr +i` 的两个真实副作用是什么？
> - `logrotate` 轮转失败、包管理器升级写不进去。
> - 所以只适合「明确不变且变更流程会先解锁」的文件。
> - **第一反应不要是什么**：不要给 `/var/log`、`/etc` 批量加 `+i`。
