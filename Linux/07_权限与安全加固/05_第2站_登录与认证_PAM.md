## 0. 30 秒速览

> [!abstract] 这一篇只要记住五句话
> - **PAM 把认证拆成四类栈**：`auth` 证明你是谁，`account` 决定现在能不能登录，`password` 决定改密码规则，`session` 决定登录后做什么。
> - **一条 PAM 行有四个字段**：`type control module-path module-arguments`；`requisite` 失败立即返回，`required` 失败要等栈结束再返回，`sufficient` 成功可跳过剩余模块。
> - **`limits.conf` 是 PAM 登录会话的事**：systemd 服务不走这套栈，所以改 `limits.conf` 对服务不生效，要在 unit 里写 `LimitNOFILE=`。
> - **失败锁定和密码质量不是所有发行版都默认开**：Ubuntu 24.04 默认没有启用 `pam_faillock`/`pam_pwquality`，RHEL 9 走 `authselect` 的 `with-faillock`。
> - **改 PAM 前必须留带外会话**：一条写错的 `auth` 栈可能把自己锁在门外，且它影响的是所有登录入口。

## 1. 四类栈与 PAM 行结构

| 栈 | 回答的问题 | 典型模块 |
| --- | --- | --- |
| `auth` | 你是谁、凭据对不对 | `pam_unix`、`pam_faillock`、`pam_cap` |
| `account` | 你现在是否允许登录 | `pam_unix`、`pam_nologin`、`pam_access` |
| `password` | 改密码要满足什么规则 | `pam_unix`、`pam_pwquality` |
| `session` | 登录后准备什么环境/资源 | `pam_umask`、`pam_limits`、`pam_systemd` |

`/etc/pam.d/common-auth` 的简化结构如下（Ubuntu 24.04 实测，非逐行完整）：

```text
auth	[success=1 default=ignore]	pam_unix.so nullok
auth	requisite			pam_deny.so
auth	required			pam_permit.so
auth	optional			pam_cap.so
```

控制标志的差别：

- `requisite`：失败立即返回，后面不执行。
- `required`：失败也继续执行，最终仍失败，避免泄露「哪一步失败」。
- `sufficient`：成功则跳过剩余模块，常用来「先试本地，再试远端」。
- `optional`：结果通常不影响主结果。
- `[success=N default=ignore]`：按返回码跳转，现代发行版常见。

> [!warning] 不要在没留带外会话时改 PAM
> 改 `common-auth`、`system-auth`、`password-auth` 会同时影响 SSH、控制台、`sudo` 等多个入口。动手前先保留一个已登录的 root 会话，另开窗口验证。

## 2. 失败锁定：`pam_faillock`

`pam_faillock` 的默认参数在 `faillock.conf(5)`：`deny=3`（连续失败 3 次锁定）、`fail_interval=900`（15 分钟窗口）、`unlock_time=600`（锁 10 分钟）。

Ubuntu 上只存在 `/etc/security/faillock.conf`，但**没有被 PAM 引用**；要启用需要在 `common-auth` 的 `pam_unix` 前后加 preauth/authfail，并在 `common-account` 加模块。RHEL 9 用 `authselect select <profile> with-faillock` 管理，失败锁定默认开箱。

```bash
grep -rl 'pam_faillock' /etc/pam.d 2>/dev/null
                                # 验证：当前 PAM 是否引用失败锁定；Ubuntu 默认通常为空
faillock --user $(id -un)       # 验证：查看该账号的失败记录
faillock --user $(id -un) --reset   # 验证：解锁；只能在有权限的实验机上做
```

> [!note] `pam_faillock` 与 `pam_tally2` 不要混用
> 新系统应使用 `pam_faillock`；老资料里的 `pam_tally2` 已逐步被替代。复制粘贴旧配置前先确认发行版和 PAM 版本。

## 3. 密码质量：`pam_pwquality`

`pam_pwquality` 在 `password` 栈里加规则：最小长度、复杂度、字典——**但不含密码历史**（历史由 `pam_pwhistory` 或 `pam_unix` 的 `remember=` 负责，两者常被混为一谈）。Ubuntu 需要装 `libpam-pwquality` 并写进 `common-password`；RHEL 9 通常由 `authselect` 的密码策略模块提供。

```bash
grep -rl 'pam_pwquality' /etc/pam.d 2>/dev/null
                                # 验证：是否启用密码质量；Ubuntu 默认通常为空
grep -vE '^[[:space:]]*(#|$)' /etc/pam.d/common-password
                                # 验证：看实际生效的 password 栈
```

## 4. `pam_umask` 与 `pam_limits` 的落点

这两个模块常用来解释「改了配置为什么不生效」：

- `pam_umask` 在 `session` 栈读 `/etc/login.defs` 的 `UMASK`，只影响**登录会话**。
- `pam_limits` 在 `session` 栈读 `/etc/security/limits.conf`，只影响**经 PAM 登录的进程**。
- systemd 服务不经这套 PAM 栈，所以要分别用 unit 的 `UMask=` 和 `LimitNOFILE=`。

```bash
grep -rl 'pam_umask' /etc/pam.d       # 验证：哪些服务栈会应用 umask
grep -rl 'pam_limits' /etc/pam.d      # 验证：哪些服务栈会应用 limits.conf
```

## 5. 实验：在实验机上启用失败锁定并验证

> [!example]- 实验：`pam_faillock` 的锁定与解锁
> **怎么做**：在可快照实验机上，先留一个已登录 root 会话；用 `authselect`（RHEL）或手工编辑 PAM（Ubuntu）启用 `pam_faillock`，再用一个测试账号连续输错密码 3 次。
> **预期**：第 3 次失败后账号被锁，`faillock --user <user>` 出现失败记录；未锁定会话仍可用。
> **风险**：可能把测试账号锁住；不要在 root 上只测一次就切走。
> **耗时**：约 10 分钟。
> **回滚**：`faillock --user <user> --reset`；移除刚加的 PAM 行并复测。

## 常见坑

| 常见做法或说法 | 后果或事实 |
| --- | --- |
| 改 `limits.conf` 期望 systemd 服务生效 | 服务不走 PAM 登录栈，要在 unit 里写 `LimitNOFILE=` |
| 改 PAM 前不留带外会话 | 写错 `auth` 栈可能把自己锁在门外 |
| 把 `pam_tally2` 配置抄到新系统 | 新系统应使用 `pam_faillock` |
| 以为装了 `faillock.conf` 就启用了失败锁定 | 文件存在不等于被 PAM 引用 |
| 认为所有发行版失败锁定都默认开 | Ubuntu 需自行启用，RHEL 9 开箱即用 |

## 决策练习

> [!question]- 场景：同事发现 `pam_faillock` 配置已经写进 `/etc/security/faillock.conf`，但测试账号连续输错 5 次仍能登录。他说「配置没生效，重装 pam」。你怎么办？
> A. 重装 PAM 包
> B. 先确认配置是否真的被引用：`grep -rl pam_faillock /etc/pam.d`；同时看发行版是 `authselect` 管理还是手工 common-auth，然后补引用、复测、回滚
> C. 直接给测试账号 `passwd -l`
>
> **答案：B。**
> A 不是根因，PAM 包本身没问题。
> C 锁的是密码，不是失败锁定策略，没有解决配置未生效。
> B 是正解：**配置文件存在不等于策略开启，先查引用链，再按发行版正确落地。**

## 要点自测

> [!question]- PAM 四类栈各管什么？用一句话说清。
> - `auth`：证明你是谁；`account`：现在能不能登录；`password`：改密码规则；`session`：登录后准备环境和资源。
> - **第一反应不要是什么**：不要看到登录失败就只查 `auth`，账号过期属于 `account`。

> [!question]- 为什么 `limits.conf` 对 systemd 服务不生效？
> - `pam_limits` 在 PAM 登录会话里设置 rlimit；systemd 服务不经这套栈。
> - 服务用 unit 的 `LimitNOFILE=`、`TasksMax=` 等配置。
> - **第一反应不要是什么**：不要在 `limits.conf` 反复加行来修服务限制。

> [!question]- Ubuntu 和 RHEL 9 的失败锁定入口差在哪？
> - Ubuntu：手工把 `pam_faillock` 加入 `common-auth`/`common-account`。
> - RHEL 9：用 `authselect select <profile> with-faillock` 管理，默认 profile 带失败锁定。
> - **第一反应不要是什么**：不要把一套发行版的 PAM 文件原样复制到另一套。
