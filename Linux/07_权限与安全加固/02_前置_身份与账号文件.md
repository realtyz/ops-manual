## 0. 30 秒速览

> [!abstract] 这一篇只要记住五句话
> - **账号判断看数值，不看名字**：内核按 UID/GID 判定；`root` 只是「UID 0」的一个惯例名字，真正危险的是 **UID 0**。
> - **`/etc/passwd` 里只有 `x`**：真实密码哈希在 `/etc/shadow`，`shadow` 默认 `640 root:shadow`，普通用户读不到。
> - **`passwd` 7 个字段、`shadow` 9 个字段**：`shadow` 后 6 个字段管密码有效期、失效与账号过期，默认值几乎都是「永不过期」。
> - **主组与附加组不是一回事**：主组在 `passwd` 第 4 字段，附加组在 `/etc/group` 的成员列表；加组要用 `usermod -aG`，不是 `-G`。
> - **NSS 决定「去哪查账号」**：`nsswitch.conf` 里 `files systemd` 表示只看本地；接 LDAP/SSSD 后要用 `getent`，不能只读 `/etc/passwd`。

## 1. 四个文件各存什么

| 文件 | 内容 | 典型权限 | 关键点 |
| --- | --- | --- | --- |
| `/etc/passwd` | 账号名、UID、主 GID、GECOS、家目录、登录 shell | `644 root:root` | 第 2 字段是 `x`，不是密码 |
| `/etc/shadow` | 密码哈希、密码有效期、账号过期 | `640 root:shadow` | 只有 root/`shadow` 组可读 |
| `/etc/group` | 组名、GID、成员列表 | `644 root:root` | 成员列表是附加组成员，不含主组 |
| `/etc/gshadow` | 组密码、组管理员 | `640 root:shadow` | 现代系统很少用组密码 |

```bash
getent passwd $(id -u)         # 验证：看当前账号在 passwd 里的 7 个字段
getent shadow $(id -un)        # 验证：普通用户通常 Permission denied，确认 shadow 的隔离
id                             # 验证：uid、gid、主组名、附加组列表一次看全
```

## 2. `/etc/passwd` 的 7 个字段

字段顺序：`name:passwd:UID:GID:GECOS:home:shell`。

```text
realtyz:x:1000:1000:Real User,,,:/home/realtyz:/bin/bash
```

| 字段 | 含义 | 核查时注意 |
| --- | --- | --- |
| `name` | 登录名 | 人类账号一般 UID≥1000，系统账号 UID<1000 |
| `passwd` | 固定为 `x` | 真实哈希在 `/etc/shadow`；这里出现可读哈希就是异常 |
| `UID` | 用户 ID | **UID 0 只有 root 一个**；其他 UID 0 都是危险账号 |
| `GID` | 主组 ID | 决定新建文件默认属组 |
| `GECOS` | 注释/全名 | 不用来判定身份 |
| `home` | 家目录 | 家目录属主、权限异常会影响 SSH 的 `StrictModes` |
| `shell` | 登录 shell | `nologin`/`false` 表示不能交互登录，但**不等于完全停用** |

## 3. `/etc/shadow` 的 9 个字段

字段顺序：`name:hash:last_change:min_days:max_days:warn_days:inactive:expire:reserved`。

| 字段 | 含义 | 默认/典型值 | 加固方向 |
| --- | --- | --- | --- |
| 1 | 用户名 | — | 与 `passwd` 对齐 |
| 2 | 密码哈希 | `$6$`/`$y$`；`!` 或 `*` 表示锁定 | 只存哈希，不存明文 |
| 3 | 上次改密日期（1970 起天数） | `passwd -S` 可读 | 记录改密时间 |
| 4 | 最小改密间隔 | `0` | 防止用户反复改回旧密码 |
| 5 | 最大有效期 | `99999` | **必须收紧** |
| 6 | 到期提醒 | `7` | 提醒天数 |
| 7 | 到期后禁用宽限 | `-1` | `-1` 表示永不禁用 |
| 8 | 账号过期日期 | 空 | 用 `usermod -e 1` 停用账号 |
| 9 | 保留 | 空 | — |

```bash
passwd -S $(id -un)           # 验证：密码状态 L/NP/P、改密日期、min/max/warn/inactive
chage -l $(id -un)            # 验证：shadow 后 6 个字段的人类可读版本
grep -E '^(UMASK|PASS_MAX_DAYS|PASS_MIN_DAYS|PASS_WARN_AGE)' /etc/login.defs
                              # 验证：新建账号的默认值来源，但不会回头改已有账号
```

> [!warning] `passwd -l` / `usermod -L` 不等于「停用账号」
> 它们只是在密码哈希前加 `!`，锁住**密码认证**这一条路。已部署的 SSH 公钥、`sudo` 的 `NOPASSWD`、其他 PAM 来源仍可能通过。真正停用要同时做：`usermod -e 1`（或 `chage -E 0`）、清理 `authorized_keys` 与 sudoers、确认没有长期会话（`who`/`w`/`loginctl`）。

## 4. UID、主组与附加组

```bash
id                             # 验证：uid / gid / groups 的完整视图
getent group $(id -gn)         # 验证：主组记录
groups $(id -un)               # 验证：主组 + 附加组
```

- **主组**：`/etc/passwd` 第 4 字段；用户登录后新建文件默认属主组，由 `umask` 决定组权限。
- **附加组**：`/etc/group` 的成员列表；一个用户可以属于多个组，权限判定时所有组都会被考虑。
- **改组成员**：附加组要用 `usermod -aG <group> <user>`；漏掉 `-a` 会把原有附加组覆盖掉，这是高频误操作。

## 5. NSS 决定「账号在哪查」

```bash
grep -E '^(passwd|group|shadow):' /etc/nsswitch.conf
                              # 验证：files 表示本地文件，sss/ldap 表示远端目录
getent passwd someuser        # 验证：按 NSS 顺序查账号，不要直接只读 /etc/passwd
```

本地 `/etc/passwd` 只是 NSS 的一个数据源。企业环境接入 LDAP/SSSD 后，账号可能在远端；**判断账号是否存在、UID 是多少，统一用 `getent`**，而不是直接 `grep /etc/passwd`。

## 常见坑

| 常见做法或说法 | 后果或事实 |
| --- | --- |
| 看到 `passwd` 里的 `x` 以为是密码 | 真实哈希在 `shadow`；`passwd` 里的 `x` 只是占位 |
| 用 `usermod -G` 代替 `-aG` | 覆盖原有附加组，用户突然丢权限 |
| 只锁密码就宣布停用账号 | 公钥、`NOPASSWD`、长期会话仍可进入 |
| 只 `grep /etc/passwd` 判断账号是否存在 | LDAP/SSSD 账号看不到；应用 `getent` |
| 以为 UID 0 一定要叫 root | 内核只看 UID 数值，其他名字的 UID 0 同样危险 |

## 决策练习

> [!question]- 场景：你在排查一台机器，发现 `awk -F: '$3==0{print}' /etc/passwd` 输出两个账号：`root` 和一个叫 `ops` 的账号。同事说「名字不是 root，没关系」。你怎么办？
> A. 同意同事，只看名字
> B. 立即按异常账号处理：确认 `ops` 来源、登录 shell、`shadow` 状态、`authorized_keys`、sudoers，并与其他机器基线对比；若无法解释，按入侵事件上报
> C. 只把 `ops` 改名为 `root_backup`，方便辨认
>
> **答案：B。**
> A 错误：内核判定身份看 UID，任何 UID 0 都是完整超级用户。
> C 是掩盖问题，改名不改变它已经拥有 root 权限的事实。
> B 是正解：**UID 0 账号多一个，就是最高优先级事件**，先定性来源和影响面，再决定处置。

## 要点自测

> [!question]- `passwd`、`shadow`、`group` 分别存什么？为什么 `passwd` 世界可读而 `shadow` 不行？
> - `passwd`：账号元信息与 UID/GID，无敏感哈希；`shadow`：密码哈希与有效期，必须隔离；`group`：组与附加成员。
> - `shadow` 只允许 root/`shadow` 组读，是为了降低哈希被爆破和离线恢复的风险。
> - **第一反应不要是什么**：不要把 `shadow` 权限放宽给普通用户「方便查账号」。

> [!question]- 主组和附加组有什么不同？加附加组为什么必须 `-aG`？
> - 主组写在 `passwd` 第 4 字段，新建文件默认属它；附加组写在 `group` 成员列表，用于共享目录/设备等多组授权。
> - `usermod -G` 会**替换**附加组列表，`-aG` 才是追加。
> - **第一反应不要是什么**：不要为了省事直接改 `/etc/group` 手工加成员而不留变更记录。

> [!question]- 为什么「锁密码」不等于「停用账号」？
> - 因为密码只是认证入口之一；SSH 公钥、`sudo NOPASSWD`、已有会话、其他 PAM 来源仍可能绕过。
> - 停用账号要组合：账号过期 + 清理授权文件 + 终止会话。
> - **第一反应不要是什么**：不要在处置离职账号时只跑一条 `passwd -l`。
