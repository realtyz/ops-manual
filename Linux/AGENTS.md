# Repository Guidelines

本仓库是 Obsidian 中的 Linux 运维学习笔记库，不是代码工程：没有构建系统、依赖管理与自动化测试。贡献即「写作」，优先保证**准确、可复现、可判断**。

**内容怎么写，一律以 `Linux/写作规约.md` 为准**；本文件只讲仓库结构、协作流程与校验方式。

## 结构

- `00_学习大纲.md`：学习路线图，各阶段按**里程碑**过关（不设天数）。
- `写作规约.md`：内容写作的唯一依据。
- `AGENTS.md`：本文件。
- `NN_主题/`：每个阶段一个目录，内含：
  - `00_导读与知识地图.md`：**导航篇**，只承担地图职责——知识地图（时间主线 + 横切线）、术语速查、故障现场定位表、篇目索引、参考文档；

## 写作：以 `写作规约.md` 为准

最容易忘的三条（完整清单见规约第四节）：

1. **不写结构声明**：不写"这篇讲什么""必须先读什么""和后面的关系"。
2. **不出现等级与技能编号**（`M1–M8`/`T0–T4`/`L1–L4`），原理篇不写动手章节与脚本。
3. **给出数值就要给出读法**：是什么、单位、判据、与谁同看、转向哪一步——五件事缺一不可。

## 以文档为准，实机其次

机制、默认值、字段口径**先查权威文档**（man、内核 `Documentation/`、发行版官方文档、厂商手册），中文速查用 `https://cmd.ifdev.cn/c/{cmd}.html`（例：`ls` → `https://cmd.ifdev.cn/c/ls.html`），**但结论只以权威文档为准**；文档说不清或与观察冲突时才上机，并且：

- 上机结果与内核版本、发行版、硬件、容器环境强相关，**没出现预想结果优先怀疑环境不匹配**；
- 内核文档与 man 手册按**与目标机器同一主版本**取（优先 6.x），引用时写明依据的版本；老版本 `Documentation/` 里的接口与默认值可能已经变过；
- 要把实机结果写进正文，必须写清环境，并说明它可能只在该环境成立；
- 客观事实（关键路径、字段名、输出格式、版本门控）可以也应当上机核对。

**中文速查站与 man 的分工**：`https://cmd.ifdev.cn/c/{cmd}.html` 是社区维护的中文命令手册（`https://cmd.ifdev.cn/hot.html` 可查全部 607 个命令的索引），用来**快速摸清一个命令有哪些选项与子命令、以及中文语境下怎么称呼它**；**正文引用前一律回 man 与官方文档核一遍**——该站是翻译整理项目，更新滞后于包版本，且不覆盖内核参数、`/proc`、`/sys` 与 `man 2/3/5` 的接口。分工固定为：**cmd 站用来定位，man 与官方文档用来定稿**。

**金标准环境**（需要复现时的默认机器，不是结论的适用范围）：Ubuntu 24.04.5 LTS（VMware 虚拟机）/ 内核 `6.8.0-139-generic` / systemd 255（`255.4-1ubuntu8.17`）/ cgroup v2 / 4 vCPU / `MemTotal` 约 7894 MiB / swap 4095 MiB / 根分区 ext4 on LVM / 时区 `Etc/UTC` / root 可用，另有 `realtyz`（uid=1000）。实验机 `192.168.246.128`（root 与 realtyz 均免密，**可从开发机直接 `ssh` 上机实测**——核对文档口径、复跑实验、写变更演练都在它上面做）。已知限制：该机 `perf` 的 `dTLB-*` 事件恒为 0，`numactl --hardware` 只有 1 个节点——涉及 TLB 计数与 NUMA 的结论不可在该机取得。

**阶段 11 重写期的实测记录**（供其它章节引用同一口径）：`sysctl` 的读取集与顺序已用 `strace` 逐条实测——开机路径 `systemd-sysctl.service` 只读 `.d` 目录（`/etc/sysctl.d/`、`/run/sysctl.d/`、`/usr/local/lib/sysctl.d/`、`/usr/lib/sysctl.d/`），**不读 `/etc/sysctl.conf`**；procps 的 `sysctl --system`（本机 procps 2:4.0.4）在 `.d` 之后**再读一次 `/etc/sysctl.conf`**。本机 `/etc/sysctl.d/99-sysctl.conf -> ../sysctl.conf` 由 **systemd 包**提供（`dpkg -S` 已核），`/etc/sysctl.conf` 是靠这条软链的 `99-` 字典序排到最后，不是路径特例。覆盖对抗实验：`/etc/sysctl.d/99-zz-lab-test.conf`=1111 与 `/etc/sysctl.conf`=2222 同时存在时，`sysctl --system` 后读到 2222；实验已回滚（值回 4096、两个测试文件不存在、无残留行）。`net.core.somaxconn` 无任何写入点、运行时 4096 与 `/usr/include/x86_64-linux-gnu/bits/socket.h` 的 `SOMAXCONN` 一致。另核：`sysstat-collect.timer` 的 `OnCalendar=*:00/10`（10 分钟周期）；`man 8 nstat` 原文确认默认输出是「自上一次使用以来的增量」、`-a` 才是绝对累计值。

## 校验

定稿前逐条走完规约第九节的自检。仓库级的四条人工校验：

1. **计数一致性**：本文件阶段表、`00_学习大纲.md` 的阶段描述、各章 `00_导读` 的篇目索引，三者与实际目录一致（`Get-ChildItem <章目录> -File`）；
2. **链接解析**：导航篇里的 wikilink 逐个确认存在；正文篇不应有 wikilink；
3. **编码纪律**：这些笔记是 UTF-8 中文，用脚本读时必须显式指定 UTF-8（PowerShell 用 `-Encoding UTF8`）；按默认编码读会把中文变成 `?`，让 `(?m)^created:` 这类行首正则失配并产生假告警；
4. **速查站不越权**：正文里凡选项名、默认值、单位与字段口径，都要能回到 man 或官方文档对上；只在 cmd 站见过、man 页里查不到或含义相反的说法不得写进正文（该站的示例仍多是 RHEL/CentOS 7 时代，`ifconfig`、`netstat`、`service` 一类已被本机取代）。
