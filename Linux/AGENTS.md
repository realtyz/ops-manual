## Build, Test, and Development Commands

- 预览：用 Obsidian 打开本目录，确认 Mermaid 图、callout、wikilink 正常渲染。
- 列出全部笔记：`rg --files -g '*.md'`。
- 检查 frontmatter：`rg -n '^(tags|created):' -g '*.md'`，每篇须同时含有 `tags` 与 `created`（`AGENTS.md` 本身除外）。
- 检查标题层级：`rg -n '^# ' -g '*.md'`，每篇只允许一个一级标题。
  - **已知误报**：代码块里行首的 `# ` 注释会被计成标题。当前有 **5 篇**会命中，核对时排除：`07/07_第4站_ACL与扩展属性`、`08/02_前置_unit文件语法与位置`、`08/04_第1站_描述与装载`、`09/05_日志的落点_journald与rsyslog`、`10/12_横切_基线与容量台账`。
- 交叉引用自查：`rg -n '\[\[' -g '*.md'`，逐个确认链接指向存在的笔记。
- 阶段结构自查：每个阶段目录**有且仅有一个** `00_` 开头的主笔记，且主笔记的「子笔记索引」覆盖目录内全部子笔记。
- 计数一致性：本文件的阶段表、`00_学习大纲.md` 的篇数/计数描述，都要与目录实际内容一致（大纲里出现过「收口两篇」其实只有一篇这类笔误，改结构时顺手核一遍）。
- **读文件的编码纪律**：这些笔记是 UTF-8 中文，用脚本读时必须显式指定 UTF-8（PowerShell 用 `Get-Content -Encoding UTF8`，或直接用编辑器的 read 工具）。按默认编码读会把中文变成 `?`，使 `(?m)^created:` 这类行首正则**失配并产生假告警**——2026-09 审核中就因此误报过「10 个文件缺 `created`」。

## Coding Style & Naming Conventions

- 新建笔记一律从模板复制：`Copy-Item '99_Linux笔记模板.md' 'NN_主题.md'`，再删除模板内的使用说明；**但模板骨架待更新，落笔以「三、子笔记固定骨架」为准**。
- 文件与章节编号使用阿拉伯数字，正文用简体中文，术语保留英文原词（`cgroup`、`Page Cache`）。
- 命令、参数、配置项用行内代码 `` `like this` ``；**代码块的语言标签必须与实际内容一致**：要执行的 shell 命令用 `bash`，systemd unit / INI 式配置文件用 `ini`，命令输出、日志、目录树、Runbook 模板与伪代码用 `text`，流程图用 `mermaid`（GRUB 提示符等非 shell 环境的命令仍用 `text`）。命令块要注明「验证什么」与预期输出。
- 跨笔记引用用 wikilink，跨目录用路径写法：`[[Linux/00_学习大纲|00_学习大纲]]`、`[[Kubernetes/04_网络]]`。
- 默认值、内核差异与发行版差异必须标注适用版本；数字必须带单位与测试条件。
- 单位在同一篇内必须统一：容量统一用 MiB，时间统一用秒（写「90 秒」而不是「两分钟」），不要在同段里混用 MB 与 MiB。
- **写进 unit / timer 的 `%` 必须转义成 `%%`**（`%T`/`%N`/`%s` 会被 systemd 当说明符先展开，`systemd-analyze verify` 还不报错）。
- **版本门控的指令/参数要标最低版本**（如 `ProtectProc=`/`ProcSubset=` ≥247、`OOMPolicy=` ≥243、`LogsDirectory=` ≥246、`Type=exec` ≥240）——旧发行版上会静默失效。

## 一、结构：主笔记 + 子笔记

- 一个阶段 = 一个目录 + 一篇 00 号主笔记：`NN_主题/00_导读与知识地图.md`。
- 主笔记只承担「地图」职责，不放正文细节，固定包含：参考资料、读者定位与前置自检、30 秒速览、**知识地图**（时间主线 + 贯穿多环节的横切线）、**生产技能地图**（技能编号 / 可观察行为 / 交付物 / 在哪几篇练）、**训练台阶**、学习路线、术语速查、**故障现场定位表**（现象 → 哪一环 → 现场在哪 → 第一反应不要做什么 → 去哪一篇）、子笔记索引表。
- 训练台阶固定四级：T0 读通 → T1 观测（只读，生产机也可做）→ T2 可回滚变更 → T3 故障注入与恢复 → T4 限时模拟。
- 入口用主笔记：`00_学习大纲.md` 的「对应笔记」指向 `[[Linux/NN_主题/00_导读与知识地图|NN 主题]]`。

## 二、双主线：知识 + 技能

- **知识主线**：一条时间主线（流程/时序）+ 若干条贯穿多环节的横切线。
- **技能主线**：把「这一章要交付什么能力」写成编号技能（可观察行为 + 交付物），并配四级训练台阶。
- 验收标准从「能讲清」改为**能交出东西**：一份基线卡、一份带回滚的变更记录、一份演练记录、一段 Runbook。

## 三、子笔记固定骨架

1. `> [!cite] 参考资料`：man 页 + 官方文档 + 一句实测状态（未实测就照实写，不要伪造）。
2. 定位块：**这篇讲什么 / 必须先读什么 / 读完能回答 / 所属**（属于哪条主线、练哪个技能）。
3. `## 0. 30 秒速览`：4~6 条结论，每条带可复现的证据；写成两行——第一行一句短结论（加粗），第二行以「证据：」或「怎么验证：」开头，写实测数字或一条可执行的判据（阶段 9、阶段 10 均按此形态）。数字保留原始精度与条件，不伪造实测。
4. 正文：概念与机制 → 命令与现场 → 按需的生产动作。
   - 需要动手的篇目，把实验步骤写成 `> [!example]-` 折叠块（标题写明「实验 N：…」，内含怎么做/预期/风险/耗时/回滚），由收口篇的实验总览与索引负责串起来。
5. `## 常见坑`：表格，列为「常见做法或说法 | 后果或事实」。
6. `## 决策练习`：一个场景 + 三个选项 + 为什么选它、为什么另外两个不对。
7. `## 要点自测`：可折叠问答卡。
8. 结尾一行导航：`> 上一篇：… ｜ 下一篇：…`（该章最后一篇写「回到地图：00 导读」）。

## 四、写作约定（面向刚入职的运维/SRE）

- 读者定位：会基本 shell、用过 `systemctl`/`top`，但没碰过本阶段涉及的机制；术语首次出现给中文解释 + 英文原词，缩写首次出现要展开（如 BLS、MOK、LBA）。
- 命令块注释统一写 `# 验证：…`；**不要写行首就只有 `#` 的注释行**，否则会被标题层级检查误判；需要分段说明就写成代码块外的正文，或把说明并到相邻命令的行尾注释里。
- 语言标签不要一律用 `text` 兜底：一段要照着敲的命令就是 `bash`，一段要看懂的输出才是 `text`。混在一块的（例如实验块里「命令 + 预期输出」）按主要用途取标签，或拆成两个代码块。
- 破坏性操作必须标注「只在可快照的实验机」；纯只读观测要写明「生产机上也可以做」。
- **命令要能复制即用**：设备名/单元名/PID 一律用变量或占位符捕获，**不要硬编码**（例如 `losetup --find --show` 的结果必须存进变量，后续用它，不能在下一行写死 `/dev/loopN`）。
- **管道后的退出码要用 `${PIPESTATUS[0]}`**，或干脆不接管道、重定向到文件再读——`A | B || C` 里的 `||` 取的是 `B` 的退出码，兜底分支会变成死代码。
- 「第一反应不要是什么」是必备句式，比命令清单更能体现经验。
- 「生产动作」小节**按必要性保留**：只有含风险、或产出物明确的操作序列才写；纯巡检、纯只读的内容用检查表表达，不要硬套这个格式。
- 每篇给出的验证方法要落到「验收标准」上（例如参数改动用 `cat /proc/cmdline` 验收，而不是「配置文件已修改」）。

## 五、禁止项

- 不设「回到路线图」小节；回链由主笔记的索引承担。
- 不设「验证进度」小节；资料出处与实测状态写进开头的「参考资料」。
- **引用链接只在章节内部使用**，不引用其他章节的笔记；确需提及时用阶段编号写纯文本（如「深水区在阶段 8」）。大纲与各章主笔记的索引不在此限。
- 速览只放结论，不要往里堆术语。
- 不再新增单篇 `NN_主题.md`（该形式已废除，见「Project Structure」）。

## 六、修订后必须同步

- 改动 `00_学习大纲.md` 的阶段结构时，同步对应阶段主笔记的子笔记索引与「对应笔记」链接，并复核本文件的阶段表。
- 主笔记的子笔记索引登记全部子笔记；新增或改名子笔记后同步更新索引与相邻篇的导航行。
- 新增或重构章节时先备份（`.bak`），内容全部迁移并逐条核对后删除，不要长期留着。

## Testing Guidelines

**金标准环境**（所有「实测」结论的默认复现环境）：
Ubuntu 24.04.5 LTS（VMware 虚拟机）/ 内核 `6.8.0-139-generic` / systemd 255（`255.4-1ubuntu8.17`）/ cgroup v2（`cgroup2fs`）/ 4 vCPU / `MemTotal` 7894 MiB / swap 4095 MiB / 根分区 `/dev/mapper/ubuntu--vg-ubuntu--lv`（ext4 on LVM，46.9 G）/ 网卡 `ens33`（`e1000`，单队列）/ 时区 `Etc/UTC` / root 可用，另有 `realtyz`（uid=1000）。**实验机 IP：`192.168.246.128`（root 与 realtyz 均免密）。**

- 验证方式是「在真实实验机上复现」，没有测试框架。任何标为「实测」的命令与输出都应实际跑过；未跑过的必须显式写「未实测 + 原因 + 补做方式」。
- **破坏性操作**（打满磁盘、改坏 `/etc/fstab`、`down` 网卡、`echo c > /proc/sysrq-trigger`）**只在「可快照 + 有独立控制台」的实验机上做**；本机只有 SSH、无控制台，因此这几类**保持未实测**，用临时 loop 文件系统 / netns 做等价复现。
- **数字要有三条尾巴：单位、版本、采集条件**；转引数字必须能溯源到源阶段，**不要在复习章写源阶段根本没有的数字**（2026-09 审核就发现过整簇 IO 数字无法溯源）。
- **跨章同名知识点的口径必须一致**：同一参数/默认值/机制在多章出现时，措辞与数值要对齐（历史高发点：sysctl 加载顺序、`tcp_tw_reuse` 默认值、端口段划分、`sadf` 时区、IO 数字簇、`sshd`/`ssh` 与 `nfs-server` 的服务名）。
- **「实测」标签下的自证链要完整**：写了实测数字，就要让读者能照着复现；脚本里的降级/兜底分支必须真的会执行（别写成死代码）。
- 定稿前逐条走完模板末尾的自检清单，以及本文「Build, Test」里的结构自查与计数一致性。

## 七、高发错误清单（2026-09 审核结论，修订时优先自查）

修订任何一篇前，先扫一眼自己是否踩了这几类（都是本轮审核真实命中过的）：

1. **默认值写反**：ext4 `errors=` 默认是 `continue`（不是 `remount-ro`）；`tcp_tw_reuse` 内核默认就是 `2`（不是 0）；`fs.inotify.max_user_instances` 默认固定 `128`（不是按内存算）；`RuntimeMaxUse` 是 `/run` tmpfs 的 10%（不是内存的 10%）。**默认值一律 `sysctl`/`tune2fs -l`/`journald` 启动日志现场取，不能凭发行版猜。**
2. **报错文本混为一谈**：`ENOSPC`（No space left）、`EDQUOT`（Disk quota exceeded）、`EROFS`（Read-only file system）是三个不同的 errno，不能并成「报错文本一样」。
3. **机制归因错位**：同一个观察值被安到错误的开关上——`User=` 只换 uid/gid（不清空 `CapBnd`、不等于 `NoNewPrivileges`）；`setenforce 0` 只是切 permissive（**审计与 AVC 仍在**，不是「把证据关掉」）；`copytruncate` 保持 inode 不变，**「旧 fd 把内容写进归档」是 `create` 的行为**。
4. **归因与观察不符**：如「保留块导致 root 能建空文件」——空文件不占数据块；保留块影响的是**数据写入**。
5. **命令达不到声称的效果**：`ps -e -o pid,comm | grep -c '\['` 数不到内核线程（`comm` 没有方括号）；`sar -n DEV` 有表头（看不到是被 `tail` 截掉了）；`tune2fs -l` 没有 `Bytes per inode` 字段；`xfs_quota project -c` 是 check（clear 是 `-C`、setup 是 `-s`）。
6. **跨章/跨篇数字与口径打架**：同一个量在不同篇给出不同值或不同方向（IO 延迟、负载、端口耗尽、`top` 首屏语义）。
7. **未标发行版/版本**：命令、服务名、配置文件路径、unit 语法，只要 RHEL 与 Debian 系不同就必须标注；未标注按缺陷处理。
8. **危险命令缺边界**：破坏性操作没有「只在可快照实验机」、没有回滚步骤、没有上限控制。
