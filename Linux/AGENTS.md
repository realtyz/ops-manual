# Repository Guidelines

本仓库是 Obsidian 中的 Linux 运维学习笔记库，不是代码工程：没有构建系统、依赖管理与自动化测试。贡献即「写作」，请优先保证笔记准确、可复现、可交叉引用。

## Project Structure & Module Organization

- `00_学习大纲.md`：学习路线图，定义阶段编号、周期、产出目标与各阶段 checklist。
- `99_Linux笔记模板.md`：新笔记的唯一模板，包含 frontmatter、章节骨架与自检清单。
- `NN_主题.md`：单篇形式的阶段笔记，`NN` 与路线图中的阶段编号一致。
- `NN_主题/`：**拆分形式的阶段目录**（阶段 2 已按此形式重写）：目录内的 `00_导读与知识地图.md` 是主笔记（地图），其余 `NN_关键词.md` 是子笔记，编号从 `01` 起。
- 图片、附件等资源与本笔记同目录存放，文件名避免中文空格与特殊字符。

## Build, Test, and Development Commands

- 预览：用 Obsidian 打开本目录，确认 Mermaid 图、callout、wikilink 正常渲染。
- 列出全部笔记：`rg --files -g '*.md'`。
- 检查 frontmatter：`rg -n '^(tags|created):' -g '*.md'`，每篇须同时含有 `tags` 与 `created`。
- 检查标题层级：`rg -n '^# ' -g '*.md'`，每篇只允许一个一级标题（代码块里以 `#` 独占一行的注释会被误报，写法见下方写作约定）。
- 交叉引用自查：`rg -n '\[\[' -g '*.md'`，逐个确认链接指向存在的笔记。
- 阶段结构自查：每个阶段目录有且仅有一个 `00_` 开头的主笔记，且主笔记的「子笔记索引」覆盖目录内全部子笔记。

## Coding Style & Naming Conventions

- 新建笔记一律从模板复制：`Copy-Item '99_Linux笔记模板.md' 'NN_主题.md'`，再删除模板内的使用说明。
- 文件与章节编号使用阿拉伯数字，正文用简体中文，术语保留英文原词（`cgroup`、`Page Cache`）。
- 命令、参数、配置项用行内代码 `` `like this` ``；**代码块的语言标签必须与实际内容一致**：要执行的 shell 命令用 `bash`，systemd unit / INI 式配置文件用 `ini`，命令输出、日志、目录树、Runbook 模板与伪代码用 `text`，流程图用 `mermaid`（GRUB 提示符等非 shell 环境的命令仍用 `text`）。命令块要注明「验证什么」与预期输出。
- 跨笔记引用用 wikilink，跨目录用路径写法：`[[Linux/00_学习大纲|00_学习大纲]]`、`[[Kubernetes/04_网络]]`。
- 默认值、内核差异与发行版差异必须标注适用版本；数字必须带单位与测试条件。
- 单位在同一篇内必须统一：容量统一用 MiB，时间统一用秒（写「90 秒」而不是「两分钟」），不要在同段里混用 MB 与 MiB。

### 一、结构：主笔记 + 子笔记

- 一个阶段 = 一个目录 + 一篇 00 号主笔记：`NN_主题/00_导读与知识地图.md`。
- 主笔记只承担「地图」职责，不放正文细节，固定包含：参考资料、读者定位与前置自检、30 秒速览、**知识地图**（时间主线 + 贯穿多环节的横切线）、**生产技能地图**（技能编号 / 可观察行为 / 交付物 / 在哪几篇练）、**训练台阶**、学习路线、术语速查、**故障现场定位表**（现象 → 哪一环 → 现场在哪 → 第一反应不要做什么 → 去哪一篇）、子笔记索引表。
- 训练台阶固定四级：T0 读通 → T1 观测（只读，生产机也可做）→ T2 可回滚变更 → T3 故障注入与恢复 → T4 限时模拟。
- 子笔记从 `01` 起编号，文件名 `NN_关键词.md`，按「一次能讲透、且自带闭环」的知识点切分，不要按术语碎切。
- 入口用主笔记：`00_学习大纲.md` 的「对应笔记」指向 `[[Linux/NN_主题/00_导读与知识地图|NN 主题]]`。

### 二、双主线：知识 + 技能

- **知识主线**：一条时间主线（流程/时序）+ 若干条贯穿多环节的横切线。
- **技能主线**：把「这一章要交付什么能力」写成编号技能（可观察行为 + 交付物），并配四级训练台阶。
- 验收标准从「能讲清」改为**能交出东西**：一份基线卡、一份带回滚的变更记录、一份演练记录、一段 Runbook。

### 三、每篇子笔记的固定骨架

1. `> [!cite] 参考资料`：man 页 + 官方文档 + 一句实测状态（未实测就照实写，不要伪造）。
2. 定位块：**这篇讲什么 / 必须先读什么 / 读完能回答 / 所属**（属于哪条主线、练哪个技能）。
3. `## 0. 30 秒速览`：4~6 条结论，每条带可复现的证据；推荐写成两行——第一行一句短结论（加粗），第二行以「证据：」或「怎么验证：」开头，写实测数字或一条可执行的判据（阶段 9、阶段 10 均按此形态）。数字保留原始精度与条件，不伪造实测。
4. 正文：概念与机制 → 命令与现场 → 按需的生产动作。
   - 需要动手的篇目，把实验步骤写成 `> [!example]-` 折叠块（标题写明「实验 N：…」，内含怎么做/预期/风险/耗时/回滚），由收口篇的实验总览与索引负责串起来。
5. `## 常见坑`：表格，列为「常见做法或说法 | 后果或事实」。
6. `## 决策练习`：一个场景 + 三个选项 + 为什么选它、为什么另外两个不对。
7. `## 要点自测`：可折叠问答卡。
8. 结尾一行导航：`> 上一篇：… ｜ 下一篇：…`。

### 四、写作约定（面向刚入职的运维/SRE）

- 读者定位：会基本 shell、用过 `systemctl`/`top`，但没碰过本阶段涉及的机制；术语首次出现给中文解释 + 英文原词，缩写首次出现要展开（如 BLS、MOK、LBA）。
- 命令块注释统一写 `# 验证：…`；**不要写以 `#` 独占一行的注释**，否则会被标题层级检查误判；需要分段说明就写成代码块外的正文，或把说明并到相邻命令的行尾注释里。
- 语言标签不要一律用 `text` 兜底：一段要照着敲的命令就是 `bash`，一段要看懂的输出才是 `text`。混在一块的（例如实验块里「命令 + 预期输出」）按主要用途取标签，或拆成两个代码块。
- 破坏性操作必须标注「只在可快照的实验机」；纯只读观测要写明「生产机上也可以做」。
- 「第一反应不要是什么」是必备句式，比命令清单更能体现经验。
- 「生产动作」小节**按必要性保留**：只有含风险、或产出物明确的操作序列才写；纯巡检、纯只读的内容用检查表表达，不要硬套这个格式。
- 每篇给出的验证方法要落到「验收标准」上（例如参数改动用 `cat /proc/cmdline` 验收，而不是「配置文件已修改」）。

### 五、禁止项

- 不设「回到路线图」小节；回链由主笔记的索引承担。
- 不设「验证进度」小节；资料出处与实测状态写进开头的「参考资料」。
- **引用链接只在章节内部使用**，不引用其他章节的笔记；确需提及时用阶段编号写纯文本（如「深水区在阶段 8」）。本条适用于**已重写**的章节；尚未重写的旧笔记保持现状，等重写该章时一并清理。
- 速览只放结论，不要往里堆术语。

- 主笔记的子笔记索引登记全部子笔记；新增或改名子笔记后同步更新索引与相邻篇的导航行。
- 重写旧笔记时先备份（`.bak`），内容全部迁移并逐条核对后再删除，不要长期留着。

## Testing Guidelines

没有测试框架，验证方式是「在真实实验机上复现」。任何命令与输出都应实际跑过；破坏性操作（打满磁盘、改坏 `/etc/fstab`、触发 panic）只在可快照的实验机执行。定稿前逐条走完模板末尾的自检清单，以及「章节重写规范」里的结构自查与同步清单。

## Commit & Pull Request Guidelines

本目录由上级仓库 `ObsidianNote` 管理（Git 根在上一级），没有独立的提交规范可循。提交信息建议沿用 `docs: 重写阶段 2 为「主笔记 + 子笔记」结构` 这类写法，说明改了哪篇笔记与改动原因。PR 需包含：受影响笔记清单、验证环境（发行版 / 内核版本 / cgroup 版本）、路线图链接是否同步更新，以及渲染截图（涉及 Mermaid 或 callout 时）。

## Agent-Specific Instructions

修改 `00_学习大纲.md` 的阶段结构时，必须同步更新对应阶段主笔记（`NN_主题/00_导读与知识地图.md`）的子笔记索引与「对应笔记」链接；新增笔记后同时补上路线图中的链接与 checklist 条目。

重写任何章节时，一律遵循本文件的「章节重写规范」：**正在重写的那一章**以规范为准，其余尚未重写的旧笔记保持现状，不做顺带改动。
