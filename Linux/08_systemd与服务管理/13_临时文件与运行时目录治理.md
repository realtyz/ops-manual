# 临时文件与运行时目录治理

## 0. 30 秒速览

> [!abstract] 这一篇只要记住六句话
> - **`/tmp`、`/run` 由 `systemd-tmpfiles` 按声明式规则维护**：规则文件在 `/usr/lib/tmpfiles.d/`、`/etc/tmpfiles.d/`（系统）与 `~/.config/user-tmpfiles.d/`（用户）。
> - **本机实测 `/tmp` 的规则是 `D /tmp 1777 root root 30d`，由 `systemd-tmpfiles-clean.timer` 每天跑一次**（next 为 23 小时后）——所以「文件在 `/tmp` 里怎么没了」的第一种解释就是它，第二种是重启（tmpfs），第三种是 `PrivateTmp`。
> - **age 默认同时看 mtime/atime/ctime**（`age-by=abcmABM`）：**只要其中任一时间戳比「当前时间 - age」更新，就不会清理**。
> - **实测反直觉现象**：`touch -d "40 days ago"` 造出的「老文件」不会被删，因为它的 **ctime 是「现在」**；把规则改成 `m:30d`（只看 mtime）后立刻被删。
> - **服务的数据按生命周期放对地方**：跨重启持久用 `/var/lib`（`StateDirectory=`），临时但需跨进程共享用 `/run`（`RuntimeDirectory=`），纯易失用 `/tmp`（且知道它会被清/可能私有）。
> - **让 systemd 建目录**：`StateDirectory=`/`RuntimeDirectory=`/`LogsDirectory=`/`CacheDirectory=` 会自动创建目录并设好属主权限，比手写 `mkdir` 更可靠，配合 `ProtectSystem=strict` 尤其好用。

## 1. 规则长什么样、放在哪

一条 tmpfiles 规则的格式是 `Type Path Mode User Group Age Argument`，例如：

```text
D /tmp 1777 root root 30d
```

| 类型 | 语义 |
| --- | --- |
| `d` | 创建目录；**其内容按 age 清理** |
| `D` | 创建目录，并在 `--remove` 时清空内容（`--clean` 仍按 age） |
| `e` | 只调整已存在的文件/目录（不创建），并按 age 清理 |
| `x` / `X` | 排除某些路径不参与清理 |
| `r` / `R` | 删除文件 / 递归删除目录（**无年龄判断**） |
| `f` / `F` | 创建文件 / 创建并清空 |
| `L` | 创建软链 |

规则文件的位置与优先级和 unit 类似：`/etc/tmpfiles.d/` 覆盖 `/usr/lib/tmpfiles.d/`；用户规则在 `~/.config/user-tmpfiles.d/`。

```bash
grep -vE "^\s*(#|$)" /usr/lib/tmpfiles.d/tmp.conf          # 验证：本机规则
systemctl list-timers --all --no-pager | grep tmpfiles     # 验证：清理任务的调度时间
systemd-tmpfiles --cat-config | grep -A2 "/tmp"            # 验证：生效规则（合并所有来源）
systemd-tmpfiles --user --cat-config | grep -A1 <你的路径>  # 验证：用户规则
```

本机实测：

```text
$ grep -vE "^\s*(#|$)" /usr/lib/tmpfiles.d/tmp.conf
D /tmp 1777 root root 30d
$ systemctl list-timers --all --no-pager | grep tmpfiles
Fri 2026-09-18 20:51:16 CST 23h Thu 2026-09-17 20:49:29 CST 39min ago \
  systemd-tmpfiles-clean.timer  systemd-tmpfiles-clean.service
```

即：**`/tmp` 由 `systemd-tmpfiles-clean.timer` 每天跑一次，按 `D /tmp ... 30d` 删除 30 天前的条目**。

## 2. age 的判据：为什么老文件没被删

`tmpfiles.d(5)` 的规则是：**年龄由 mtime、atime、ctime 共同决定，默认 `age-by=abcmABM`——只要其中任一时间戳比「当前时间 - age」更新，就不会清理**（目录默认忽略 ctime，避免清理动作自己刷新 ctime）。

实测：

```text
$ printf "%s\n" "d /home/realtyz/lab-tmpfiles 0700 realtyz realtyz 30d" \
    > ~/.config/user-tmpfiles.d/lab.conf
$ : > ~/lab-tmpfiles/m1; touch -d "40 days ago" ~/lab-tmpfiles/m1
$ stat -c "%n mtime=%y ctime=%z" ~/lab-tmpfiles/m1
m1 mtime=2026-08-08 21:30:52 +0800 ctime=2026-09-17 21:30:52 +0800   # ctime 是「现在」！
$ systemd-tmpfiles --user --clean; ls ~/lab-tmpfiles
m1                                                                   # 没删
```

改成只看 mtime（`age-by` 前缀 `m:`）后，同一个文件立刻被删：

```text
$ printf "%s\n" "d /home/realtyz/lab-tmpfiles 0700 realtyz realtyz m:30d" \
    > ~/.config/user-tmpfiles.d/lab.conf
$ systemd-tmpfiles --user --clean; ls ~/lab-tmpfiles
（只剩新文件）                                                        # 删了
```

**`touch`、复制、改名以及任何写入都会刷新 ctime**——所以「用 `touch -d` 造一个老文件来测试清理」是最容易骗过自己的实验；真实场景里，一个刚被复制过来的旧文件也不会被清理。要精确控制判据用 `age-by` 前缀，如 `m:30d`（只看 mtime）、`c:7d`（只看 ctime）。

> [!important] `age-by` 前缀的字母含义
> `a`=atime、`b`=birth time、`c`=ctime、`m`=mtime，大写表示「目录条目」的对应时间。前缀写 `m:30d` 就是「只用 mtime 判断」。**不确定时先用 `systemd-tmpfiles --dry-run`（或 `--clean` 的对照实验）验证，再看结果。**

## 3. `/tmp` 文件消失的四种原因

按可能性排序：

1. **`systemd-tmpfiles-clean.timer`**：本机规则是 `D /tmp 1777 root root 30d`，每天跑一次——超龄即删。
2. **重启 / tmpfs**：`/tmp` 若是 tmpfs（很多发行版的 `tmp.mount`），重启即清空。
3. **`PrivateTmp=yes`**：服务自己的 `/tmp` 是私有 tmpfs，服务停止时消失（子笔记 08）。
4. **应用自己清理**：有些软件启动时清理自己的临时目录。

| 场景 | 服务看到的 `/tmp` | 宿主/其他服务能看到吗 |
| --- | --- | --- |
| 普通服务 | 宿主 `/tmp` | 能 |
| `PrivateTmp=yes` | 私有 tmpfs | 不能（除非进命名空间） |
| 容器（Docker/K8s） | 容器自己的 `/tmp` | 不能 |

```bash
systemctl show <unit> -p PrivateTmp               # 验证：这个服务是不是私有 /tmp
stat -c "%n mtime=%y ctime=%z" /tmp/somefile      # 验证：这个文件到底「多老」
systemd-tmpfiles --cat-config | grep -A2 "/tmp"   # 验证：本机对 /tmp 的规则
```

## 4. 服务的数据该放哪

这是「临时文件治理」对运维最实际的一条建议：

| 数据性质 | system 单元放哪 | user 单元放哪 | 用哪个选项让 systemd 建 |
| --- | --- | --- | --- |
| 跨重启必须保留（状态、数据库文件、队列） | `/var/lib/<app>` | `~/.local/state/<app>` | `StateDirectory=app` |
| 运行期共享、重启可丢（socket、pid、锁） | `/run/<app>` | `$XDG_RUNTIME_DIR/<app>` | `RuntimeDirectory=app` |
| 日志 | `/var/log/<app>` | `~/.local/state/log/<app>` | `LogsDirectory=app` |
| 可重建的缓存 | `/var/cache/<app>` | `~/.cache/<app>` | `CacheDirectory=app` |
| 纯临时、可随时丢 | `/tmp`（或服务私有 `/tmp`） | 同左 | 无需声明 |

两列都要看：`StateDirectory=`/`LogsDirectory=` 的落点由 **unit 类型**决定（`systemd.exec(5)` 的 Table 2），本章实验全在 user 单元里做，所以看到的是 `~/.local/state` 那一路，不要照着 system 路径去找。

```ini
[Service]
RuntimeDirectory=myapp        # system 单元：/run/myapp；user 单元：$XDG_RUNTIME_DIR/myapp（属主设为 User=，停止后可清理）
StateDirectory=myapp          # system 单元：/var/lib/myapp；user 单元：~/.local/state/myapp
LogsDirectory=myapp           # system 单元：/var/log/myapp；user 单元：~/.local/state/log/myapp
CacheDirectory=myapp          # system 单元：/var/cache/myapp；user 单元：~/.cache/myapp
ProtectSystem=strict
ReadWritePaths=/var/lib/myapp /var/log/myapp /run/myapp /var/cache/myapp
```

```bash
systemctl show myapp.service -p RuntimeDirectory -p StateDirectory -p LogsDirectory -p CacheDirectory
ls -ld /run/myapp /var/lib/myapp /var/log/myapp     # system 单元；user 单元改为 $XDG_RUNTIME_DIR/myapp ~/.local/state/myapp
```

> [!warning] 不要把跨重启的数据放在 `/tmp` 或 `/run`
> `/tmp` 会被 tmpfiles 清理、可能被 `PrivateTmp` 隔离；`/run` 是 tmpfs，重启即失。**这两处只适合「丢了能重建」的数据**。需要持久化就用 `StateDirectory=`，需要跨进程但不持久就用 `RuntimeDirectory=`。

## 5. 常用命令

| 命令 | 作用 | 风险 |
| --- | --- | --- |
| `systemd-tmpfiles --cat-config` | 列出生效规则（含所有来源） | 只读 |
| `systemd-tmpfiles --create` | 按规则创建缺失的文件/目录 | 会建目录、设权限 |
| `systemd-tmpfiles --clean` | 按 age 清理 | **会删文件** |
| `systemd-tmpfiles --remove` | 删除规则里标记为可删的条目 | **会删文件** |
| `systemd-tmpfiles --dry-run` | 只显示将要做什么（配合其它动作） | 只读 |
| `systemctl list-timers systemd-tmpfiles-clean.timer` | 清理任务的调度 | 只读 |

先干跑，确认要删什么：

```bash
systemd-tmpfiles --user --clean --dry-run
systemd-tmpfiles --cat-config | grep -n "lab"
```

### 实验 10：tmpfiles 的 age 语义

> [!example]- 实验 10：制造一个「40 天前的老文件」，看它为什么没被清
> **怎么做**：建 `~/.config/user-tmpfiles.d/lab.conf` 写 `d <目录> 0700 $USER $USER 30d`；在目录里 `touch -d "40 days ago"` 造一个文件，用 `stat -c "%n mtime=%y ctime=%z"` 看两个时间戳；执行 `systemd-tmpfiles --user --clean` 观察是否被删。再把规则改成 `m:30d` 重跑。
> **预期**：默认规则下文件**不**被删（ctime 是「现在」）；改成 `m:30d` 后**被删**。
> **风险**：低（用户级、专用临时目录）；**耗时**：约 10 分钟；**回滚**：`rm -f ~/.config/user-tmpfiles.d/lab.conf`、`rm -rf <目录>`。
> 机器：任意能跑 `systemd-tmpfiles --user` 的环境。**系统级 `--clean` 不要在生产机上试**——它按系统规则删真正的 `/tmp`、`/run`。

## 常见坑

| 常见做法或说法 | 后果或事实 |
| --- | --- |
| 「`/tmp` 里的文件应该是永久的」 | 它按 age 清理（本机 30 天），还可能是 tmpfs / PrivateTmp；跨重启数据不能放这 |
| 「`touch -d` 造的老文件会被清理」 | `touch` 刷新了 ctime，默认 `age-by` 看 ctime，所以不删；要测判据得用 `m:` 前缀 |
| 「清理没生效」 | 先用 `stat` 看 mtime/ctime/atime，再对照 `--cat-config` 的规则；判据可能不是你想的那个 |
| 把 tmpfiles 规则理解成「定时器」 | 规则只是「怎么维护」，真正定时执行的是 `systemd-tmpfiles-clean.timer` |
| 在服务里往 `/run/<app>` 写持久数据 | `/run` 是 tmpfs，重启即失；持久数据用 `StateDirectory=` |
| 手写 `mkdir` + `chown` 建服务目录 | 容易和 `ProtectSystem=strict` 打架；用 `RuntimeDirectory=`/`StateDirectory=` 让 systemd 建 |
| 直接删 `/tmp` 的清理规则「以防万一」 | 那是把整机的临时文件治理一起关掉，`/tmp` 会越积越多 |
| 在 `/tmp` 放跨进程共享的锁文件且服务开了 `PrivateTmp` | 别的进程看不到那个文件，IPC/锁直接失效 |

## 决策练习

> [!question]- 场景：一个自研服务把「待处理的队列文件」写在 `/tmp/myapp/` 里，最近发现队列文件偶尔整批消失，重启后就正常。你要定位。
> A. 认为是应用 bug，让开发加日志
> B. 先看 `systemd-tmpfiles --cat-config | grep -A2 /tmp` 与 `systemctl show <unit> -p PrivateTmp`，确认是定时清理还是私有 `/tmp`；再把队列改到 `StateDirectory=` 对应的持久目录
> C. 把 `/usr/lib/tmpfiles.d/tmp.conf` 里的 `D /tmp` 规则删掉
> **答案：B。**
> A 可能拖很久，也可能不是应用逻辑问题。
> C 把整机 `/tmp` 治理关掉，风险外溢到所有服务。
> B 是正解：**先确定「谁在清」，再把数据放到与生命周期匹配的位置**。

## 要点自测

> [!question]- `/tmp` 里的文件是谁在清、什么时候清？
> - `systemd-tmpfiles-clean.timer` 每天跑一次（本机实测 next 为 23 小时后），按 `/usr/lib/tmpfiles.d/tmp.conf` 的 `D /tmp 1777 root root 30d` 删除超龄条目。
> - 此外重启（tmpfs）、`PrivateTmp`（服务私有 tmpfs）、应用自清理也会让文件消失。
> - 验证：`systemctl list-timers | grep tmpfiles`、`systemd-tmpfiles --cat-config | grep -A2 /tmp`。
> - **第一反应不要是什么**：不要为了「保险」把 `/tmp` 规则删掉——那是把整机治理关掉。

> [!question]- `systemd-tmpfiles --clean` 为什么有时不删「很久没改」的文件？
> - 默认年龄判据是 mtime/atime/ctime 一起看：**任一时间戳较新就不清理**。
> - `touch`、复制、改名都会刷新 ctime，所以刚被「造旧」或刚被复制过来的文件会被保护。
> - 要精确控制就用 `age-by` 前缀，例如 `m:30d` 只看 mtime、`c:7d` 只看 ctime。
> - **第一反应不要是什么**：不要一看到「没删」就说清理没生效——先 `stat -c "%y %z"` 看三个时间戳。

> [!question]- 服务的数据应该放 `/tmp`、`/run` 还是 `/var/lib`？
> - 跨重启必须保留 → system 单元 `/var/lib/<app>`、user 单元 `~/.local/state/<app>`（都是 `StateDirectory=`）。
> - 运行期共享、重启可丢 → system 单元 `/run/<app>`、user 单元 `$XDG_RUNTIME_DIR/<app>`（都是 `RuntimeDirectory=`）。
> - 纯临时、可随时丢 → `/tmp`（注意 age 清理与 `PrivateTmp`）。
> - 让 systemd 建目录比手写 `mkdir` 更可靠，且能和 `ProtectSystem=strict` 配合。
> - **第一反应不要是什么**：不要把「图省事」写在 `/tmp` 当成能长久的方案。
