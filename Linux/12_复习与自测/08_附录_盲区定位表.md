# 附录：盲区定位表

自测完成后暴露出的"不会"分两类：一类确实未知，另一类是**自认为掌握**。两者的补法完全不同，但在表现上都呈现为"这道题没有答好"。

本表的作用是把"无法作答"这一现象定位到**四条线与约束环上的具体位置**，据此确定补哪一篇、以及如何验证补缺完成。

## 1. 定位表

第一列为自身出现的现象，不是系统故障现象。

| 出现的现象 | 所属资源线 | 缺口类型 | 补法 | 验收方式 |
| --- | --- | --- | --- | --- |
| 面对现象时无法判断"属于哪条线" | 四条线之间 | 分类能力 | 回到《总纲》确认四条线各自提供何种资源，再用《连接点矩阵》的速查表做归类练习 | 抽取十个现象，能立即指出所属线与涉及的两个连接点 |
| 每条线可单独表述，但无法串联 | 连接点 | 衔接处 | 绘制三张图：机器的静态全貌、一个动作经过的层、一次故障的传导链 | 交由同事查看 30 秒，其能说出该图所回答的问题 |
| 仅能给出结论，无法给出证据 | 观察面 | 证据层 | 回到对应阶段的实操篇重新执行命令，记录输出形态（而不是命令本身） | 每条结论旁均能写出一行"命令 + 数值形态 + 条件" |
| 知道应查看哪个字段，但无法说明"多少算异常" | 观察面 | 判据与基线 | 先建立基线：同一口径、带时间戳、至少两次读数、跨一个业务周期；再由观测反推上限（见《压力与排队》的容量算法） | 能说明"与基线比较、与哪一项对照、看到它后转向哪一步"，并给出该字段的基线值 |
| 数字能记住，但单位与条件经常遗漏 | 观察面 | 口径 | 统一容量用 MiB、时间用秒；每个数字补充"窗口 + 工具版本 + 并发" | 任取一个数字，能完整说明单位、来源与成立条件 |
| 被追问"依据是什么"即无法作答，第二问更无法承接 | 全部 | 边界与代价 | 每条结论后补三行：何种条件下不成立、该做法牺牲什么、回滚方式是什么 | 同一道题可承接两层追问，每层均能作答 |
| 原理表述顺畅，但被问及对应命令时无法给出 | 观察面 | 判据与证据 | 将"现象 → 判据 → 命令"整理为三列表格 | 任取一个现象，能在十秒内给出命令及其验证目标 |
| 命令均掌握，但说不清何时不可使用 | 约束环与组织层 | 风险 | 每个动作写一句"第一反应不要做什么" | 二十个高风险动作的"不要做"能脱口而出 |
| 内容可用中文表述，但换成容器场景即无法作答 | 约束环第 3 层 | 命名空间与 cgroup | 明确宿主侧与容器侧各自的取数位置，做一次对照 | 三类容器现象（被终止、被限流、连接失败）均有对应的宿主侧取证路径 |
| 能够讲述但不敢在真实机器上操作 | 持久线与组织层 | 实操经验 | 执行演练链中可自行恢复的项目（独立挂载点与独立命名空间） | 一份含观测指纹与恢复耗时的演练记录 |
| 遇到"偶发"类问题即无从下手 | 连接线与算力线 | 队列意识 | 回到《压力与排队》掌握四条线各自的排队点与计数器 | 给定一个偶发失败场景，能指出应先查看哪个队列与哪一项累计计数 |
| 修改配置后问题消失，但无法解释此前为何未生效 | 约束环 | 生效链 | 掌握五层（四层技术上限 + 组织层）与"生效值取法"；对每一类各取一次生效值 | 能举出一个"已修改但未生效"的层间错位实例 |
| 知道需要备份，但无法判断达到何种程度才算充分 | 持久线与组织层 | 可恢复性 | 阅读 RTO/RPO 与备份的验收方式（能够恢复并计时） | 能说明快照、副本、归档各自不能防范的情形 |
| 复盘时写不出改进项 | 组织层 | 交付标准 | 改进项一律写成"动作 + 责任人 + 期限 + 验收方式" | 任抽一条改进项，四个要素齐全 |
| 压力下处置失去条理 | 观察面与组织层 | 顺序 | 固定三项动作：先量化影响面、先执行可逆动作、一次只改一个变量 | 在值班场景下能按顺序说明前三步 |
| 无法判断自身水平 | — | 验收标准缺失 | 使用下一篇《能力自检清单》逐项核对，而不是凭印象 | 清单中每一项都能指出自身所处档位 |

## 2. 六类缺口与补法

定位到"缺的是哪一层"之后，补法就固定了。这六类里前五类是知识缺口，最后一类是节奏缺口。

| 缺口 | 典型表现 | 补法 | 不要做什么 |
| --- | --- | --- | --- |
| **结论型** | 完全没有方向，连术语都不熟悉 | 回到对应阶段的原理篇，用自己的话写出定义并配一个反例 | 不要从背结论开始 |
| **判据型** | 知道应查看什么，但不知道多少算异常 | 先确定该字段的基线；做一次单变量对比（只改一个条件，观察输出变化） | 不要凭感觉设定阈值，也不要用其它机器的数值当本机阈值 |
| **证据型** | 能判断，但给不出证据 | 重新执行命令，记录**输出形态**与关键数值 | 不要只记录命令而不记录输出 |
| **边界型** | 结论正确，但更换条件后即失效 | 列出三条反例：分别更换内核版本、发行版、容器环境各验证一次 | 不要以"应该大致相同"作结 |
| **代价型** | 知道怎么做，不知道风险 | 补三行：代价、回滚方式、影响面 | 不要把风险留给别人发现 |
| **节奏型** | 复习断档、每次都从头再来 | 一次只处理一个能讲完的闭环（现象 → 判据 → 命令 → 边界），每条错题写下下一次复查日期 | 不要一次补三小时 |

补缺的正确形态是**带着一个具体问题回到一到两篇**，不是重读一整章。如果发现"越补越多、每篇都要重读"，通常说明缺的不是细节，而是前置概念——回到《总纲》重新确认那一条线的账本与判据。

## 3. 五件交付物

能力不能靠"我觉得会了"验收。以下五件是这一阶段唯一可交付、可给别人看的对象；每一件都要能被第三方检查。

| # | 交付物 | 内容要求 | 验收方式 |
| --- | --- | --- | --- |
| 1 | **体系图** | 至少两张：机器上有什么（静态全貌）、一个动作怎么穿过各层（动态全貌） | 给同事看 30 秒，他能说出这张图在回答什么问题 |
| 2 | **错题清单** | 五列：题目 / 当时的答案 / 正确口径 / 缺的那一层 / 下一次复查日期 | 任抽五条，都能看到"缺的那一层"与具体日期 |
| 3 | **一页纸** | 一屏内；含现象、判据、命令、阈值、边界、"不要做什么" | 给没读过这套笔记的人看 3 分钟，他能复述动作顺序 |
| 4 | **限时答辩记录** | 一轮 30 分钟；含六段答案（现象与影响面 → 分层 → 证据 → 结论 → 止损 → 改进）与两层追问 | 内容里同时出现判据、命令、边界、止损与回滚 |
| 5 | **端到端演练记录** | 含实验前基线、观测指纹、恢复动作、恢复耗时、清理复核、未实测清单 | 任抽一条，能说出"指纹长什么样、恢复用了多久" |

收口检查（五件齐了再勾）：

- [ ] 体系图能解释一个真实现象（例如"服务变慢"的定位路径）
- [ ] 错题清单里每条都有复查日期，且至少完成过一轮 D+1
- [ ] 一页纸的每一行都能溯源到一篇原文
- [ ] 限时答辩记录里有一道题的自评偏低，并已重做
- [ ] 演练记录里明确写出未实测的部分与补做方式

复查日期只写四个：D+1、D+3、D+7、D+21。它不是学习方法，只是"这条错题什么时候再碰一次"的排期；没有日期的错题等于没有复查。

## 4. 五张随身卡

前四张对应高压场景，各一屏内，内容都是判断顺序而不是命令清单；第五张是给组织的产物，交出去就算完成。

**值班卡（30 秒能念完）**

1. 分级与通报：影响面多大、要不要叫人、要不要向上报。
2. 止损：限流 → 摘流量 → 回滚 → 扩容 → 重启（顺序按可逆性，一次只改一个变量）。
3. 取证：在止损的并行线上做，先记下当时的读数。
4. 验证：指标 + 业务 + 观察窗口，三者都要。
5. 升级：解释不了但服务还活着，也要升级。

**通报卡（首报四要素 + 节奏 + 升级线）**

1. **首报要素**：影响面（谁、多严重）、当前状态（在处理还是已止损）、已做的动作、下一次更新时间。缺少任何一项，接收方都会再次询问，处置过程将被重复打断。
2. **更新节奏**：约定一个固定间隔（例如每 15 或 30 分钟），到点就更新——哪怕内容是"没有新进展"。事故期间最贵的不是信息少，是信息不对称。
3. **升级条件**（写到纸面上，不要临场判断）：影响面扩大、止损动作无效、需要跨团队列授权、超过预定时间仍未定位、涉及数据安全。
4. **对外口径**：谁有权对外发布、发布前确认什么（影响面数字、是否涉及用户数据、恢复时间预期）。工程师不要在群里自行对外承诺恢复时间。

**交接卡（班次级交接，四项都要写）**

1. 未闭环事项：每条带当前状态与下一个动作责任人。
2. 观察中的变更：刚做完、还在观察窗口内的改动（注明窗口何时结束）。
3. 暂缓与静默的告警：被静默/抑制/延后的告警及其**到期时间**——最危险的交接项，静默到期没人接就是漏报。
4. 下次复查时间：错题清单与台账里到期的事项。

交接的验收标准是**接班人无需再行询问即可接手**。

**面试卡（回答任何开放题都用同一副骨架）**

1. 现象与影响面：什么时候开始、谁受影响、多严重。
2. 分层：先按线排除，指出落在哪条线与哪个连接点。
3. 证据：命令 + 数值形态 + 成立条件。
4. 结论：判断是什么、置信度、支持与排除的理由。
5. 止损：先做可逆动作，给出回滚方式。
6. 改进：补一项监控或流程，带责任人与验收方式。

**四句边界（任何时候都能背出来）**

- 先做可逆的，不可逆的排在最后。
- 一次只改一个变量。
- 证据会消失，取证排在处置之前。
- 重启能恢复不等于问题被解释；根因留给复盘。

## 5. 常见误解

| 常见做法或说法 | 后果或事实 |
| --- | --- |
| 盲区处置就是"再读一次那一章" | 先判断缺哪一层。缺判据却去重读机制，一下午都补不上 |
| 错题只记正确答案 | 最关键的一列是"当时出错的原因"；只抄答案第二次还会错在同一处 |
| 排期排得很满（每天四小时以上） | 第三天开始无法作答；宁可每天两段、每段 25 分钟，也不要一次补三小时 |
| 只排"读书"不排"产物" | 复习变成重读；每段必须有一个看得见的产出 |
| 只处理新错题，不复查老错题 | 老错题会重新变成新错题；D+1 / D+3 / D+7 是硬性动作 |
| 为了凑交付物而抄一页纸 | 抄写不提高提取强度；一页纸必须是压出来的，不是摘出来的 |
| 演练只做纸面推演 | 少了观测指纹与耗时；"会讲"与"会做"之间差一次动手 |
| 把未实测的当实测写 | 更换环境后结论会被推翻；如实标注反而更可靠 |

## 要点自测

- 盲区定位的第一步是什么？为什么它决定补缺是 20 分钟还是一下午？
- 六类缺口里哪几类是知识缺口，哪一类不是？非知识那一类怎么处置？
- 为什么"越补越多"通常说明缺的是前置概念？
- 五件交付物里哪一件最容易被省略？它的验收点有哪几个？
- 为什么错题要写"下一次复查日期"？不写会怎样？
- 五张随身卡里共同的骨架是哪几步？
- 交接卡里最危险的一项是哪个？为什么"静默的告警"必须带到期时间？
- 通报卡的首报四要素中，缺少哪一项会导致接收方反复询问？
- 四句边界里哪一句最容易被违反？为什么？
