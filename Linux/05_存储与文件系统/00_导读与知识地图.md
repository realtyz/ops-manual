# 存储与文件系统

## 知识地图

### 一块盘的服役一生

时间主线跟着**一块盘**走：从被机器认出来，到拥有分区与文件系统，到挂进目录树开始服役，到容量长大，最后到坏掉、可控地换走。

```mermaid
flowchart LR
  A["① 接管<br/>认盘 · 分区 · 记台账"] --> B["② 成型<br/>选型 · mkfs · 验挂"]
  B --> C["③ 上岗<br/>挂载 · fstab · 验收"]
  C --> D["④ 长大<br/>池 · 在线扩容 · 快照"]
  D --> E["⑤ 冗余与退役<br/>RAID · 健康 · 换盘"]
```

| # | 阶段 | 这个阶段在发生什么 | 到这个阶段要能说清什么 |
| --- | --- | --- | --- |
| 1 | 接管 | 内核识别块设备、读出盘头的分区表元数据，并写下新的分区表。 | 设备名为什么靠不住，以及动手前的三问各自要回答什么。 |
| 2 | 成型 | `mkfs` 在设备上写下超级块、inode 表、块位图与日志区等结构。 | 选型的三问各自问什么，以及哪些参数一旦定下就再也改不了。 |
| 3 | 上岗 | 内核把文件系统的根接到一个目录上，并交给 systemd 保持。 | 挂载为什么遮住目录原有的内容，以及哪两个挂载选项决定出错时的保护行为。 |
| 4 | 长大 | 内核在块设备与文件系统之间插入一层映射。 | 从「盘变大」到「业务可用空间变大」要依次经过哪几层。 |
| 5 | 冗余与退役 | 内核用冗余数据继续服务，并重建缺失的成员。 | 重建窗口为什么是风险，以及换盘最容易在哪三步出事。 |

### 三个跨阶段的核对对象

主线之外还有三个量需要跨阶段核对。这三个量各自不产生新的现象，但每一个判断都要用到它们，因此要在下面写明的每一个阶段核对其字段。

- **容量口径与归属。** 它贯穿全部五个阶段。接管阶段要读 `lsblk` 的 `SIZE` 与 `parted print` 给出的分区起止扇区，才能确认这块盘与这些分区上还有没有别人在用；成型阶段由 `mkfs` 定下块大小与 inode 密度，因此此后只有读 `tune2fs -l` 的 `Block size` 与 `Inode count`，才能把「文件有多大」换算成「占多少块」；上岗阶段由挂载选项决定配额记账是否开启，所以要读 `/proc/mounts` 里该挂载点的选项；长大阶段要读 `lvs` 的 `data_percent` 与 `metadata_percent`，才知道池里还剩多少可分配空间；冗余与退役阶段要读 `mdadm --detail` 的阵列容量与成员状态，才能确认换盘之后可用容量回到预期。这一条最后要回答的是：`df` 与 `du` 对不上时，差值落在被持有的已删除文件、被挂载覆盖的目录、保留块与元数据、稀疏文件这四类中的哪一类。
- **容量上限与拒绝写入。** 它贯穿成型、上岗、长大与冗余和退役这四个阶段，回答的是「还有空间却写不进去」。成型阶段的上限是块数与 inode 数；上岗阶段的上限是 ext4 的保留块与配额，前者读 `tune2fs -l` 的 `Block count` 与 `Reserved block count` 两个字段之比，后者读配额报表里的用量、软硬限与宽限期状态；长大阶段的上限是池的数据与元数据上限，读 `lvs` 的 `data_percent` 与 `metadata_percent`；此外还有一类上限与空间无关，进程的句柄上限读 `/proc/<pid>/limits`，事件监控的上限读 `fs.inotify.*` 这几个内核参数。这一条最后要回答的是：拒绝写入的是哪一个上限，以及报错原文是 `ENOSPC`、`EDQUOT` 还是 `EROFS`。
- **写入顺序与完整性证据。** 它贯穿上岗、长大与冗余和退役这三个阶段。上岗阶段要读 `/proc/mounts` 里的挂载选项，确认 `errors=remount-ro` 这类出错行为是否显式配置过；长大阶段要读 `/proc/meminfo` 的 `Dirty` 与 `Writeback`，判断写入是积压在页缓存里，还是卡在设备上；冗余与退役阶段要读 `smartctl -a` 的重映射扇区数与待处理扇区数、以及 `/proc/mdstat` 的成员标记，判断退化的位置在介质上还是在冗余关系上。这一条最后要回答的是：哪些动作不可逆，以及处置顺序为什么必须固定。

## 术语速查

| 名词 | 一句话解释 | 在哪一篇展开 |
| --- | --- | --- |
| 块设备（block device） | 能按固定大小的块随机寻址的存储，盘、分区、阵列、逻辑卷都是它 | 原理：块设备、分区与池 |
| 分区表 / GPT / MBR | 记录「这块盘被切成几段」的元数据；GPT 是现代默认，MBR 单盘上限 2 TiB | 原理：块设备、分区与池 |
| 设备名漂移 | 同一块盘在换插槽、加盘或云盘重挂后，名字可能从 `sdb` 变成 `sdc` | 原理：块设备、分区与池 |
| PV / VG / LV | 物理卷 / 卷组 / 逻辑卷，卷管理器的三层结构 | 原理：块设备、分区与池 |
| 精简置备（thin provisioning） | 允许卷声明空间大于池实际容量的做法，池写满会波及全组 | 原理：块设备、分区与池 |
| RAID / 重建 | 多盘冗余阵列 / 用冗余数据恢复缺失盘内容的过程 | 原理：块设备、分区与池 · 体系 |
| URE | 厂商标称的不可恢复读错误率，直接决定重建失败概率的量级 | 原理：块设备、分区与池 |
| 块 / 块大小 | 文件系统分配空间的最小单位；建文件系统时定下，之后改不了 | 原理：文件系统的结构与选型 |
| inode | 文件的元数据（权限、属主、时间、链接数、块指针），不含文件名 | 原理：文件系统的结构与选型 |
| 目录项（dentry） | 把文件名映射到 inode 号的对应关系；名字存在这里 | 原理：文件系统的结构与选型 |
| 超级块 | 记录文件系统的块数、inode 数与状态等汇总字段；它的备份副本是救援入口 | 原理：文件系统的结构与选型 |
| 日志（journal） | 按顺序记录元数据的变更，崩溃后靠重放恢复一致性 | 原理：文件系统的结构与选型 |
| 分配组（AG） | XFS 把空间切成的独立管理单元，支持并行分配，也是它不能缩容的原因 | 原理：文件系统的结构与选型 |
| 表观大小 / 实际占用 | 表观大小是文件声称的字节数，实际占用是真正分配的块数；稀疏文件上两者差别很大 | 原理：块设备、分区与池 · 实操 |
| 保留块 | ext4 默认留给 root 的那部分空间，普通用户写不进去 | 原理：容量边界、挂载与可见性 |
| 配额 / 项目配额 | 给用户、组或**目录树**设的容量上限；目录级边界用项目配额 | 原理：容量边界、挂载与可见性 |
| `ENOSPC` / `EDQUOT` / `EROFS` | 三种不同的 errno：`ENOSPC` 表示文件系统上已无可用资源，`EDQUOT` 表示配额到顶，`EROFS` 表示文件系统处于只读 | 原理：容量边界、挂载与可见性 |
| 句柄（fd） | 进程打开文件或套接字的编号，有会话、服务、系统三级上限 | 原理：容量边界、挂载与可见性 |
| inotify | 文件事件监控机制，有 watch 数、实例数与事件队列三道上限 | 原理：容量边界、挂载与可见性 |
| 绑定挂载（bind mount） | 把一个已有目录再挂到另一个位置，同一份内容两个入口 | 原理：容量边界、挂载与可见性 |
| Page Cache / 回写 | Page Cache 用空闲内存缓存文件内容，回写则负责把脏页稍后异步落盘 | 原理：写入路径与完整性 |
| `fsync` | 要求内核把数据落到设备的动作；不调用就只有缓存保证 | 原理：写入路径与完整性 |
| `errors=remount-ro` | 出错即把文件系统重挂只读；**ext4 默认是出错继续** | 原理：写入路径与完整性 |
| 干跑检查 | 只报告不修改的检查（如 `e2fsck -n`、`xfs_repair -n`） | 原理：写入路径与完整性 · 实操 |
| `await` / `aqu-sz` / `%util` | `await` 是平均完成时间（含排队），`aqu-sz` 是平均队列深度，`%util` 是设备忙的时间比例 | 实操 |
| `svctm` | 已废弃的列，工具文档已标注不可靠，不要用它下结论 | 实操 |
| 介质健康计数 | 重映射扇区数、待处理扇区数与寿命消耗等；判据是同一计数的趋势，而不是单次读数 | 体系 · 实操 |
| 硬挂载 / 软挂载（`hard`/`soft`） | 网络存储的对端不可达时，硬挂载会无限重试并让进程停在不可中断睡眠，软挂载会超时返回错误而可能造成数据不一致 | 原理：写入路径与完整性 |
| 多路径（multipath） | 同一存储的多条物理路径聚合与故障切换；切换瞬间有秒级 IO 停顿 | 原理：写入路径与完整性 |
| 回收通知（TRIM） | 文件系统告诉闪存盘「哪些块已无效可擦除」的动作 | 原理：写入路径与完整性 |
| `data_percent` / `metadata_percent` | 池中数据与元数据的使用百分比，两个都必须监控 | 体系 · 治理 |

## 故障现场定位表

排障的第一问不是「怎么修」，而是「**这块空间由哪个文件系统或哪一层负责、拒绝写入的是哪一类上限、这条链路的哪一层有问题**」。这张表用来把现象定位到类别，再进对应篇目。

| 你看到的现象 | 属于哪一类 | 现场在哪 | 第一反应不要做 |
| --- | --- | --- | --- |
| 写入报 `No space left on device`，容量还有余 | inode 或保留块 | 容量与 inode 两个使用率、文件系统的保留块字段 | 不要因为「还有空间」就否掉磁盘方向 |
| 写入报 `Disk quota exceeded` | 配额 | 配额报表、软硬限与宽限期状态、挂载选项里的记账开关 | 不要和 `No space left on device` 混为一谈 |
| 删了大文件，用量不降 | 已删除但仍被持有 | 进程的打开句柄清单 | 不要反复删同一个文件，也不要先重启整机 |
| `df` 与 `du` 差了几十 GiB | 四类不一致 | 被持有的删除文件、被覆盖的目录、保留块与元数据、稀疏文件 | 不要说「某个工具不准」就结束 |
| 挂载后目录里原有数据「消失」 | 被挂载覆盖 | 从上层绑定挂载查看 | 不要以为数据被删了，更不要在里面重建同名文件 |
| 目录「应该」在独立盘上，其实不在 | 归属假设未验证 | 该路径实际属于哪个文件系统 | 不要用目录名推断文件系统归属 |
| 文件系统突然变只读 | 内核保护动作 | 内核日志与硬件健康计数 | **不要重挂为可写** |
| 内核日志出现介质错误 / IO 错误 | 硬件先兆 | 内核日志、健康关键计数 | 不要先重启（现场会被清掉） |
| 阵列降级 | 冗余丢失 | 阵列状态与成员标记 | 不要立刻拔盘换新 |
| 设备完成时间很高 | 排队或设备退化 | 完成时间与队列深度的组合、请求大小、读/写分开看 | 不要只看一个列就宣布饱和或换盘 |
| 写入变慢、进程进不可中断睡眠 | 回写积压或存储链路 | 脏页与回写量、进程级 IO、网络存储参数 | 不要跳过取证直接重启 |
| 整机容量命令卡住、大量进程不可中断睡眠 | 挂载点卡死 | 内核日志、多路径状态、网络可达性 | 不要批量强杀进程 |
| 网络存储对端抖动，写请求长时间无响应 | 挂载语义 | 挂载选项与超时重传参数、对端与网络状态 | 不要为了「不卡」把写场景改成软挂载 |
| 闪存盘写入变慢、寿命告警 | 回收与磨损 | 回收任务的启用状态、寿命消耗与备用块余量 | 不要把它当容量问题，也不要只看单次寿命读数 |
| 重启后进紧急模式、报挂载失败 | 挂载配置 | 失败的挂载单元与其日志 | 不要重装 |
| 云盘扩容了但业务容量没变 | 链路只做了一半 | 沿设备、分区、PV、VG、LV、文件系统逐层核对 | 不要跳过中间层直接扩文件系统 |
| 共享目录被一个租户写满 | 缺边界 | 目录用量排行、配额报表 | 不要只做事后清理 |
| 应用报 `too many open files` 或监控漏事件 | 非空间的容量上限 | 进程实际生效的限制、系统级计数与事件监控上限 | 不要只调大上限而不看应用设计 |
| 健康计数出现非零值 | 需要看趋势 | 同一计数的历史序列 | 不要用单次数值决定换盘 |

两个容易被忽略的边界：

- **「够不够」与「谁在用」是两个问题。** 前者要读各文件系统的容量字段（`df` 的已用块与可用块、`df -i` 的 `IUse%`、配额报表、`lvs` 的 `data_percent`），后者要看目录树与进程。混在一起问，就会得出「还有 40% 怎么可能写不进去」这类结论。
- **「变慢」与「写坏」是两种结局。** 回写积压、排队、重建都制造变慢（可观测、可调优）；只读、介质错误、阵列降级制造数据风险（先取证，再动手）。**修复类动作大多不可逆**，这是处置顺序必须固定的原因。
