## 0. 30 秒速览

> [!abstract] 这一篇只要记住五句话
> - **KiB ≠ KB**：`KiB/MiB/GiB/TiB` 是 1024 进位，`KB/MB/GB/TB` 是 1000 进位。`df -h` 用 1024 进位（等价于 1024 的 GiB），厂商与网络带宽用 1000 进位。
> - **标称 1TB 的盘，`df -h` 大约显示 931GiB，再扣掉元数据才是可用**——这不是「少了」。
> - **`ls -l` 是表观大小、`du` 是实际占块、`df` 是文件系统账本**；三个数字不一样是正常的（稀疏文件、延迟分配、元数据、保留块）。
> - **`/proc` 与 `/sys` 是内核的窗口**：设备列表在 `/proc/partitions`，挂载在 `/proc/mounts`，IO 计数在 `/proc/diskstats`，队列与调度器在 `/sys/block/<dev>/queue/`。
> - **基线要连环境一起记**：设备型号/序列号、介质类型（`ROTA`）、文件系统类型与挂载选项、单位口径；缺一项，半年后这份数据就不可比。

## 1. 容量单位：先解决「数字对不上」的第一层

| 写法 | 进制 | 常见出现位置 |
| --- | --- | --- |
| `KiB`/`MiB`/`GiB`/`TiB` | 1024 进位（2¹⁰ 的幂） | Linux 的 `df -h`、`free -h`、`lsblk`、本笔记全文 |
| `KB`/`MB`/`GB`/`TB` | 1000 进位 | 硬盘与云盘标称、网络带宽、`dd`/`fio` 的带宽输出 |

```bash
df -h /        # 验证：1024 进位（GiB 口径，Linux 习惯写法）
df -H /        # 验证：1000 进位（GB 口径，和厂商标称/云厂商控制台对齐）
lsblk -b -o NAME,SIZE   # 验证：原始字节数（不带任何单位歧义，写台账时用这个最稳）
```

**为什么 1TB 的盘 `df -h` 只有 931GiB？**

1. **进位差**：厂商的 1TB = 10¹² 字节；1024 进制的 1TiB = 1.0995×10¹² 字节。所以 10¹² 字节 ≈ **931GiB**。
2. **文件系统元数据**：inode 表、日志、位图、超级块备份都占用空间，`mkfs` 之后就「少」了一点。
3. **保留块**：ext4 默认再留 5% 给 root（子笔记 09），普通用户看到的可用空间又要少一截。
4. **分区表与对齐**：分区一般从 1MiB 处开始，对齐会浪费掉开头一点点空间（这是好事，不要为省这 1MiB 去破坏对齐）。

```bash
lsblk -b -o NAME,SIZE,TYPE          # 验证：设备的总字节数（第一个"台阶"）
df -B1 /data                        # 验证：文件系统总容量与可用容量（第二个"台阶"，单位是字节）
tune2fs -l /dev/<dev> | grep -E 'Block count|Reserved block count|Block size'
                                     # 验证：ext4 的总块数、预留块数与块大小（第三个"台阶"，可以自己算账）
```

## 2. 三个「大小」口径

```bash
ls -l /data/bigfile                  # 验证：表观大小（文件声称的字节数）
du -h /data/bigfile                  # 验证：实际占用（真正分配了多少块）
du -h --apparent-size /data/bigfile  # 验证：强制按表观大小统计，与 ls -l 对齐
stat /data/bigfile                   # 验证：Size（表观）与 Blocks（512B 块数）同屏对照
df -h /data                          # 验证：文件系统账本视角（含元数据与预留块）
```

| 口径 | 谁在算 | 什么时候会「偏」 |
| --- | --- | --- |
| 表观大小 | `ls -l`、`stat %s`、`du --apparent-size` | 稀疏文件（空洞不计块）、压缩/重删文件系统 |
| 实际占用 | `du`、`stat %b` | 小于块的文件也会占满一个块；稀疏文件远小于表观大小 |
| 文件系统账本 | `df` | 含元数据与预留块；含「已删除但被进程持有」的部分 |

> [!important] 容量预估要用哪一个？
> **估算「这块盘能不能放下」时用表观大小**（业务看到的是文件大小）；**估算「还能写多少」时用 `df`**；**排查「空间被谁吃了」时用 `du`**，但要记得它看不见两类东西（子笔记 09）。

## 3. 设备层：`/dev`、`/proc` 与 `/sys`

```bash
lsblk -o NAME,SIZE,TYPE,FSTYPE,MOUNTPOINT,ROTA,MODEL,SERIAL
                                     # 验证：一屏看全四层（含序列号，台账与换盘要用）
cat /proc/partitions                 # 验证：内核认到的块设备与区块数（最原始的设备清单）
cat /sys/block/sda/queue/rotational  # 验证：0=SSD/NVMe，1=机械盘（与 lsblk 的 ROTA 同源）
cat /sys/block/sda/queue/scheduler   # 验证：当前 IO 调度器（方括号里是生效值，子笔记 11）
cat /sys/block/sda/queue/nr_requests # 验证：块层队列深度上限（子笔记 11、12）
cat /sys/block/sda/queue/read_ahead_kb   # 验证：预读窗口（顺序读场景的常见调优点）
```

| 观测点 | 内容 | 什么时候看 |
| --- | --- | --- |
| `/proc/partitions` | 主设备号、次设备号、区块数、设备名 | 需要最原始的设备清单（脚本里常用） |
| `/sys/block/<dev>/size` | 设备容量（**512 字节扇区数**） | 校验设备大小；`size × 512` 就是字节数 |
| `/sys/block/<dev>/queue/*` | 调度器、队列深度、预读、`rotational` | 判断设备类型与调度策略 |
| `/proc/mdstat` | 软 RAID 状态与重建进度 | 有 `mdadm` 阵列时必看（子笔记 08） |

## 4. 挂载层：`/proc/mounts` 与 `findmnt`

```bash
findmnt -o TARGET,SOURCE,FSTYPE,OPTIONS       # 验证：当前挂载关系与参数（首选，输出好读）
cat /proc/mounts | head                       # 验证：内核视角的挂载表（脚本里常用）
grep -v '^#' /etc/fstab                       # 验证：配置里写了什么（和实际挂载对比是排障第一步）
findmnt --verify --verbose                    # 验证：fstab 语法与可挂载性（改完必跑，子笔记 06）
```

**`/proc/mounts` 与 `/etc/fstab` 的关系**：前者是**当前实际生效**的挂载，后者是**开机时希望生效**的挂载。两者不一致很常见（自动挂载、手动挂载、挂载失败），排障时要先问「以哪个为准」——**永远是 `/proc/mounts`（实际状态）为准**。

## 5. IO 计数：`/proc/diskstats`

```bash
cat /proc/diskstats | head -5    # 验证：每块设备的读/写次数、扇区数、耗时（iostat 的数据就来自这里）
iostat -x 1 3                    # 验证：把上面的原始计数换算成速率与延迟（子笔记 12 详解各列）
```

`/proc/diskstats` 每行前三个字段是「主设备号、次设备号、设备名」，后面依次是读完成次数、读合并次数、读扇区数、读耗时（ms）、写完成次数……**它给的是「开机以来的累计值」**，判断现场必须做差值（这正是 `iostat` 做的事）。看它的价值在于：**没有 `sysstat` 包时也能取到 IO 数据**。

## 6. 生产动作：一份可复用的存储基线卡

接一台机器时按下面五组取数，**全程只读、生产机也可以做**，把输出存成一份文件（例如 `/root/storage-baseline-$(date +%F).txt`）：

```bash
date; hostname; uname -r; cat /etc/os-release | head -2
                                     # 验证：时间与版本（决定默认值与行为差异）
lsblk -o NAME,SIZE,TYPE,FSTYPE,MOUNTPOINT,ROTA,MODEL,SERIAL,UUID
                                     # 验证：设备 → 分区 → 文件系统 → 挂载点 + 身份（型号/序列号/UUID）
df -hT; df -i                        # 验证：容量与 inode 两个视角（ext4 必看 inode）
findmnt -o TARGET,SOURCE,FSTYPE,OPTIONS
                                     # 验证：挂载参数（有没有 nofail/_netdev/noatime/ro）
pvs; vgs; lvs; cat /proc/mdstat      # 验证：有 LVM/RAID 时的池与阵列结构
cat /sys/block/<dev>/queue/scheduler; cat /sys/block/<dev>/queue/rotational
                                     # 验证：调度器与介质类型
smartctl -H /dev/<dev>; nvme list    # 验证：健康总判定与 NVMe 设备清单（子笔记 08）
```

> [!tip] 第一反应不要是「直接开始清理或扩容」
> 基线没取就动手，等于**先把现场改掉再看**：你不知道昨天是多少、也不知道 `df` 与 `du` 差在哪。容量类故障几乎都是累积出来的，**「与上次基线对比」是唯一能看出趋势的手段**。

## 常见坑

| 常见做法或说法 | 后果或事实 |
| --- | --- |
| 把 `df -h` 的 GiB 和厂商标称的 GB 直接比 | 1TB 标称 ≈ 931GiB，差值是进位口径造成的，不是丢盘 |
| 用 `du` 的合计去核对 `df` | 两者口径不同，还有四类正常差异（子笔记 09）；核对要说明差在哪一类 |
| 只看 `/etc/fstab` 判断挂载状态 | fstab 是「期望」，`/proc/mounts`/`findmnt` 才是「实际」 |
| 用 `/proc/diskstats` 的累计值直接下结论 | 它是开机以来的累计数，必须做差值或用 `iostat` 换算 |
| 认为 `lsblk` 显示的 SIZE 就是可用空间 | 那是设备容量，不含文件系统元数据、分区表与预留块 |
| 用 `du -sh /` 去查根分区占用 | 会跨挂载点统计别的文件系统；要加 `-x`，还要处理权限与稀疏文件 |
| 基线只记容量不记型号与挂载参数 | 迁移、扩缩容、性能对比时无法复现条件，数据不可比 |

## 决策练习

> [!question]- 场景：业务方说「我们的 1TB 数据盘，`df -h` 只显示 931G，你们是不是少给了 70G？另外实际只能写 880G，剩下 50G 去哪了？」
> A. 回答「换算问题，不用管」
> B. 分三步解释：① 1TB（10¹² B）换算成 1024 进制约为 931GiB，这是单位口径；② 扣掉文件系统元数据与分区对齐，可用会再少一点；③ ext4 还默认预留 5% 给 root（`tune2fs -l` 的 `Reserved block count`），`df` 的可用空间已经扣掉了它——如果是数据盘，可以在评估后调小预留比例
> C. 直接把盘重新格式化，把 `-m 0` 用上，把空间「要回来」
>
> **答案：B。**
> A 太粗暴：业务方会继续认为你敷衍，而且「能写多少」的问题没答。
> C 是破坏性操作：重建文件系统会清空数据，而且 `-m 0` 会让 root 在磁盘写满时失去自救空间，**系统盘绝对不能这么干**。
> B 是正解：**把三个「台阶」一次讲清，再给出可选的调优动作与代价**——这就是 M1 基线卡里「把数字说得清」的能力。

## 要点自测

> [!question]- `df -h`、`df -H`、`lsblk -b` 的区别是什么？
> - `df -h` 用 1024 进位（GiB），`df -H` 用 1000 进位（GB），`lsblk -b` 给原始字节数。
> - 与云厂商控制台、硬盘标称对齐时用 1000 进位；写台账、做精确对账时用字节数。
> - **第一反应不要是什么**：不要把两者差出来的 7% 当成「丢盘」去报障。

> [!question]- `ls -l` 显示 1GiB，`du` 显示 100MiB，可能是什么情况？
> - 稀疏文件（虚拟机镜像、数据库数据文件常见）：只有真正写过的部分占块，其余是空洞。
> - 也可能是压缩/重删文件系统或 `reflink`（写时复制）共享了数据块。
> - **第一反应不要是什么**：不要认为 `du` 或 `ls` 有一个坏了；先看 `stat` 的 Size 与 Blocks。

> [!question]- 没有装 `sysstat`，能看 IO 吗？
> - 能：`/proc/diskstats` 有累计读写次数、扇区数、耗时；取两次快照做差值即可。
> - 设备与队列信息在 `/sys/block/<dev>/queue/`；阵列状态在 `/proc/mdstat`。
> - **第一反应不要是什么**：不要把累计值当瞬时值，也不要把「装工具」当成排障的前提。

> [!question]- 一份合格的存储基线卡至少要有什么？
> - 身份：型号、序列号、容量、介质类型（`ROTA`）、设备名。
> - 结构：分区/池/阵列/文件系统类型、UUID/LABEL、挂载点与挂载参数。
> - 水位：`df -hT`、`df -i`、LVM 水位、配额使用率。
> - 环境：发行版与内核版本、采集时间、调度器与关键参数（这些决定默认值）。
> - **第一反应不要是什么**：不要只存一份 `df -h` —— 它既没有身份信息，也没有 inode 视角。
